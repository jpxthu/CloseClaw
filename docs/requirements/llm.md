# LLM 需求

## 概述

User 可以使用多家 AI 供应商的模型进行对话和工具调用，无需关心底层协议差异，获得一致的聊天体验。

## 功能需求

### F1. 多供应商统一对话

#### 供应商配置与凭据

模型与供应商的配置内容、协议选择及调用凭据由本模块定义。调用凭据以明文字段保存在所属供应商配置中，不使用独立的统一凭据目录；明文存放不改变凭据访问保护、输入不回显与日志脱敏要求。

模型与供应商配置（含凭据）变更须重启 Gateway 后生效，重启前沿用原有已生效配置。某个供应商的配置或凭据不可用时，只影响实际依赖该供应商的模型能力，不阻止其他供应商、IM 接入或 CLI 提供无关功能；缺少可用模型时，依赖该模型的操作按失败处理，不因故障隔离而自动切换模型。

> **交叉引用**：通用明文凭据存放与保护。详见 [config §F5](config.md)（凭据存放与保护）。
> **交叉引用**：配置变更检测与重载。详见 [config §F4](config.md)（配置重载）。
> **交叉引用**：启动期配置恢复与故障隔离。详见 [config §F3](config.md)（启动容错与备份恢复）。
> **交叉引用**：重启执行与通知。详见 [daemon §F6](daemon.md)（配置触发的网关重启）。
> **交叉引用**：模型解析与调用失败。详见 [F11](#f11-session-模型选择)（Session 模型选择）与 [F12](#f12-调用失败与重试)（调用失败与重试）。

#### 供应商与账户查询

User 或 Agent 可以使用不同 AI 供应商的模型发起对话。支持的供应商包括 MiniMax、GLM（智谱）、DeepSeek、火山方舟（VolcEngine）、MiMo（小米）。

Owner 和 User 可以通过斜杠指令 `/status` 查询当前 Session 所用供应商的账户信息；每次执行均向供应商实时获取，查询项包括：

- 余额：账户可用余额（如 DeepSeek 的账户余额）
- 用量配额：套餐等级、时间窗口限额与已用百分比（如 GLM 的套餐等级与限额）

不同供应商支持的查询项不同：

- 不支持某一查询项时，系统提示该供应商不支持该项。
- 查询失败时，该项展示为不可用并给出原因。
- 上述两种情况均不影响 `/status` 的其他查询项。

账户信息以供应商 API 的实时返回为准，系统不做本地估算。

> **交叉引用**：供应商账户信息的查询入口。详见 [slash §F4](slash.md)（状态查询）。

#### 统一响应与协议选择

User 收到的响应内容在语义上是统一的：文本块、Thinking 块、Tool 调用块与 Tool 结果块。User 在使用阶段无需关心底层采用 OpenAI 协议还是 Anthropic 协议。

底层协议在模型配置阶段确定，Owner 可在供应商级或模型级的配置中覆盖默认协议选择。Owner 手动覆盖协议时，系统在 Session 启动时校验目标协议是否支持该模型声明的能力，若存在能力丢失风险，以系统消息提示 Owner，但不拒绝覆盖。

> **交叉引用**：回复内容块的展示名称与等级控制。详见 [processor_chain §F4](processor_chain.md)（出站回复展示等级控制）。
> **交叉引用**：模型与供应商配置。详见 [config §F1](config.md)（多文件配置结构）。
> **交叉引用**：生效机制分类汇总。详见 [config §F7](config.md)（生效机制与重启类判定）。
> **交叉引用**：对话历史的完整保留。详见 [session §F1](session.md)（对话持久化与恢复）。
> **交叉引用**：长对话的上下文压缩与原文保留。详见 [session §F3](session.md)（长对话压缩）。
> **交叉引用**：本模块在完整消息链路中的位置。详见 [message_flow §F1](message_flow.md)（入站链路）。

### F2. 流式实时输出

User 可以在 LLM 生成响应的过程中实时看到内容，无需等待完整响应。

流式输出中断时（指单次响应的异常终止），系统向 User 提示该响应不完整，并按以下规则决定哪些内容写入对话历史与后续上下文：

- 文本块：中断时，本次回复的全部文本（含中断前已接收的部分）不写入对话历史，也不参与后续上下文
- Thinking 块：中断时，已完整接收的推理/思考内容写入对话历史并参与后续上下文；未完整接收的部分不写入
- Tool 调用块与 Tool 结果块：中断时，已返回结果的工具调用与其结果成对写入对话历史并参与后续上下文；未返回结果的调用不写入

已写入内容与中断时保留在界面的内容，其呈现仍受展示等级约束。系统关闭等进程级终止不属于本节范围，按 daemon 模块的关闭流程处理。

> **交叉引用**：已输出内容的界面保留与出站降级。详见 [gateway §F7](gateway.md)（出站消息统一处理）。
> **交叉引用**：进程级终止时的 Session 记录处理。详见 [daemon §F3](daemon.md)（强制关闭）。
> **交叉引用**：展示的片段粒度与中断呈现。详见 [im_adapter §F4](im_adapter.md)（流式增量渲染）。
> **交叉引用**：推理/思考内容的界面呈现。详见 [F3](#f3-推理过程可见与安全)（推理过程可见与安全）。
> **交叉引用**：展示等级与中断时的过滤约束。详见 [processor_chain §F4](processor_chain.md)（出站回复展示等级控制）。

### F3. 推理过程可见与安全

User 在展示等级允许时可以看到模型的推理/思考过程。推理/思考内容对应 Thinking 块，作为独立内容块保留在对话历史中，参与后续对话的上下文。

是否向界面交付 Thinking 块由展示等级决定；允许展示时，呈现方式按界面区分：

- 终端界面：具体呈现由终端需求定义
- IM 平台：具体呈现由对应平台的适配需求定义，不要求所有平台具备相同的展示形式或交互能力

推理/思考内容仅对该对话的 User 可见，不向其他 Session 暴露。

> **交叉引用**：推理/思考内容的流式下发形态。详见 [im_adapter §F4](im_adapter.md)（流式增量渲染）。
> **交叉引用**：飞书平台的 Thinking 块呈现。详见 [im_adapter/feishu §F4](im_adapter/feishu.md)（飞书输出展示）。
> **交叉引用**：各界面的默认展示等级与过滤规则。详见 [processor_chain §F4](processor_chain.md)（出站回复展示等级控制）。
> **交叉引用**：终端的推理/思考呈现。详见 [cli §F2](cli.md)（终端输出渲染）。

### F4. 推理强度控制

#### 档位与生效范围

User 可以查询和修改当前 Session 的推理强度档位，取值为 low / medium / high / max / off，默认 high。运行时设置覆盖默认值，仅对当前 Session 生效（Session 归档恢复后仍保留），不持久化到配置。off 表示关闭推理输出。

#### off 的供应商差异

选择 off 关闭推理输出时，具体行为取决于供应商能力。部分供应商的模型总是输出推理/思考内容（如 DeepSeek 的 thinking 无法真正关闭，MiMo 在所有场景下均输出推理/思考），在这些供应商上选择 off 仅将推理/思考强度降至最低档位（即 low）。

#### 非法值与降级

当 User 输入非法档位值时，系统忽略非法输入并回显当前生效的档位。

若所选模型不具备推理能力，推理强度设置不生效，模型按无推理方式运行，不再适用档位降级。

对于 low / medium / high / max，若所选模型具备推理能力但不支持所请求的档位，系统自动降级到该模型支持的最高档位，不额外提示错误。

off 按上文「off 的供应商差异」处理。

> **交叉引用**：推理强度的指令入口。详见 [slash §F10](slash.md)（推理强度控制）。
> **交叉引用**：推理强度设置在 Session 归档恢复后的保留。详见 [session §F5](session.md)（推理强度控制）。

### F5. 工具调用

Agent 可以在对话中调用工具——系统向 AI 模型发起请求后，模型可以发出工具调用指令，系统执行后将结果返回给模型。

在工具调用的多轮交互中，系统需将最近一次模型响应中的推理/思考内容在后续请求中带回给模型，确保上下文连续性。

> **交叉引用**：可供 Agent 调用的工具清单与能力说明。详见 [tools §F1](tools.md)（工具注册与发现）。

### F6. 供应商配置向导

#### 向导流程

Owner 可以通过 CLI 交互式向导完成 LLM 供应商的初始配置，无需手动编辑配置文件。向导流程为：选择供应商 → 输入凭据（已配置可跳过） → 发现可用模型 → 选择模型 → 选择系统默认模型 → 确认并写入配置。写入完成后返回供应商选择，Owner 可继续配置其他供应商或结束向导。

凭据输入时不回显字符，输入完成后给出即时反馈告知 Owner 已接收；确认写入后，凭据以明文保存在对应供应商配置中。

#### 重复运行与模型选择

向导可重复运行。向导展示支持的供应商列表，Owner 选择本次要配置的供应商。若该供应商的凭据已配置，Owner 可以选择跳过凭据输入步骤，直接进入模型发现。

模型选择支持以下写法：

- 多选：逐一给出要选中的模型序号
- 范围语法：如 `1-3,5`
- 全选关键字：选中全部可用模型

#### 模型集合与移除

勾选结果表示本次向导执行后该供应商保留的模型集合：已配置的模型默认预选；提交勾选结果并完成二次确认后，取消勾选的模型从配置中移除。

确认页单独列出本次将被移除的模型。

被任一已注册 Agent 配置为默认主模型或子 Session 默认模型的模型不可移除。不可移除的模型在确认页提示引用的 Agent 并保持选中状态，其余模型按勾选结果写入。

除上述不可移除的模型外，本次写入后该供应商允许没有保留模型；但系统内（跨供应商）至少需保留一个模型。系统内无任何保留模型时，向导拒绝写入并提示至少保留一个模型，不进入后续步骤。

#### 系统默认模型选择

系统中尚无系统默认模型且存在保留模型时，向导必须要求指定；候选为按本次勾选结果写入后系统中保留的全部模型。

重复运行时，默认预选当前系统默认模型，Owner 可直接确认或改选；候选同样为本次写入后系统中保留的全部模型。

当前系统默认模型未被保留时，Owner 必须改选其他模型。

> **交叉引用**：系统默认模型的取值与继承规则。详见 [F11](#f11-session-模型选择)（Session 模型选择）。

#### 跳过与取消

向导中 Owner 可以随时取消，不留下中间状态文件。

凭据校验阶段失败（认证失败 / 权限不足 / 网络超时）时，Owner 可以重试，也可以跳过当前供应商。

跳过当前供应商时：

- 系统不写入该供应商的任何配置（含凭据），该供应商已有配置保持不变。
- 系统返回供应商选择步骤，Owner 可以继续选择其他供应商，或结束向导。
- 跳过不影响其他供应商已完成的配置。

系统中尚无任何供应商配置时，Owner 跳过全部供应商后系统保持未配置状态，不产生系统默认模型。

> **交叉引用**：供应商凭据配置与存放。详见 [F1](#f1-多供应商统一对话)（多供应商统一对话）。
> **交叉引用**：CLI 向导的确认、取消与非交互选项。详见 [cli §F4](cli.md)（配置向导与校验）。
> **交叉引用**：初始 Agent 的创建。详见 [agent §F5](agent.md)（初始 Agent 创建）。

### F7. 模型发现

系统在配置过程中从供应商 API 获取可用模型列表，结合内置知识库自动填充每个模型的推荐参数。推荐参数包括：

- 最大上下文窗口
- 最大输出 token 数
- 默认温度
- 是否为推理模型
- 支持的推理档位
- 推荐协议
- 支持的输入类型

推荐协议来源于内置知识库的模型元数据，配置向导据此预填默认协议。内置知识库同时提供 token 单价，用于计价。

动态探测优先——先调用供应商 API 获取最新列表。API 不可用时回退到内置知识库，并向 Owner 标注回退来源。回退后 Owner 可以选择重新发起在线发现，重新发起不设次数上限。

凭据认证失败或权限不足不属于 API 不可用，不触发内置知识库回退。向导提示具体原因并返回凭据输入步骤，Owner 可以重试或跳过当前供应商。

系统仅支持内置知识库中收录的模型，API 返回的未收录模型不会被展示。

> **交叉引用**：默认协议在供应商级或模型级的覆盖。详见 [F1](#f1-多供应商统一对话)（多供应商统一对话）。
> **交叉引用**：token 单价详见 [F9](#f9-用量统计)（用量统计）。
> **交叉引用**：凭据失败后的跳过语义。详见 [F6](#f6-供应商配置向导)（供应商配置向导）。

### F8. 缓存成本优化

系统利用供应商的缓存机制降低 API token 费用：请求前缀中不变的内容被缓存到 AI 服务端，后续请求命中缓存时仅收取少量费用。

缓存策略按供应商适配，由系统自动处理，User 仅感知到 API 费用降低效果，无需关心内部实现差异。

对于本身不提供缓存能力的供应商，系统在该 Session 首次调用该供应商时向 User 发出一次性提示，告知该供应商无缓存费用优化；同一 Session 内不再重复。

> **交叉引用**：不变内容与变化内容的划分及前缀稳定性保证。详见 [system_prompt §F7](system_prompt.md)（API 前缀缓存利用）。

### F9. 用量统计

#### 调用用量与费用

User 可以看到每次 API 调用的 token 用量和预估费用。token 用量的展示项包括：

- 输入 token 总数与输出 token 总数
- 缓存命中 token 数与缓存写入 token 数
- 缓存命中率
- 推理/思考 token 数
- 文本输出 token 数（与推理/思考 token 数分开统计）

跨多轮对话累计用量统计，Session 归档或被清理时清零；归档 Session 恢复后用量统计重新累计。如果 API 响应不携带缓存字段，缓存相关字段显示为 0。

#### 预估费用

预估费用按以下口径计算。

**单价来源**：内置知识库为模型提供输入、缓存命中、缓存写入与输出四类 token 单价。内置知识库未提供计价数据的模型，Owner 可以在模型配置中覆盖单价。

**计算方式**：预估费用 = 未缓存输入 token 数 × 输入单价 + 缓存命中 token 数 × 缓存命中单价 + 缓存写入 token 数 × 缓存写入单价 + 输出 token 总数 × 输出单价。其中未缓存输入 token 数 = 输入 token 总数 − 缓存命中 token 数 − 缓存写入 token 数，不重复计价。推理/思考 token 计入输出 token 总数、按输出单价计，不重复计价。

**分项缺失**：供应商未返回缓存命中 token 数时视为无缓存命中，未返回缓存写入 token 数时视为无缓存写入；对应部分按输入单价计。

**无法计价**：模型在内置知识库与 Owner 配置中均无单价时，预估费用显示为不可用，不显示为 0。

预估费用仅供参考，以供应商实际账单为准。

#### 缓存命中率

单次 API 调用展示的缓存命中率 = 供应商返回的缓存命中 token 数 ÷ 本次输入 token 总数 × 100%。缓存命中 token 数指供应商返回的实际命中缓存的输入 token 数。输入 token 总数包括未缓存输入、缓存命中与缓存写入，不包含输出 token；供应商的输入计数已包含缓存部分时，不再另行累加。

Session 累计缓存命中率 = 累计缓存命中 token 数 ÷ 累计输入 token 总数 × 100%，用于当前 Session 的累计用量查询。先分别累计分子和分母，再计算比值，不对各次调用的百分比取平均。

单次与累计缓存命中率均依据供应商返回的实际用量计算，不以缓存命中一致性校验中的理论参考值替代实际命中量。

#### 上下文窗口

User 可以查看当前 Session 的上下文窗口占用率（已用 token 数 ÷ 最大上下文窗口），以百分比展示。已用 token 数 = 最大上下文窗口 − 当前剩余空间，剩余空间的口径见 [session §F3](session.md)（长对话压缩）。Session 历史接近窗口上限时，系统以可视化指示向 User 展示窗口占用状态。

#### 缓存命中一致性校验

系统对每次 API 调用的缓存命中数据做一致性校验，识别供应商侧缓存异常（如本应命中的缓存前缀未命中）。

校验依据两个 token 数：本次调用的缓存命中 token 数，与上一次 API 调用的输入 token 总数。两者均取自供应商响应返回的用量数据（供应商的真实计费口径），输入 token 总数沿用「缓存命中率」的定义。上一次 API 调用的输入 token 总数作为本次校验的理论参考值，不替代本次实际命中量。系统不做本地 token 化，也不对 token 数做估算。

系统在响应同时明确返回输入 token 总数与缓存命中 token 数时逐次校验。参与比较的调用须为同一 Session 内上一次 API 调用请求的追加扩展，即 System Prompt 与历史前缀保持不变，仅在尾部追加新内容。

满足上述条件时，比较本次调用的缓存命中 token 数与上一次 API 调用的输入 token 总数：偏差 = 上一次 API 调用的输入 token 总数 − 本次调用的缓存命中 token 数，偏差的绝对值超出容忍余量即判定为缓存异常。容忍余量足够覆盖 token 边界对齐等细微差异，避免误报。容忍余量的口径由设计定义。

以下情形不参与校验，以免误报：

- 请求前缀未保持不变的调用（对话压缩、历史被改写、流式中断导致的历史前缀变化、System Prompt 变化）
- 供应商不提供缓存能力的调用
- 响应不同时返回输入 token 总数与缓存命中 token 数的调用

判定为缓存异常时，系统记录降级告警日志；若当前 User 为 Owner，另向 Owner 发送系统通知。校验逐次调用即时进行，每条缓存异常独立上报，不做去重。

涉及缓存命中数值口径的需求，须以真实采集的供应商响应数据为准。实测采集样本与结论见仓库内 `tests/fixtures/llm/`（含 README，字段语义与缓存数值粒度以该目录实测记录为准）。

### F11. Session 模型选择

#### 模型配置

Owner 可以为每个 Agent 分别配置默认主模型与子 Session 默认模型，两项均可缺省。两项均为 config 中对应 Agent 配置档案的模型选择项。

系统默认模型是 config 中模型定义的全局配置项，由 Owner 在首次配置向导中从系统中保留的全部模型中选择，后续通过重复运行配置向导修改。

#### Agent 默认主模型

给定 Agent ID 时，系统使用该 Agent 配置的默认主模型；未配置时使用系统默认模型。主 Session 直接采用该结果。

#### 子 Session 模型

子 Session 的模型按以下规则确定：

1. spawn 指定了模型：直接使用指定模型，不再读取 Agent 配置。
2. 未指定模型：取目标 Agent 配置的子 Session 默认模型。
3. 目标 Agent 未配置子 Session 默认模型：使用该 Agent 的默认主模型。
4. 目标 Agent 也未配置默认主模型：使用系统默认模型。

系统默认模型不存在时，模型解析失败，系统提示 Owner 完成供应商与系统默认模型配置。

### F12. 调用失败与重试

系统对 LLM API 调用失败按错误类型处理：

- 瞬时错误（限流、网络超时、供应商 5xx）：系统自动重试，采用指数退避。
- 认证失败、计费/配额错误、非法请求：不重试。
- 上下文溢出：按 session §F3 的上下文溢出兜底处理，不适用本节重试规则。
- 其他错误：不重试。

重试耗尽后，系统向 User 明确提示失败，不自动切换为其他模型。重试次数、退避参数与超时阈值由设计确定。

> **交叉引用**：调用失败的日志记录。详见 [F10](#f10-调试日志)（调试日志）。
> **交叉引用**：上下文溢出兜底。详见 [session §F3](session.md)（长对话压缩）。

### 性能

- 流式输出实时呈现，User 无需等待完整响应
- 对提供缓存能力的供应商，系统维持对话中不变内容的高缓存命中率，费用优化效果随连续对话保持稳定

> **交叉引用**：流式行为。详见 [F2](#f2-流式实时输出)（流式实时输出）。

> **交叉引用**：缓存命中一致性校验。详见 [F9](#f9-用量统计)（用量统计）。

### 可用性

- 配置向导中凭据校验失败时，系统给出明确的错误原因（认证失败 / 权限不足 / 网络超时），允许 Owner 重试或跳过当前供应商
- 模型发现 API 不可用时自动回退到内置知识库，不阻塞配置流程
- 单次响应中断时，已输出内容保留在界面（呈现受展示等级约束），并展示错误提示（不含系统关闭等进程级终止）

- 凭据输入时不回显字符

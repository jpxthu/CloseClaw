# LLM 模块需求

## 概述

User 可以使用多家 AI 供应商的模型进行对话和工具调用，无需关心底层协议差异，获得一致的聊天体验。

## 功能需求

### F1. 多供应商统一对话

#### 供应商与账户查询

User 或 Agent 可以使用不同 AI 供应商的模型发起对话。支持的供应商包括 MiniMax、GLM（智谱）、DeepSeek、火山方舟（VolcEngine）、MiMo（小米）。

User 可以查询供应商账户的余额（如 DeepSeek）或用量配额（如 GLM 的套餐等级、时间窗口限额和已用百分比）。

#### 统一响应与协议选择

User 收到的响应内容在语义上是统一的：文本块、Thinking 块、Tool 调用块与 Tool 结果块。User 在使用阶段无需关心底层采用 OpenAI 协议还是 Anthropic 协议。

底层协议在模型配置阶段确定，User 可在供应商级或模型级的配置中覆盖默认协议选择。User 手动覆盖协议时，系统在 Session 启动时校验目标协议是否支持该模型声明的能力，若存在能力丢失风险，以系统消息提示 User，但不拒绝覆盖。

> **交叉引用**：回复内容块的展示名称与等级控制详见 [processor_chain §F4](processor_chain.md)（出站回复展示等级控制）。
> **交叉引用**：模型与供应商配置详见 [config §F1](config.md)（多文件配置结构）。
> **交叉引用**：模型定义与凭据变更属重启生效类，生效机制详见 [config §F7](config.md)（生效机制与重启类判定）。
> **交叉引用**：模型定义与凭据变更的检测及自动重启触发详见 [config §F4](config.md)（配置重载）。
> **交叉引用**：对话历史的完整保留详见 [session §F1](session.md)（对话持久化与恢复）。
> **交叉引用**：长对话的上下文压缩与原文保留详见 [session §F3](session.md)（长对话压缩）。

### F2. 流式实时输出

User 可以在 LLM 生成响应的过程中实时看到内容，无需等待完整响应。

流式输出过程中如果发生错误，系统向 User 提示该响应不完整，已输出的文本片段保留在界面上继续展示。不完整的文本回复不写入对话上下文。已累积的推理/思考内容保留在对话历史中参与后续上下文；其界面展示仍受展示等级约束。

> **交叉引用**：展示的片段粒度与中断呈现详见 [im_adapter §F4](im_adapter.md)（流式增量渲染）。
> **交叉引用**：推理/思考内容的界面呈现详见 [F3](#f3-推理过程可见与安全)（推理过程可见与安全）。
> **交叉引用**：出站降级处理详见 [gateway §F7](gateway.md)（出站消息统一处理）。
> **交叉引用**：展示等级与中断时的过滤约束详见 [processor_chain §F4](processor_chain.md)（出站回复展示等级控制）。

### F3. 推理过程可见与安全

User 可以看到模型的推理/思考过程。推理/思考内容作为独立内容块保留在对话历史中，参与后续对话的上下文。

推理/思考内容对应 Thinking 块。是否向界面交付该块由展示等级决定；允许展示时，呈现方式按界面区分：

- 终端界面：具体呈现由终端需求定义
- IM 平台：渲染为折叠推理区块，User 可展开查看完整内容

> **交叉引用**：推理/思考内容的流式下发形态详见 [im_adapter §F4](im_adapter.md)（流式增量渲染）。
> **交叉引用**：各界面的默认展示等级与过滤规则详见 [processor_chain §F4](processor_chain.md)（出站回复展示等级控制）。
> **交叉引用**：终端的推理/思考呈现详见 [cli §F2](cli.md)（终端输出渲染）。

推理/思考内容仅对该对话的 User 可见，不向其他 Session 暴露。

### F4. 推理强度控制

User 可以调整模型的推理/思考强度档位（low / medium / high / max），默认 high；也可以选择 off 关闭推理输出。

User 可以查询和修改当前 Session 的推理强度档位；修改仅对当前 Session 生效，不持久化到配置。

选择 off 关闭推理输出时，具体行为取决于供应商能力：部分供应商的模型在设计上总是输出推理/思考内容（如 DeepSeek 的 thinking 无法真正关闭，MiMo 在所有场景下均输出推理/思考），在这些供应商上选择 off 仅将推理/思考强度降至最低档位。

当 User 输入非法档位值时，系统忽略非法输入并回显当前生效的档位。

对于 low / medium / high / max，若所选模型不支持所请求的档位，系统自动降级到该模型支持的最高档位，不打扰 User；off 按上文的专门规则处理。

> **交叉引用**：推理强度的指令入口详见 [slash §F10](slash.md)（推理强度控制）。
> **交叉引用**：推理强度设置在 Session 归档恢复后的保留详见 [session §F5](session.md)（推理强度控制）。

### F5. 工具调用

Agent 可以在对话中调用工具——系统向 AI 模型发起请求后，模型可以发出工具调用指令，系统执行后将结果返回给模型。

在工具调用的多轮交互中，系统需将最近一次模型响应中的推理/思考内容在后续请求中带回给模型，确保上下文连续性。

> **交叉引用**：可供 Agent 调用的工具清单与能力说明详见 [tools §F1](tools.md)（工具注册与发现）。

### F6. 供应商配置向导

Owner 可以通过 CLI 交互式向导完成 LLM 供应商的初始配置，无需手动编辑配置文件。向导流程为：选择供应商 → 输入凭据 → 发现可用模型 → 选择模型 → 确认并写入配置。

凭据输入时不回显字符，输入完成后给出即时反馈告知 Owner 已接收。

向导可重复运行。若供应商和凭据均已配置，再次运行时自动跳过供应商选择和凭据输入步骤，直接从模型发现步骤开始。再次运行时已配置的模型默认预选。Owner 取消选择某个模型后，该模型不会从已有配置中删除。

模型选择支持多选、范围语法（如 `1-3,5`）和全选关键字。

向导中 Owner 可以随时取消，不留下中间状态文件。

> **交叉引用**：凭据存储详见 [config §F5](config.md)（凭据安全隔离）。
> **交叉引用**：CLI 向导的确认、取消与非交互选项详见 [cli §F4](cli.md)（配置向导与校验）。

### F7. 模型发现

系统在配置过程中可以自动从供应商 API 获取可用模型列表，结合内置知识库自动填充每个模型的推荐参数（上下文窗口大小、最大输出 token 数、默认温度、是否为推理模型、推荐协议、支持的输入类型等）。

推荐协议来源于内置知识库的模型元数据，配置向导据此预填默认协议，User 可在供应商级或模型级的配置中覆盖默认协议选择。

动态探测优先——先调用供应商 API 获取最新列表。API 不可用时回退到内置知识库，并向 User 标注回退来源。

系统仅支持内置知识库中收录的模型，API 返回的未收录模型不会被展示。

### F8. 缓存成本优化

系统利用供应商的缓存机制降低 API token 费用：请求前缀中不变的内容被缓存到 AI 服务端，后续请求命中缓存时仅收取少量费用。

> **交叉引用**：不变内容与变化内容的划分及前缀稳定性保证详见 [system_prompt §F7](system_prompt.md)（API 前缀缓存利用）。

缓存策略按供应商适配，由系统自动处理，User 仅感知到 API 费用降低效果，无需关心内部实现差异。

对于本身不提供缓存能力的供应商，系统在 Session 首次使用时向 User 发出一次性提示，告知该供应商无缓存费用优化；后续不再重复。

### F9. 用量统计

#### 调用用量与费用

User 可以看到每次 API 调用的 token 用量和预估费用，展示项包括：

- 输入与输出 token 数
- 缓存命中 token 数与缓存写入 token 数
- 缓存命中率
- 推理消耗的 token 数，与文本输出 token 分开统计

预估费用基于模型单价计算，仅供参考，以供应商实际账单为准。

跨多轮对话累积用量统计，Session 结束时清零。如果 API 响应不携带缓存字段，缓存相关字段显示为 0。

#### 缓存命中率

展示的缓存命中率 = 供应商返回的实际缓存命中 token 数 ÷ 输入 token 总数 × 100%。输入 token 总数包括未缓存输入、缓存读取与缓存写入，不包含输出 token；供应商的输入计数已包含缓存部分时，不重复相加。

Session 累计命中率 = 累计实际缓存命中 token 数 ÷ 累计输入 token 总数 × 100%。先分别累计分子和分母，再计算比值，不对各次调用的百分比取平均。

展示值依据供应商返回的实际用量计算，不以缓存命中一致性校验中的理论参考值替代实际命中量。

#### 上下文窗口

User 可以查看当前 Session 的上下文窗口占用率（已用 token 数 / 最大上下文窗口，含使用百分比）。Session 历史接近窗口上限时，系统以可视化指示向 User 展示窗口占用状态。

#### 缓存命中一致性校验

系统对每次 API 调用的缓存命中数据做一致性校验，识别供应商侧缓存异常（如本应命中的缓存前缀未命中）。

校验依据的两个 token 数——本次调用的缓存命中 token 数与上一轮调用的输入 token 数——均直接取自供应商响应返回的用量数据（供应商的真实计费口径）。系统不做本地 token 化，也不对 token 数做估算。

系统在响应同时明确返回输入 token 总数与缓存命中 token 数时逐次校验。参与比较的调用须为同一 Session 内上一轮调用请求的追加扩展，即 System Prompt 与历史前缀保持不变，仅在尾部追加新内容。

满足上述条件时，比较本次调用的缓存命中 token 数与上一轮调用的输入 token 总数；偏差超出容忍范围即判定为缓存异常。容忍余量足够覆盖 token 边界对齐等细微差异，避免误报。判定阈值与容忍余量的口径由设计文档定义。

以下情形不参与校验，以免误报：

- 请求前缀未保持不变的调用（对话压缩、历史被改写、System Prompt 变化）
- 响应不同时返回输入 token 总数与缓存命中 token 数的调用

判定为缓存异常时，若当前 User 为 Owner，系统向 Owner 发送系统通知，并记录错误日志。校验逐次调用即时进行，每条缓存异常独立上报，不做去重。

> **交叉引用**：错误日志的级别详见 [debug_log §F2](debug_log.md)（分层日志级别）。

涉及缓存命中数值口径的需求，须以真实采集的供应商响应数据为准。实测采集样本与结论见仓库内 `tests/fixtures/llm/`（含 README，字段语义与缓存数值粒度以该目录实测记录为准）。

> **交叉引用**：斜杠指令查询用量统计的展示项详见 [slash §F4](slash.md)（状态查询）。
> **交叉引用**：上下文窗口的压缩告警与阈值详见 [session §F3](session.md)（长对话压缩）。

### F11. Session 模型选择

Owner 可以为每个 Agent 配置默认 LLM 模型，以及该 Agent 创建子 Session 时使用的默认模型。

模型调用失败时向 User 明确提示失败，不自动切换为其他模型。

子 Session 的最终模型按以下优先级确定：spawn 显式指定的模型 > 父 Agent 配置中的子 Session 默认模型 > 目标 Agent 配置的默认模型 > 系统默认模型。

> **交叉引用**：Agent 模型选择配置的生效边界详见 [session §F1](session.md)（对话持久化与恢复）。
> **交叉引用**：模型配置在 Agent 档案中的承载维度详见 [agent §F1](agent.md)（Agent 配置档案）。
> **交叉引用**：spawn 的模型覆盖参数详见 [session §F4](session.md)（子 Session 委托与协调）。
> **交叉引用**：配置变更的检测与重载详见 [config §F4](config.md)（配置重载）。

## 非功能需求

### 性能

- 流式输出实时呈现，User 无需等待完整响应
- 对话中不变内容的缓存维持高命中率，费用优化效果随连续对话保持稳定

> **交叉引用**：流式行为详见 [F2](#f2-流式实时输出)（流式实时输出）。
> **交叉引用**：缓存优化详见 [F8](#f8-缓存成本优化)（缓存成本优化）。
> **交叉引用**：缓存命中一致性校验详见 [F9](#f9-用量统计)（用量统计）。

### 可用性

- 配置向导中凭据输入失败时，给出明确的错误原因（认证失败 / 网络超时 / 权限不足），允许 User 重试或跳过
- 模型发现失败时自动回退到内置知识库，不阻塞配置流程
- 流式输出中断时保留已输出内容，并展示错误提示

> **交叉引用**：模型发现的回退行为详见 [F7](#f7-模型发现)（模型发现）。
> **交叉引用**：流式中断行为详见 [F2](#f2-流式实时输出)（流式实时输出）。

### 可靠性

- 系统为每个模型选择适用的协议；当 User 手动覆盖协议导致能力丢失风险时，系统在 Session 启动时提示 User，避免能力静默丢失
- User 选择 off 关闭推理输出时，供应商不支持关闭的不视为错误——系统降至最低档位

> **交叉引用**：协议覆盖提示详见 [F1](#f1-多供应商统一对话)（多供应商统一对话）。
> **交叉引用**：推理强度与 off 的处理详见 [F4](#f4-推理强度控制)（推理强度控制）。

### 安全性

- 推理/思考内容仅对该对话的 User 可见，不向其他 Session 暴露
- 凭据输入时不回显字符

> **交叉引用**：推理内容的隔离原则详见 [F3](#f3-推理过程可见与安全)（推理过程可见与安全）。
> **交叉引用**：凭据的存储与安全隔离详见 [config §F5](config.md)（凭据安全隔离）。

### 可观测性

- User 可查询累积 token 用量和缓存命中率统计
- API 调用失败时，错误原因和上下文可通过调试日志查看

> **交叉引用**：日志事件详见 [F10](#f10-调试日志)（调试日志）。

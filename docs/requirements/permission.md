# Permission 需求

## 概述

Owner 需要按 Agent 与 User 身份限定操作权限，为文件访问范围和命令执行提供可控的审批通道，并以沙盒强制落实文件访问边界。

Agent 工具调用与命令执行（含后台任务）受本模块的权限控制；Owner 通过 `/exec` 执行命令的豁免见 [F4](#f4-owner-特权)。系统自身行为（Session 管理、消息路由、系统提示构建，以及状态查询、设置等非命令类斜杠指令）不经过权限评估。

## 功能需求

### F1. 身份体系

Owner 需要系统区分两种独立身份。

#### Agent 身份

每个 Agent 有独立的权限边界，其操作始终在某个 User 上下文中执行。新建 Agent 的默认权限：

- 默认具备：收发消息
- 默认具备：自身 Agent workspace 的读写能力；Agent-User workspace 的强制授权与 AGENTS.md 修改保护见 [F3](#f3-权限决策模型)
- 默认具备：在沙盒内执行不在白名单也不在黑名单的命令（结构解析无法确定者除外，见 [F2](#f2-权限维度)、[F12](#f12-沙盒)）
- 默认具备：按自身配置档案的工具范围调用工具（范围与默认工具见 [tools §F1](tools.md)（工具注册与发现））
- 默认拒绝：上述两类 workspace 之外的读、写
- 默认拒绝：在宿主上执行的命令（默认命令白名单为空）
- 默认拒绝：黑名单内的命令（命令黑名单默认为空）
- 默认拒绝：网络访问、配置写入
- 权限不足时的直接拒绝与审批条件见 [F5](#f5-审批工作流)。

#### User 身份

- IM 用户 ↔ User 的绑定规则与基数详见 [config §F1](config.md)（多文件配置结构）；CLI 渠道不参与绑定，其 User 上下文恒为 Owner（见 [cli §F1](cli.md)（终端对话））。
- User 由 Owner 在权限配置中直接添加，不存在自助注册与注册审批；新建 User 默认无任何权限，收发消息也需 Owner 显式授予。
- 未注册用户在任何入口（IM 私聊、群聊提及等）发起的消息都不产生任何响应——不回复、不提示，也不因此创建 User。
- 已注册但没有收发消息权限的 User 同样静默，不产生任何响应。
- Agent-User workspace 强制授权（见 [F3](#f3-权限决策模型)）在无收发消息权限时不构成可交互能力。
- 不区分用户组，所有权限以个人为单位。

Owner 的 User ID 固定为 `owner`。

#### 初始 Agent 例外

初始 Agent 是上述默认权限的例外，例外由其权限配置提供。权限配置不可用时的加载容错统一遵循 [F6](#f6-权限配置管理)（权限配置管理）。

- 七个权限维度全部开放，黑名单命令与 [F7](#f7-高风险操作管控) 的全部高风险文件访问限制对初始 Agent 同样生效。
- 沙盒模式为放行模式，该基线属高风险模式，见 [F12](#f12-沙盒)（沙盒）。
- 权限配置文件的访问限制见 [F4](#f4-owner-特权)（Owner 特权）。

#### User 上下文来源

User 上下文由场景决定：

- IM 消息：来自发送者
- CLI 渠道：恒为 Owner（见 [cli §F1](cli.md)（终端对话））
- 子 Session：继承父 Session 的 User 上下文

> **交叉引用**：IM 消息的发送者标识等入站归一化字段。详见 [im_adapter §F2](im_adapter.md)（入站消息归一化）。
> **交叉引用**：机器人 ↔ Agent、IM 用户 ↔ User 两类双向绑定（含入站/出站方向与基数规则）的权威定义与存储。详见 [config §F1](config.md)（多文件配置结构）。
> **交叉引用**：同一人在多个机器人语境下的平台标识归并。详见 [message_flow §F3](message_flow.md)（跨机器人身份归并）。
> **交叉引用**：消息路由到 Agent。详见 [gateway §F4](gateway.md)（普通消息路由到对话）。
> **交叉引用**：平台、发送者、会话对端、账号四项标识共同确定主 Agent Session。详见 [session §F1](session.md)（对话持久化与恢复）。
> **交叉引用**：平台身份标识按接收方应用语境取值、跨应用隔离（如飞书 open_id）。详见 [im_adapter/feishu §F1](im_adapter/feishu.md)（飞书入站消息接收）。
> **交叉引用**：初始 Agent 的创建规则。详见 [agent §F5](agent.md)（初始 Agent 创建）。
> **交叉引用**：Agent 的工具范围与默认工具。详见 [tools §F1](tools.md)（工具注册与发现）。

### F2. 权限维度

Owner 需要七个独立管理的权限维度。

#### 读

控制 Agent 可读取的文件和目录范围。范围由沙盒以操作系统级强制，放行模式的差异见 [F12](#f12-沙盒)（沙盒）。

#### 写

控制 Agent 可写入的文件和目录范围。范围由沙盒以操作系统级强制，放行模式的差异见 [F12](#f12-沙盒)（沙盒）。写权限包含读权限（能写必然能读），读权限不包含写权限。

#### 工具调用

控制 Agent 能否调用某个工具。仅符合工具调用格式的 LLM 输出会进入工具模块，格式解析先于权限评估；工具调用行为见 [llm §F5](llm.md)（工具调用）。Agent 通过工具进行的文件读写由读/写维度评估，本维度不重复评估。

- 可用工具集合 = 配置档案的工具范围 ∩ 本维度允许调用的工具；本维度规则只能收窄该范围，不能扩大。
- spawn 工具是唯一例外：该 Agent 生效的层级深度大于 0 时，spawn 工具强制开放，不受工具白名单、工具黑名单与本维度规则的收窄。层级深度与其他创建控制仍由 [session §F4](session.md)（子 Session 委托与协调）定义。

#### 收发消息

控制 User 与 Agent（LLM）之间的消息往来：User 消息送入 LLM，以及 LLM 与工具发往 User 的消息。该维度在所有渠道一致生效；Owner 作为调用方时其 User 侧规则被豁免（见 [F4](#f4-owner-特权)）。

#### 网络访问

控制 Agent 可访问的网络资源（主机、端口），默认拒绝所有网络访问。沙盒内的命令无法访问网络，本维度作用于以下两类请求。

##### 在宿主上执行的命令

命令执行前按本维度判定网络访问。命令列入白名单或已获准在宿主上执行，均不代替网络授权；网络权限不足直接拒绝，不进入审批。

放行模式下命令缺省在宿主上执行且不进入审批，这类命令的网络访问不受本维度约束，属于放行模式的高风险基线。

##### 工具发起的网络访问

工具自身的网络请求同样受本维度约束。

#### 配置写入

控制 Agent 能否写入 CloseClaw 的业务配置文件（配置文件类别见 [config §F1](config.md)（多文件配置结构））。默认拒绝，本维度权限不足直接拒绝，不进入审批。

具备本维度权限后，对业务配置文件的写入仍按 [F7](#f7-高风险操作管控) 的高风险文件访问限制处理。

权限配置文件不在本维度范围内，对任何 Agent 一律不可读写（见 [F4](#f4-owner-特权)）。凭据文件的独立保护要求见 [config §F5](config.md)（凭据安全隔离）。

> **交叉引用**：记忆配置的独立访问限制。详见 [memory §F7](memory.md)（记忆挖掘的开关与参数配置）。

AGENTS.md 不属于本维度覆盖的业务配置文件，其修改权限由 [F4](#f4-owner-特权) 定义。

#### 命令行

控制 Agent 可执行的命令，覆盖工具调用发起的命令与后台任务中的命令执行。Owner 通过斜杠指令执行命令的豁免见 [F4](#f4-owner-特权)。黑名单与白名单并存，同一命令同时列入两表时黑名单优先。

命令的处理顺序固定为：黑名单 → 结构解析 → 白名单 → 沙盒模式与执行位置。本维度补充以下规则：

- 执行位置：缺省由沙盒模式决定；Agent 可在单次调用中显式指定执行位置（见 [F12](#f12-沙盒)）。
- 白名单：以「可执行文件 + 参数前缀」为粒度授权——同一可执行文件可按不同参数前缀分别列入白名单或黑名单（如 `git status` 列入白名单、`git push` 列入黑名单）；白名单命令在宿主上执行无需审批。
- 审批：非白名单命令请求在宿主上执行时进入审批（仅默认模式；严格模式直接拒绝，放行模式无需审批）。
- 结构解析：命令在执行前经过结构解析（见 [tools §F8](tools.md)（命令结构解析））。解析无法确定的命令按沙盒模式分流：
  - 默认模式：进入审批
  - 严格模式：一律拒绝（含无法确定是否属于白名单的命令）
  - 放行模式：不进入审批，按该调用指定的执行位置执行（未指定时缺省在宿主上执行）
- 解释器类命令（Shell 等脚本解释器）与特权类命令（如 `sudo`）不得加入白名单，否则沙盒约束失效：请求将它们加入白名单时直接拒绝，审批提示不提供该选项。
- 严格模式与放行模式的差异见 [F12](#f12-沙盒)。

### F3. 权限决策模型

Owner 需要 Agent 维度和 User 维度的交集决策：操作只有在双方都允许时才放行，任一方拒绝即拒绝。

#### 两类 workspace

**Agent workspace** 的读写在 Agent 维度默认具备，但实际操作仍受当前 User 权限约束，不构成跨 User 的无条件放行；AGENTS.md 的修改另受 F4 的专属保护。

**Agent-User workspace** 是每个 Agent-User 组合的独立目录，位于操作系统标准配置目录下，由系统自动创建和管理。其强制授权仅覆盖该组合的专属目录，不能因路径层级关系而扩展到 Agent workspace 共用文件或其他 User 的目录。

#### 决策顺序

权限配置文件保护与 AGENTS.md 修改保护优先于下列放行路径，见 F4；受沙盒约束的操作仍须满足 F12 的引擎可用性要求。

放行优先级：

1. 本次操作所需的其它权限维度均满足后，属 [F7](#f7-高风险操作管控) 高风险范围的文件访问只能单次放行，不经其它任何放行路径；其它权限不足不得通过该审批补齐。Owner 的斜杠指令命令执行豁免（见 [F4](#f4-owner-特权)）不受本条约束。
2. 未命中时，Agent-User 组合对其专属 Agent-User workspace 路径的读写自动放行，不受任何拒绝规则影响（含沿 spawn 链路传播的拒绝）；该强制授权不适用于 Agent workspace。
3. 其余操作按 Agent 维度与 User 维度的交集决策；Owner 作为调用方时跳过 User 维度（见 [F4](#f4-owner-特权)）。

权限评估不沿用历史结果：Agent 的每次操作都按当前生效规则重新评估，不缓存评估结论。规则变更即时生效以此机制为前提，热加载详见 [F6](#f6-权限配置管理)。

> **交叉引用**：操作系统标准配置目录的位置。详见 [platform §F2](platform.md)（操作系统标准配置目录）。
> **交叉引用**：Agent workspace 的定义与归属。详见 [agent §F7](agent.md)（Agent workspace）。
> **交叉引用**：AGENTS.md 的位置与加载。详见 [system_prompt §F1](system_prompt.md)（身份与行为准则定义）。

### F4. Owner 特权

本节调用方以 [F1](#f1-身份体系) 的 User 上下文来源为准。

#### 通用特权

Owner 在权限决策中享有以下特权：

- **User 维度豁免**：Owner 作为调用方时，跳过所有 User 维度规则，仅评估 Agent 维度。这意味着 Owner 不会被 User 规则拦截，只受该 Agent 自身权限边界的限制。
- **权限配置独占**：权限规则的修改仅 Owner 可进行——通过权限指令新增、在审批时以「加入白名单」新增，或直接修改权限配置文件删除（见 [F6](#f6-权限配置管理)）。权限配置文件对任何 Agent（含初始 Agent）一律不可读写，不进入审批，也不存在放行路径。
- **审批独占**：所有审批请求只推送给 Owner，非 Owner User 没有审批权力；Owner 的审批决策（单次放行 / 加入白名单 / 拒绝）见 [F5](#f5-审批工作流)。
- **命令执行豁免**：Owner 通过 `/exec` 斜杠指令执行的命令默认放行——不进入权限评估与审批流程，不受沙盒约束，也不受 Agent 维度的命令规则与沙盒模式约束（含严格模式下仅白名单可执行的限制）。
  - 唯一例外是被列入黑名单的命令：对 Owner 同样一律拒绝、不进入审批。
  - `/exec` 仅 Owner 可用（见 [slash §F8](slash.md)（命令执行））。

Owner 通过 Agent 发起的操作仍按 [F5](#f5-审批工作流) 判断直接拒绝或进入审批；非命令类斜杠指令（含审批指令与权限指令 `/perm`）不进入权限评估（见概述），审批通道始终可被 Owner 使用。

#### AGENTS.md 修改独占

Owner 与某个 Agent 对话时，可以让该 Agent 修改其自身的 AGENTS.md。

当前操作的 User 上下文非 Owner 时，不得修改 AGENTS.md，直接按写权限拒绝，不进入审批。Agent 拥有 Agent workspace 的权限不代替 Owner 身份。

该限制对所有 Agent（含初始 Agent）生效，不因允许规则、白名单、两类 workspace 的授权、命令执行方式或沙盒模式放宽。

> **交叉引用**：AGENTS.md 的内容、固定位置与自动加载。详见 [system_prompt §F1](system_prompt.md)（身份与行为准则定义）。
> **交叉引用**：修改内容进入 System Prompt 的时机。详见 [system_prompt §F6](system_prompt.md)（内容缓存与自动刷新）。

### F5. 审批工作流

审批仅用于 Agent 的文件访问范围与命令执行授权，不是其它权限不足的替代授权入口。

#### 审批触发

只有本次操作所需的其它权限均已满足，文件访问或命令执行才可按下方条件进入审批。

**直接拒绝，不进入审批**：

- 黑名单命令（见 [F2](#f2-权限维度)）
- 严格模式下白名单外的命令、结构解析无法确定的命令，以及它们在宿主上执行的请求（见 [F12](#f12-沙盒)）
- 沙盒引擎不可用或初始化失败时，受沙盒约束的操作（见 [F12](#f12-沙盒)）
- 子 Session 中权限不足的操作：直接返回拒绝结果，不创建审批请求、不通知 Owner（见 [F9](#f9-子-session-权限继承)）
- 工具不在该 Agent 的可用范围内——不在配置档案的工具范围，或被工具调用维度规则收窄（spawn 例外见 [F2](#f2-权限维度)；Agent 侧提示见 [tools §F12](tools.md)（权限拒绝提示））
- 收发消息维度的权限不足，入站消息的静默要求见 [F1](#f1-身份体系)
- 网络访问、配置写入维度的权限不足
- 权限配置文件的访问（见 [F4](#f4-owner-特权)）
- 非 Owner User 上下文中对 AGENTS.md 的修改（见 [F4](#f4-owner-特权)）

**进入审批**：

- 非白名单命令请求在宿主上执行（仅默认模式；放行模式下命令缺省即在宿主上执行，无需审批）
- 默认模式下命令结构解析无法确定的命令（严格模式与放行模式下的处置见 [F2](#f2-权限维度)；解析口径见 [tools §F8](tools.md)（命令结构解析））
- Agent 文件读写超出实际生效的读/写路径范围（含被读写规则拒绝的操作，见 [F12](#f12-沙盒)），以及 [F7](#f7-高风险操作管控) 要求单次放行的高风险文件访问

符合审批条件的操作自动创建审批请求并推送给 Owner。

#### 重复申请处理

同一个 Agent-User 组合下存在未决审批时，操作类型与参数相同的重复申请仍按当前生效规则重新评估：

- 重新评估后已允许：直接放行。
- 仍被拒绝：直接返回拒绝结果，不复用也不延长已有的审批请求，不重复推送审批。

审批完成后，Agent 可重新发起同一操作。

#### 审批请求内容

推送的审批请求需包含：

- 发起操作的 Agent ID
- 当前 User ID
- 操作类型和参数
- Agent 与 User 对本次操作的实际权限现状，明确指出哪一方缺少授权；不适用或已豁免的一方明确标注为「不适用」或「已豁免」，不展示为缺少权限
- 是否属于高风险操作
- 审批单号
- 审批指令的用法提示（含审批单号的写法）

审批单号全局唯一，跨会话与跨渠道均有效，不按会话重新编号。

审批提示不展示风险等级分级，也不包含 Agent 撰写的操作用途说明；「是否属于高风险操作」按 [F7](#f7-高风险操作管控) 的判定口径。

#### 投递

审批请求的投递目标与平台回退见 [gateway §F7](gateway.md)（出站消息统一处理）。Owner 在任意会话发出的审批指令均按审批单号命中对应请求，与发出指令的会话无关；CLI 终端内的审批提示与终端内审批见 [cli §F1](cli.md)（终端对话）。

#### Owner 决策

Owner 通过审批指令表达决策。IM 审批提示与 CLI 终端提示两个入口均走同一审批处理逻辑。

Owner 不需手动选择 Agent 或 User 作为放行主体。接受审批时，系统依据当前实际权限，为缺少授权的一方或双方补足本次所需的文件访问或命令授权；已有授权覆盖的范围不重复授权。

Owner 可做出三种决策：

- **单次放行**：仅放行本次操作，不写入权限规则。被放行的文件访问在本次调用中不受沙盒范围限制，调用结束即失效，不改变后续调用的边界。
- **加入白名单**：写入权限配置，只为尚未被现有授权覆盖的范围新增允许规则。
- **拒绝**：不修改权限，并返回本次操作的权限拒绝。

命令类操作只涉及 Agent 维度，命令白名单属于 Agent 维度资产；Owner 自身作为调用方时 User 维度已豁免。文件访问的主体与范围仍按 [F3](#f3-权限决策模型) 决定，审批不额外授予其它权限维度。

#### 等待机制

##### 等待范围与时长

Agent 一轮调用多个工具时，有权限的工具可先执行；符合审批条件的工具调用进入等待状态，等待 Owner 审批，其余被拒绝的调用直接返回拒绝结果。

审批不设等待上限，也不超时，直到 Owner 作出决策。等待只作用于发起该操作的那一次工具调用：同一轮中的其他工具调用照常执行并返回结果，不因一条审批未决而整体停摆。

##### 等待期间的交互

等待期间不向 Agent 返回任何提示——不提示「等待审批」，也不提示「先做别的工作」；该次工具调用保持挂起。

Agent 在非 Owner User 上下文中发起的操作进入审批等待时，系统向该 User 发送最小化通知，告知操作正在等待 Owner 授权，不展示审批单号或敏感操作参数；该通知不进入 Agent 上下文，也不写入对话历史。

##### 等待结束与重新评估

等待结束时 Agent 只看到两种结果之一：工具执行结果；或仅报被拒绝权限维度的权限拒绝（见 [F8](#f8-安全边界)）。不出现「审批未通过」「审批超时」「Owner 未批准」一类字样。

Owner 审批完成后，被放行的调用继续执行，执行结果按该工具通常的返回方式返回；未被放行的调用按上述权限拒绝返回。

Owner 同意放行时，按其作出决策那一刻的当前生效规则重新评估并按上方「Owner 决策」处理，不为新规则已覆盖的范围重复授权；若按当前规则已属上方「直接拒绝」场景，则直接返回拒绝。

#### 运维边界

- 正常关闭或重启时，未决审批按强制中止处理：清空等待中的审批请求，并向对应 Agent 返回权限拒绝（只报被拒绝的权限维度，见 [F8](#f8-安全边界)）。
- 同一审批单号的重复决策只第一次生效，后续返回「已处理」，不改变已生效的结果。
- 对不存在的单号发出审批指令，返回明确错误。

> **交叉引用**：审批指令的语法与 Immediate 标记。详见 [slash §F13](slash.md)（审批指令）。
> **交叉引用**：权限配置的生效机制与重载。详见 [config §F4](config.md)（配置重载）。

### F6. 权限配置管理

Owner 需要灵活高效地管理权限规则。

#### 规则构成

一条权限规则由规则主体（Agent 或 User）、作用维度、生效对象、决策结果（允许 / 拒绝）四项构成。

##### 各维度的生效对象形态

- 读、写：文件系统路径
- 命令行：可执行文件 + 参数前缀
- 工具调用：工具名
- 网络访问：主机与端口
- 收发消息、配置写入：不细分对象，规则直接作用于该维度

##### 规则主体的限制

命令行与工具调用两个维度只能以 Agent 为规则主体。命令执行不作为 User 维度的权限项，`/exec` 斜杠指令的可用范围见 [slash §F8](slash.md)（命令执行）。工具范围配置由 Agent 档案承载，其语义见 [tools §F1](tools.md)（工具注册与发现）。

##### 规则与名单的映射

- 命令行的允许规则即该 Agent 命令白名单的条目，拒绝规则即黑名单的条目。
- 读写的允许规则按路径给出范围。
- Agent 配置档案中的工具范围不属于权限规则，其语义见 [tools §F1](tools.md)（工具注册与发现）。
- 高风险操作名单内的对象不能被允许规则放行（见 [F7](#f7-高风险操作管控)）。

规则的存储位置、文件格式与语法属实现细节（由设计文档定义）；需求层约束是必须能完整表达上述四项要素，并允许 Owner 直接修改配置文件完成删除。

#### 修改方式

Owner 可通过权限指令（新增规则，见 [slash §F16](slash.md)（权限配置管理））新增权限规则，也可在审批时选择「加入白名单」新增规则；规则删除由 Owner 直接修改权限配置文件完成。权限配置属于 config 的业务配置文件（见 [config §F1](config.md)（多文件配置结构）），现有规则的查看见 [cli §F7](cli.md)（权限规则查询与校验）。通过权限指令与审批修改时，系统直接处理，不在 Agent 会话流程内执行，并在执行前验证调用方是否为 Owner。直接修改配置文件后的重载见 [config §F4](config.md)（配置重载）。

Agent 的沙盒模式同属权限配置，可通过权限指令修改当前 Session 所属 Agent 的沙盒模式（见 [slash §F16](slash.md)（权限配置管理）），也可直接修改权限配置文件调整任意 Agent 的沙盒模式；均仅 Owner 可操作。

#### 热加载

权限规则与沙盒模式的变更均即时生效，无需重启 Agent 或系统。下一次权限评估即使用新配置。

#### 加载容错

启动时权限配置文件损坏、缺失或无法加载，先按 [config §F3](config.md)（启动容错与备份恢复）尝试恢复可用备份；恢复成功后使用恢复的权限配置并通知 Owner。恢复失败不阻塞 Agent 加载，CloseClaw 照常启动，并保留其余可正常加载的权限配置；缺失部分按拒绝处理，不放大权限。仅当无任何可用配置时，Agent 退化为系统默认权限（见 [F1](#f1-身份体系)），并明确通知 Owner——初始 Agent 的例外同样依赖其权限配置，退化后不再享有。

> **交叉引用**：权限配置文件的备份恢复机制。详见 [config §F3](config.md)（启动容错与备份恢复）。
> **交叉引用**：权限配置的重载与生效机制。详见 [config §F4](config.md)（配置重载）。

### F7. 高风险操作管控

Owner 需要系统对高风险文件访问施加额外限制：

- 高风险操作永远只能单次放行，不能被加入白名单。
- 高风险操作的审批提示不显示「加入白名单」选项。
- 名单按路径命中，作用于 Agent 对名单内路径的文件读写操作；命令对同一路径的访问按命令行维度评估（见 [F2](#f2-权限维度)）。
- 名单由系统预定义并随版本更新增补，Owner 不能自行增删。
- 当前高风险范围为版本控制目录（`.git`）的读写，以及 [F2](#f2-权限维度) 配置写入维度覆盖的业务配置文件写入；后者须先具备该维度权限，不能通过文件审批补齐。

### F8. 安全边界

Owner 需要以下安全保障：

- **配置保护**：权限配置文件对 Agent 一律不可读写，不受规则、白名单机制或 Agent-User workspace 强制授权影响（见 [F4](#f4-owner-特权)）。
- **AGENTS.md 修改保护**：AGENTS.md 的修改保护见 [F4](#f4-owner-特权)，文件工具与命令进程不得成为非 Owner User 间接修改该文件的旁路。
- **系统设计约束**：权限系统不提供以下能力：关闭 Owner 身份校验、绕过权限评估。
- **workspace 路径安全**：Agent ID 和 User ID 不得导致两类 workspace 的归属混淆或越权访问，不得使 Agent workspace 共用文件被误认成 Agent-User 专属文件。
- **workspace 并发创建**：并发创建两类 workspace 目录时不得相互干扰或失败。
- **最小信息原则**：Agent 被权限规则拒绝或被审批拒绝时，只收到被拒绝的权限维度名称（读、写、工具调用、收发消息、网络访问、配置写入、命令行；工具调用维度按工具不可用呈现，见 [tools §F12](tools.md)（权限拒绝提示）），不暴露规则名称、优先级、配置路径；拒绝信息中也不说明该结果是否由 Owner 的审批决策产生。被多个维度同时拒绝时并列列出多个维度。

### F9. 子 Session 权限继承

Owner 需要子 Session 的权限不超出父 Agent：

- 父 Agent 派生子 Session 时，子 Session 的实际权限 = 目标 Agent 的配置权限 ∩ 父 Session 的实际权限 ∩ 继承的 User 上下文权限。
- 权限沿 spawn 链路只能变窄，不能变宽。
- 链路中所有父 Agent 的拒绝规则沿链路向子 Session 传播——每增加一级深度，拒绝约束只增不减。
- 沿链路传播的拒绝约束在每次评估中一并生效，与交集结果取更严者。
- Agent-User workspace 强制授权（见 [F3](#f3-权限决策模型)）不参与上述交集——子 Session 同样自动获得目标 Agent 与继承的 User 组合所对应专属目录的读写；目标 Agent 的 Agent workspace 不属此例外，其实际权限仍沿链路取交集，AGENTS.md 的修改保护按继承的 User 上下文生效。
- 子 Session 被拒绝时直接返回拒绝结果，不进入审批、不通知 Owner。
- 子 Session 不与 User 交互：收发消息维度对子 Session 恒为拒绝，子 Session 只与父 Session 通信。

> **交叉引用**：子 Session 的创建与委托协调。详见 [session §F4](session.md)（子 Session 委托与协调）。
> **交叉引用**：spawn 工具的权限例外。详见 [F2](#f2-权限维度)（权限维度）。

### F12. 沙盒

Owner 需要 Agent 的文件访问范围以**操作系统级强制**落地，而非仅靠路径规则匹配——Agent 可能编写脚本反复拼接路径，规则难以穷尽；沙盒在操作系统层拦截越界访问，无论路径如何拼装都无法绕过。

#### 强制范围

沙盒强制约束 Agent 发起的以下两类访问：

- 文件操作类工具访问（读取、写入、编辑、目录列举、内容搜索等）
- 在沙盒内执行的命令进程（含其调用的脚本与子进程）发起的文件访问

斜杠指令由系统执行，不经过沙盒；放行模式下文件工具访问不经沙盒强制，见下方「沙盒模式」。

#### 边界来源

边界来自按 [F3](#f3-权限决策模型) 与 [F9](#f9-子-session-权限继承) 求得的实际生效读/写路径范围：

- 可读范围 = 可写范围 ∪ 读维度配置的路径范围（写入必然伴随读取）。
- 读/写维度的路径范围由 [F1](#f1-身份体系) 的默认能力与允许规则共同给出，拒绝规则从中扣除（拒绝优先）；既无默认能力也无允许规则覆盖的路径不在范围内。
- Agent-User workspace 路径按 [F3](#f3-权限决策模型) 自动纳入可读写范围；Agent workspace 按实际权限纳入，并始终落实 [F4](#f4-owner-特权) 的 AGENTS.md 修改保护。

#### 沙盒模式

沙盒模式是 Agent 权限基线中的一个配置项（不属于权限规则的四要素模型，见 [F6](#f6-权限配置管理)），按 Agent 维度配置，User 维度不覆写。

沙盒能力对所有 Agent 恒可用，不存在关闭沙盒的配置——Agent 可在单次调用中指定执行位置（见「执行位置」），能否在宿主上执行由沙盒模式决定。沙盒模式决定的是**命令的授权与缺省执行位置，以及文件工具访问是否受沙盒范围强制**，不是沙盒本身是否启用。共三种模式（同一命令同时列入白名单与黑名单时黑名单优先，见 [F2](#f2-权限维度)）：

- **默认模式**（默认）
  - 白名单命令：沙盒内外均允许执行
  - 其余命令：在沙盒内执行，受范围强制（结构解析无法确定者除外，见 [F2](#f2-权限维度)）
  - 黑名单命令：一律拒绝
- **严格模式**
  - 白名单命令：沙盒内外均允许执行
  - 其余命令（含黑名单命令）：一律拒绝
- **放行模式**（高风险模式，默认不启用；初始 Agent 的基线即放行模式）
  - 白名单命令：沙盒内外均允许执行
  - 其余命令：缺省在宿主上执行，不强制沙盒、也不因超出读写范围被拒绝；Agent 仍可在单次调用中选择在沙盒内执行，此时受范围强制
  - 文件访问不经沙盒范围强制，仅由权限评估按读写规则判定文件工具发起的访问
  - 黑名单命令：仍一律拒绝

#### 执行位置

执行位置是命令调用上的可选参数——命令始终可以选择在沙盒内执行（沙盒恒可用）；缺省位置由沙盒模式决定：默认模式与严格模式在沙盒内，放行模式在宿主上。

部分命令无法在沙盒内完成（如需网络访问或交互式登录），Agent 可在单次调用中指定在宿主上执行；其中非白名单命令的请求按沙盒模式分流：

- 默认模式：进入审批（见 [F5](#f5-审批工作流)）。
- 严格模式：直接拒绝。
- 放行模式：缺省即在宿主上执行，无需审批（见 [F5](#f5-审批工作流)）。

白名单命令在沙盒内外执行均无需审批。

#### 不降级

沙盒引擎不可用或初始化失败时（区别于放行模式下主动选择在宿主上执行），受沙盒约束的操作一律拒绝执行，不降级为无约束执行，也不进入审批。

#### 沙盒引擎

沙盒引擎采用操作系统原生隔离机制、按平台选择：Linux 以 bubblewrap 为主、内核 Landlock 兜底（WSL2 按 Linux 处理），macOS 以 Seatbelt 实现。选用操作系统原生机制的原因：用户无需安装容器运行时，进程级开销小，且无需定义宿主与沙盒之间的文件挂载映射。

> **交叉引用**：操作系统差异的统一收敛方式。详见 [platform §F5](platform.md)（系统差异隔离）。
> **交叉引用**：宿主上执行请求的审批决策、等待与投递机制。详见 [F5](#f5-审批工作流)（审批工作流）。
> **交叉引用**：后台任务执行的定义。详见 [tools §F5](tools.md)（后台任务执行）。

## 非功能需求

- **性能**：权限评估不构成 Agent 操作的可感知瓶颈：开销不随 Session 数量、Agent 数量、历史审批记录或运行时长增长，仅与当前生效规则集相关。
- **可用性**：审批请求在操作进入审批后立即推送，不因系统内部处理引入 Owner 可感知的延迟；投递目标与平台回退见 [gateway §F7](gateway.md)（出站消息统一处理）。
- **可用性**：系统应在无 Owner 在线时保持可用——等待中的审批请求不应阻塞系统其他功能。
- **安全性**：沙盒以操作系统级能力强制文件访问范围——Agent 无法通过路径拼接、变形或派生进程绕过（放行模式下的例外见 [F12](#f12-沙盒)）；沙盒引擎不可用或初始化失败时的处置见 [F12](#f12-沙盒)。

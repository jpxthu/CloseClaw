# IM Adapter 需求

## 概述

IM Adapter 模块满足 CloseClaw 跨消息平台运行的核心诉求——用户和 Agent 可以通过飞书、Discord、Telegram 等多种 IM 平台与 CloseClaw 交互，消息格式在各平台间无缝转换，无需感知底层平台差异。

## 功能需求

### F1. 多平台插件化适配

CloseClaw 需要支持多种 IM 平台，每个平台以独立插件形式接入。新增平台不改变现有平台及核心功能的行为。平台支持可按需启用——默认只启用配置过的平台；平台启停的生效机制见非功能需求。

每个平台插件负责本平台消息与统一格式的互转，并提供该平台特有的工具能力。

### F2. 入站消息归一化

来自不同 IM 平台的消息在进入系统内部前，需要被归一化为统一的中间消息结构，使下游模块（Processor Chain、Gateway、LLM）无需感知平台差异。归一化工作由各平台插件在入站解析时完成。

归一化后的消息包含平台标识、发送者、会话对端、账号标识、消息正文等标准化字段。各平台特有的元数据（如 API 字段名、租户标识等）不进入归一化结构。

- **平台标识**：消息来源平台
- **发送者**：发消息的用户在该平台上的身份标识；标识取值按接收方机器人应用隔离，同一用户在同一平台、不同机器人应用语境下的取值不同且不可直接互换
- **会话对端**：消息所属会话的上下文锚点，由平台插件按平台语义确定——如私聊取对方用户、群聊取群、支持话题的平台取话题。会话对端不足以唯一锚定会话时（如私聊中多个话题并行），平台插件在取值内携带更细粒度的上下文区分（如话题标识），保证同一会话内的消息对端取值相同、不同会话间取值不同
- **账号标识**：发送者对应的 CloseClaw 用户 ID，同一用户在不同 IM 平台的账号归并为同一用户 ID；归并按「平台 + 接收方机器人应用 + 发送者标识」定位发送者，不假定发送者标识在平台内唯一
- **消息正文**：消息的文本内容

接收消息的机器人与发送者是两个独立身份：消息路由到机器人所绑定的 Agent（绑定关系由配置定义，详见 [gateway §F4](gateway.md)（普通消息路由到对话）），账号标识由发送者经身份映射得到。

引用/回复消息：若平台支持消息引用功能，被引用消息的文本内容需截断后拼接到消息正文前（截断至 500 字符，超出部分追加 ...），以引用形式呈现。

> **交叉引用**：非文本消息（图片、文件、音频等）的处理由 Gateway 负责，详见 [gateway §F3](gateway.md)（消息类型识别与非文本处理）。

### F3. 出站消息格式自动选择

Agent 输出消息在发送到 IM 平台前，需根据内容特征自动选择输出格式。默认使用富格式消息；仅当消息内容为纯文本（无任何格式标记、无换行、无 Thinking/Tool 块、无交互指令）时，才使用轻量文本消息。

包含以下任一特征的内容使用富格式消息：markdown 格式（标题、粗体、斜体、代码块、列表、引用、链接、分割线）、换行符、Thinking 块、Tool 块、交互指令（按钮等交互元素）。

格式选择由系统自动完成，用户和 Agent 无需手动指定输出格式。

### F4. 流式增量渲染

Agent 流式输出时，消息应逐步渲染并发送到 IM 平台，使用户在 Agent 响应生成过程中即可看到已生成的内容，无需等待完整响应。

文本内容以完整、连贯的片段逐步展示，连续输出不出现长时间停顿。代码块以完整块输出，确保语法高亮正确渲染。

Thinking 块和 Tool 块累积完整内容后一次性展示。图片、音频、文件等非文本消息不参与流式渲染，直接交由平台格式渲染处理。

流式渲染出错时，不再产生新的增量输出。

> **交叉引用**：流错误的统一降级处理由 Gateway 负责，详见 [gateway §F7](gateway.md)（出站消息统一处理）。

### F5. 代码块语法高亮

消息中的代码块需要按标注的编程语言进行语法高亮渲染，各平台按自身能力提供最佳渲染效果：

- 平台原生支持代码块高亮的，使用平台原生能力
- 终端等环境，通过终端显示能力实现语法高亮
- 平台不支持代码块高亮的，以纯文本形式展示代码

各平台支持高亮的语言范围由自身能力决定。

### F6. 渲染与发送分离

Agent 输出需先渲染、后发送两个独立步骤。渲染将 Agent 输出转为平台可识别的消息格式，发送将渲染后的消息推送到 IM 平台。

> **交叉引用**：渲染与发送之间的拦截检查（审计、频率限制等）由 Gateway 负责，详见 [gateway §F7](gateway.md)（出站消息统一处理）。

### F7. 平台接口真实性验证

IM 平台的接口行为可能随平台侧变更而漂移（事件结构、字段语义、接口可用性等）。为在不依赖日常运行的情况下及时发现此类变化：

- 除基于已采集真实数据的离线验证外，每个平台还需提供一套使用真实平台账号的验证手段：向平台发起真实收发，验证接口行为与已采集数据仍一致
- 该验证不进入自动化流程，由维护者不定期手动触发
- 平台凭证与真实身份信息不落在代码库内

### F8. 调试日志

IM Adapter 模块在以下环节记录调试日志：
- 入站消息解析（平台、消息类型、解析耗时）
- 出站渲染结果（平台、渲染耗时）
- 平台 API 调用发送结果（平台、目标、耗时）

> **交叉引用**：日志框架定义（格式、级别、追踪标识、存储轮转、隐私脱敏）详见 [debug_log](debug_log.md)（调试日志）。

### F9. 媒体文件收发与存储

IM 平台上的图片、文件等媒体在收发时落盘存储，使媒体内容可被 Agent 使用、且不随平台链接过期而失效。

**入站**：

- 平台插件在接收到含媒体的消息时，立即将媒体下载并存储到统一的媒体存储目录（入站子目录），不依赖平台侧临时链接的可用期
- 归一化消息通过媒体引用字段携带媒体；媒体引用由系统解析为本地媒体文件，下游模块不接触平台侧下载链接与凭证
- 入站媒体保留经安全净化的原始文件名并附加唯一后缀防止冲突；记录文件大小与 MIME 类型

**Agent 上下文形态**：

- 图片类媒体以图片内容直接进入 LLM 上下文，使 Agent 能直接看图；超过大小阈值的图片以媒体引用进入上下文
- 非图片媒体（文件、音频等）以媒体引用进入上下文，Agent 通过引用使用媒体内容
- 上下文的文本表示中只出现媒体引用，不出现本地文件系统路径

**出站**：

- Agent 发送媒体时，接收的媒体以媒体引用形式表示，Agent 生成的文件以工作区内路径表示；相对路径基于工作区解析
- 系统仅从工作区目录与媒体存储目录读取待发送的媒体文件；范围外路径拒绝发送并给出清晰错误
- 发出的媒体保留副本到媒体存储目录（出站子目录），供审计与重发

**生命周期**：

- 媒体清理支持两种机制：跟随 Session 生命周期（Session 被清理或不再被任何 Session 引用时清理对应媒体；归档不算清理）；以及按固定保留期清理，保留期可配置，默认 7 天。跟随 Session 生命周期的清理机制为可选项，可不提供；若提供，须以低优先级执行，不影响系统的正常使用
- 清理机制可同时启用，互不依赖

> **交叉引用**：保留期属于媒体配置项，变更后自下一次清理扫描起生效；配置重载机制详见 [config §F4](config.md)（配置重载）。

## 非功能需求

### 可扩展性

- 新增平台或停用已有平台后需重启才生效；重启由配置变更自动触发，无需手动操作，详见 [config §F4](config.md)（配置重载）

### 稳定性

- 单个平台插件的初始化失败不影响其他已启用平台的正常运行
- 平台 API 调用失败时，系统正常降级，不导致进程崩溃

### 安全性

- 平台凭证（token 等）由各平台插件自行管理，不在模块间传递

# IM Adapter 需求

## 概述

IM Adapter 模块满足 CloseClaw 跨消息平台运行的核心诉求——用户和 Agent 可以通过飞书、Discord、Telegram 等多种 IM 平台与 CloseClaw 交互，消息格式在各平台间无缝转换，无需感知底层平台差异。

## 功能需求

### F1. 多平台插件化适配

CloseClaw 需要支持多种 IM 平台，每个平台以独立插件形式接入。新增平台不改变现有平台及核心功能的行为。平台支持可按需启用——默认只启用配置过的平台。

每个平台插件负责本平台消息与统一格式的互转，并提供该平台特有的工具能力。

> **交叉引用**：平台启停（插件列表）与渠道配置变更的生效机制详见 [config §F7](config.md)（生效机制与重启类判定）。
> **交叉引用**：上述配置变更的检测及自动重启触发详见 [config §F4](config.md)（配置重载）。
> **交叉引用**：平台特有工具能力的接入方式详见 [tools §F9](tools.md)（工具扩展接入）。

### F2. 入站消息归一化

来自不同 IM 平台的消息在进入系统内部前，需要被归一化为统一的消息形式，使下游模块无需感知平台差异。归一化工作由各平台插件在入站解析时完成。

#### 归一化字段

归一化后的消息使用下列标准化字段。平台特有的元数据只以取值形式承载在标准字段中——取值随平台变化，字段名统一，平台特有的字段名本身不进入归一化结构。

- **平台标识**：消息来源平台
- **发送者**：发消息的用户在该平台上的身份标识
  - 取值按接收方机器人应用隔离：同一用户在同一平台、不同机器人应用语境下的取值不同且不可直接互换
- **会话对端**：区分 Session 的标识，由各平台插件按平台语义确定，取值粒度随平台形态而定，不设跨平台的统一取值规则
  - 同一 Session 内消息的会话对端取值相同
  - 在同一平台、同一发送者、同一账号标识下，不同会话对端对应不同 Session；同一会话对端下可存在多个历史 Session，由 Session 侧按活跃时间区分
  - 会话对端取值可由发送者等信息参与组合，四项标识仍并列参与判定，不因取值重叠而改变判定方式
  - 平台自然锚点不足以区分 Session 时，插件在取值内补充更细粒度的上下文信息
- **账号标识**：发送者对应的 CloseClaw User ID，经身份映射得到
  - 无法映射为已注册 User 时，按 permission 的身份准入要求静默终止，不自行创建 User 或回复提示
- **消息正文**：消息的文本内容

#### 身份与会话映射

一条入站消息的归一化字段共同确定「路由到哪个 Agent、归属哪个 User、进入哪个 Session」。接收消息的机器人应用与发送者是两个独立身份：

- **接收方机器人应用 → Agent**：决定消息路由到的 Agent
- **发送者 → User**：发送者的平台身份标识解析为 CloseClaw User ID
- **四项标识（平台标识、发送者、会话对端、账号标识）+ 路由到的 Agent → Session**：共同确定主 Agent Session

各平台特有字段的名称与取值语义由平台子文档定义。

> **交叉引用**：机器人与 Agent 的绑定及消息路由详见 [gateway §F4](gateway.md)（普通消息路由到对话）。
> **交叉引用**：机器人 ↔ Agent、IM 用户 ↔ User 两类双向绑定（含入站/出站方向与基数规则）的权威定义详见 [config §F1](config.md)（多文件配置结构）。
> **交叉引用**：入站归一化在完整消息流链路中的位置详见 [message_flow §F1](message_flow.md)（入站链路）——建议结合阅读以理解完整产品流程。
> **交叉引用**：跨机器人应用的发送者标识如何归并为同一 User，详见 [message_flow §F3](message_flow.md)（跨机器人身份归并）。
> **交叉引用**：User 身份体系、入站身份准入与静默要求详见 [permission §F1](permission.md)（身份体系）。
> **交叉引用**：Session 的确定、查找、创建与恢复详见 [session §F1](session.md)（对话持久化与恢复）。
> **交叉引用**：飞书标识的名称与取值语义详见 [im_adapter/feishu §F1](im_adapter/feishu.md)（飞书入站消息接收）。

#### 消息内容范围

- **消息引用**（用户对某条已有消息的引用/回复，平台以引用类字段表达）：不在当前范围——系统不识别引用关系、不回查被引用消息正文，被引用内容不进入 Agent 上下文
- **话题（thread）会话不属于引用**：按平台语义支持，见各平台子文档
- **消息正文中的内嵌媒体标记**：从正文剥离，不进入归一化正文

> **交叉引用**：非文本消息（图片、文件、音频）的处理详见 [gateway §F3](gateway.md)（消息类型识别与非文本处理）。

### F3. 出站消息格式自动选择

Agent 输出消息在发送到 IM 平台前，需根据展示等级过滤后的可见内容特征与目标平台能力自动选择输出格式，用户和 Agent 无需手动指定。

流式与非流式的区别在于内容的展示时机；通用层不限定其使用的消息格式。各平台的消息形态、格式选择条件与展示交互由平台子文档定义，不要求所有平台使用相同的展示形式或具备相同的交互能力。

> **交叉引用**：内容块名称与展示等级过滤规则详见 [processor_chain §F4](processor_chain.md)（出站回复展示等级控制）。
> **交叉引用**：飞书平台的格式选择详见 [im_adapter/feishu §F3](im_adapter/feishu.md)（飞书消息发送）。
> **交叉引用**：CLI 终端的展示规则详见 [cli §F2](cli.md)（终端输出渲染）。

### F4. 流式增量渲染

流式（Streaming）输出时，消息应逐步渲染并发送到 IM 平台，使用户在 Agent 响应生成过程中即可看到已生成的内容，无需等待完整响应；非流式输出则在消息完整生成后再展示。具体展示形式由各平台按自身能力确定，不以某一种消息格式或交互能力为前提。

文本内容以连贯的片段逐步展示：原则上以结构边界（如换行、句末标点）为切分依据，不逐字堆砌；为尽早呈现，结构边界未至时可先行下发已生成内容，不积压至响应结束。代码块以完整块输出，确保语法高亮正确渲染。

展示等级允许的 Thinking 块和 Tool 块累积完整内容后一次性展示——两者均在块结束后交付平台渲染器，不参与增量流式。

流式中断时，对该回复展示等级允许的内容按以下规则呈现：

- Thinking 块按已累积内容原样展示
- Tool 调用块展示工具名与已累积的参数概要（只展示已解析出的参数键值，未解析出的部分不展示），并明确标注该调用已中断、未完成
- 中断前已产生的 Tool 结果按 Tool 结果块规则正常展示
- 错误提示在以上内容之后呈现
- 中断时尚未产生的内容不展示

已累积但尚未交付的 Thinking/Tool 块按已生成内容处理，不属于 Gateway 出站降级规则所指「未生成的回复内容」与「不完整的新增量」。

非文本消息（图片、文件、音频）不在当前范围，不参与流式渲染。

> **交叉引用**：非文本消息的处理规则详见 [gateway §F3](gateway.md)（消息类型识别与非文本处理）。
> **交叉引用**：流式渲染错误的统一降级处理由 Gateway 负责。详见 [gateway §F7](gateway.md)（出站消息统一处理）。
> **交叉引用**：内容块名称、展示等级与中断时的过滤约束详见 [processor_chain §F4](processor_chain.md)（出站回复展示等级控制）。
> **交叉引用**：等级允许展示的 Thinking 块的界面呈现与可见范围详见 [llm §F3](llm.md)（推理过程可见与安全）。
> **交叉引用**：代码块高亮规则详见 [F5](#f5-代码块语法高亮)（代码块语法高亮）。

### F5. 代码块语法高亮

消息中的代码块需要按标注的编程语言进行语法高亮渲染，各平台按自身能力提供最佳渲染效果：

- 平台原生支持代码块高亮的，使用平台原生能力实现语法高亮
- 平台原生不支持、但其显示环境具备高亮能力的，通过该环境的显示能力实现语法高亮
- 平台不支持代码块高亮的，以纯文本形式展示代码

各平台支持高亮的语言范围由自身能力决定。

### F6. 渲染与发送分离

Agent 输出先渲染为平台可识别的消息格式，再发送到 IM 平台；渲染与发送是两个相互独立的环节。

> **交叉引用**：出站消息的统一处理由 Gateway 负责。详见 [gateway §F7](gateway.md)（出站消息统一处理）。

### F7. 平台接口真实性验证

IM 平台的接口行为可能随平台侧变更而漂移（事件结构、字段语义、接口可用性等）。为了在不依赖日常运行的情况下及时发现此类变化：

- 除基于已采集真实数据的离线验证外，每个平台还需提供一套使用真实平台账号的验证手段：向平台发起真实的发送与接收，比对事件结构、标识类字段语义与接口返回结构是否与已采集样本一致
- 差异逐条记录，并判定是否影响主链路，使漂移在影响日常使用前被发现
- 该验证不进入自动化流程，由 Owner 不定期手动触发
- 平台凭证与真实身份信息不存储于代码库内

### F8. 调试日志

IM Adapter 模块在以下环节记录调试日志：
- 入站消息解析（平台、消息类型、解析耗时）
- 被忽略的平台事件（群聊消息、交互事件、表情回应等，含平台与事件类型；各平台另有字段要求的以平台子文档为准）
- 出站渲染结果（平台、渲染耗时）
- 平台 API 调用发送结果（平台、目标、发送耗时）

> **交叉引用**：飞书平台事件的附加日志字段详见 [im_adapter/feishu §F2](im_adapter/feishu.md)（飞书消息事件处理）。
> **交叉引用**：完整消息链路追踪详见 [debug_log §F1](debug_log.md)（完整消息链路追踪）。
> **交叉引用**：分层日志级别详见 [debug_log §F2](debug_log.md)（分层日志级别）。
> **交叉引用**：日志存储与保留详见 [debug_log §F3](debug_log.md)（日志存储与保留）。
> **交叉引用**：隐私保护详见 [debug_log §F4](debug_log.md)（隐私保护）。

### F9. IM 平台配置归属

每个 IM 平台的渠道配置（接入参数、凭据字段、平台特有开关）由本模块及对应平台子文档定义；config 只提供通用配置能力，不定义任何平台配置项（职责边界见 [README](README.md) 模块职责与需求归属）。

- 平台未配置时不启用；单个平台配置损坏或恢复失败时，按 [config §F3](config.md)（启动容错与备份恢复）只停用该平台，其他平台与 CLI 不受影响。
- 平台需要系统保存的凭据字段随该平台渠道配置以明文存放，访问控制与展示脱敏见 [config §F5](config.md)（凭据存放与保护）；由平台官方工具管理凭证的具体方式见平台子文档。平台凭据字段随渠道配置变更，属重启生效类（见 [config §F7](config.md)（生效机制与重启类判定））。

## 非功能需求

### 稳定性

- 单个平台插件的初始化失败不影响其他已启用平台的正常运行
- 平台 API 调用失败时，系统正常降级，不导致进程崩溃

### 安全性

- 平台需要系统保存时，凭据由配置模块加载、校验并由该平台适配器使用，不进入其他模块的业务数据流；日志与校验结果的凭据脱敏见 [config §F5](config.md)（凭据存放与保护）

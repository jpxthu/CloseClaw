# Memory 需求

## 概述

Memory 是实验性功能：开启挖掘子功能后，Agent 可在多次 Session 之间积累对用户的认知——记住用户纠正过什么、做过什么决策、Agent 犯过什么错、自己发现了什么规律，形成后续功能可用的记忆库。

## 功能需求

### F1. Session 结束后自动挖掘记忆

挖掘功能开启时，每次主 Agent Session 结束后（以进入归档为判定时点），系统自动从对话历史中挖掘值得长期保留的信息，不依赖 Agent 在对话中自行记录。

#### 触发与运行

- 挖掘过程独立运行，不与用户交互
- 子 Session 与无 Bootstrap 文件的 Session 不触发挖掘

#### 事件产出

- 挖掘产出结构化的事件（event）。每条事件包含标题、事件摘要、正文和类别，可选携带经验教训（lesson；仅错误和不满事件可携带），并关联若干实体
- 事件分四类：
    - **错误（error）**：Agent 在对话中出现的明确错误（判断失误、操作不当、误解需求）
    - **不满（anger）**：用户对 Agent 的纠正或不满表达
    - **决策（decision）**：用户明确的偏好选择或设计决策
    - **洞察（insight）**：Agent 经过反复尝试发现的简单规律，值得沉淀为经验的发现
- 挖掘只提取对未来对话有参考价值的持久信息，不记录临时聊天细节（如一次性闲聊、当前任务进度等）

#### 经验教训

- 从错误和不满事件中提炼经验教训（lesson）——事件级的经验摘要
- lesson 随事件保留，不直接生效，不引用具体消息编号

#### 挖掘范围与上限

- 挖掘时参考同一 Agent、同一 User 的全部历史事件，不设历史事件回看窗口
- 避免重复产出：同一 Agent、同一 User 下，类别、标题与关联实体均相同的事件视为重复，不再次产出
- 对话轮数低于阈值（默认 5 轮）时，该 Session 因过短被自动跳过，不挖掘
- 一轮指一条 User 消息及其触发的 Agent 回复
- 每次挖掘产出的事件数有上限（默认 10 条）
- 超出上限时，优先保留高信号事件：
    - 错误和不满优先于洞察
    - 洞察优先于决策
    - 同类别内优先保留较新事件

### F2. 以实体体系组织记忆

记忆围绕实体（entity）组织——把事件关联到具体的人物、主题、产品、动作等，便于记忆的组织与关联。实体类型体系在 [SAG](https://github.com/Zleap-AI/SAG) 的类型划分基础上增加兜底类型（已由 Owner 选定采用，MIT License）。

#### 实体类型

- 系统提供 11 种实体类型：
    - 时间（time）
    - 地点（location）
    - 人物（person）
    - 组织（organization）
    - 主题（subject）
    - 产品（product）
    - 指标（metric）
    - 动作（action）
    - 作品（work）
    - 群体（group）
    - 标签（tags，暂定，兜底类型）

#### 实体分配与合并

- 挖掘时为每条事件分配关联实体：按类型与名称精确匹配已有实体，无匹配时创建新实体
- 同一 Agent、同一 User 下同类型同名实体自动合并，不重复创建
- 实体名称需简洁，长度以词为单位计：
    - 汉字：每 2 个汉字计 1 个词，奇数个汉字向上取整（如 5 个汉字计 3 个词）
    - 英文：每个单词计 1 个词
    - 数字与标点不计入词数
    - 中英混排：汉字折算的词数与英文单词数相加
    - 上限：至少 1 个词，总计不超过 10 个词；该上限固定、不可配置，超限名称由挖掘环节精简至不超过 10 个词

### F7. 记忆挖掘的开关与参数配置

Owner 可以为挖掘子功能控制开关。

#### 开关与权限

- 挖掘未显式开启则关闭——记忆系统不会在 Owner 不知情的情况下运行
- 记忆配置仅 Owner 可修改，非 Owner User 不可见、不可改
- 记忆配置以 Agent 为配置粒度，其效果覆盖该 Agent 下所有 User

#### 配置层级与生效

- 除 F2 规定的实体名称词数上限外，所有开关项、模型选择项与参数项均支持两级配置：
    - 全局配置
    - 按 Agent 配置
- 按 Agent 配置时：
    - Agent 不声明则继承全局配置
    - Agent 声明部分字段则仅覆盖其声明的字段
- 配置修改后无需重启，下次触发时自动生效
- 挖掘使用的 LLM 模型可独立配置，不强制使用主 Agent Session 的模型

#### 参数与默认值

- 会话长度阈值：对话轮数 5 轮
- 事件产出上限：10 条

> **暂缓**：本功能域暂不开发、暂不设计。

## 非功能需求

- **可用性**：挖掘失败不阻塞正常对话；失败时丢弃本次挖掘结果，不重试，不影响后续 Session 的挖掘。
- **安全性**：记忆数据按 Agent 与 User 双重隔离——同一 Agent 下不同 User 的记忆互不干扰，不同 Agent 的记忆也互不干扰。
- **安全性**：Agent 从系统移除时，其记忆数据一并删除，不迁移给其他 Agent；记忆数据包括事件、lesson、实体与行为规则文件。
- **可观测性**：挖掘产出、跳过、截断、去重与失败记录调试日志。

> **交叉引用**：调试日志的分级与脱敏规范详见 [debug_log §F2](debug_log.md)（分层日志级别）、[debug_log §F4](debug_log.md)（隐私保护）。

> **交叉引用**：Agent 与 User 的身份定义详见 [permission §F1](permission.md)（身份体系）。

# Memory 需求

> **实验性功能**：Memory 模块为实验性功能。已涵盖大框架和整体思路，其中的标签体系、记忆提取方式、记忆库搜索方式等细节处于实验迭代中。

## 概述

Agent 在跨 Session 的使用中积累对用户的认知——记住用户纠正过什么、做过什么决策、Agent 自己发现了什么规律，在后续对话中自动引用这些记忆，无需用户重复说明。

记忆体系围绕两个核心概念组织：

- **事件（event）**：从 Session 中挖掘出的值得长期保留的信息单元。每条事件包含标题、摘要、正文、类别（error / anger / decision / insight）、可选的经验教训（lesson），并关联若干实体。
- **实体（entity）**：事件关联的对象——可以是人、主题、产品、动作等。每个实体指定一种类型、名称和描述。

## 功能需求

### F1. Session 结束后自动挖掘记忆

每次 Session 结束后，系统自动从对话记录中挖掘值得长期保留的信息，不依赖 Agent 在对话中自行记录。

- 挖掘过程以独立 Session 运行，不与用户交互
- 挖掘产出结构化的事件（event），每条事件包含：标题、摘要、正文、类别、可选的经验教训（lesson），并关联若干实体
- 事件分四类：
  - **错误（error）**：Agent 在对话中出现的明确错误（判断失误、操作不当、误解需求）
  - **不满（anger）**：用户对 Agent 的纠正或不满表达
  - **决策（decision）**：用户明确的偏好选择或设计决策
  - **洞察（insight）**：Agent 经过反复尝试发现的简单规律，值得沉淀为经验的发现
- 从错误和不满事件中提炼经验教训（lesson）——事件级的经验摘要，随事件保留，不以独立条目注入对话，不引用具体消息编号
- 挖掘只提取对未来对话有参考价值的持久信息，不记录临时聊天细节（如一次性闲聊、当前任务进度等）
- 挖掘时参考已记录的事件，避免重复产出
- 对话轮数或用户消息数任一低于可配置的会话长度阈值时，该简短 Session 自动跳过，不挖掘
- 每次挖掘产出的事件数有上限，优先保留高信号事件（错误和不满优先于普通决策）

### F2. 以实体体系组织记忆

记忆围绕实体（entity）组织——把事件关联到具体的人、主题、产品、动作等，便于后续搜索和关联。实体类型体系沿用 [SAG](https://github.com/Zleap-AI/SAG)（由 Owner 指定选用；MIT License）。

- 系统提供 11 种实体类型：
    - 时间（time）、地点（location）、人物（person）、组织（organization）、主题（subject）、产品（product）、指标（metric）、动作（action）、作品（work）、群体（group）
    - 标签（tags，暂定，兜底类型）
- 不同类型的实体在记忆搜索中的重要性不同——主题和动作是最高价值类型
- 挖掘时为每条事件分配关联实体：优先匹配已有实体，无匹配时创建新实体
- 同一 Agent 下同类型同名实体自动合并，不重复创建
- 实体名称简洁——名称中的汉字总数按两个汉字折算为一个词、奇数时向上取整（如 5 个汉字计 3 个词）；英文单词各计一个词；两部分相加总计不超过 10 个词
- 不同 Agent 的实体库相互隔离——各自的实体独立维护，不跨 Agent 共享或合并

### F3. 定期将事件升格为行为规则

> **暂缓**：本功能域暂不开发、暂不设计。重启时机与具体机制由 Owner 另行决定。

**目标形态**：将事件升格为持久的行为规则。

### F4. 对话中自动注入相关记忆

每次用户或 Agent 发送消息时，系统自动搜索与该消息相关的记忆，浓缩后注入对话，无需 Agent 自行判断是否需要搜索。

- 搜索从当前消息和最近对话上下文中提取查询概念
- 在已有实体关联体系中匹配相关实体，再通过实体反查关联事件
- 搜索到的相关事件浓缩为简短摘要后注入消息列表
- 同一 Session 中已注入过的记忆不重复注入
- 搜索结果注入位置因触发者而异——用户消息触发时置于用户消息之后，Agent 消息触发时置于下一轮用户消息之前
- 搜索超时则放弃本轮，不阻塞对话
- 挖掘、搜索自身的 Session 不触发搜索——它们不需要消费自己的产出
- 子 Session 不触发搜索

> **交叉引用**：子 Session 的记忆加载与隔离约束。详见 [system_prompt §F8](system_prompt.md)（Session 类型适配）。

> **交叉引用**：挖掘的功能定义详见 [F1](#f1-session-结束后自动挖掘记忆)（Session 结束后自动挖掘记忆）。

### F5. 用户可查阅的行为规则

> **暂缓**：本功能域是 F3 的产出形态，随 F3 一并暂不开发、暂不设计。

**目标形态**：升格产出的行为规则以用户可查阅、可手动编辑的文件形式提供。

### F6. 可选的叙事摘要

> **暂缓**：本功能域是 F3 的后续产出，随 F3 一并暂不开发、暂不设计。

**目标形态**：升格完成后生成一份自然语言叙事摘要，描述本轮从事件到规则的升格过程，仅供用户查阅。

### F7. 记忆功能的精细化开关

用户可以为当前生效的两个子功能（挖掘、搜索）分别控制开关。

- 未显式开启则全部关闭——记忆系统不会在用户不知情的情况下运行
- 所有开关支持全局配置和按 Agent 分别配置
- 按 Agent 配置时：Agent 不声明则继承全局配置；Agent 声明部分字段则仅覆盖其声明的字段
- 配置修改后无需重启，下次触发时自动生效
- 各子功能使用的 LLM 模型可独立配置，不强制使用主 Agent Session 的模型
- 各子功能的关键参数均可按需调整：
    - 挖掘：会话长度阈值（对话轮数 / 用户消息数）、事件产出上限
    - 搜索：超时时间、回看对话上下文的轮数、注入摘要长度

> **交叉引用**：配置体系的目录结构详见 [config §F1](config.md)（多文件配置结构）。

> **交叉引用**：重载机制与生效规则详见 [config §F4](config.md)（配置重载）。

### F8. 记忆的自然遗忘

> **暂缓**：本功能域暂不开发、暂不设计。

**目标形态**：记忆像人类记忆一样随时间自然衰退，长期不再出现的事件逐步淡化。

## 非功能需求

- 记忆数据按 Agent 隔离，不同 Agent 的记忆互不干扰

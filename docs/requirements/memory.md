# Memory 需求

## 概述

Memory 是实验性功能：开启相应子功能后，Agent 可在跨 Session 的使用中积累对用户的认知——记住用户纠正过什么、做过什么决策、Agent 自己发现了什么规律，在后续对话中自动注入这些记忆，无需用户重复说明。

## 功能需求

### F1. Session 结束后自动挖掘记忆

挖掘功能开启时，每次主 Agent Session 结束后，系统自动从对话记录中挖掘值得长期保留的信息，不依赖 Agent 在对话中自行记录。

- 挖掘过程独立运行，不与用户交互
- 子 Session 不触发挖掘
- 挖掘产出结构化的事件（event），每条事件包含：标题、摘要、正文、类别、可选的经验教训（lesson），并关联若干实体
- 事件分四类：
  - **错误（error）**：Agent 在对话中出现的明确错误（判断失误、操作不当、误解需求）
  - **不满（anger）**：用户对 Agent 的纠正或不满表达
  - **决策（decision）**：用户明确的偏好选择或设计决策
  - **洞察（insight）**：Agent 经过反复尝试发现的简单规律，值得沉淀为经验的发现
- 从错误和不满事件中提炼经验教训（lesson）——事件级的经验摘要，随事件保留
- lesson 不进入注入摘要，也不以独立条目注入对话，不引用具体消息编号
- 挖掘只提取对未来对话有参考价值的持久信息，不记录临时聊天细节（如一次性闲聊、当前任务进度等）
- 挖掘时参考同一 Agent、同一 User 已记录的全部事件，避免重复产出
- 对话轮数低于阈值（默认 5 轮）时，该简短 Session 自动跳过，不挖掘；一轮指一条 User 消息及其触发的 Agent 回复
- 每次挖掘产出的事件数有上限（默认 10 条），优先保留高信号事件：错误和不满优先于洞察，洞察优先于决策

> **交叉引用**：对话历史的存储与归属详见 [session §F1](session.md)（对话持久化与恢复）。

> **交叉引用**：记忆挖掘作为系统级后台任务的生命周期管理详见 [daemon §F5](daemon.md)（系统级后台任务生命周期）。

### F2. 以实体体系组织记忆

记忆围绕实体（entity）组织——把事件关联到具体的人物、主题、产品、动作等，便于后续搜索和关联。实体类型体系采用 [SAG](https://github.com/Zleap-AI/SAG) 的类型划分（由 Owner 指定选用，MIT License）。

- 系统提供 11 种实体类型：
    - 时间（time）
    - 地点（location）
    - 人物（person）
    - 组织（organization）
    - 主题（subject）
    - 产品（product）
    - 指标（metric）
    - 动作（action）
    - 作品（work）
    - 群体（group）
    - 标签（tags，暂定，兜底类型）
- 不同类型的实体在记忆搜索中的权重不同，主题和动作权重最高
- 挖掘时为每条事件分配关联实体：优先匹配已有实体，无匹配时创建新实体
- 同一 Agent、同一 User 下同类型同名实体自动合并，不重复创建
- 实体名称简洁——名称中的汉字总数按两个汉字折算为一个词，奇数时向上取整（如 5 个汉字计 3 个词）；英文单词各计一个词；汉字折算的词数与英文单词数相加，总计不超过 10 个词。该上限固定、不可配置；超限名称由挖掘环节精简

### F4. 对话中自动注入相关记忆

搜索功能开启时，主 Agent Session 中每次用户或 Agent 发送消息，系统自动搜索与该消息相关的记忆，浓缩后注入消息列表，无需 Agent 自行判断是否需要搜索。

- 搜索从当前消息和最近对话上下文中提取查询概念
- 在当前 Agent 与 User 的实体体系中匹配相关实体，再通过实体反查关联事件
- 搜索到的相关事件浓缩为简短的记忆摘要（不含 lesson）后注入消息列表，单次注入默认最多 5 条事件
- 同一 Session 中已注入过的事件不重复注入，按事件 ID 判重
- 搜索结果注入位置因触发者而异：
    - 用户消息触发时置于用户消息之后
    - Agent 消息触发时置于下一轮用户消息之前；若之后没有下一轮 User 消息，则置于该 Agent 消息之后
- 搜索超时则放弃本轮搜索，不阻塞对话
- 挖掘与搜索过程本身不触发搜索——它们不需要消费自己的产出
- 子 Session 与无 Bootstrap 文件的 Session 不触发搜索

> **交叉引用**：挖掘的功能定义详见 [F1](#f1-session-结束后自动挖掘记忆)（Session 结束后自动挖掘记忆）。

### F7. 记忆功能的精细化开关

Owner 可以为当前的挖掘、搜索两个子功能分别控制开关。

- 未显式开启则全部关闭——记忆系统不会在 Owner 不知情的情况下运行
- 记忆配置仅 Owner 可修改，非 Owner User 不可见、不可改
- 除 F2 规定的实体名称词数上限外，所有开关、模型与参数项均支持全局配置和按 Agent 分别配置
- 按 Agent 配置时：
    - Agent 不声明则继承全局配置
    - Agent 声明部分字段则仅覆盖其声明的字段
- 配置修改后无需重启，下次触发时自动生效
- 各子功能使用的 LLM 模型可独立配置，不强制使用主 Agent Session 的模型
- 各子功能的关键参数均可按需调整，括号内为默认值：
    - 挖掘：会话长度阈值（对话轮数 5 轮）、事件产出上限（10 条）
    - 搜索：超时时间（2 秒）、回看对话上下文的轮数（6 轮）、注入记忆摘要总长度（500 字）、单次注入事件数上限（5 条）

> **交叉引用**：重载机制与生效规则详见 [config §F4](config.md)（配置重载）。

> **交叉引用**：Agent 配置档案中的记忆配置字段详见 [agent §F1](agent.md)（Agent 配置档案）。

### F8. 记忆的自然遗忘

> **暂缓**：本功能域暂不开发、暂不设计。

**目标形态**：记忆随时间自然衰退，长期不再出现的事件逐步淡化，如同人脑记忆。

## 非功能需求

- **可用性**：挖掘或搜索失败不阻塞正常对话。
- **安全性**：记忆数据按 Agent 与 User 双重隔离——同一 Agent 下不同 User 的记忆互不干扰，不同 Agent 的记忆也互不干扰；Agent 被删除时，其记忆数据一并删除，不迁移给其他 Agent。

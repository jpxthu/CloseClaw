# Processor Chain 需求

## 概述

来自 IM 平台与 CLI 的消息遵守一致的处理规则——入站保留用户正文并建立消息追踪，出站按展示等级控制可见内容，入站与出站均记录可用于排查问题的调试日志。

## 功能需求

### F1. 入站消息统一处理

来自 IM 平台与 CLI 的入站消息统一记录原始内容、建立消息追踪，并遵守正文保真规则。

不同渠道不改变用户正文保真与消息追踪的基本约定。

> **交叉引用**：日志记录范围、级别与过滤约束。详见 [F6](#f6-调试日志)（调试日志）。
> **交叉引用**：空消息处理。详见 [gateway §F2](gateway.md)（入站消息预处理）。
> **交叉引用**：非文本消息处理。详见 [gateway §F3](gateway.md)（消息类型识别与非文本处理）。

### F2. 消息追踪标识

正常情况下，每条入站消息都有独立且唯一的消息追踪标识，用于串联该消息在各处理环节中的日志。该标识不是 Session 的标识，不用于查找或创建 Session；具体格式与生成方式不在需求层规定。

消息追踪异常不阻断消息处理，尽力保留已有日志关联，允许追踪链路不完整，并记录降级告警。

> **交叉引用**：Session 的查找与消息追踪标识相互独立。详见 [session §F1](session.md)（对话持久化与恢复）。
> **交叉引用**：消息追踪标识的跨环节日志关联。详见 [debug_log §F1](debug_log.md)（完整消息链路追踪）。

### F3. 入站正文保真

用户发送的正文原样交给后续对话或指令处理，不自动整理格式。正文中的字符（包括不可见字符）、空格、换行、代码与 Markdown 均保留，不压缩连续空行或删除行尾空格。

允许清理明确不属于用户正文的平台附带控制信息，不得借此改写用户正文。清理失败时保留原始正文继续处理，并记录降级告警，不丢失消息。

非文本消息不执行正文格式整理，其支持范围与提示规则由 Gateway 定义。

> **交叉引用**：平台消息归一化。详见 [im_adapter §F2](im_adapter.md)（入站消息归一化）。
> **交叉引用**：非文本消息的支持范围。详见 [gateway §F3](gateway.md)（消息类型识别与非文本处理）。

### F4. 出站回复展示等级控制

#### 等级与内容

Owner 和 User 可以控制当前 Session 在 IM 平台或 CLI 中的展示等级。内容块名称统一为文本块、Thinking 块（推理/思考内容）、Tool 调用块与 Tool 结果块；Tool 块是后两者的统称。

| 展示等级 | 文本块 | Thinking 块 | Tool 调用块 | Tool 结果块 |
|---------|--------|-------------|-------------|-------------|
| full（完整） | 展示 | 展示 | 展示 | 展示 |
| normal（标准） | 展示 | 隐藏 | 展示 | 展示 |
| off（仅文本） | 展示 | 隐藏 | 隐藏 | 隐藏 |

展示等级只控制可见内容，不改变模型推理强度、Agent 行为与工具执行。展示等级过滤不删除应保留的对话历史，也不减少模型应获得的上下文。

#### 基础配置

Owner 可以在配置中分别设置 IM 与 CLI 的基础展示等级，可选值为 full、normal 或 off。未配置时，IM 默认 full，CLI 默认 normal。full 仅表示允许展示全部内容块，界面是否展开这些内容由对应界面需求定义。

#### 运行时临时切换

Owner 和 User 在运行时切换的等级只临时覆盖当前 Session，不影响其他 Session，也不要求持久保存。服务重启后，或运行中需要重新读取配置时，可以回到配置中的基础展示等级。基础配置的变更生效时机，以及其他场景下临时覆盖是否保留，需求层不定义，由设计根据架构选择自然的处理方式。

同一条回复沿用开始时生效的展示等级，切换只对其后开始的回复生效，不追溯修改已发送内容。

#### 流式展示

流式和非流式回复均在内容交付展示前执行展示等级过滤。流式回复中，允许展示的文本逐步输出，不等待整条回复生成完毕；被隐藏的内容不进入出站渲染与发送，也不参与输出格式选择。

#### 中断与过滤异常

回复中断时仍遵守该回复的展示等级，不因中断而补发本应隐藏的内容。已生成但尚未展示的 Thinking 块与 Tool 块，仅在等级允许时按 IM Adapter 的中断呈现规则处理。中断或错误提示不因展示等级被隐藏，其余中断降级遵守 Gateway 的出站消息统一处理规则。

展示等级过滤本身失败时，停止本次回复的后续内容发送，保留已发送部分并提示处理失败，记录异常；不得回退发送未过滤的原始内容。

> **交叉引用**：展示等级的切换方式。详见 [slash §F11](slash.md)（展示等级）。
> **交叉引用**：配置重载机制。详见 [config §F4](config.md)（配置重载）。
> **交叉引用**：IM 格式选择。详见 [im_adapter §F3](im_adapter.md)（出站消息格式自动选择）。
> **交叉引用**：流式输出与中断呈现。详见 [im_adapter §F4](im_adapter.md)（流式增量渲染）。
> **交叉引用**：Thinking 内容的界面呈现与可见范围。详见 [llm §F3](llm.md)（推理过程可见与安全）。
> **交叉引用**：终端呈现。详见 [cli §F2](cli.md)（终端输出渲染）。
> **交叉引用**：出站错误降级总则。详见 [gateway §F7](gateway.md)（出站消息统一处理）。

### F6. 调试日志

对入站和出站的消息处理过程按统一分级体系记录调试日志：

| 日志事件 | 级别 |
|---------|------|
| 消息追踪标识建立结果 | 中间状态 |
| 正文保真处理结果 | 中间状态 |
| 展示等级过滤结果 | 中间状态 |
| 入站原始消息全文 | 完整内容 |
| 处理后的出站消息全文 | 完整内容 |
| 发生回退但仍可正常处理的情况 | 降级告警 |
| 无法继续处理的故障 | 异常 |

上述日志的最低记录级别、存储保留、凭据脱敏与复用规则统一遵守 Debug Log 的定义。

> **交叉引用**：日志链路关联。详见 [debug_log §F1](debug_log.md)（完整消息链路追踪）。
> **交叉引用**：日志最低记录级别与分级。详见 [debug_log §F2](debug_log.md)（分层日志级别）。
> **交叉引用**：日志存储保留。详见 [debug_log §F3](debug_log.md)（日志存储与保留）。
> **交叉引用**：凭据脱敏。详见 [debug_log §F4](debug_log.md)（隐私保护）。
> **交叉引用**：日志复用。详见 [debug_log §F6](debug_log.md)（现有日志机制复用）。

## 非功能需求

1. **可靠性**：处理失败时遵守入站与出站各自的恢复边界，不因异常突破用户选择的展示范围。
2. **性能**：入站与出站处理的复杂度应达到满足功能与稳定性要求的理论最优，不引入可避免的额外消息扫描或处理步骤，不使处理管道成为消息链路中的感知瓶颈。
3. **可扩展**：增加新的消息处理能力不改变已有处理行为。
4. **可观测**：处理故障记录足够的定位上下文，日志分级清晰一致。

> **交叉引用**：正文清理失败处理。详见 [F3](#f3-入站正文保真)（入站正文保真）。
> **交叉引用**：出站过滤异常处理。详见 [F4](#f4-出站回复展示等级控制)（出站回复展示等级控制）。

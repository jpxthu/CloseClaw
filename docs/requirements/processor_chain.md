# Processor Chain 需求

## 概述

来自 IM 平台与 CLI 的消息遵守一致的处理规则——入站保留用户正文并建立消息追踪，出站按展示等级控制可见内容，两端记录可用于排查问题的调试日志。

## 功能需求

### F1. 入站消息统一处理

来自 IM 平台与 CLI 的入站消息统一记录原始内容、建立消息追踪，并遵守正文保真规则。

不同渠道不改变用户正文保真与消息追踪的基本约定。日志记录范围、级别与过滤约束统一按 F6 执行。

> **交叉引用**：空消息与非文本消息的处理详见 [gateway §F2](gateway.md)（入站消息预处理）、[gateway §F3](gateway.md)（消息类型识别与非文本处理）。

### F2. 消息追踪标识

正常情况下，每条入站消息都有独立且唯一的消息追踪标识，用于串联该消息在各处理环节中的日志。该标识不是 Session 的标识，不用于查找或创建 Session；具体格式与生成方式不在需求层规定。

消息追踪异常不阻断消息处理，尽力保留已有日志关联，并记录降级告警。此时允许追踪链路不完整，不因无法建立完整追踪而拒绝用户消息。

> **交叉引用**：Session 的查找与消息追踪标识相互独立。详见 [session §F1](session.md)（对话持久化与恢复）。
> **交叉引用**：完整链路追踪与异常情况下的关联范围详见 [debug_log §F1](debug_log.md)（完整消息链路追踪）。

### F3. 入站正文保真

用户发送的正文原样交给后续对话或指令处理，不自动整理格式。正文中的空格、换行、代码、Markdown 与字符均保留，不压缩连续空行、不删除行尾空格，也不笼统删除不可见字符。

允许清理明确不属于用户正文的平台附带控制信息，不得借此改写用户正文。清理失败时保留原始正文继续处理，并记录降级告警，不丢失消息。

非文本消息不执行正文格式整理，其支持范围与提示规则由 Gateway 定义。

> **交叉引用**：平台消息归一化详见 [im_adapter §F2](im_adapter.md)（入站消息归一化）。
> **交叉引用**：非文本消息的支持范围详见 [gateway §F3](gateway.md)（消息类型识别与非文本处理）。

### F4. 出站回复展示等级控制

#### 等级与内容

Owner 和 User 可以控制当前 Session 在 IM 平台或 CLI 中展示的回复细节。内容块名称统一为文本块、Thinking 块（推理/思考内容）、Tool 调用块与 Tool 结果块；Tool 块是后两者的统称。

| 展示等级 | 文本块 | Thinking 块 | Tool 调用块 | Tool 结果块 |
|---------|--------|-------------|-------------|-------------|
| full（完整） | 展示 | 展示 | 展示 | 展示 |
| normal（标准） | 展示 | 隐藏 | 展示 | 展示 |
| off（仅文本） | 展示 | 隐藏 | 隐藏 | 隐藏 |

展示等级只控制可见内容，不改变模型推理强度、Agent 行为与工具执行，不删除应保留的对话历史，也不减少模型应获得的上下文。

#### 配置与临时切换

Owner 可以在配置中设置 IM 与 CLI 的基础展示等级，取值均为 full、normal 或 off。未配置时，IM 默认 full，CLI 默认 normal。full 表示内容可查看，不要求默认全部展开；各界面的具体呈现由对应界面需求定义。

运行时切换只临时覆盖当前 Session 的展示等级，不影响其他 Session，也不要求持久保存。服务重启或运行过程中需要重新读取配置时，可以回到配置中的基础展示等级。基础配置的变更生效时机，以及其他场景下临时覆盖是否保留，需求层不定义，由设计根据架构选择自然的处理方式。

展示等级切换不影响正在生成的回复，只对切换后开始的回复生效；同一条回复始终沿用其开始时生效的等级，不追溯修改已发送内容。

#### 流式展示与异常

流式和非流式回复均在内容交付展示前执行等级过滤。流式回复中，允许展示的文本仍逐步输出，不等待整条回复生成完毕；被隐藏的内容不进入出站渲染与发送，也不参与输出格式选择。

回复中断时仍遵守该回复的展示等级，不因中断而补发本应隐藏的内容。已发送的内容保留；已生成但尚未展示的 Thinking/Tool 内容，仅在等级允许时按中断展示规则处理。中断或错误提示不因展示等级被隐藏。

展示过滤本身失败时，停止本次回复的后续内容发送，保留已发送部分并提示处理失败，记录异常；不得回退发送未过滤的原始内容。

> **交叉引用**：配置重载机制详见 [config §F4](config.md)（配置重载）。
> **交叉引用**：IM 格式选择与流式中断展示详见 [im_adapter §F3](im_adapter.md)（出站消息格式自动选择）、[im_adapter §F4](im_adapter.md)（流式增量渲染）。

### F6. 调试日志

对入站和出站的消息处理过程按统一分级体系记录调试日志：
- 消息追踪标识建立结果、正文保真处理结果、展示等级过滤结果：中间状态
- 入站原始消息全文与处理后的出站消息全文：完整内容
- 发生回退但仍可正常处理的情况：降级告警
- 无法继续处理的故障，以及日志写入失败：异常

上述事件是否实际记录遵守配置的最低日志级别；默认不记录完整内容。所有日志均遵守凭据脱敏规则，“全文”不表示可以记录凭据明文。同一事件不重复记录。

> **交叉引用**：日志框架定义详见 [debug_log §F1](debug_log.md)（完整消息链路追踪）、[debug_log §F2](debug_log.md)（分层日志级别）、[debug_log §F3](debug_log.md)（日志存储与保留）、[debug_log §F4](debug_log.md)（隐私保护）、[debug_log §F6](debug_log.md)（现有日志机制复用）。

## 非功能需求

1. **可靠性**：入站追踪或正文清理失败不丢失消息，继续处理原始正文；出站过滤失败按 F4 停止后续内容发送，不使用未过滤内容兜底。其他出站错误遵守 Gateway 的统一降级规则。
2. **性能**：入站与出站处理选择满足功能与稳定性要求的理论最优复杂度，不引入可避免的额外消息扫描或处理步骤，不使处理管道成为消息链路中的感知瓶颈。
3. **可扩展**：增加新的消息处理能力不改变已有处理行为。
4. **可观测**：处理故障记录足够的定位上下文，使用统一的“异常”与“降级告警”级别，不混用无明确定义的告警名称。

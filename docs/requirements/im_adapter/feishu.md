# 飞书需求

## 概述

飞书是 IM Adapter 模块的一个平台实现。用户通过飞书私聊与 Agent 交互，Agent 输出以卡片消息、代码块等形式在飞书中渲染，Agent 可使用飞书平台特有工具（消息操作、日历、文档等）完成平台操作。

飞书平台适配基于飞书官方 CLI（`lark-cli`）实现，不使用 webhook 回调模式。

涉及飞书平台特有数据与格式的需求，须以真实采集的平台数据为准。基于官方 CLI 实测采集的事件样本与字段语义结论见 `tests/fixtures/feishu/cli-poc/`（含 README，字段语义以该目录实测记录为准）。

## 功能需求

### F1. 飞书入站消息接收

系统通过飞书 CLI 的事件订阅（WebSocket 长连接，无需公网回调地址）接收飞书消息，支持以下消息类型：

- **文本消息**：提取纯文本正文。
- **富文本消息**（飞书的 post 消息）：展开为可读文本，保留的内容特征见下。
- **引用/回复消息**：提取被引用消息的文本内容，拼接规则见 [im_adapter §F2](../im_adapter.md)（入站消息归一化）。
- **话题消息**：识别话题消息，话题 ID 解析与回复定位见 [F7](#f7-飞书话题与-session-匹配)。
- **非文本消息**（图片、文件、音频等）：媒体下载与存储、Agent 使用媒体的方式见 [im_adapter §F9](../im_adapter.md)（媒体文件收发与存储）；后续处置与 Gateway 对非文本消息的处理不冲突（详见 [gateway §F3](../gateway.md)（消息类型识别与非文本处理））。图片消息可能以富文本形式到达（图片为内嵌元素、可伴随文字），识别规则见 `tests/fixtures/feishu/cli-poc/`（字段语义以该目录实测记录为准）。
- **表情消息**：表情符号渲染为文本占位符形式（如 `[OK]`、`[赞]`）。

富文本消息保留以下内容特征：

- 标题、段落
- 有序/无序列表（含多级嵌套）
- 文本样式：粗体、删除线、下划线及其组合
- @提及（渲染为用户名）
- 引用块
- 内嵌媒体占位符（如图片以 `[图片]` 表示）
- 行内代码

链接暂不解析，不保留。

入站解析后输出归一化消息。各字段语义见 [im_adapter §F2](../im_adapter.md)（入站消息归一化），其中平台特有的取值为：

- 平台标识：固定为 feishu
- 账号标识：经身份映射得到的 CloseClaw 用户 ID

接收消息的机器人身份不进入归一化字段，原则见 [im_adapter §F2](../im_adapter.md)（入站消息归一化）。机器人到 Agent 的绑定与路由逻辑详见 [gateway §F4](../gateway.md)（普通消息路由到对话）。

### F2. 飞书消息事件处理

除消息接收外，系统需处理以下飞书事件：

- **消息回应**（对已有消息添加表情，区别于上文的「表情消息」）：用户对消息添加表情回应时，系统接收该事件，可用作 Agent 交互信号。
- **卡片按钮点击**：用户点击卡片按钮时，系统接收按钮动作并路由到对应处理逻辑。（暂不启用，与 [F5](#f5-飞书交互指令)（飞书交互指令）一并暂缓）

### F3. 飞书消息发送

Agent 输出通过飞书发送给用户。消息格式自动选择规则见 [im_adapter §F3](../im_adapter.md)（出站消息格式自动选择）。飞书将轻量文本消息映射为文本消息，将富格式消息映射为卡片消息。

### F4. 飞书卡片渲染

Agent 输出的富格式内容需正确渲染为飞书卡片。

**标题提取**：首行 `#` 标题提取为卡片标题（蓝色），标题行不进入正文。

**正文元素映射**（「原生」指飞书平台的对应原生样式）：

| 内容 | 飞书卡片呈现 |
|------|------------|
| `# 标题` | 卡片标题（蓝色） |
| `##` 及更低级标题 | 原生标题样式 |
| 粗体 / 斜体 | 原生粗体 / 斜体 |
| 删除线 / 下划线 | 原生删除线 / 下划线 |
| 行内代码 | 原生行内代码 |
| 代码块 | 原生代码块（飞书平台自行进行语法高亮） |
| 引用 | 原生引用块 |
| 列表（有序/无序） | 原生列表 |
| 链接 | 原生可点击链接 |
| 分割线 | 原生水平分割线 |

**特殊块渲染**：
- **Thinking 块**：以折叠推理区块的形式展示。
- **Tool 调用块**：以工具调用描述形式展示，含工具名和参数概要。
- **Tool 结果块**：展示工具调用的结果内容。

### F5. 飞书交互指令

> **暂不启用**：与 [F2](#f2-飞书消息事件处理)「卡片按钮点击」同属一条交互链路，按钮渲染与点击回执一并暂缓。

Agent 输出中的交互指令（按钮）在飞书卡片中渲染为可点击按钮：

- 首个按钮渲染为主要样式（突出显示）
- 后续按钮渲染为默认样式
- 所有按钮平铺在卡片底部操作区域

用户点击按钮后，系统通过按钮交互事件接收按钮动作信息并执行对应操作。

### F6. 飞书平台工具

Agent 可使用以下飞书平台工具，在对话中完成平台特有操作：

| 工具分组 | 能力范围 |
|---------|---------|
| 飞书 IM 操作 | 发送消息、撤回消息、编辑消息、表情回应等 |
| 飞书日历 | 日程创建、查询、修改、删除 |
| 飞书任务 | 任务创建、查询、修改、删除 |
| 飞书多维表格 | 表格数据读写、记录管理 |
| 飞书文档 | 文档创建、编辑、读取 |
| 飞书云盘 | 文件上传、下载、管理 |
| 飞书电子表格 | 表格创建、编辑、读取 |

### F7. 飞书话题与 Session 匹配

用户与 Agent 的私聊中，Session 按话题粒度划分：

- **顶层消息**（非话题回复的普通消息）：每条开启一个新 Session；会话对端为对方用户与该顶层消息的消息标识的组合，保证不同顶层消息间对端取值互不相同
- **话题回复**（对已有消息做话题式回复）：归入该话题对应的已有 Session；会话对端为对方用户与话题标识的组合，保证同一话题内对端取值相同、不同话题间取值不同；话题标识为飞书的事件字段 `thread_id`
- 出站时，Agent 对 Session 的回复携带话题标识定向回复到原话题，保持会话连续

话题标识的归一化取值见 [im_adapter §F2](../im_adapter.md)（入站消息归一化）的会话对端字段。

## 非功能需求

### 性能

- 卡片消息渲染不应显著增加消息发送延迟（用户感知与普通 IM 消息相当）

### 可靠性

- 飞书 API 调用失败时按 [im_adapter](../im_adapter.md)（稳定性）所述原则降级，Agent 继续运行不受影响
- 工具调用失败时 Agent 收到清晰错误反馈

### 可观测性

- 非文本入站消息记录日志
- 表情回应记录日志，便于分析交互行为

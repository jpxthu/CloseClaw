# 飞书需求

## 概述

飞书是 IM Adapter 模块的一个平台实现。用户通过飞书私聊与 Agent 交互，Agent 输出以文本消息、卡片消息两种形式在飞书中渲染，Agent 可使用飞书平台工具（消息操作、日历、任务、多维表格、文档、云盘、电子表格）完成平台特有操作。

飞书平台适配基于飞书官方 CLI 实现——事件订阅与平台接口调用由 CLI 承担，系统不自建 webhook 服务、不保存平台凭证（Owner 确定的技术选型）。

## 功能需求

### F1. 飞书入站消息接收

涉及飞书平台特有数据与格式的需求，须以真实采集的平台数据为准。基于官方 CLI 实测采集的事件样本与字段语义结论见 `tests/fixtures/feishu/cli-poc/`（含 README，字段语义以该目录实测记录为准）。

系统通过飞书官方 CLI 的事件订阅接收飞书消息，需识别的消息形态如下（非文本消息当前不纳入处理）：

- **文本消息**（`text`）：提取纯文本正文。
- **富文本消息**（`post`）：展开为可读文本，保留的内容特征见下。
- **话题回复消息**：按 `thread_id` 识别话题形态，标识解析与回复定位见 [F7](#f7-飞书话题与-session-匹配)。
- **非文本消息**（图片、文件等）：不在当前范围，处理规则见 [gateway §F3](../gateway.md)（消息类型识别与非文本处理）。

#### 不在当前范围

- **群聊消息**：按 `chat_type=group` 在入站解析阶段识别并丢弃，记录调试日志
- **消息引用**：引用关系不解析、不拼接被引用正文（见 [im_adapter §F2](../im_adapter.md)（入站消息归一化））；话题回复不属于引用，按 [F7](#f7-飞书话题与-session-匹配) 处理
- **卡片按钮交互**：见 [F2](#f2-飞书消息事件处理)（飞书消息事件处理）
- **非文本消息的媒体下载与存储**：见 [gateway §F3](../gateway.md)（消息类型识别与非文本处理）

图片按到达形态分别处理：

- 作为独立消息到达时，按非文本消息规则处理
- 作为富文本内嵌元素（可伴随文字）到达时，按富文本规则识别行内图片标记

到达形态的识别规则以上述实测记录为准。

#### 富文本正文特征

富文本消息保留以下内容特征：

- 标题（并入正文首行，具体形式以实测记录为准）
- 段落
- @提及（渲染为显示名）
- 内嵌图片可被识别，但其标记从正文剥离、不进入归一化正文（剥离规则见 [im_adapter §F2](../im_adapter.md)（入站消息归一化））；媒体不在当前范围
- 链接（以 `[文本](URL)` 形式出现）

富文本正文到达时已丢失样式属性（粗体、斜体、删除线、下划线）、行内代码与引用块等排版信息，入站不做样式还原；正文中的 Markdown 字面字符按原文保留。

话题关系由事件字段 `thread_id` 表达，不依赖正文标记；引用类字段当前不解析、不使用（不在当前范围，见本节「不在当前范围」）。

#### 归一化字段

入站解析后输出归一化消息。各字段语义见 [im_adapter §F2](../im_adapter.md)（入站消息归一化），其中平台特有取值为：

- 平台标识：固定为 feishu
- 发送者：飞书 open_id，按接收方机器人应用语境取值
- 账号标识：经身份映射得到的 CloseClaw 用户 ID
- 会话对端：按顶层消息 / 话题回复两类会话粒度取值，见 [F7](#f7-飞书话题与-session-匹配)
- 消息正文：文本消息取纯文本正文；富文本消息取展开后的可读文本

接收方机器人应用不进入归一化字段（其用于确定消息路由到的 Agent），原则见 [im_adapter §F2](../im_adapter.md)（入站消息归一化）。机器人到 Agent 的绑定与路由逻辑详见 [gateway §F4](../gateway.md)（普通消息路由到对话）。

#### 事件标识语义

飞书事件字段与语义如下（仅列标识类字段，实测记录见上述样本目录）：

| 标识 | 事件字段 | 语义 |
|------|---------|------|
| 接收方机器人应用 | — | 接收该事件的机器人应用，由接收方飞书官方 CLI 实例所绑定的应用配置确定 |
| 发送者 | `sender_id`（`ou_`） | 发送者在该接收方应用语境下的 open_id |
| 会话 | `chat_id`（`oc_`）+ `chat_type`（`p2p`；`group` 仅出现在群聊事件，群聊不在当前范围） | 消息所属会话 |
| 消息 | `message_id`（`om_`） | 消息标识 |
| 话题 | `thread_id`（`omt_`） | 话题标识；顶层消息无此字段 |
| 话题根消息 | `root_id` | 话题根消息；当前不解析、不使用（引用不在范围） |
| 直接父消息 | `reply_to` | 直接父消息；当前不解析、不使用（引用不在范围） |
| 事件 | `event_id`（信封式事件为 `header.event_id`） | 事件标识 |

**open_id 按接收方应用语境取值**：采集数据中 Owner 的 open_id 按应用语境分为 `<open_id_owner_b1ctx>` / `<open_id_owner_b2ctx>` 两个不同占位符，印证 [im_adapter §F2](../im_adapter.md)（入站消息归一化）所述的跨应用隔离语义；跨应用归并规则见 [message_flow §F3](../message_flow.md)（跨机器人身份归并）。

> **交叉引用**：群聊消息的路由层排除规则、接收方机器人应用与 Agent 的绑定与消息路由详见 [gateway §F4](../gateway.md)（普通消息路由到对话）。
> **交叉引用**：Session 的确定、创建与恢复详见 [session §F1](../session.md)（对话持久化与恢复）。
> **交叉引用**：平台特有工具的注册与发现详见 [tools §F9](../tools.md)（工具扩展接入）。

### F2. 飞书消息事件处理

除消息接收外，系统需处理以下飞书事件：

- **表情回应**（对已有消息添加表情）：用户对消息添加表情回应时，系统接收该事件并记录日志（消息标识、回应者标识、表情类型、事件时间；字段名以实测记录为准），作为交互行为的可观测信号；该事件不进入对话上下文，也不触发 Agent 回复。
- **卡片按钮交互**（`card.action.trigger`）：按钮交互不在当前范围。事件到达后忽略并记录调试日志，不回复、不进入对话上下文。

### F3. 飞书消息发送

Agent 输出通过飞书发送给用户。消息格式自动选择规则见 [im_adapter §F3](../im_adapter.md)（出站消息格式自动选择）。飞书将文本消息渲染为原生文本消息，将卡片消息渲染为卡片——前者对应 im_adapter 的轻量文本消息，后者对应 im_adapter 的富格式消息。

### F4. 飞书卡片渲染

Agent 输出的富格式内容需正确渲染为飞书卡片。

#### 标题提取

Agent 输出的首行 `#` 标题提取为卡片标题（蓝色），标题行不进入正文。

#### 正文元素映射

「原生」指飞书平台的对应原生样式：

| 内容 | 飞书卡片渲染 |
|------|------------|
| `# 标题`（仅首行） | 卡片标题（蓝色） |
| `# 标题`（首行之外） | 原生标题样式 |
| `##` 及更深层级标题（`##`~`######`） | 原生标题样式 |
| 段落 | 原生正文文本 |
| 粗体 / 斜体 | 原生粗体 / 斜体 |
| 删除线 / 下划线 | 原生删除线 / 下划线 |
| 行内代码 | 原生行内代码 |
| 代码块 | 原生代码块（语法高亮由飞书负责） |
| 引用 | 原生引用块 |
| 列表（有序/无序） | 原生列表 |
| 链接 | 原生可点击链接 |
| 分割线 | 原生水平分割线 |

#### 特殊块渲染

- **Thinking 块**：渲染为折叠推理区块。
- **Tool 调用块**：渲染为工具调用描述，含工具名和参数概要；中断时展示已解析的参数概要并标注该调用已中断、未完成。
- **Tool 结果块**：展示工具调用的结果内容。

### F6. 飞书平台工具

Agent 可使用以下飞书平台工具，在对话中完成平台特有操作：

| 工具分组 | 能力范围 |
|---------|---------|
| 飞书 IM 操作 | 发送消息、撤回消息、编辑消息、对消息添加/撤回表情回应等 |
| 飞书日历 | 日程创建、查询、修改、删除 |
| 飞书任务 | 任务创建、查询、修改、删除 |
| 飞书多维表格 | 表格数据读写、记录管理 |
| 飞书文档 | 文档创建、编辑、读取 |
| 飞书云盘 | 文件上传、下载、管理 |
| 飞书电子表格 | 表格创建、编辑、读取 |

本表为能力范围概述，不穷举具体工具。

### F7. 飞书话题与 Session 匹配

用户与 Agent 的私聊中，Session 按顶层消息与话题粒度划分——飞书的会话形态天然对应这两种粒度，不同平台可按自身形态定义：

- **顶层消息**（非话题回复的普通消息）：每条开启一个新 Session；会话对端为发送者与该顶层消息的消息标识的组合
- **话题回复**（对已有消息做话题式回复）：归入该话题对应的 Session——话题回复首次到达时按其 `thread_id` 建立对应 Session，后续该话题下回复持续归入同一 Session；会话对端为发送者与话题标识的组合

话题标识为飞书的事件字段 `thread_id`。话题回复直接归入该话题对应的 Session，不拼接被引用消息正文。

出站时，话题回复场景下 Agent 的回复携带话题标识，定向回复到该 Session 对应的话题；顶层消息场景下直接回复到该飞书会话（不进入话题）。

会话对端由发送者标识（open_id）与消息标识或话题标识组合而成，归一化取值规则见 [im_adapter §F2](../im_adapter.md)（入站消息归一化）。

## 非功能需求

### 性能

- 卡片消息渲染不引入额外显著处理开销，与普通 IM 消息渲染保持同一量级

### 可靠性

- 飞书 API 调用失败时按 [im_adapter](../im_adapter.md#稳定性)（稳定性）所述原则降级，Agent 继续运行不受影响
- 工具调用失败时 Agent 收到明确错误信息

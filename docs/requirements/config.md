# Config 需求

## 概述

配置模块满足 Owner 对 CloseClaw 配置的日常管理需求：单文件损坏不波及其他配置文件、写入操作不会损坏已有配置、敏感凭据与业务配置安全隔离。配置的生效时机由各消费模块决定，配置模块提供变更检测、通知和重启类配置的自动重启触发能力。

## 功能需求

### F1. 多文件配置结构

Owner 的 CloseClaw 配置按职责拆分为多个独立配置文件，集中存放在配置目录下。单个文件损坏不波及其他文件。

配置文件的职责包括模型定义、渠道配置、账户绑定、Gateway 参数、插件列表、会话参数、系统设置等。其中「账户绑定」记录 IM 侧身份与 CloseClaw 侧身份的对应关系：机器人对应到 Agent，IM 用户对应到 User。

CloseClaw 通过显式注册清单管理 Agent 加载：只有在注册清单中列出的 Agent ID 才会被加载，目录中存在但未注册的 Agent 配置会被忽略。注册清单支持注释格式，注释掉某行即取消注册。每个 Agent 拥有独立的配置目录，存放该 Agent 的配置文件。

项目仓库可以包含项目级 Agent 注册清单和配置，与用户级 Agent 注册清单和配置合并使用：Agent ID 列表取并集，配置字段以项目级优先覆盖用户级。

> **交叉引用**：配置目录的操作系统标准位置详见 [platform §F2](platform.md)（操作系统标准配置目录）。
> **交叉引用**：账户绑定中 User 身份与绑定规则详见 [permission §F1](permission.md)（身份体系）。
> **交叉引用**：机器人与 Agent 的绑定及消息路由详见 [gateway §F4](gateway.md)（普通消息路由到对话）。

### F2. 安全写入

CloseClaw 修改配置文件时，校验失败或写入中断不会产生部分覆盖或损坏的配置文件，原有配置保持不变。

### F3. 启动容错与备份恢复

CloseClaw 启动时，若某个配置文件损坏或无法解析，自动使用最新的一份可用备份恢复；每个配置文件自动保留有限份数的近期备份。

恢复成功后 CloseClaw 正常启动并记录警告；恢复失败（如无可用备份）时拒绝启动。配置文件存在但部分字段缺失时的默认值处理见 F6，凭据文件加载失败的处理见 F5。

### F4. 配置重载

Owner 在 CloseClaw 运行时编辑配置文件后，变更的生效时机取决于各消费模块的设计，不由配置模块统一决定；本文件不重复定义各模块的生效机制细节，统一分类与汇总索引见 F7。

配置模块检测到文件变更后通知相关模块，各模块自行决定重载策略。对属于重启类的配置，配置模块在变更确认后触发网关择机重启。

**配置生效机制文档化原则**：凡消费 config 配置的模块，其需求文档必须写明两项内容：

- 本模块所消费配置的生效机制（即配置变更后何时生效）；
- 指向 [config §F4](config.md)（配置重载）的交叉引用。

生效机制的分类、重启类判定标准与各配置文件的归属矩阵详见 F7。

> **交叉引用**：网关择机重启的完整行为（择机窗口、消息暂存补投、变更合并、完成通知）详见 [daemon §F6](daemon.md)（配置触发的网关重启）。

Owner 对同一文件短时间内的多次写入只触发一次重载。重载校验失败时，若该配置文件此前已成功加载过，保留内存中的旧配置继续运行，不恢复备份文件，通过 IM 通知 Owner；若发生变更的配置文件为运行期间新增、从未成功加载过，则阻塞该配置的加载及依赖该配置的后续流程。启动时的损坏处理见 F3。

### F7. 生效机制与重启类判定

配置按生效机制分为以下类别：

- **即时生效**：配置变更后立即生效，下一次相应操作即使用新配置。
- **边界生效**：配置变更在某个使用边界统一生效——如新会话创建、System Prompt 组装、周期任务的下一次扫描触发。
- **重启生效（重启类）**：配置变更后须重启 Gateway 方可生效；重启由配置模块确认变更后触发、daemon 择机执行（见 F4），重启执行前系统按旧配置运行。

**重启类判定标准**：变更后是否需要重启，取决于配置所支撑的服务——Gateway 服务参数（监听端口、入站队列容量）、IM 平台启用清单、模型与凭据定义等支撑 Gateway 服务运行的配置属重启类；其余配置变更后无需重启即可生效。

**各配置文件的生效机制归属**（本表为汇总索引：「生效机制」列为类别归属与触发边界摘要，「定义位置」列为该配置生效机制的权威定义章节）：

| 配置 | 生效机制 | 定义位置 |
|------|---------|----------|
| 权限规则（permissions.json 及权限白名单） | 即时生效 | [permission §F6](permission.md)（权限配置管理） |
| Agent 配置与注册清单 | 边界生效（下次新建会话） | [agent §F6](agent.md)（运行时配置查询） |
| 会话生命周期参数 | 边界生效（下次触发/新会话） | [session §F6](session.md)（会话归档与清理） |
| 技能目录与清单 | 边界生效（下次 System Prompt 组装） | [skills §F5](skills.md)（技能文件变更）、[system_prompt §F6](system_prompt.md)（内容缓存与自动刷新） |
| 记忆配置 | 边界生效（下次触发） | [memory §F7](memory.md)（记忆功能的精细化开关） |
| 日志级别与保留期 | 边界生效（下一条日志/下次清理） | [debug_log §F2](debug_log.md)（分层日志级别）、[debug_log §F3](debug_log.md)（日志存储与保留） |

> 本表为汇总索引，各配置生效机制的权威定义为「定义位置」所列模块文档；若模块文档与本表不一致，以模块文档为准，并应修订本表使之与模块文档一致。

### F5. 凭据安全隔离

API Key 等敏感凭据文件与业务配置文件分开存放，按服务商分文件存储。业务配置只引用服务商名称，不直接包含凭据内容，凭据在 CloseClaw 运行时自动关联。凭据文件加载失败不阻塞 CloseClaw 启动，仅影响依赖该凭据的功能。

### F6. 配置版本兼容

CloseClaw 配置结构变更时，已有配置文件必须可被新版本正常加载。配置中缺失的字段使用默认值加载，不再支持的旧字段被静默忽略，不阻塞启动。

# Config 需求

## 概述

配置模块为 Owner 提供 CloseClaw 配置的日常管理能力：单文件损坏不会连带损坏其他配置文件、写入操作不会损坏已有配置、凭据访问受控且不在校验结果与日志中回显。生效机制由配置模块统一分类（见 [F7](#f7-生效机制与重启类判定)（生效机制与重启类判定）），各消费模块据此执行；配置模块提供变更检测、通知和重启生效类配置的自动重启触发能力。

## 功能需求

### F1. 多文件配置结构

Owner 的 CloseClaw 配置按职责拆分为多个独立配置文件与子目录，集中存放在配置目录下。单个文件损坏不会连带损坏其他文件；启动期的损坏处置见 [F3](#f3-启动容错与备份恢复)（启动容错与备份恢复）。

配置按职责分为以下配置类别（独立配置文件或配置目录）：

- 模型定义
- 渠道配置（各 IM 平台的接入参数；需要系统保存的凭据字段随本类配置存放）
- 账户绑定
- Gateway 参数
- 插件列表（启用的平台插件）
- Session 参数
- 权限配置（权限规则、沙盒模式）
- Agent 配置档案（每个 Agent 独立目录）
- Agent 注册清单
- 技能目录与清单
- 记忆配置（含全局配置与各 Agent 配置档案内的按 Agent 字段）
- 日志配置（最低日志级别、日志保留天数）
- 展示等级配置（IM 与 CLI 的基础展示等级）
- workflow 定义

插件列表决定系统加载哪些平台插件（平台启停语义详见 [im_adapter §F1](im_adapter.md)（多平台插件化适配））；渠道配置存放各已启用平台的接入参数（启用判定见 [im_adapter §F9](im_adapter.md)（IM 平台配置归属））。各 IM 平台的渠道配置分别独立存放，单个平台的渠道配置损坏不影响其他平台。

以上配置类别均对应业务配置文件；权限配置文件的校验与加载容错另见 [permission §F6](permission.md)（权限配置管理）。其中「技能目录与清单」「workflow 定义」的语义由 [skills §F2](skills.md)（技能目录层级）、[skills §F4](skills.md)（技能清单）、[workflow §F1](workflow.md)（workflow 定义）定义，config 仅承载其目录位置与清单来源。

凭据不是独立的配置类别，以明文字段随所属模块的配置存放，存放与保护要求见 [F5](#f5-凭据存放与保护)（凭据存放与保护）。

AGENTS.md 是独立于 Agent 配置档案的身份与行为准则文件，不作为本节的业务配置文件管理。

后续如有系统设置，可考虑单列一个配置文件。

#### 账户绑定

「账户绑定」建立 IM 侧身份与 CloseClaw 侧身份的双向关系，分两类。每类绑定在两个方向的消息流中分别使用：

- **机器人 ↔ Agent**：入站时由接收方机器人应用解析出 Agent（入站路由）；出站时由 Agent 解析出机器人（出站选择）。
- **IM 用户 ↔ User**：入站时由发送者解析出 User（会话归属、权限主体）；出站时由 User 解析出该 User 对应的 IM 用户（Agent 主动向该 User 发送消息时定位其标识）。

基数规则（不随配置变更放宽）：

- **机器人 ↔ Agent**：同一 IM 平台内一一对应——一个机器人只对应一个 Agent，一个 Agent 在同一平台只对应一个机器人。
- **IM 用户 ↔ User**：同一 IM 平台内一一对应——一个 IM 用户只对应一个 User，一个 User 在同一平台只对应一个 IM 用户。
- **计数单位**：基数中的「IM 用户」以自然人为计数单位，不是平台侧的用户标识（跨机器人应用的标识归并详见 [message_flow §F3](message_flow.md)（跨机器人身份归并））。
- **跨平台**：单个 CloseClaw User 可对应多个 IM 平台的用户，单个 CloseClaw Agent 可对应多个 IM 平台的机器人。

两类绑定的变更生效时机分别见 [F7](#f7-生效机制与重启类判定)（生效机制与重启类判定）（其中「IM 用户 ↔ User」在需求层不定义）；一类绑定的变更不改变另一类绑定的内容。

#### Agent 注册清单

CloseClaw 通过显式注册清单管理 Agent 加载：只有在注册清单中列出的 Agent ID 才会被加载，目录中存在但未注册的 Agent 配置会被忽略。注册清单支持注释格式，注释掉某行即取消注册（便于 Owner 直接编辑清单取消注册）。每个 Agent 拥有独立的配置目录，存放该 Agent 的配置档案文件。

> **交叉引用**：配置目录的操作系统标准位置。详见 [platform §F2](platform.md)（操作系统标准配置目录）。
> **交叉引用**：身份体系与跨平台身份映射。详见 [permission §F1](permission.md)（身份体系）。
> **交叉引用**：机器人与 Agent 的绑定及消息路由。详见 [gateway §F4](gateway.md)（普通消息路由到对话）。
> **交叉引用**：入站归一化字段（发送者、接收方机器人应用等）。详见 [im_adapter §F2](im_adapter.md)（入站消息归一化）。
> **交叉引用**：平台、发送者、会话对端、账号四项标识共同确定主 Agent Session。详见 [session §F1](session.md)（对话持久化与恢复）。
> **交叉引用**：本模块定义的绑定在完整消息流链路中的使用位置。详见 [message_flow §F1](message_flow.md)（入站链路）；完整消息流建议结合阅读以理解完整产品流程。
> **交叉引用**：出站方向的对应位置。详见 [message_flow §F2](message_flow.md)（出站链路）。
> **交叉引用**：IM 平台渠道配置与凭据字段的归属。详见 [im_adapter §F9](im_adapter.md)（IM 平台配置归属）。
> **交叉引用**：模型定义与供应商配置（含凭据）的归属。详见 [llm §F6](llm.md)（供应商配置向导）。
> **交叉引用**：Agent 配置档案的能力维度。详见 [agent §F1](agent.md)（Agent 配置档案）。
> **交叉引用**：AGENTS.md 与能力配置的区分。详见 [agent §F2](agent.md)（身份与人格分离）。
> **交叉引用**：AGENTS.md 的位置与加载。详见 [system_prompt §F1](system_prompt.md)（身份与行为准则定义）。
> **交叉引用**：AGENTS.md 内容变更的生效时机。详见 [system_prompt §F6](system_prompt.md)（内容缓存与自动刷新）。

### F2. 安全写入

CloseClaw 修改配置文件时，写入前的合法性校验不通过或写入中断，不会产生部分覆盖或损坏的配置文件，原有配置保持不变。合法性判定口径见 [F8](#f8-配置校验)（配置校验）；含凭据的配置写入同样保证原子性，凭据字段本身的校验不通过不阻止写入，见 [F5](#f5-凭据存放与保护)（凭据存放与保护）。

### F3. 启动容错与备份恢复

CloseClaw 启动时，若某份业务配置文件无法解析，或其合法性判定存在错误（判定口径见 [F8](#f8-配置校验)（配置校验）；权限配置文件的口径见 [permission §F6](permission.md)（权限配置管理）），恢复前先另存故障配置副本供 Owner 查询，再用最新的可用备份覆盖原配置文件。每份业务配置文件在每次成功加载后自动留存一份备份，共保留最近 5 份，该份数为固定策略，不作为可配置项。

恢复成功后 CloseClaw 正常启动、记录回退事件，并告知 Owner 该配置文件已被回退。恢复失败（如无可用备份、或候选备份同样损坏）时按故障隔离原则处置：只停用依赖该配置的平台或功能，其余入口与功能照常提供服务；仅当故障配置属于系统启动所必需的公共依赖（即其不可用导致无法确定启动所需信息）时，才拒绝整体启动。

- **单个 Agent 的配置档案**：该 Agent 不加载，其余 Agent 与系统正常启动；
- **单个 IM 平台的渠道配置**：只停用该平台，该平台的消息收发不可用；CLI 与其他无关平台照常提供服务；
- **除上述两类外、不属于启动必需公共依赖的单个模块配置**：只停用依赖该配置的功能，其余功能正常提供服务（如插件列表损坏时停用平台插件加载，CLI 与其余功能照常；插件列表可退化为不加载任何平台插件，因此不阻断启动）；
- **Agent 注册清单**：拒绝启动——注册清单决定系统启动时加载哪些 Agent，启动时损坏或缺失无法确定需加载的 Agent 清单，属系统启动所必需的公共依赖；注册清单的运行期变更在下次新建 Session 时生效。
- **权限配置**：不属于启动必需公共依赖，不拒绝启动，其加载失败的处理见 [permission §F6](permission.md)（权限配置管理）。

上述恢复成功与失败处置均需告知 Owner：拒绝启动时通过 CLI 启动错误输出告知；其余处置经仍可用的 IM 平台通知，无可用 IM 平台时在 CLI 中呈现恢复信息。

凭据字段缺失或无效不适用本节（不阻塞启动，见 [F5](#f5-凭据存放与保护)（凭据存放与保护））；配置文件存在但部分字段缺失时的默认值处理见 [F6](#f6-配置版本兼容)（配置版本兼容）。

> **交叉引用**：IM 通知的发送链路。详见 [message_flow §F2](message_flow.md)（出站链路）。

### F4. 配置重载

Owner 在 CloseClaw 运行时编辑配置文件后，变更的实际生效按 [F7](#f7-生效机制与重启类判定)（生效机制与重启类判定）的分类执行：重启生效类由配置模块触发、daemon 择机执行重启，其余由各消费模块执行对应的生效处理；本文件不重复定义各模块的生效机制细节。

#### 变更检测与通知

配置模块检测到文件变更后按 [F7](#f7-生效机制与重启类判定)（生效机制与重启类判定）的分类通知依赖该配置的消费模块，各模块执行对应的生效处理。对属于重启生效类的配置，配置模块在变更确认后触发重启（由 daemon 择机执行）。

#### 生效机制文档化原则

消费本模块配置的模块，其需求文档必须写明两项内容：

- 该配置在需求层需要明确的生效机制（即配置变更后何时生效）；
- 若确实无法在需求层确定，必须在消费方需求文档或本模块 [F7](#f7-生效机制与重启类判定)（生效机制与重启类判定）汇总表中显式写明「需求层不定义」，并由设计文档从架构层面给出确定的生效时机；
- 指向本模块 F4（配置重载）的交叉引用。

已在本文件 [F7](#f7-生效机制与重启类判定)（生效机制与重启类判定）汇总表中给出结论或声明「需求层不定义」的配置，消费方文档以交叉引用代替，不重复定义；生效机制分类表见 F7。

> **交叉引用**：Gateway 择机重启的完整行为（择机窗口、消息暂存补投、变更合并、完成通知）。详见 [daemon §F6](daemon.md)（配置触发的网关重启）。

#### 重复写入与重载失败处置

- **连续写入**：Owner 对同一文件的连续多次写入，在同一重载周期内只触发一次重载。
- **重载时合法性校验不通过、且该配置此前已成功加载过**（判定口径见 [F8](#f8-配置校验)（配置校验））：保留此前已生效的配置继续运行，不恢复备份文件，通过 IM 通知 Owner；无可用 IM 平台时在 CLI 中呈现。
- **重载时合法性校验不通过、且该配置文件为运行期间新增、从未成功加载过**：阻塞该配置的加载及所有依赖该配置的功能，通过 IM 通知 Owner；无可用 IM 平台时在 CLI 中呈现。

启动时的损坏处理见 [F3](#f3-启动容错与备份恢复)（启动容错与备份恢复）。

### F5. 凭据存放与保护

#### 存放

- 凭据以明文字段随所属模块的配置存放：模型与供应商凭据随模型定义存放，IM 平台凭据在需要系统保存时随该平台渠道配置存放。
- 由平台官方工具管理的凭证不复制到 CloseClaw 配置；不另设统一的凭据目录或凭据文件。
- 凭据字段所在配置文件的组织、加载、校验执行、安全写入、备份与重载由本模块提供。
- 凭据字段的名称、含义与默认值由消费该配置的功能模块定义。
- 凭据内容仅 Owner 可访问；含凭据的配置备份与故障副本同受该保护。凭据的访问保护不通过整份配置文件禁读写实现，具体机制由设计层确定。
- 配置校验结果与调试日志不回显凭据内容。
- 凭据输入时不回显。

#### 加载失败与校验

- 凭据字段缺失或无效不阻塞 CloseClaw 启动，仅影响依赖该凭据的模型调用与渠道消息收发；凭据字段校验不通过也不阻止所在配置文件的安全写入与加载。
- 凭据字段的校验为单独的存在性与格式校验，不适用 [F8](#f8-配置校验)（配置校验）的合法性判定口径。缺失或格式非法为警告，给出字段级定位但不回显凭据内容；校验不通过时仅停用依赖该凭据的模型调用或渠道消息收发。

### F6. 配置版本兼容

CloseClaw 配置结构变更时，已有配置文件必须可被新版本正常加载：新增字段必须提供默认值，不要求 Owner 手工补全。配置中缺失的字段使用默认值加载，不再支持的旧字段在加载时被静默忽略，不阻塞启动。

### F7. 生效机制与重启类判定

配置按生效机制分为以下类别：

- **即时生效**：配置变更后即生效，下一次相应操作即使用新配置。
- **边界生效**：配置变更在某个使用边界统一生效——如新 Session 创建、System Prompt 组装、周期任务的下一次扫描触发。
- **重启生效（重启类）**：配置变更后须重启 Gateway 方可生效；重启由配置模块在变更确认后触发，由 daemon 择机执行（见 [F4](#f4-配置重载)（配置重载）），重启执行前系统按旧配置运行。
- **需求层不定义**：个别配置的变更生效时机在需求层不定义，由设计文档从架构层面确定（见下表）。

#### 重启类判定标准

对于生效时机可在需求层确定的配置，变更后是否需要重启取决于配置所支撑的服务——支撑 Gateway 服务运行的配置（Gateway 参数、渠道配置、插件列表、账户绑定—机器人 ↔ Agent、模型定义等）属重启生效类；其余配置变更后无需重启即可生效。各行配置的权威归属见下表「定义位置」列。

### F8. 配置校验

配置合法性的判定采用统一口径，适用于以下场景：

- 写入前校验
- 启动加载
- 运行期重载
- Owner 通过 CLI 发起的配置校验（见 [cli §F4](cli.md)（配置向导与校验））

其中权限配置文件的校验见 [permission §F6](permission.md)（权限配置管理）；凭据字段的校验见 [F5](#f5-凭据存放与保护)（凭据存放与保护）。凭据字段不适用本节的合法性判定，不阻断所在文件的加载与写入。合法性校验通过是加载的前提；启动加载时业务配置文件校验不通过，先按 [F3](#f3-启动容错与备份恢复)（启动容错与备份恢复）走备份恢复，恢复失败再按 F3 的分类处置。

校验结论分为错误与警告两级：

- **错误**：配置文件无法解析（如格式损坏、编码非法）、字段类型或取值非法、必填且无默认值的字段缺失。存在任一错误时，该文件校验不通过——不写入、不加载（启动期的备份恢复见 [F3](#f3-启动容错与备份恢复)（启动容错与备份恢复））。凭据字段的缺失或非法不适用本项，见 [F5](#f5-凭据存放与保护)（凭据存放与保护）。
- **警告**：不影响加载、但可能不符合 Owner 意图的情形。未知字段（含拼写错误与已废弃字段）在加载时按 [F6](#f6-配置版本兼容)（配置版本兼容）静默忽略，手动校验时向 Owner 提示；跨文件引用指向不存在的对象（如账户绑定指向未注册的 Agent、配置引用不存在的模型）同样属于警告。存在警告时该文件仍然通过校验：CLI 校验时随结果向 Owner 呈现，加载与重载时仅记录警告、不中断加载。

缺失字段的默认值处理与已废弃字段的忽略见 [F6](#f6-配置版本兼容)（配置版本兼容）；必填且无默认值的字段缺失构成错误，其余缺失不构成错误。

## 非功能需求

- **性能**：配置写入操作不阻塞消息处理与会话运行（因配置未成功加载而依赖该配置的功能不可用除外）
- **安全性**：凭据内容仅 Owner 可访问，详见 [F5](#f5-凭据存放与保护)（凭据存放与保护）

# Config 需求

## 概述

配置模块满足 Owner 对 CloseClaw 配置的日常管理需求：单文件损坏不会连带损坏其他配置文件、写入操作不会损坏已有配置、敏感凭据与业务配置安全隔离。生效机制由配置模块统一分类（见 [F7](#f7-生效机制与重启类判定)（生效机制与重启类判定）），各消费模块据此执行；配置模块提供变更检测、通知和重启生效类配置的自动重启触发能力。

## 功能需求

### F1. 多文件配置结构

Owner 的 CloseClaw 配置按职责拆分为多个独立配置文件与子目录，集中存放在配置目录下。单个文件损坏不会连带损坏其他文件；启动期的损坏处置见 [F3](#f3-启动容错与备份恢复)（启动容错与备份恢复）。

配置按职责分为以下配置来源（独立配置文件或配置目录）：

- 模型定义
- 渠道配置（各 IM 平台的接入参数）
- 账户绑定
- Gateway 参数
- 插件列表（启用的平台插件）
- Session 参数
- 权限配置（权限规则、沙盒模式）
- Agent 配置档案（每个 Agent 独立目录）
- Agent 注册清单
- 技能目录与清单
- 记忆配置
- 日志配置（最低日志级别、日志保留天数）
- 展示等级配置（IM 与 CLI 的基础展示等级）
- workflow 定义
- 凭据（按服务商分文件存放）

插件列表决定系统加载哪些平台插件（平台启停语义详见 [im_adapter §F1](im_adapter.md)（多平台插件化适配））；渠道配置存放各已启用平台的渠道级参数。

以上类别中，除凭据外均为业务配置文件；权限配置文件的校验与加载容错另见 [permission §F6](permission.md)（权限配置管理）。其中「技能目录与清单」「workflow 定义」的语义由 [skills §F5](skills.md)（技能文件变更）、[workflow §F1](workflow.md)（workflow 定义）定义，config 仅承载其目录位置与启用开关。

后续如有系统设置，可考虑单列一个配置文件。

#### 账户绑定

「账户绑定」建立 IM 侧身份与 CloseClaw 侧身份的双向关系，分两类。每类绑定在两个方向的消息流中分别使用：

- **机器人 ↔ Agent**：入站时由接收方机器人应用解析出 Agent（入站路由）；出站时由 Agent 解析出机器人（出站选择）。
- **IM 用户 ↔ User**：入站时由发送者解析出 User（会话归属、权限主体）；出站时由 User 解析出该 User 对应的 IM 用户（Agent 主动向该 User 发送消息时定位其标识）。

基数（铁律，不随配置变更放宽）：

- **机器人 ↔ Agent**：同一 IM 平台内一一对应——一个机器人只对应一个 Agent，一个 Agent 在同一平台只对应一个机器人。
- **IM 用户 ↔ User**：同一 IM 平台内一一对应——一个 IM 用户只对应一个 User，一个 User 在同一平台只对应一个 IM 用户。基数中的「IM 用户」以自然人为计数单位，不是平台侧的用户标识（跨机器人应用的标识归并详见 [message_flow §F3](message_flow.md)（跨机器人身份归并））。
- **跨平台**：单个 CloseClaw User 可对应多个 IM 平台的用户，单个 CloseClaw Agent 可对应多个 IM 平台的机器人。

两类绑定的变更生效时机分别见 [F7](#f7-生效机制与重启类判定)（生效机制与重启类判定）（其中「IM 用户 ↔ User」在需求层不定义）；一类绑定的变更不改变另一类绑定的内容。

#### Agent 注册清单

CloseClaw 通过显式注册清单管理 Agent 加载：只有在注册清单中列出的 Agent ID 才会被加载，目录中存在但未注册的 Agent 配置会被忽略。注册清单支持注释格式，注释掉某行即取消注册。每个 Agent 拥有独立的配置目录，存放该 Agent 的配置文件。

> **交叉引用**：配置目录的操作系统标准位置详见 [platform §F2](platform.md)（操作系统标准配置目录）。
> **交叉引用**：身份体系与跨平台身份映射详见 [permission §F1](permission.md)（身份体系）。
> **交叉引用**：机器人与 Agent 的绑定及消息路由详见 [gateway §F4](gateway.md)（普通消息路由到对话）。
> **交叉引用**：入站归一化字段（发送者、接收方机器人应用等）详见 [im_adapter §F2](im_adapter.md)（入站消息归一化）。
> **交叉引用**：平台、发送者、会话对端、账号四项标识共同确定主 Agent Session 详见 [session §F1](session.md)（对话持久化与恢复）。
> **交叉引用**：本模块定义的绑定在完整消息流链路中的使用位置详见 [message_flow §F1](message_flow.md)（入站链路）；完整消息流建议结合阅读以理解完整产品流程。
> **交叉引用**：出站方向的对应位置详见 [message_flow §F2](message_flow.md)（出站链路）。

### F2. 安全写入

CloseClaw 修改配置文件时，写入前的合法性校验不通过或写入中断，不会产生部分覆盖或损坏的配置文件，原有配置保持不变。合法性判定口径见 [F8](#f8-配置校验)（配置校验）；凭据文件的写入同受本节约束，其校验口径见 [F5](#f5-凭据安全隔离)（凭据安全隔离）。

### F3. 启动容错与备份恢复

CloseClaw 启动时，若某份业务配置文件无法解析，或其合法性判定存在错误（判定口径见 [F8](#f8-配置校验)（配置校验）；权限配置文件的口径见 [permission §F6](permission.md)（权限配置管理）），自动使用最新的可用备份恢复；每份业务配置文件在每次成功加载后自动留存一份备份，共保留最近 5 份，该份数为固定策略，不作为可配置项。

恢复成功后 CloseClaw 正常启动、记录警告，并通过 IM 通知 Owner 该配置文件已被回退。恢复失败（如无可用备份、或候选备份同样损坏）时按配置文件类别处置：

- **单个 Agent 的配置档案**：该 Agent 不加载，其余 Agent 与系统正常启动，并通过 IM 通知 Owner；
- **Agent 注册清单**：拒绝启动——注册清单决定系统加载哪些 Agent，损坏或缺失时无法确定需加载的 Agent 清单；
- **权限配置文件**：不拒绝启动，其加载失败的处理见 [permission §F6](permission.md)（权限配置管理）；
- **其余业务配置文件**：拒绝启动。

凭据文件不适用本节（其加载失败不阻塞启动，见 [F5](#f5-凭据安全隔离)（凭据安全隔离））；配置文件存在但部分字段缺失时的默认值处理见 [F6](#f6-配置版本兼容)（配置版本兼容）。

> **交叉引用**：IM 通知的发送链路详见 [message_flow §F2](message_flow.md)（出站链路）。

### F4. 配置重载

Owner 在 CloseClaw 运行时编辑配置文件后，变更的实际生效由各消费模块按 [F7](#f7-生效机制与重启类判定)（生效机制与重启类判定）的分类执行；本文件不重复定义各模块的生效机制细节。

#### 变更检测与通知

配置模块检测到文件变更后按 [F7](#f7-生效机制与重启类判定)（生效机制与重启类判定）的分类通知相关模块，各模块执行对应的生效处理。对属于重启生效类的配置，配置模块在变更确认后触发重启（由 daemon 择机执行）。

#### 生效机制文档化原则

消费本模块配置的模块，其需求文档必须写明两项内容：

- 该配置在需求层需要明确的生效机制（即配置变更后何时生效）；若确实无法在需求层确定，必须在消费方需求文档或本模块 [F7](#f7-生效机制与重启类判定)（生效机制与重启类判定）汇总表中显式写明「需求层不定义」，并由设计文档从架构层面给出确定的生效时机；
- 指向本模块 F4（配置重载）的交叉引用。

已在本文件 [F7](#f7-生效机制与重启类判定)（生效机制与重启类判定）汇总表中给出结论或声明「需求层不定义」的配置，消费方文档以交叉引用代替，不重复定义。

生效机制的分类、重启类判定标准与各配置文件的归属矩阵见 [F7](#f7-生效机制与重启类判定)（生效机制与重启类判定）。

> **交叉引用**：Gateway 择机重启的完整行为（择机窗口、消息暂存补投、变更合并、完成通知）详见 [daemon §F6](daemon.md)（配置触发的网关重启）。

#### 重复写入与重载失败处置

- **连续写入**：Owner 对同一文件的连续多次写入只触发一次重载。
- **重载时合法性校验不通过**（判定口径见 [F8](#f8-配置校验)（配置校验））：若该配置文件此前已成功加载过，保留此前已生效的配置继续运行，不恢复备份文件，通过 IM 通知 Owner；若发生变更的配置文件为运行期间新增、从未成功加载过，则阻塞该配置的加载及所有依赖该配置的功能，并通过 IM 通知 Owner。

启动时的损坏处理见 [F3](#f3-启动容错与备份恢复)（启动容错与备份恢复）。

### F5. 凭据安全隔离

#### 存放与隔离

- 凭据存放于配置目录下的独立子目录 `credentials/`（该位置属产品级文件布局，便于 Owner 统一备份与迁移），按服务商分文件存储；该子目录不属于业务配置文件范围。
- 凭据文件仅 Owner 可读写。业务配置只引用服务商名称，不直接包含凭据内容；凭据由系统在配置加载时自动关联。

#### 加载失败与校验

- 凭据文件加载失败不阻塞 CloseClaw 启动，仅影响依赖该凭据的模型调用与渠道消息收发。
- 凭据文件的校验为单独的存在性与格式校验，不适用 [F8](#f8-配置校验)（配置校验）的合法性判定口径。

### F6. 配置版本兼容

CloseClaw 配置结构变更时，已有配置文件必须可被新版本正常加载：新增字段必须提供默认值，不要求 Owner 手工补全。配置中缺失的字段使用默认值加载，不再支持的旧字段在加载时被静默忽略，不阻塞启动。

### F7. 生效机制与重启类判定

配置按生效机制分为以下类别：

- **即时生效**：配置变更后即生效，下一次相应操作即使用新配置。
- **边界生效**：配置变更在某个使用边界统一生效——如新 Session 创建、System Prompt 组装、周期任务的下一次扫描触发。
- **重启生效（重启类）**：配置变更后须重启 Gateway 方可生效；重启由配置模块在变更确认后触发、由 daemon 择机执行（见 [F4](#f4-配置重载)（配置重载）），重启执行前系统按旧配置运行。
- **需求层不定义**：个别配置的变更生效时机在需求层不定义，由设计文档从架构层面确定（见下表）。

#### 重启类判定标准

对于生效时机可在需求层确定的配置，变更后是否需要重启取决于配置所支撑的服务——支撑 Gateway 服务运行的配置（Gateway 参数、渠道配置、插件列表、账户绑定—机器人 ↔ Agent、模型与凭据定义等）属重启生效类；其余配置变更后无需重启即可生效。各行配置的权威归属见下表「定义位置」列。

### F8. 配置校验

配置合法性的判定采用统一口径，适用于以下场景：

- 写入前校验
- 启动加载
- 运行期重载
- Owner 通过 CLI 发起的配置校验（见 [cli §F4](cli.md)（配置向导与校验））

其中权限配置文件的校验见 [permission §F6](permission.md)（权限配置管理），凭据文件的校验见 [F5](#f5-凭据安全隔离)（凭据安全隔离）。合法性校验通过是加载的前提；启动加载时业务配置文件校验不通过，先按 [F3](#f3-启动容错与备份恢复)（启动容错与备份恢复）走备份恢复，恢复失败再按 F3 的分类处置。

校验结论分为错误与警告两级：

- **错误**：配置文件无法解析（如格式损坏、编码非法）、字段类型或取值非法、必填且无默认值的字段缺失。存在任一错误时，该文件校验不通过——不写入、不加载（启动期的备份恢复见 [F3](#f3-启动容错与备份恢复)（启动容错与备份恢复））。
- **警告**：不影响加载、但可能不符合 Owner 意图的情形，包括未知字段（加载时按 [F6](#f6-配置版本兼容)（配置版本兼容）静默忽略；手动校验时向 Owner 提示，以便区分拼写错误与已废弃字段）、跨文件引用指向不存在的对象（如账户绑定指向未注册的 Agent、配置引用不存在的模型）。存在警告时该文件仍然通过校验：CLI 校验时随结果向 Owner 呈现，加载与重载时仅记录警告、不中断加载。

缺失字段的默认值处理与已废弃字段的忽略见 [F6](#f6-配置版本兼容)（配置版本兼容）；其中必填且无默认值的字段缺失构成错误，其余缺失不构成错误。

## 非功能需求

- 配置写入操作不阻塞消息处理与会话运行（因配置未成功加载而依赖该配置的功能不可用除外）
- 凭据仅 Owner 可访问

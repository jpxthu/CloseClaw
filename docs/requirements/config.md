# Config 需求

## 概述

配置模块提供按职责组织配置、可靠读写、校验、备份恢复和变更重载的通用能力，使 Owner 可以管理 CloseClaw 配置；各功能模块自行定义所消费配置的内容与行为，配置故障不拖累无实际依赖关系的功能。

## 功能需求

### F1. 多文件配置结构

CloseClaw 配置按职责拆分为多个独立配置文件与子目录，集中存放在配置目录下。单个文件损坏不会连带损坏其他文件；启动期的损坏处置见 [F3](#f3-启动容错与备份恢复)（启动容错与备份恢复）。

配置来源包括以下类别；本节列举文件组织范围，不定义各模块的业务配置字段：

- 模型与供应商配置
- 渠道配置
- 账户绑定
- Gateway 参数
- 插件列表
- Session 参数
- 权限配置
- Agent 配置档案（每个 Agent 独立目录）
- Agent 注册清单
- 技能目录与清单
- 记忆配置
- 日志配置
- 展示等级配置
- workflow 定义

上述配置中的凭据随所属模块的配置保存，不作为独立配置来源；通用存放与保护要求见 [F5](#f5-凭据存放与保护)（凭据存放与保护）。权限配置文件的语义校验与加载容错见 [permission §F6](permission.md)（权限配置管理）。

技能与 workflow 的定义内容分别归 skills 与 workflow，config 提供配置来源组织与加载能力，不另行定义其业务开关。AGENTS.md 不作为本节的业务配置文件管理。

> **交叉引用**：IM 渠道、平台插件及账户绑定配置。详见 [im_adapter §F9](im_adapter.md)（平台接入配置）。

#### Agent 注册清单

CloseClaw 通过显式注册清单管理 Agent 加载：只有在注册清单中列出的 Agent ID 才会被加载，目录中存在但未注册的 Agent 配置会被忽略。注册清单支持注释格式，注释掉某行即取消注册。每个 Agent 拥有独立的配置目录，存放该 Agent 的配置文件。运行期间注册变更对新建及已有 Session 的影响，以 session 的生效边界为准。

> **交叉引用**：配置目录的操作系统标准位置。详见 [platform §F2](platform.md)（操作系统标准配置目录）。
> **交叉引用**：Agent 配置档案的内容。详见 [agent §F1](agent.md)（Agent 配置档案）。
> **交叉引用**：Agent 配置档案与注册清单变更的生效边界。详见 [session §F1](session.md)（对话持久化与恢复）。

### F2. 安全写入

CloseClaw 修改配置文件时，写入前的合法性校验不通过或写入中断，不会产生部分覆盖或损坏的配置文件，原有配置保持不变。含明文凭据的配置同受本节约束；凭据内容的访问限制不因写入通用配置文件而放宽。

> **交叉引用**：配置合法性的判定。详见 [F8](#f8-配置校验)（配置校验）。
> **交叉引用**：凭据存放与保护。详见 [F5](#f5-凭据存放与保护)（凭据存放与保护）。

### F3. 启动容错与备份恢复

启动时，若某份业务配置文件无法解析，或存在使其整体无法加载的合法性错误，恢复前先另存故障配置副本供 Owner 查询，再用最新的可用备份覆盖原配置文件。文件可解析且各独立配置可被可靠区分时，某个供应商、机器人等独立配置的错误不使同文件中无实际依赖关系的有效配置一并失效，不将其当作整份文件损坏处理。每份业务配置文件在每次整体校验通过且成功加载后自动留存一份备份，共保留最近 5 份，该份数为固定策略，不作为可配置项。

恢复成功后使用恢复的配置、记录警告，并通过 IM 通知 Owner 该配置文件已被回退。恢复失败（如无可用备份、或候选备份同样损坏）时，不再一律拒绝整个系统启动，而按实际依赖范围处理：

- **单个 Agent 的配置档案**：该 Agent 不加载，其余 Agent 与无关功能正常启动。
- **权限配置文件**：按 permission 的加载容错规则处理，不因配置缺失而放大权限。
- **各功能模块的配置**：仅阻塞无法取得有效配置的功能及其实际依赖方；无实际依赖关系的模块、CLI 与其他 IM 平台继续启动和提供服务。
- **系统启动必需的公共配置**：仅当其缺失或损坏使系统无法建立启动必需的公共能力时，才拒绝整体启动；不能仅因配置属于某一文件类别，就把局部故障升级为整体启动失败。

配置故障及受影响功能通过 IM 通知 Owner；通知投递本身不能成为其他功能启动的前置条件。各入口的就绪与接收消息边界见 daemon。配置文件可解析但其中凭据缺失或不可用时，影响范围仍按所属模块与实际依赖关系确定，不扩大为无关功能不可用。

> **交叉引用**：配置合法性的判定。详见 [F8](#f8-配置校验)（配置校验）。
> **交叉引用**：权限配置的专属校验与加载容错。详见 [permission §F6](permission.md)（权限配置管理）。
> **交叉引用**：启动依赖与各入口独立就绪。详见 [daemon §F1](daemon.md)（系统启动）。
> **交叉引用**：主动通知投递及失败处理。详见 [gateway §F7](gateway.md)（出站消息统一处理）。
> **交叉引用**：配置缺失字段的默认值。详见 [F6](#f6-配置版本兼容)（配置版本兼容）。

### F4. 配置重载

本节规定运行期间的首次加载与配置重载，启动期的加载与恢复见 [F3](#f3-启动容错与备份恢复)（启动容错与备份恢复）。Owner 在 CloseClaw 运行时编辑配置文件后，配置模块检测变更并通知相关消费模块。变更的实际生效时机由各消费模块定义，本文件通过 [F7](#f7-生效机制与重启类判定)（生效机制与重启类判定）统一分类和索引，不重复定义各模块的业务行为。

#### 变更检测与通知

各消费模块执行自身配置的生效处理。变更确认以对应独立配置通过校验、可以用于替代其原有配置为前提；校验失败的配置不构成生效或重启触发条件。对于已确认且属于重启生效类的变更，配置模块触发重启，由 daemon 择机执行。

> **交叉引用**：Gateway 择机重启的完整行为。详见 [daemon §F6](daemon.md)（配置触发的网关重启）。

#### 生效机制文档化原则

各配置项的生效机制须在所属功能模块需求中明确；若需求明确不约束具体表现，或确实无法在需求层确定，须显式写明“需求层不定义”，由设计从架构层面给出确定的生效时机。消费模块须引用本节的通用重载机制。

[F7](#f7-生效机制与重启类判定)（生效机制与重启类判定）的表格仅作分类摘要与权威定义索引，不因汇总了某个结论，就要求消费模块删去其权威定义。其他引用方以摘要、本地应用及回链关联，不另设一套可独立修订的生效规则。

#### 重复写入与重载失败处置

- **连续写入**：Owner 对同一文件的连续多次写入只触发一次重载。
- **可解析文件中的独立配置更新**：各独立配置可被可靠区分时，分别校验与处理。有效变更按所属模块的生效规则生效；错误项已有生效配置的，保留该项原有配置；错误项尚无生效配置的，仅阻塞该项及其实际依赖方。一个错误项不阻止同文件内其他无关有效配置生效。
- **文件无法解析或整体不可加载**：保留此前从该文件成功加载并生效的配置，不恢复备份文件；没有可用旧配置的功能按实际依赖范围不可用，不影响无关功能。

上述运行期规则不以文件创建时间或此前是否尝试加载为判定条件；没有已生效配置的项按首次加载处理，有已生效配置的项在更新失败时沿用原值。权限配置仍遵循 permission 的专属语义与容错限制，不得因忽略错误规则而放大权限。

上述配置错误均通过 IM 通知 Owner。独立配置按项生效不改变 F2 的文件安全写入要求：一次配置文件写入仍须完整校验并原子成功，不写入部分内容。

> **交叉引用**：合法性判定口径。详见 [F8](#f8-配置校验)（配置校验）。
> **交叉引用**：权限配置的专属语义及加载容错。详见 [permission §F6](permission.md)（权限配置管理）。
> **交叉引用**：启动时的损坏处理。详见 [F3](#f3-启动容错与备份恢复)（启动容错与备份恢复）。
> **交叉引用**：主动通知投递及失败处理。详见 [gateway §F7](gateway.md)（出站消息统一处理）。

### F5. 凭据存放与保护

#### 明文存放与内容归属

凭据作为所属功能模块配置的一部分，以明文字段保存在相应配置文件中，不另设统一的 `credentials/` 目录。模型与供应商凭据由 llm 定义，IM 平台凭据由 im_adapter 及对应平台子文档定义；config 仅提供通用配置的加载、保存、校验、安全写入、备份与重载能力，不定义凭据的业务字段及认证语义。

#### 访问保护

凭据内容仅 Owner 可读写；与其他配置字段同处一个文件不改变这一限制。含凭据的配置备份及故障副本同受该保护，配置校验结果与日志不得因明文存放而回显凭据内容。

> **交叉引用**：配置文件的访问与写入权限。详见 [permission §F2](permission.md)（权限维度）。
> **交叉引用**：日志凭据脱敏。详见 [debug_log §F4](debug_log.md)（隐私保护）。
> **交叉引用**：模型与供应商凭据配置。详见 [llm §F1](llm.md)（多供应商统一对话）。
> **交叉引用**：IM 平台配置。详见 [im_adapter §F9](im_adapter.md)（平台接入配置）。

### F6. 配置版本兼容

CloseClaw 配置结构变更时，已有配置文件必须可被新版本正常加载：新增字段须提供兼容的默认值或默认状态，不因字段新增就拒绝加载旧配置。凭据等不能预置有效值的字段，默认状态为未配置，不生成虚构凭据；未配置时仅影响实际依赖它的功能，不阻塞无关功能。其余缺失字段使用各消费模块定义的默认值，不再支持的旧字段在加载时被静默忽略。

### F7. 生效机制与重启类判定

配置按生效机制分为以下类别：

- **即时生效**：配置变更后即生效，下一次相应操作即使用新配置。
- **边界生效**：配置变更在某个使用边界统一生效，如新 Session 创建、System Prompt 组装或周期任务的下一次扫描触发。
- **重启生效（重启类）**：配置变更后须重启 Gateway 方可生效；重启执行前系统按旧配置运行，重启触发与执行分别见 [F4](#f4-配置重载)（配置重载）和 [daemon §F6](daemon.md)（配置触发的网关重启）。
- **需求层不定义**：配置变更的生效时机不在需求层限定，由设计从架构层面确定。

#### 重启类判定标准

是否需要重启及具体生效边界，由消费该配置的功能模块需求定义；config 据其结论提供分类与通用重载能力，不按配置的存放位置另定生效规则。需求层不定义的配置，由设计确定其生效方式。

### F8. 配置校验

配置合法性的判定采用统一机制，适用于写入前校验、启动加载、运行期重载及 Owner 通过 CLI 发起的配置校验。具体字段、默认值与业务取值约束由消费模块定义，config 执行校验，不自行定义 IM、LLM 等模块的字段语义。

权限配置的专属语义校验见 permission；凭据随所属业务配置一并校验，不再作为独立文件单独校验。配置校验不回显凭据内容。

校验结论分为错误与警告两级：

- **错误**：配置文件无法解析（如格式损坏、编码非法）、字段类型或取值非法、必填且无默认值的字段缺失。写入前存在任一错误时，不写入该文件，保持原有配置不变。加载时的备份恢复、旧配置沿用及功能隔离分别由 F3（启动期）与 F4（运行期）定义；本节的错误结论不另设一套加载失败处置。
- **警告**：不影响加载、但可能不符合 Owner 操作意图的情形，包括未知字段、跨文件引用指向不存在的对象（如账户绑定指向未注册的 Agent、配置引用不存在的模型）。存在警告时配置仍通过校验：CLI 校验时随结果向 Owner 呈现，加载与重载时仅记录警告、不中断加载。

缺失字段的默认值及默认未配置状态见 F6；必填且无默认值的字段缺失构成错误，其余缺失不构成错误。“未配置”不等于对应功能已就绪，各模块仍按自身接入与认证要求判定可用性。未知与已废弃字段在加载时静默忽略，手动校验时对未知字段给出警告，以便区分拼写错误与已废弃字段。

> **交叉引用**：权限配置的专属语义与校验。详见 [permission §F6](permission.md)（权限配置管理）。
> **交叉引用**：启动期备份恢复与故障隔离。详见 [F3](#f3-启动容错与备份恢复)（启动容错与备份恢复）。

## 非功能需求

- 配置写入操作不阻塞消息处理与会话运行；因配置不可用而受影响的功能范围，遵循 [F3](#f3-启动容错与备份恢复)（启动容错与备份恢复）与 [F4](#f4-配置重载)（配置重载）。
- 配置中的凭据访问与脱敏遵循 [F5](#f5-凭据存放与保护)（凭据存放与保护），明文存放不改变访问限制。

# Config 需求

## 概述

配置模块为 Owner 提供按职责组织配置、安全读写、校验、备份恢复与变更重载的日常管理能力，并保护配置中的凭据内容。

## 功能需求

### F1. 多文件配置结构

#### 配置来源与文件组织

CloseClaw 配置按职责拆分为多个独立配置文件与子目录，集中存放在配置目录下。单个文件损坏不会连带损坏其他文件，启动期的损坏处置由 F3 定义。

配置按职责分为以下类别，存放在对应的配置文件或目录中：

- 模型定义
- 渠道配置（各 IM 平台的接入参数；需要系统保存的凭据字段随本类配置存放）
- 账户绑定
- 插件列表（加载的平台插件）
- Session 参数
- 权限配置（权限规则、沙盒模式）
- Agent 配置档案（每个 Agent 独立目录）
- Agent 注册清单
- 技能目录与清单
- 记忆配置（含全局配置与各 Agent 配置档案内的按 Agent 字段）
- 日志配置（最低日志级别、日志保留天数）
- 展示等级配置（IM 与 CLI 的基础展示等级）
- workflow 定义

各 IM 平台的渠道配置分别独立存放，单个平台的渠道配置损坏不影响其他平台。

配置项的业务语义由所属功能模块定义，config 承载其配置来源与文件组织；各类配置的生效机制及权威定义索引见 F7。

#### 业务配置的管理范围

承载上述配置的文件属于业务配置文件，权限配置文件的校验与加载容错由 permission 定义。

#### 账户绑定

账户绑定建立 IM 侧身份与 CloseClaw 侧身份的双向关系，分两类：

- **机器人 ↔ Agent**：入站时由接收方机器人应用解析出 Agent（入站路由）；出站时由 Agent 解析出机器人（出站选择）。
- **IM 用户 ↔ User**：入站时由发送者解析出 User（会话归属、权限主体）；出站时由 User 解析出该 User 对应的 IM 用户（Agent 主动向该 User 发送消息时定位其标识）。

基数规则不随配置变更放宽：

- **机器人 ↔ Agent**：同一 IM 平台内一一对应，一个机器人只对应一个 Agent，一个 Agent 在同一平台只对应一个机器人。
- **IM 用户 ↔ User**：同一 IM 平台内一一对应，一个 IM 用户只对应一个 User，一个 User 在同一平台只对应一个 IM 用户。
- **计数单位**：基数中的 IM 用户以自然人为计数单位，不是平台侧的用户标识。
- **跨平台**：单个 CloseClaw User 可对应多个 IM 平台的用户，单个 CloseClaw Agent 可对应多个 IM 平台的机器人。

一类绑定的变更不改变另一类绑定的内容。两类绑定的变更生效时机由 F7 分类。

> **交叉引用**：平台、发送者、会话对端、账号四项标识共同确定主 Agent Session。详见 [session §F1](session.md)（对话持久化与恢复）。

#### Agent 注册清单

CloseClaw 通过显式注册清单管理 Agent 加载：只有在注册清单中列出的 Agent ID 才会被加载，目录中存在但未注册的 Agent 配置会被忽略。注册清单支持注释格式，注释掉某行即取消注册。

每个 Agent 拥有独立的配置目录，存放该 Agent 的配置档案文件。运行期间注册变更对新建及已有 Session 的影响，以 Session 模块的生效边界为准。

> **交叉引用**：Agent 配置档案的能力维度。详见 [agent §F1](agent.md)（Agent 配置档案）。
> **交叉引用**：Agent 配置档案与注册清单变更的生效边界。详见 [session §F1](session.md)（对话持久化与恢复）。

### F2. 安全写入

CloseClaw 修改配置文件时，写入前的合法性校验不通过或写入中断，不会产生部分覆盖或损坏的配置文件，原有配置保持不变。

含凭据的配置写入同样保证整体成功或保持原状；凭据字段校验失败是否阻止写入，按 F5 处理。

> **交叉引用**：配置合法性的判定。详见 [F8](#f8-配置校验)（配置校验）。
> **交叉引用**：凭据字段的校验与写入约束。详见 [F5](#f5-凭据存放与保护)（凭据存放与保护）。
> **交叉引用**：配置文件的访问与写入权限。详见 [permission §F2](permission.md)（权限维度）、[permission §F4](permission.md)（Owner 特权）。

### F3. 启动容错与备份恢复

#### 备份与恢复

CloseClaw 启动时，若某份业务配置文件无法解析或未通过合法性校验，恢复前先另存故障配置副本供 Owner 查询，再用最新的可用备份覆盖原配置文件。

每份业务配置文件在每次成功加载后自动留存一份备份，共保留最近 5 份。该份数为固定策略，不作为可配置项。

> **交叉引用**：配置合法性的判定口径。详见 [F8](#f8-配置校验)（配置校验）。
> **交叉引用**：权限配置文件的专属校验与加载容错。详见 [permission §F6](permission.md)（权限配置管理）。

#### 恢复结果与故障隔离

恢复成功后使用恢复的配置正常启动，并记录回退事件。恢复失败（如无可用备份或候选备份同样损坏）时，只停用依赖该配置的平台或功能，其余入口与功能照常提供服务。仅当故障配置属于系统启动所必需的公共依赖、其不可用导致无法确定启动所需信息时，才拒绝整体启动。

- **单个 Agent 的配置档案**：该 Agent 不加载，其余 Agent 与系统正常启动。
- **单个 IM 平台的渠道配置**：只停用该平台，该平台的消息收发不可用；CLI 与其他无关平台照常提供服务。
- **Agent 注册清单**：拒绝启动。注册清单决定系统启动时加载哪些 Agent，启动时损坏或缺失无法确定需加载的 Agent 清单，属于系统启动所必需的公共依赖。
- **权限配置**：不属于启动必需公共依赖，不拒绝启动，其加载失败的处理以 permission 的专属规则为准。
- **上述类别之外、不属于启动必需公共依赖的模块配置**：只停用依赖该配置的功能，其余功能正常提供服务。插件列表损坏时可退化为不加载任何平台插件，CLI 与其余功能照常，不阻断启动。

> **交叉引用**：权限配置的专属加载容错。详见 [permission §F6](permission.md)（权限配置管理）。
> **交叉引用**：恢复事件的日志分级。详见 [debug_log §F2](debug_log.md)（分层日志级别）。

#### 告知与适用范围

恢复成功与失败处置均需告知 Owner 所采取的措施；发生回退时明确告知该配置文件已被回退。告知通道如下：

- 拒绝启动时，通过 CLI 启动错误输出告知。
- 其余处置经仍可用的 IM 平台通知；无可用 IM 平台时，在 CLI 中呈现恢复信息。

凭据字段缺失或无效不适用本节的备份恢复，不阻塞启动。配置文件存在但部分字段缺失时，按 F6 处理默认值。

> **交叉引用**：凭据字段的校验与故障影响。详见 [F5](#f5-凭据存放与保护)（凭据存放与保护）。
> **交叉引用**：缺失字段的默认值。详见 [F6](#f6-配置版本兼容)（配置版本兼容）。
> **交叉引用**：主动通知的投递与失败处理。详见 [gateway §F7](gateway.md)（出站消息统一处理）。
> **交叉引用**：恢复信息在 CLI 中的呈现。详见 [cli §F4](cli.md)（配置向导与校验）。

### F4. 配置重载

#### 变更检测与通知

CloseClaw 运行期间，配置模块检测配置文件变更，并按 F7 的分类通知依赖该配置的消费模块。各消费模块执行相应的生效处理。对属于重启生效类的配置，配置模块在变更确认后触发重启，由 Daemon 择机执行。

> **交叉引用**：配置生效机制分类。详见 [F7](#f7-生效机制与重启类判定)（生效机制与重启类判定）。
> **交叉引用**：配置触发的择机重启。详见 [daemon §F6](daemon.md)（配置触发的网关重启）。

#### 重复写入与重载失败处置

- **连续写入**：同一文件的连续多次写入，在同一重载周期内只触发一次重载。
- **重载时合法性校验不通过，且该配置文件此前已成功加载过**：保留此前已生效的配置继续运行，不恢复备份文件。
- **重载时合法性校验不通过，且该配置文件为运行期间新增、从未成功加载过**：阻塞该配置的加载及所有依赖该配置的功能。

上述重载失败均通过 IM 通知 Owner；无可用 IM 平台时，在 CLI 中呈现。启动时的损坏处理由 F3 定义。

> **交叉引用**：配置合法性的判定口径。详见 [F8](#f8-配置校验)（配置校验）。
> **交叉引用**：启动期配置恢复与故障隔离。详见 [F3](#f3-启动容错与备份恢复)（启动容错与备份恢复）。
> **交叉引用**：主动通知的投递与失败处理。详见 [gateway §F7](gateway.md)（出站消息统一处理）。
> **交叉引用**：重载失败信息在 CLI 中的呈现。详见 [cli §F4](cli.md)（配置向导与校验）。

### F5. 凭据存放与保护

#### 明文存放与内容归属

CloseClaw 不另设统一的凭据目录或凭据文件。需由 CloseClaw 保存的凭据以明文字段随所属模块的配置存放：供应商凭据随模型定义存放，IM 平台凭据随该平台渠道配置存放。由平台官方工具管理的凭据不复制到 CloseClaw 的配置文件中。

凭据字段所在配置文件的组织、加载、校验执行、安全写入、备份与重载由 config 提供。凭据字段的名称、含义与默认值由消费该字段的功能模块定义。

> **交叉引用**：供应商凭据的配置。详见 [llm §F6](llm.md)（供应商配置向导）。
> **交叉引用**：平台凭据的配置与管理归属。详见 [im_adapter §F9](im_adapter.md)（IM 平台配置归属）。

#### 访问与展示保护

凭据内容仅 Owner 可访问，含凭据的配置备份与故障副本同受该保护。凭据的访问保护不通过整份配置文件禁读写实现，具体机制由设计文档确定。

凭据输入时不回显，配置校验结果不回显凭据内容；调试日志中的凭据脱敏遵循日志模块的隐私保护规则。

> **交叉引用**：凭据在日志中的脱敏规则。详见 [debug_log §F4](debug_log.md)（隐私保护）。

#### 凭据字段校验

凭据字段单独进行存在性与格式校验，不适用 F8 的合法性判定口径。缺失或格式非法为警告，给出字段级定位但不回显凭据内容。

凭据字段缺失或无效不阻塞 CloseClaw 启动，校验不通过也不阻止所在配置文件的安全写入与加载；仅停用依赖该凭据的模型调用或渠道消息收发。

> **交叉引用**：一般配置合法性的判定。详见 [F8](#f8-配置校验)（配置校验）。

### F6. 配置版本兼容

CloseClaw 配置结构变更时，已有配置文件必须可被新版本正常加载：新增字段必须提供默认值，不要求 Owner 手工补全。

配置中缺失的字段使用消费模块定义的默认值加载。不再支持的旧字段在加载时被静默忽略，不阻塞启动。

> **交叉引用**：配置项行为与默认值的归属。详见 [需求文档](README.md#模块职责与需求归属)（模块职责与需求归属）。

### F7. 生效机制与重启类判定

#### 生效类别

配置按生效机制分为以下类别：

- **即时生效**：配置变更后即生效，下一次相应操作即使用新配置。
- **边界生效**：配置变更在某个使用边界统一生效，如新 Session 创建、System Prompt 组装或下一次扫描触发。
- **重启生效（重启类）**：配置变更后须重启 Gateway 方可生效，重启执行前系统按旧配置运行。触发与择机执行分别由 F4 与 Daemon 定义。
- **需求层不定义**：配置变更的生效时机在需求层不定义，由设计文档从架构层面确定。

> **交叉引用**：重启触发。详见 [F4](#f4-配置重载)（配置重载）。
> **交叉引用**：择机重启的执行。详见 [daemon §F6](daemon.md)（配置触发的网关重启）。

#### 重启类判定标准

对于生效时机可在需求层确定的配置，变更后是否需要重启取决于配置所支撑的服务。支撑 Gateway 服务运行的配置（渠道配置、插件列表、账户绑定—机器人 ↔ Agent、模型定义等）属于重启生效类，其余配置变更后无需重启即可生效。

### F8. 配置校验

#### 适用范围

配置合法性的判定采用统一口径，适用于以下场景：

- 写入前校验。
- 启动加载。
- 运行期重载。
- Owner 通过 CLI 发起的配置校验。

权限配置文件的校验由 permission 定义。凭据字段单独按 F5 校验，不适用本节的合法性判定，不阻断所在文件的加载与写入。

> **交叉引用**：CLI 配置校验的入口与呈现。详见 [cli §F4](cli.md)（配置向导与校验）。
> **交叉引用**：权限配置文件的专属校验。详见 [permission §F6](permission.md)（权限配置管理）。
> **交叉引用**：凭据字段的校验。详见 [F5](#f5-凭据存放与保护)（凭据存放与保护）。

#### 错误

以下情形构成错误：

- 配置文件无法解析，如格式损坏、编码非法。
- 字段类型或取值非法。
- 必填且无默认值的字段缺失。

存在任一错误时，该文件校验不通过，不写入、不加载。启动期的备份恢复及运行期的旧配置沿用、功能阻塞分别由 F3、F4 定义。

> **交叉引用**：启动期备份恢复与故障隔离。详见 [F3](#f3-启动容错与备份恢复)（启动容错与备份恢复）。
> **交叉引用**：运行期重载失败处置。详见 [F4](#f4-配置重载)（配置重载）。

#### 警告

不影响加载、但可能不符合 Owner 意图的情形属于警告，包括：

- 未知字段（含已废弃字段）：加载时静默忽略，CLI 配置校验时向 Owner 提示。
- 跨文件引用指向不存在的对象，如账户绑定指向未注册的 Agent、配置引用不存在的模型。

存在警告时，该文件仍通过校验。CLI 配置校验时，警告随结果向 Owner 呈现；加载与重载时，上述字段静默忽略，其余警告仅记录、不中断加载。

> **交叉引用**：旧字段的兼容处理。详见 [F6](#f6-配置版本兼容)（配置版本兼容）。
> **交叉引用**：校验警告的日志分级。详见 [debug_log §F2](debug_log.md)（分层日志级别）。

#### 缺失字段与默认值

不满足上述错误条件的缺失字段不构成错误，按 F6 使用默认值加载。

> **交叉引用**：缺失字段的默认值处理。详见 [F6](#f6-配置版本兼容)（配置版本兼容）。

## 非功能需求

- **性能**：配置写入操作不阻塞消息处理与会话运行；因配置未成功加载而依赖该配置的功能不可用除外。
- **安全性**：凭据内容仅 Owner 可访问，保护要求由 F5 定义。

> **交叉引用**：凭据内容的访问保护。详见 [F5](#f5-凭据存放与保护)（凭据存放与保护）。

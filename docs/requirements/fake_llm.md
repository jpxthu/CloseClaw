# Fake LLM Server 需求

## 概述

测试者可以在不依赖真实模型、算力和外部网络的环境中，用本地可完全受控的假 LLM 服务对 CloseClaw 的完整 LLM 调用链路进行确定性、可复现的端到端测试。

## 功能需求

### F1. 独立进程与黑盒接入

测试者可以把 Fake LLM Server 作为独立进程在本地启动并监听本地回环地址，通过配置把 CloseClaw 的模型端点指向该本地地址，从而对编译后的真实二进制进行黑盒端到端测试。

Fake LLM Server 是开发与测试工具，不进入发布构建。

### F2. 双协议覆盖

Fake LLM Server 同时讲 OpenAI 与 Anthropic 两种标准对话协议，完整覆盖两种协议的请求、响应与流式形态。

Fake LLM Server 不模拟具体供应商或模型的特有行为——各供应商、各模型的差异通过 fixture 在单元测试层面验证。Fake LLM Server 关注协议层面的正确性：两种协议的请求解析、响应序列化、流式事件序列、工具调用与推理/思考的协议表示。

### F3. 场景驱动与确定性

测试者通过场景文件声明「给定请求特征 → 返回什么响应」。场景可覆盖文本回复、推理/思考、工具调用、流式输出、错误、延迟、token 用量，并支持多轮对话中逐轮给出不同响应。

同一场景下同一输入产出同一输出，测试可重复执行、结果稳定，不依赖时序或随机性。

场景格式与集成测试共用同一套定义，测试者编写的场景可在集成测试与黑盒端到端测试之间复用。

### F4. 流式输出模拟

Fake LLM Server 能以流式方式逐段输出响应，测试者可控制分段粒度与段间间隔，用于验证 CloseClaw 的流式解析、实时展示与中断处理。

两种协议的流式事件序列均被完整模拟，使 CloseClaw 屏蔽协议差异的能力可被验证。

### F5. 错误与重试注入

测试者可注入各类错误：HTTP 错误（如认证失败、限流、超时、服务端错误）、流式输出中途中断。

错误可触发 CloseClaw 的重试与回退行为（如限流触发的退避重试），用于验证重试与回退逻辑。

测试者也可注入延迟（首 token 延迟、逐段延迟、整体延迟），用于验证超时与回退路径（如模型发现超时）。

### F6. token 用量模拟

Fake LLM Server 可在每次响应中返回完整的 token 用量信息——输入、输出、推理消耗、缓存命中、缓存写入——各字段均可按场景配置，且支持在多轮对话中逐轮变化。

用量字段可缺失（模拟不返回缓存字段的响应）。

> **交叉引用**：字段缺失时 CloseClaw 的显示行为，详见 [llm §F9](llm.md)（用量统计）。

### F7. KV cache 前缀缓存模拟

Fake LLM Server 能模拟前缀缓存的完整生命周期：首次请求写入缓存、后续请求命中缓存、缓存断开（命中量骤降）、缓存过期。

缓存命中可随请求前缀的稳定性自动变化——请求前缀保持稳定时持续命中，前缀变化时断开——以模拟真实供应商的前缀缓存行为。

测试者也可显式注入每轮响应返回的缓存命中/写入 token 数，用于精确验证 CloseClaw 的缓存命中率统计与命中率下降告警。

这是 Fake LLM Server 重点覆盖的 KV cache 相关能力（前缀稳定性、命中率、缓存断开）。

### F8. 推理/思考模拟

Fake LLM Server 能按两种协议各自的形态输出模型的推理/思考内容——OpenAI 协议的推理字段、Anthropic 协议的思考内容块与签名。

测试者可控制是否输出推理、推理强度档位，验证 CloseClaw 的推理可见性与推理强度档位。

各供应商在推理行为上的差异（如某些供应商的推理无法关闭、某些供应商强制回传推理内容）通过 fixture 在单元测试层面验证。

### F9. 工具调用模拟

Fake LLM Server 能模拟模型发出工具调用请求，含流式分片、多轮工具调用回传、并行工具调用，用于验证 CloseClaw 的工具调用与多轮推理内容回传。

### F10. 模型发现模拟

Fake LLM Server 能模拟模型列表查询端点，返回模型列表；可注入认证失败、超时、服务端错误、未知模型，用于验证 CloseClaw 的模型发现、过滤未知模型、以及失败时回退到内置知识库的逻辑。

### F11. 协议 fixture 与单元测试

Fake LLM Server 配有一套 JSON 格式的协议 fixture，覆盖 OpenAI 与 Anthropic 两种协议的完整协议面——响应结构、流式事件序列、工具调用、推理/思考、用量字段、错误响应结构。

这套 fixture 用于单元测试：既验证 Fake LLM Server 生成的响应符合协议格式，也验证 CloseClaw 能正确解析这些响应。

## 非功能需求

### 性能

- Fake LLM Server 的响应时间不随场景数量增加而增长

### 可用性

- 场景定义简洁、易编写、可复用，测试者无需了解真实模型或协议底层实现
- 无外部依赖：不依赖真实模型、算力、外部网络

### 可靠性

- 场景间相互隔离，一个场景注入的错误或延迟不污染后续场景
- 多个并发会话互不干扰，可模拟真实的多会话并发

### 安全性

- 仅监听本地回环地址，不对公网暴露
- 不进入发布构建，不随产品分发

### 可观测性

- 记录每次请求匹配到的场景、返回的响应与用量、缓存命中与断开事件，便于测试失败时定位

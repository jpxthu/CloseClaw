# Gateway 需求

## 概述

Gateway 满足 User 通过不同 IM 平台与 CLI 渠道发送消息、使用斜杠指令或与 Agent 对话，并在对应渠道收到回复的诉求。

## 功能需求

### F1. 多平台消息统一接入

User 可以通过飞书、Discord、Telegram 等 IM 平台以及 CLI 渠道发送消息，系统对不同渠道的消息采用统一的处理方式。

Gateway 自身运行参数的业务语义由本模块定义，其变更须重启 Gateway 后生效；各 IM 平台的接入参数与凭据不在本模块或 config 中另行定义。

> **交叉引用**：IM 平台的插件化接入与启用范围详见 [im_adapter §F1](im_adapter.md)（多平台插件化适配）。
> **交叉引用**：IM 平台消息的统一形式与平台差异处理详见 [im_adapter §F2](im_adapter.md)（入站消息归一化）。
> **交叉引用**：CLI 渠道的终端对话与调用者身份详见 [cli §F1](cli.md)（终端对话）。
> **交叉引用**：IM 平台配置。详见 [im_adapter §F9](im_adapter.md)（平台接入配置）。
> **交叉引用**：各入口独立就绪与启动条件。详见 [daemon §F1](daemon.md)（系统启动）。
> **交叉引用**：配置变更检测与重载。详见 [config §F4](config.md)（配置重载）。

### F2. 入站消息预处理

- 入站身份准入先于任何回复与指令分派；未通过准入的消息按 Permission 模块的静默要求终止，不因消息类型、斜杠指令、排队或错误提示产生响应
- 空消息（既无文本正文也无媒体内容）在入站预处理阶段丢弃，不进入后续处理

> **交叉引用**：入站身份准入与静默要求详见 [permission §F1](permission.md)（身份体系）。
> **交叉引用**：入站正文保真由 Processor Chain 模块负责。详见 [processor_chain §F3](processor_chain.md)（入站正文保真）。

### F3. 消息类型识别与非文本处理

系统能识别文本、图片、文件、音频等多种消息类型。

#### 消息分类

按以下顺序判定消息的处理方式：

1. 含文本正文的消息（如带内嵌图片的富文本）按文本消息处理，再分派到 LLM 对话或斜杠指令流程。
2. 无文本正文但含媒体内容的消息（含仅剩内嵌图片标记的富文本）按非文本消息处理。
3. 既无文本正文也无媒体内容的按空消息丢弃。

> **交叉引用**：空消息处理详见 [F2](#f2-入站消息预处理)（入站消息预处理）。
> **交叉引用**：普通文本消息的路由详见 [F4](#f4-普通消息路由到对话)（普通消息路由到对话）。
> **交叉引用**：斜杠指令的路由详见 [F5](#f5-斜杠指令拦截与分派)（斜杠指令拦截与分派）。
> **交叉引用**：平台正文归一化及内嵌媒体标记的剥离规则详见 [im_adapter §F2](im_adapter.md)（入站消息归一化）。

#### 非文本消息的当前处理

非文本消息（图片、文件、音频）不在当前范围：不进入 LLM 对话，不做媒体下载与存储。系统记录调试日志，并向 User 回复明确的「暂不支持该类型消息」提示。

### F4. 普通消息路由到对话

#### 消息范围

群聊消息不在当前范围，由平台插件在入站解析阶段识别并丢弃，不进入 Gateway、不路由、不回复。

经类型识别后且不以 `/` 开头的文本消息进入 LLM 对话流程。

> **交叉引用**：群聊消息丢弃的日志由 IM Adapter 记录。详见 [im_adapter §F8](im_adapter.md)（调试日志）。

#### Agent 路由与绑定变更

消息路由到接收该消息的机器人所绑定的 Agent，机器人 ↔ Agent 的绑定内容由 IM 平台接入配置定义。该类绑定变更须重启 Gateway 后生效；重启前已接收的消息按变更前的绑定关系处理。

> **交叉引用**：绑定关系变更的生效分类详见 [config §F7](config.md)（生效机制与重启类判定）。
> **交叉引用**：绑定关系变更的配置重载机制详见 [config §F4](config.md)（配置重载）。
> **交叉引用**：入站排队与重启补投详见 [F6](#f6-入站消息队列与过载保护)（入站消息队列与过载保护）。

#### Session 衔接

确定 Agent 后，Session 查找、创建与归档恢复由 Session 模块负责，包含向 User 展示的提示语；Gateway 不参与查找、创建与归档恢复。

Session 确定后进入 LLM 对话流程。Session 查找或创建发生异常时，系统向 User 回复错误提示。

> **交叉引用**：Session 查找、创建与归档恢复详见 [session §F1](session.md)（对话持久化与恢复）。
> **交叉引用**：入站归一化字段与身份 / 会话映射（接收方机器人应用 → Agent、发送者 → User、四项标识 → Session）详见 [im_adapter §F2](im_adapter.md)（入站消息归一化）。
> **交叉引用**：User 身份体系与绑定规则详见 [permission §F1](permission.md)（身份体系）。
> **交叉引用**：Session 的排队条件与消息排队行为详见 [session §F10](session.md)（消息排队）。
> **交叉引用**：机器人 ↔ Agent 双向绑定（入站路由、出站选择）与基数规则。详见 [im_adapter §F9](im_adapter.md)（平台接入配置）。
> **交叉引用**：本节在完整消息流链路中的位置详见 [message_flow §F1](message_flow.md)（入站链路）——建议结合阅读以理解完整产品流程。

### F5. 斜杠指令拦截与分派

- User 可以发送以 `/` 开头的斜杠指令，指令在进入 LLM 对话之前被拦截，不追加到对话历史
- Immediate 斜杠指令绕过排队条件，立即受理
- 非 Immediate 斜杠指令在不满足排队条件时直接执行，在满足排队条件时进入所属 Session 的待处理队列

> **交叉引用**：指令所属 Session 的确定详见 [session §F1](session.md)（对话持久化与恢复）。
> **交叉引用**：Owner 专用指令的标注、非 Owner 调用时的处理与各指令的 Immediate 标记详见 [slash §F1](slash.md)（斜杠指令入口）。
> **交叉引用**：审批指令的 Owner 专用语义详见 [slash §F13](slash.md)（审批指令）。
> **交叉引用**：被审批操作的等待、执行与结果返回规则详见 [permission §F5](permission.md)（审批工作流）。
> **交叉引用**：排队条件与排队提示详见 [session §F10](session.md)（消息排队）。
> **交叉引用**：Session 活跃维度详见 [session §F11](session.md)（Session 活跃维度）。

### F6. 入站消息队列与过载保护

- 高并发入站消息按到达顺序进入入站消息队列处理
- 入站消息队列满时拒绝新消息，立即向 User 回复「服务繁忙，请稍后重试」
- 重启执行期间，入站新消息不再走排队与拒绝逻辑，全部暂存，重启完成后按原到达顺序补投
- 重启时仍驻留在入站消息队列、尚未完成处理的消息不会丢失

> **交叉引用**：配置触发重启的择机窗口与执行时机详见 [daemon §F6](daemon.md)（配置触发的网关重启）。

### F7. 出站消息统一处理

#### 回复发送

LLM 回复和斜杠指令回复均走同一条出站消息处理流程。

> **交叉引用**：出站消息按目标平台的要求展示，格式自动选择由 IM Adapter 模块负责。详见 [im_adapter §F3](im_adapter.md)（出站消息格式自动选择）。
> **交叉引用**：出站选择机器人走「Agent → 机器人」方向，绑定与基数规则。详见 [im_adapter §F9](im_adapter.md)（平台接入配置）。
> **交叉引用**：本节在完整出站链路中的位置详见 [message_flow §F2](message_flow.md)（出站链路）。

#### 主动通知投递

系统主动发起的通知消息（审批请求、告警等）在多平台绑定时，投递到目标 User 最近使用的 IM 平台，以该 User 最近一次发送消息的 IM 平台为准。CLI 渠道为本地会话，不参与外发投递。

投递失败时，按最近使用顺序回退到其它已绑定平台；全部失败时记录日志。

> **交叉引用**：目标 User 对应的 IM 身份与绑定关系。详见 [im_adapter §F9](im_adapter.md)（平台接入配置）。
> **交叉引用**：审批请求的收件人、业务流程与跨会话审批语义详见 [permission §F5](permission.md)（审批工作流）。
> **交叉引用**：CLI 终端内审批提示的本地呈现详见 [cli §F1](cli.md)（终端对话）。

#### 异常降级与历史记录

回复过程中出错或中断时统一降级处理：已发送给 User 的部分保留；未生成的回复内容以错误提示类系统通知替代，不向 User 追加不完整的新增量。

正常完成的 LLM 回复和斜杠指令回复发送后保存到所属 Session 的对话历史。LLM 响应中断时的保存范围遵循 LLM 模块的定义；排队提示、错误提示等面向 User 的系统通知不保存。

> **交叉引用**：LLM 响应中断时的历史保存与后续上下文范围详见 [llm §F2](llm.md)（流式实时输出）。
> **交叉引用**：中断时已累积的 Thinking 块与 Tool 块的展示详见 [im_adapter §F4](im_adapter.md)（流式增量渲染）。

### F8. 调试日志

Gateway 在以下环节记录调试日志，用于排查问题：

- 入站消息到达与队列操作（不含原始消息内容）
- 路由决策结果（斜杠指令识别 / 普通对话分发 / 排队状态）
- 非文本消息识别结果与处理（不支持的媒体类型、提示发送结果）

> **交叉引用**：入站消息原始内容日志由 Processor Chain 模块负责。详见 [processor_chain §F6](processor_chain.md)（调试日志）。
> **交叉引用**：Session 查找与生命周期事件日志由 Session 模块负责。详见 [session §F12](session.md)（调试日志）。
> **交叉引用**：出站渲染与平台 API 发送结果日志由 IM Adapter 模块负责。详见 [im_adapter §F8](im_adapter.md)（调试日志）。
> **交叉引用**：日志链路追踪详见 [debug_log §F1](debug_log.md)（完整消息链路追踪）。
> **交叉引用**：日志分级详见 [debug_log §F2](debug_log.md)（分层日志级别）。
> **交叉引用**：日志存储与保留详见 [debug_log §F3](debug_log.md)（日志存储与保留）。
> **交叉引用**：日志隐私保护详见 [debug_log §F4](debug_log.md)（隐私保护）。

## 非功能需求

### 可用性

- 入站消息队列满时的拒绝响应立即送达且清晰明确，避免 User 误以为消息丢失
- User 发送文本消息后能立即收到系统响应或排队提示，等待过程始终有反馈。Owner 审批等异步操作在完成后才送达的结果，不适用此约束

> **交叉引用**：入站过载拒绝的行为详见 [F6](#f6-入站消息队列与过载保护)（入站消息队列与过载保护）。

### 可靠性

Gateway 重启不丢失仍驻留在入站消息队列、尚未完成处理的消息。

> **交叉引用**：重启暂存与补投的行为详见 [F6](#f6-入站消息队列与过载保护)（入站消息队列与过载保护）。

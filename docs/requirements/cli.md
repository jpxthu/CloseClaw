# CLI 需求

## 概述

CLI 模块满足 Owner 通过命令行终端与 CloseClaw 交互的需求——既能进行对话交流（终端内格式化渲染输出），也能查询 Agent、Skill 与权限规则，通过配置向导管理配置文件，并直接管理 daemon 的启停。

## 功能需求

### F1. 终端对话

Owner 可以在终端中与 Agent 进行文本对话。此功能需 daemon 已运行。

- Owner 可以在终端启动对话，并在同一 CLI 进程中持续与 Agent 交互

- Owner 可以指定目标 Agent（通过 `--agent-id` 参数），不同 Agent 的对话保持独立、互不干扰；未指定时使用初始 Agent

- 终端对话按 Session 组织：同一 Agent 的多次终端对话延续同一个 Session（取该 Agent 在终端渠道最近活跃的 Session），IM 渠道的 Session 不受影响，退出终端不影响 Session 生命周期；Owner 可以通过 `/new` 强制新建

- 终端对话支持与其他 IM 平台（如飞书、Discord）相同的斜杠指令体系

- 终端对话的调用者为 Owner，无需额外认证；CLI 渠道的 User 上下文为 Owner

- Owner 可以使用 `/stop` 终止当前 Session 运行

> **交叉引用**：初始 Agent 的创建规则详见 [agent §F5](agent.md)（初始 Agent 创建）。
> **交叉引用**：Session 的确定、查找、恢复与归档详见 [session §F1](session.md)（对话持久化与恢复）。
> **交叉引用**：`/stop`、`/new` 的完整语义详见 [slash §F3](slash.md)（Session 管理）。
> **交叉引用**：斜杠指令的入口详见 [slash §F1](slash.md)（斜杠指令入口）。
> **交叉引用**：斜杠指令的拦截与分派详见 [gateway §F5](gateway.md)（斜杠指令拦截与分派）。
> **交叉引用**：不活跃 Session 的自动归档与清理详见 [session §F6](session.md)（Session 归档与清理）。

### F2. 终端输出渲染

终端对话的输出按下列规则渲染。

#### 样式渲染

正文中的 Markdown 格式标记渲染为对应的 ANSI 样式，各标记的呈现如下。

- **标题**：去掉 `#` 标记，以 ANSI 粗体呈现；一级标题附加下划线

- **粗体、斜体**：去掉标记，分别以 ANSI 粗体、斜体呈现

- **引用**：去掉 `>` 标记，整段附加 `│ ` 前缀，以弱化颜色呈现

- **链接**：呈现为「文本 (URL)」

- **分割线**：呈现为整行 `─`

- **行内代码**：去掉包裹标记，以与正文可区分的前景色呈现，不使用反色或背景色

- **删除线**：去掉标记，以 ANSI 删除线样式呈现

列表无对应 ANSI 样式，保留原始 Markdown 标记，不做渲染（无序 `- ` 或 `* `、有序 `1. `）。

终端不支持 ANSI 时，不做样式渲染，保留原始 Markdown 标记（标题、粗体、斜体、引用、链接、行内代码、删除线、分割线）与列表标记输出。

#### 特殊内容呈现

- **代码块行号**：终端在代码块左侧附加行号显示；代码块回退为纯文本输出时同样附加行号

- **未知语言回退**：代码块标注的语言无法识别时，回退为纯文本输出

- **工具调用块展示**：首行呈现工具名（形如 `⏺ <工具名>`），参数按 `key: value` 逐行缩进，与正文之间以空行分隔

- **工具结果块展示**：按行截断输出（默认保留前 20 行，被截断处以省略号标注）；展示等级为 full 时不按行截断（宽度截断仍适用）

终端不支持折叠交互，思考内容不以折叠块形式展示。

> **交叉引用**：代码块语法高亮的平台能力分档与语言范围详见 [im_adapter §F5](im_adapter.md)（代码块语法高亮）。
> **交叉引用**：思考内容的默认展示策略与按需查看详见 [llm §F3](llm.md)（推理过程可见与安全）。
> **交叉引用**：思考内容的按需查看入口为展示等级，详见 [slash §F11](slash.md)（展示等级）。
> **交叉引用**：回复包含哪些内容块由展示等级决定，详见 [processor_chain §F4](processor_chain.md)（出站回复展示等级控制）。

#### 输出适配

- **终端宽度适配**：各块输出中超过终端可用宽度（终端列宽扣除当前块的前缀开销，即块的缩进、引用前缀与代码块行号宽度）的行，在该行截断并以省略号标注，不折行、不产生溢出；终端列宽不可获得时（如输出经管道重定向），不按宽度截断，按原样输出

- **截断叠加**：工具结果块先按行截断、再按宽度截断；两者在同一行同时触发时，省略号只在该行行尾标注一次

- **流式输出**：终端按结构边界增量显示；思考内容、工具调用块与工具结果块整体输出，不参与增量流式（中断时按下条处理）

- **流式中断**：已输出内容保留在终端（终端内容不可撤回）；思考内容按既有展示规则展示，不因中断而改变；工具调用块展示已解析出的参数并标注该调用已中断；错误提示随后输出；未产生的内容不展示

> **交叉引用**：流式切分的通用规则与中断降级详见 [im_adapter §F4](im_adapter.md)（流式增量渲染）。
> **交叉引用**：终端输出的渲染与降级策略详见 [platform §F3](platform.md)（终端能力自适应）。

### F3. Daemon 生命周期管理

Owner 可以通过 CLI 命令管理 daemon 进程的启停。

- Owner 可以启动 daemon

- Owner 可以停止 daemon：停止触发优雅关闭，CLI 在关闭期间持续展示关闭进度，关闭完成后命令结束

- 关闭等待期间，Owner 再次发送停止信号（再次执行停止命令或按 Ctrl+C）即切换为强制关闭

- daemon 未运行时，Owner 执行停止操作时以提示「daemon 未运行」呈现，正常退出（不视为操作失败）

- daemon 已运行时，Owner 执行启动操作应拒绝启动新实例

> **交叉引用**：进程实例的追踪与启停机制详见 [platform §F1](platform.md)（跨平台进程生命周期管理）。
> **交叉引用**：daemon 启动过程的完整需求详见 [daemon §F1](daemon.md)（系统启动）。
> **交叉引用**：daemon 关闭过程的完整需求详见 [daemon §F2](daemon.md)（优雅关闭）。
> **交叉引用**：关闭期间强制关闭的触发与语义详见 [daemon §F3](daemon.md)（强制关闭）。
> **交叉引用**：关闭进度通知的内容与更新周期详见 [daemon §F4](daemon.md)（关闭进度可见性）。

### F4. 配置向导与校验

Owner 可以通过 CLI 管理 CloseClaw 的配置文件。

#### 交互式配置向导

Owner 通过引导式问答完成配置，经确认后写入配置文件。

- 模型发现失败时回退到内置知识库并标注回退来源；回退后 Owner 可以选择重试在线发现，重试不设次数上限；`--yes` 下不询问重试，直接使用回退结果

- Ctrl+C 可随时取消向导

- 初始 Agent 的创建由向导引导完成

- 支持跳过确认提示（`--yes`）：跳过向导中的全部确认项（含初始 Agent 创建的确认），按已输入内容与默认值直接写入配置并完成初始 Agent 创建；必需信息缺失时终止并报错，不写入配置

> **交叉引用**：模型发现 API 不可用时回退到内置知识库的行为详见 [llm §F7](llm.md)（模型发现）。
> **交叉引用**：向导的完整流程（供应商选择、凭据输入、可用模型发现与选择、确认写入）详见 [llm §F6](llm.md)（供应商配置向导）。
> **交叉引用**：初始 Agent 的创建规则详见 [agent §F5](agent.md)（初始 Agent 创建）。

#### 配置校验

Owner 可以校验现有配置文件格式的合法性。校验覆盖配置目录下的全部配置文件，逐文件独立校验、互不影响；凭据文件仅校验存在性与格式，不回显凭据内容。校验为只读，不写入配置、不触发生效。此功能无需 daemon 运行。

CLI 输出校验结果——先给出总体校验状态，校验不通过时给出字段级错误定位（配置文件路径、字段、原因）。

> **交叉引用**：配置文件结构详见 [config §F1](config.md)（多文件配置结构）。
> **交叉引用**：凭据文件的存放与加载详见 [config §F5](config.md)（凭据安全隔离）。

### F5. Agent 查询

Owner 可以通过 CLI 查询 Agent。此功能需 daemon 已运行。

- Owner 可以列出全部 Agent

- Owner 可以查询指定 Agent 的完整配置档案

> **交叉引用**：Agent 配置档案的字段结构详见 [agent §F1](agent.md)（Agent 配置档案）。
> **交叉引用**：运行时按 ID 查询完整配置档案的语义（返回字段、不含运行时派生项）详见 [agent §F6](agent.md)（运行时配置查询）。
> **交叉引用**：Agent 的注册清单与配置目录加载机制详见 [config §F1](config.md)（多文件配置结构）。
> **交叉引用**：Agent 配置变更的生效机制详见 [config §F7](config.md)（生效机制与重启类判定）。

### F6. Skill 查询

Owner 可以通过 CLI 查询 Skill 列表。此功能需 daemon 已运行。

- Owner 可以按 Agent 查询 Skill 列表，未指定 Agent 时使用初始 Agent

- 列表展示该 Agent 可用的全部技能，包含不进入 System Prompt 技能清单的条件激活技能，并标注每个技能的来源层级与激活条件

> **交叉引用**：Skill 即插即用的完整语义详见 [skills §F1](skills.md)（技能即插即用）。
> **交叉引用**：`--agent-id` 的缺省取值详见 [F1](#f1-终端对话)（终端对话）。
> **交叉引用**：技能目录的层级与覆盖优先级详见 [skills §F2](skills.md)（技能目录层级）。
> **交叉引用**：条件激活技能的清单归属详见 [skills §F6](skills.md)（条件激活）。
> **交叉引用**：技能的多 Agent 隔离详见 [skills §F8](skills.md)（多 Agent 隔离）。
> **交叉引用**：技能变更的生效时机详见 [skills §F5](skills.md)（技能文件变更）。

### F7. 权限规则查询与校验

Owner 可以通过 CLI 查看权限规则。此功能无需 daemon 运行。

- 校验权限规则的语法，输出校验结果（规则位置、原因）

- 列出已有规则，列表呈现的信息项以权限规则的规则结构为准

> **交叉引用**：CLI 提供校验规则语法与列表入口，两者均为只读；权限规则的规则结构与修改方式详见 [permission §F6](permission.md)（权限配置管理）。
> **交叉引用**：权限规则变更的生效机制详见 [config §F7](config.md)（生效机制与重启类判定）。

Owner 可以在受支持的操作系统上使用行为一致的 CLI。

> **交叉引用**：操作系统差异由 platform 统一消化，CLI 不感知平台差异，详见 [platform §F5](platform.md)（系统差异隔离）。
> **交叉引用**：支持的操作系统范围与跨平台行为一致性期望详见 [platform 非功能需求](platform.md#非功能需求)。

### F9. 命令输出呈现

F3–F7 的命令输出统一按纯文本呈现，不做 Markdown 渲染；各类输出的呈现规则如下。

- 列表：一项一行，层级以缩进表示；单项包含多个属性时，属性在同一项内依次呈现

- 配置档案：按字段逐行呈现，字段名与取值成对，按字段层级缩进

- 校验结果与出错：先给出总体状态，不通过时以「错误：<原因>」逐条呈现，必要时附下一步提示

- 操作成功：以一句确认说明结果

- 不使用颜色区分成功与失败

> **交叉引用**：终端对话输出的 Markdown 渲染规则详见 [F2](#f2-终端输出渲染)（终端输出渲染）。

### F10. 调试日志

CLI 模块在以下环节记录调试日志：

- 启动检查与命令执行（命令、执行结果、耗时）

- 配置校验结果

- daemon 启停操作

- 渲染降级与截断（终端能力降级、宽度截断、工具结果行截断）

> **交叉引用**：日志框架定义详见 [debug_log §F1](debug_log.md)（完整消息链路追踪）、[debug_log §F2](debug_log.md)（分层日志级别）、[debug_log §F3](debug_log.md)（日志存储与保留）、[debug_log §F4](debug_log.md)（隐私保护）。

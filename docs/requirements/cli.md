# CLI 需求

## 概述

CLI 模块满足 Owner 通过命令行终端与 CloseClaw 交互的需求——既能进行对话交流，也能直接管理 daemon 和系统配置。

## 功能需求

### F1. 终端对话

Owner 可以在终端中与 Agent 进行文本对话。此功能需 daemon 已运行。

- Owner 可以在终端启动对话，并在同一终端进程中持续与 Agent 交互

- Owner 可以指定目标 Agent（通过 `--agent-id` 参数），不同 Agent 的对话保持独立、互不干扰

- 终端对话支持与其他 IM 渠道（如飞书、Discord）完全一致的斜杠指令体系

- 终端对话的调用者默认为 Owner，无需额外认证

- 使用 `/stop` 结束当前对话

> **交叉引用**：`/stop` 的完整语义详见 [slash §F3](slash.md)（Session 管理）。
> **交叉引用**：不活跃 Session 的自动归档与清理详见 [session §F6](session.md)（Session 归档与清理）。

### F2. 终端输出渲染

终端对话的输出应充分利用终端能力，提供可读性良好的格式化展示。

#### 样式渲染

- **ANSI 渲染策略**：终端输出的渲染与降级策略详见 [platform §F3](platform.md)（终端能力自适应）

- **Markdown 转 ANSI**：普通文本中的 Markdown 格式标记（标题、粗体、斜体、引用、链接、分割线）渲染为对应的 ANSI 样式

- **列表标记保留**：列表无对应 ANSI 样式，保留原始 Markdown 标记（无序 `- ` 或 `* `、有序 `1. `）输出

#### 特殊内容呈现

- **代码块高亮**：代码块语法高亮遵循 [im_adapter §F5](im_adapter.md)（代码块语法高亮），终端附加行号显示，支持常见编程语言，未知语言回退为纯文本输出

- **思考过程呈现**：终端不支持折叠交互，思考过程不以折叠块形式展示

- **思考可见性**：终端界面的默认展示策略与按需查看详见 [llm §F3](llm.md)（推理过程可见与安全）；终端按需查看入口为展示等级，详见 [slash §F11](slash.md)（展示等级）

- **工具调用展示**：输出工具名称和参数

- **工具结果展示**：按行截断输出（默认保留前 20 行，被截断处以省略号标注）

- **媒体占位符**：终端不支持的媒体类型（图片、音频、文件）展示为带文件名的占位符，不尝试输出二进制内容

- **DSL 交互元素降级渲染**：按钮、选择器等交互元素在终端中渲染为纯文本提示行（如 `[Button: 标签 (action: xxx)]`、`[Select: 标签 (options: a | b | c, action: xxx)]`），因为终端不支持交互元素；交互元素的 DSL 指令定义详见 [processor_chain §F5](processor_chain.md)（DSL 交互指令）

#### 终端适配与流式输出

- **终端宽度适配**：各块输出中超过终端可用宽度的行，在该行截断并以省略号标注，不折行、不产生溢出

- **流式输出**：流式渲染行为详见 [im_adapter §F4](im_adapter.md)（流式增量渲染），终端逐行增量显示

### F3. Daemon 生命周期管理

Owner 可以通过 CLI 命令管理 daemon 进程的启停。

- Owner 可以启动 daemon，也可以停止 daemon

- daemon 未运行时执行停止操作不报错，正常退出

- daemon 已运行时执行启动操作应拒绝启动新实例

> **交叉引用**：PID 文件机制详见 [platform §F1](platform.md)（跨平台进程生命周期管理）。
> **交叉引用**：daemon 启动与关闭过程的完整需求详见 [daemon §F1–F2](daemon.md)（系统启动、优雅关闭）。

### F4. 配置管理

Owner 可以通过 CLI 管理 CloseClaw 的配置文件。

#### 交互式配置向导

通过引导式问答完成首次配置，向导完成后自动写入配置文件。

- 模型发现失败时允许 Owner 重试（不设重试次数上限）；回退到内置模型清单的行为详见 [llm §F7](llm.md)（模型发现）

- Ctrl+C 可安全退出向导，不残留不完整配置文件

- 首次配置时引导创建初始 Agent，创建规则详见 [agent §F5](agent.md)（初始 Agent 创建）

- 支持跳过确认提示（`--yes`）：跳过向导中的全部确认项，包括凭据输入确认与配置写入确认

> **交叉引用**：向导的完整流程（供应商选择与推荐协议、凭据输入、可用模型发现与选择、确认写入）详见 [llm §F6](llm.md)（供应商配置向导）。

#### 配置校验

校验现有配置文件格式的合法性并输出结果——先给出总体校验状态，校验不通过时给出字段级错误定位（配置文件路径、字段、原因）。

> **交叉引用**：配置文件结构、安全写入、重载等需求详见 [config §F1–F6](config.md)（多文件配置结构至配置版本兼容）。

### F5. Agent 管理

Owner 可以通过 CLI 列出全部 Agent、查询指定 Agent 的完整配置档案。此功能需 daemon 已运行。

> **交叉引用**：Agent 配置档案的字段结构详见 [agent §F1](agent.md)（Agent 配置档案）。
> **交叉引用**：运行时按 ID 查询完整配置档案的语义（返回字段、不含运行时派生项）详见 [agent §F6](agent.md)（运行时配置查询）。
> **交叉引用**：Agent 的注册清单与配置目录加载机制详见 [config §F1](config.md)（多文件配置结构）。

### F6. Skill 管理

Owner 可以通过 CLI 查询 Skill 列表。此功能需 daemon 已运行。

> **交叉引用**：Skill 即插即用的完整语义详见 [skills §F1](skills.md)（技能即插即用）。
> **交叉引用**：技能变更的生效时机详见 [skills §F5](skills.md)（技能文件变更）。

### F7. 权限规则查看

Owner 可以通过 CLI 查看权限规则——校验权限规则的语法，并列出已有规则。

> **交叉引用**：CLI 提供校验规则语法与列表入口（只读）；权限规则的修改通过斜杠指令完成。详见 [permission §F6](permission.md)（权限配置管理）。

### F8. 跨平台支持

Owner 可以在受支持的操作系统上使用行为一致的 CLI。

> **交叉引用**：CLI 的跨平台一致性详见 [platform §F5](platform.md)（系统差异隔离）。
> **交叉引用**：CLI 跨平台相关的用户期望详见 [非功能需求](#非功能需求)（非功能需求）。

## 非功能需求

- 终端 ANSI 能力检测应覆盖所支持平台的主流终端模拟器，确保 Owner 在不同终端环境下获得一致的格式化体验
- 终端渲染应在 Owner 的终端窗口宽度内自适应呈现，保持布局稳定

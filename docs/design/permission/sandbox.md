# 沙盒

## 概述

沙盒以操作系统级隔离强制 Agent 的文件访问范围，而不是只靠路径规则匹配。Agent 可能编写脚本反复拼接路径，规则难以穷尽；沙盒在操作系统层拦截越界访问，路径如何拼装都无法绕过。沙盒能力对所有 Agent 恒可用，不提供关闭沙盒的配置——可配置的是沙盒模式（决定命令的授权与缺省执行位置、文件工具是否受范围强制，见「模式」）。

## 架构

### 强制范围

沙盒对 Agent 发起的以下访问强制约束：

- **文件类工具**：Read / Write / Edit / Grep / Ls 等读写本地文件的工具，以及 git 操作工具中读写工作区的部分。工具到读/写维度的归类由权限引擎按操作类型判定（工具声明的只读/破坏性标记只用于索引渲染与审批提示，不构成权限判定）。文件访问由沙盒引擎在受限执行环境中执行：受限执行环境是沙盒引擎为一次文件访问建立的、受 OS 级约束的执行上下文，工具自身的其余行为与进程语义不变。
- **沙盒内执行的命令**：命令行中在沙盒内执行的进程，含其调用的脚本与子进程。

以下访问不受沙盒范围强制：

- 在宿主上执行的命令：白名单命令、默认模式下经审批获准在宿主上执行的非白名单命令，以及放行模式下缺省在宿主上执行的全部命令。
- 斜杠指令执行的命令（`/git` 写操作等）：由系统执行，不经沙盒；`/exec` 仅 Owner 可用、不进入权限评估。
- 放行模式下的文件类工具访问：仅按读/写维度的规则评估，无 OS 级边界。
- 技能正文由 skills 模块自行读取，不经本模块的工具访问路径。

### 边界来源

边界取 Agent 维度与用户维度规则求值后的允许路径，再排除规则层拒绝的路径：

```
可写范围 = (写维度允许路径 ∩ 用户维度写维度允许路径 − Agent 维度写拒绝路径 − 用户维度写拒绝路径) ∪ workspace 专属路径
可读范围 = 可写范围 ∪ (读维度允许路径 ∩ 用户维度读维度允许路径 − Agent 维度读拒绝路径 − 用户维度读拒绝路径)
```

- 允许路径由其允许规则给出；未配置允许规则时该维度允许集为空。任一维度的拒绝路径从其允许路径中扣除（拒绝优先）。
- 写蕴含读：可写范围内的路径始终可读（写权限包含读权限，需求 [permission §F2](../../requirements/permission.md)）；读拒绝只作用于读维度允许路径给出的部分。
- caller 为 Owner 时只取 Agent 维度规则（Owner 豁免用户维度，见 [README](README.md#owner-特权)）。
- 子 Session 的边界取三方交集（目标 Agent ∩ 父 Session ∩ 继承的 User 上下文）后的结果；父链路的拒绝路径同样从边界中排除，但 workspace 专属路径不因父链路拒绝收窄（需求 [permission §F9](../../requirements/permission.md)）。
- 子 Session 的生效沙盒模式取目标 Agent 配置的模式与父链路生效模式中更严者（严格 > 默认 > 放行），保证模式沿链路只能变窄。
- workspace 专属路径（路径格式与自动放行规则见 [README](README.md#决策顺序与交集)）由系统创建并纳入可读写范围；其他路径不因该授权被纳入。自动放行不免沙盒引擎可用性：引擎不可用时 workspace 的文件访问同样拒绝。
- 边界按操作发生时的当前生效规则计算，不使用历史结果；规则与模式变更只对下一次操作生效，已在运行的进程不改变边界。
- 边界以「允许访问的路径集」表达，随判定结论产出执行策略（ExecutionPolicy）交给执行层（只读授权时写路径集为空）。
- 规则层拒绝与沙盒边界同时生效：拒绝路径在 OS 边界中直接排除，沙盒内脚本也无法访问。引擎适配层负责将拒绝路径落为具体的 OS 约束（bubblewrap 以 bind 视图裁剪允许范围、Landlock 以规则叠加表达拒绝）。
- 高风险名单命中先于 workspace 自动放行：读写命中高风险名单的路径（如 `.git` 目录）即使位于边界内，也按高风险操作处理，只能单次放行（见「文件越界审批」与需求 [permission §F3](../../requirements/permission.md) 决策顺序）。

### 模式

沙盒模式是 Agent 权限基线中的配置项，按 Agent 维度配置，用户维度不覆写；默认为默认模式。它决定命令的授权与缺省执行位置、以及文件类工具访问是否受沙盒范围强制。命令同时列入白名单与黑名单时黑名单优先（优先级定义见 [权限维度](permission-dimensions.md#命令行)）。

| 模式 | 白名单命令 | 白名单外命令与脚本 | 黑名单命令 | 文件类工具 |
|------|-----------|-------------------|-----------|-----------|
| 默认模式（默认） | 权限层允许，无需审批；缺省在沙盒内执行 | 沙盒内执行（可选宿主上执行，进审批） | 拒绝 | 受范围强制 |
| 严格模式 | 权限层允许，无需审批；缺省在沙盒内执行 | 一律拒绝 | 拒绝 | 受范围强制 |
| 放行模式（高风险，默认不启用） | 权限层允许，无需审批；缺省在宿主上执行 | 缺省在宿主上执行，不因超出范围被拒；可指定沙盒内执行 | 拒绝 | 不经沙盒强制，仅按读/写规则评估 |

- 「权限层允许」指权限维度不拒绝该命令；命令若选择在沙盒内执行，仍受边界约束（沙盒是 OS 级边界，不因白名单而免除）。
- 解释器类命令（shell 等脚本解释器）以及可派生解释器的命令（make、npm 等）不得加入白名单，否则在宿主上执行即旁路沙盒约束；所有写入白名单的入口（权限指令、审批决策）都直接拒绝这类命令。
- 初始 Agent（`master`）的权限基线即放行模式（需求 [permission §F1](../../requirements/permission.md)），该基线属高风险模式。

### 命令分流

命令行维度按以下顺序分流：

1. **黑名单**：无论沙盒内外均不允许执行，也不进入审批，且先于命令安全解析生效。
2. **命令安全解析**（仅对非黑名单命令）：malicious 命令直接拦截并通知 Owner（不经审批）；uncertain 命令进入安全审批（与操作审批同一队列、同一单号空间）；trusted 命令继续（分级口径见 [tools 命令安全防护](../tools/bash-security.md)）。
3. **白名单**：权限层允许，在宿主或沙盒内执行均无需审批，执行位置由 Agent 指定，缺省按模式（默认模式与严格模式为沙盒内，放行模式为宿主）。
4. **其余命令与所有脚本**：按沙盒模式决定——默认模式在沙盒内执行，Agent 可请求在宿主上执行（进入审批，见「宿主上执行」）；严格模式直接拒绝；放行模式缺省在宿主上执行，Agent 可指定沙盒内执行。

### 宿主上执行

仅默认模式适用（严格模式下白名单外命令直接拒绝，放行模式缺省即在宿主上执行、无需审批），且不适用于黑名单命令。子 Session 场景不进入审批：静默拒绝。

Agent 为一条白名单外命令指定在宿主上执行时，须附用途说明；请求进入审批（审批类型标记为宿主上执行）。

Owner 的处置：

- **单次放行**：仅本次在宿主上执行，不持久化；下次执行仍按模式回到沙盒内。该放行只改变本次执行位置，不向规则层注入允许规则，也不改变命令白名单。
- **加入白名单**：将该命令写入命令白名单（Agent 维度资产，用户维度不覆盖），此后该命令可在宿主或沙盒内执行、无需审批。解释器类及可派生解释器的命令不可选。
- **拒绝**：命令不执行，Agent 收到拒绝结果。

该审批同时确认命令的网络访问范围：沙盒内无网络能力；请求在宿主上执行时，命令的网络访问按网络维度随本次判定一并处理，不额外拆成两次审批。加入白名单不持久化网络授权；放行模式下在宿主上执行的命令（含白名单命令）网络访问不受网络维度约束，默认模式与严格模式下白名单命令在宿主上执行前仍按网络维度评估。请求被拒绝、超时或沙盒引擎不可用时，命令不执行，不降级为无约束执行。

### 文件越界审批

文件类工具访问被拒时，按 [审批工作流](approval-workflow.md#审批分流) 分流；子 Session 场景不进入审批（静默返回拒绝）。被拒有两种成因，单次放行的落地不同：

- **越界**：允许规则未覆盖该路径 → 单次放行把该路径加入本次执行策略的允许集。
- **规则层拒绝**：命中拒绝规则 → 单次放行把该路径从本次执行策略的拒绝集中移除（仅本次执行，不写规则）。

Owner 的处置：

- **单次放行**：仅在本次操作中按 Owner 选择的维度生效；最终评估为允许时，按上述成因调整本次执行策略（越界加入允许集 / 规则拒绝从拒绝集移除），不写规则。未选维度按当前规则评估，两个维度都允许才执行；caller 为 Owner 时只有 Agent 维度。
- **加入白名单**：写入对应读/写维度的路径规则，沙盒边界随之更新；高风险路径（如 `.git` 目录）不可选。
- **拒绝**：操作被拒绝。

命中高风险名单（如 `.git` 目录）的读写即使位于边界内，也进入审批且仅单次放行可选（高风险操作见 [审批工作流](approval-workflow.md#高风险操作)）。权限配置文件的访问不在此流程内——对 Agent 一律不可读写，不进入审批（见 [权限配置管理](permission-configuration.md#配置保护)）。

放行模式下不存在沙盒边界，因而不存在「文件越界」：文件访问只按读/写规则评估，被规则拒绝时按普通权限拒绝进入审批（单次放行仅本次放行、加入白名单写入读/写维度规则）。

### 沙盒引擎

沙盒引擎采用操作系统原生隔离机制，隔离机制的选择与适配由 permission 自行实现：

- Linux：以 bubblewrap 为主，内核 Landlock 兜底；WSL2 归 Linux。
- macOS：以 Seatbelt 实现。

引擎在启动时探测可用性。通用操作系统差异（进程、文件路径、配置目录、临时目录等）走 platform 的抽象（需求 [platform §F5](../../requirements/platform.md)）；隔离机制本身属沙盒引擎职责，其平台适配不属 platform 的通用抽象。文件类工具通过受限执行环境访问文件，命令按模式与执行位置进入沙盒或宿主。

### 不降级

- 沙盒引擎不可用、初始化失败或运行期失效时，受沙盒约束的操作一律拒绝，属终局拒绝，不进入审批、不切换为宿主执行，记录调试日志，不参与审批去重（需求 [permission §F12](../../requirements/permission.md)）。
- 放行模式下的文件访问本就不受沙盒强制，不受引擎不可用影响；黑名单命令仍拒绝。
- 拒绝时 Agent 只收到操作被拒绝的结果，不暴露沙盒内部路径或规则信息。

## 数据流

```
操作请求
  │
  ├─ 文件类工具（按读/写规则评估）
  │    ├─ 命中高风险名单（如 .git）→ 审批（仅单次放行 / 拒绝）
  │    ├─ 放行模式 → 宿主进程直接访问，仅按读/写规则评估（被拒 → 普通审批）
  │    ├─ 在沙盒边界内 → 受限执行环境访问
  │    └─ 被拒（越界或规则拒绝）→ 审批（单次放行 / 加入白名单 / 拒绝）
  │
  └─ 命令
       ├─ 黑名单 → 直接拒绝（不审批）
       ├─ 命令安全解析 → malicious 拦截 / uncertain 安全审批 / trusted 继续
       ├─ 白名单 → 宿主或沙盒内执行（无需审批）
       └─ 其余命令/脚本 → 按沙盒模式
            ├─ 默认模式 → 沙盒内执行
            │    └─ 请求宿主上执行 → 审批（含网络访问确认）
            ├─ 严格模式 → 直接拒绝（不审批）
            └─ 放行模式 → 宿主上执行（可选沙盒内执行，此时无网络能力）

沙盒引擎不可用 → 受沙盒约束的操作一律拒绝（终局，不审批）
```

关键分支：

- 黑名单优先，且不进入审批。
- 严格模式下白名单外命令一律拒绝，即使该命令在默认模式下会进入沙盒。
- 放行模式命令缺省在宿主上执行、文件访问不经沙盒强制，但黑名单仍拒绝。
- 宿主上执行只改变执行位置；单次放行不改变规则，加入白名单才改变白名单。
- 文件越界审批不改变规则，除非 Owner 选择加入白名单；单次放行只作用于本次执行策略（越界加入允许集、规则拒绝从拒绝集移除），不写入规则。

## 模块关系

> 「上游/下游」指数据流与调用关系（含经 common trait 完成的调用），不等于 crate 依赖；crate 依赖以 [STANDARDS.md 依赖方向允许边表](../STANDARDS.md) 为准。

- **实现归属**：沙盒引擎由 permission 模块实现，经 [common SandboxExecutor](../common/core-traits.md#sandboxexecutor) 注入 tools 的文件类工具与命令执行层；tools 不直接依赖 permission crate。
- **上游**：权限引擎（提供当前生效的读/写规则、命令黑白名单、沙盒模式与网络判定）、tools（文件类工具与命令执行请求）、审批工作流（宿主上执行与文件越界的 Owner 决策结果回传）
- **下游**：tools（文件访问与命令执行经 SandboxExecutor 受沙盒约束）、审批工作流（越界、高风险与宿主执行请求入队）、debug_log（沙盒判定与拒绝事件）
- **共享类型 / 核心 trait**：[common SandboxExecutor](../common/core-traits.md#sandboxexecutor)（本模块实现、tools 消费）、[common ExecutionPolicy](../common/shared-types.md#risklevel--permissionrequest--permissionoperation--permissiondecision--executionpolicy--permissiondenied)（随判定结论传入的执行策略）
- **相关**：[权限维度](permission-dimensions.md)（读、写、命令行、网络维度的定义）、[权限配置管理](permission-configuration.md)（沙盒模式、命令黑白名单的存储与修改入口）、[tools 命令安全防护](../tools/bash-security.md)（命令安全解析的分级口径）、platform（通用操作系统差异）
- **无关**：LLM Provider（不参与权限判定）；IM Adapter 只渲染审批卡片，不参与沙盒判定

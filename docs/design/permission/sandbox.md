# 沙盒

## 概述

沙盒以操作系统级隔离强制 Agent 的文件访问范围，而不是只靠路径规则匹配。Agent 可能编写脚本反复拼接路径，规则难以穷尽；沙盒在操作系统层拦截越界访问，路径如何拼装都无法绕过。

## 架构

### 强制范围

沙盒启用时，强制约束两类访问：

- **文件类工具**：Read / Write / Edit / Grep / Ls 等读写本地文件的工具，以及 git_ops 中读写工作区的工具、SkillTool 读取技能文件等访问；具体工具到读/写维度的映射由 tools 声明。文件类工具在受限执行环境中运行，其文件访问由沙盒边界约束。
- **沙盒内执行的命令**：命令行中在沙盒内执行的进程，含其调用的脚本与子进程。

以下访问不受沙盒范围强制：

- 白名单命令在宿主执行，不受沙盒范围强制；其进程内文件访问也不受沙盒边界约束，因此白名单只应包含不需要越界文件访问的命令。
- Owner 通过斜杠指令执行的命令类操作按 Owner 命令执行豁免处理，不受沙盒约束；黑名单命令仍一律拒绝，且仍受命令安全解析约束（malicious 拦截、uncertain 审批）。
- `always allow` 模式下不启用沙盒，命令与文件访问不受范围强制。

### 边界来源

边界取 Agent 维度与 User+Agent 维度规则求值后的允许路径，再排除规则层 Deny 的路径：

```
可写范围 = ((Agent 写规则 ∩ User+Agent 写规则) 的允许路径 − Deny 路径) ∪ workspace 专属路径
可读范围 = ((Agent 读规则 ∩ User+Agent 读规则) 的允许路径 − Deny 路径) ∪ 可写范围
```

- 子 Session 的边界取三方交集（目标 Agent ∩ 父 Session ∩ 继承的 User 上下文）后的结果，父链路的 Deny 同样从边界中排除。
- caller 为 Owner 时，可读/可写范围只取 Agent 维度规则（∪ workspace 专属路径），不取 User+Agent 规则。
- 可写范围的 Deny 取写规则 Deny，可读范围的 Deny 取读规则 Deny；求值顺序为先求交、再减 Deny、最后与 workspace/可写范围并集。
- workspace 路径固定为 `~/.closeclaw/workspaces/{agent_id}/{user_id}/`，由系统创建并纳入可读写范围；`/cd` 或 spawn 工作目录指向其他路径时不纳入强制授权。
- workspace 专属路径命中高风险名单（如版本控制目录读写）时，仍按高风险审批处理，不直接放行。
- 边界按操作发生时的当前生效规则计算，不使用历史结果；规则与模式变更只对下一次操作生效，已在运行的进程不改变边界。
- 沙盒边界是「允许访问的文件范围」；规则层 Deny 与沙盒边界同时生效。Deny 路径在 OS 边界中直接排除，沙盒内脚本也无法访问。引擎适配层负责把 Deny 子路径落为遮蔽挂载或 Landlock 规则叠加，bubblewrap 的包含式挂载由适配层排除 Deny 路径。

### 模式

沙盒模式由权限规则定义，按 Agent 维度配置，User 维度不覆写；默认 `sandbox`。命令同时列入白名单与黑名单时黑名单优先（优先级定义见 [权限维度](permission-dimensions.md#命令行)）。

| 模式 | 白名单命令 | 黑名单命令 | 其余命令与所有脚本 | 文件类工具 |
|------|-----------|-----------|-------------------|-------------|
| `sandbox`（默认） | 宿主执行，不受范围强制 | 拒绝 | 沙盒内执行，受范围强制 | 受范围强制 |
| `whitelist` | 宿主执行，不受范围强制 | 拒绝 | 一律拒绝（含黑名单命令） | 受范围强制 |
| `always allow` | 宿主执行 | 拒绝 | 宿主执行，不受范围强制 | 不受范围强制 |

- 模式是 Agent 维度配置，User 维度不能覆盖或放宽。
- 解释器类命令（shell 等脚本解释器）以及可派生解释器的命令（make、npm 等）不得加入白名单，否则沙盒约束失效；所有加入白名单路径（斜杠规则指令、审批卡片/指令）都直接拒绝。

### 命令分流

命令行维度按以下顺序分流：

1. **黑名单**：无论沙盒内外均不允许执行，也不进入审批流程，且先于命令安全解析生效。
2. **命令安全解析**（仅对非黑名单命令）：malicious 命令直接拦截并通知 Owner（不经审批）；uncertain 命令直接进入审批；trusted 命令继续。
3. **白名单**：在宿主执行，不受沙盒范围强制。
4. **其余命令与所有脚本**：按沙盒模式决定执行位置，默认沙盒内执行。

`whitelist` 模式下白名单外的命令直接拒绝，不进入审批；`sandbox` 模式下白名单外的命令在沙盒内执行，若无法在沙盒内完成，走「移出沙盒执行」审批。

### 移出沙盒执行

仅 `sandbox` 模式适用，且不适用于黑名单命令。子 Session 与心跳场景不进入审批：子 Session 静默拒绝，心跳按任务配置跳过或通知 Owner。

部分命令无法在沙盒内完成（如需网络访问或交互式登录）时，Agent 可请求将某条命令移出沙盒、在宿主执行，并附上用途说明；请求进入审批流程。

Owner 的处置：

- **单次放行**：仅本次在宿主执行，不持久化；下次执行仍在沙盒内。该放行只改变本次执行位置，不向规则层注入 Allow，也不改变命令白名单。
- **加入白名单**：将命令写入命令白名单（Agent 维度资产，User 维度不覆盖），后续按白名单在宿主执行。高风险操作不可选；解释器类及可派生解释器的命令不可选。
- **拒绝**：命令不执行，Agent 收到拒绝结果。

移出沙盒审批同时确认命令的网络访问范围：沙盒内默认无网络能力；移出只改变执行位置，网络授权随该次审批一并决定，不额外拆成两次审批。加入白名单不持久化网络授权，后续白名单命令的网络访问仍按网络维度评估。请求被拒绝、超时或沙盒不可用时，命令不执行，不降级为无约束执行。

### 文件越界审批

文件类工具访问超出沙盒边界时，按 [审批工作流](approval-workflow.md#审批分流) 分流；子 Session 与心跳场景不进入审批。

Owner 的处置：

- **单次放行**：仅在本次操作中按 Owner 选择的维度生效；最终评估为 Allow 时，把该路径临时加入本次操作的沙盒边界，不写入规则。未选维度按当前规则评估，两个维度都 Allow 才执行。
- **加入白名单**：写入对应读/写维度的路径规则，沙盒边界随之更新；高风险路径（如版本控制目录、权限配置文件）不可选。
- **拒绝**：操作被拒绝。

权限配置文件的读取只允许 Owner 单次放行，写入一律拒绝；不因白名单机制放宽（见 [权限配置管理](permission-configuration.md#配置保护)）。

### 沙盒引擎

沙盒引擎采用操作系统原生隔离机制，按平台选择：

- Linux：以 bubblewrap 为主，内核 Landlock 兜底；WSL2 归 Linux。
- macOS：以 Seatbelt 实现。

引擎在启动时探测可用性；文件类工具通过受限执行环境访问文件，命令按模式进入沙盒或宿主。

### 不降级

- 沙盒引擎不可用、初始化失败或运行期失效时，受沙盒约束的操作一律拒绝，属终局拒绝，不进入审批、不切换为无约束执行；该行为是对需求 F5「其余场景进入审批」的显式收口，记录调试日志，不参与审批去重。
- `always allow` 模式下的操作本就不受沙盒约束，不受引擎不可用影响；黑名单命令仍拒绝。
- 拒绝时 Agent 只收到操作被拒绝的结果，不暴露沙盒内部路径或规则信息。

## 数据流

```
操作请求
  │
  ├─ 文件类工具
  │    ├─ always allow → 宿主进程直接访问，不受边界约束
  │    ├─ 在沙盒边界内且未命中高风险 → 受限执行环境访问
  │    ├─ 命中高风险 → 审批（单次放行 / 拒绝）
  │    └─ 越界 → 审批（单次放行 / 加入白名单 / 拒绝）
  │
  └─ 命令
       ├─ 黑名单 → 直接 Deny（不审批）
       ├─ 命令安全解析 → malicious 拦截 / uncertain 审批 / trusted 继续
       ├─ 白名单 → 宿主执行
       └─ 其余命令/脚本 → 按沙盒模式
            ├─ sandbox → 沙盒内执行
            │    └─ 需要移出 → 移出沙盒审批（含网络授权）
            ├─ whitelist → 直接 Deny（不审批）
            └─ always allow → 宿主执行

沙盒不可用 → 受沙盒约束的操作一律 Deny（终局，不审批）
```

关键分支：

- 黑名单优先，且不进入审批。
- `whitelist` 模式下白名单外命令一律拒绝，即使该命令在 `sandbox` 模式下会进入沙盒。
- `always allow` 不启用沙盒，但黑名单仍拒绝。
- 移出沙盒执行只适用于 `sandbox` 模式，且不适用于黑名单命令。
- 文件越界审批不改变规则，除非 Owner 选择加入白名单。

## 模块关系

- **实现归属**：沙盒引擎由 permission 模块实现，经 common 沙盒执行接口（待补，见 common doc-gap）注入 tools 与命令执行层；tools 不直接依赖 permission crate。
- **上游**：权限引擎（提供当前生效的读/写规则、命令黑白名单与沙盒模式）、tools（文件类工具与命令执行请求）、审批工作流（移出沙盒与文件越界的 Owner 决策）
- **下游**：tools（文件访问与命令执行受沙盒约束）、审批工作流（越界与移出请求进入审批）、debug_log（沙盒判定与拒绝事件）
- **相关**：[权限维度](permission-dimensions.md)（读、写、命令行、网络维度的定义）、[权限配置管理](permission-configuration.md)（沙盒模式、命令黑白名单的存储与修改入口）
- **无关**：LLM Provider（不参与权限判定）；IM Adapter 只渲染审批卡片，不参与沙盒判定

# 审批工作流

## 概述

当操作被权限引擎判定为拒绝、白名单外命令请求在宿主上执行、命令安全解析标记为可疑（uncertain），或新用户注册需要 Owner 决策时，不直接阻断——进入审批工作流，由 Owner 处置。操作类审批以全局唯一的审批单号标识，与发起会话无关；新用户注册以 `request_id` 标识，确认方式见「新用户注册审批」。

## 架构

### 审批分流

| 场景 | 处理 |
|------|------|
| 子 Session 操作 | 静默返回拒绝，不进入审批 |
| 黑名单命令 | 直接拒绝，不进入审批 |
| 沙盒引擎不可用 | 受沙盒约束的操作直接拒绝（终局，见 [沙盒](sandbox.md#不降级)） |
| 严格模式下白名单外的命令（含请求宿主执行） | 直接拒绝，不进入审批 |
| 权限配置文件的访问 | 直接拒绝，不进入审批，无放行路径（见 [权限配置管理](permission-configuration.md#配置保护)） |
| 命令安全解析为 malicious | 直接拦截并通知 Owner，不进入权限审批 |
| 命令安全解析为 uncertain | 进入安全审批（与操作审批同队列、同单号空间） |
| 白名单外命令请求在宿主上执行（仅默认模式） | 进入审批，单次放行只改变本次执行位置 |
| 文件类工具访问被拒（越界或命中规则拒绝） | 进入审批 |
| 命中高风险名单（如 `.git` 目录读写） | 进入审批，仅单次放行可选 |
| 网络访问被拒 | 进入审批；与宿主上执行同次发生时合并为一张卡片 |
| 其它权限维度的拒绝 | 进入审批 |
| 新用户注册 | 进入审批（注册请求，见「新用户注册审批」） |

### 审批队列

审批队列由 permission 实现（daemon 作为 ApprovalFlow 组件持有并装配）：

- **入队**：操作被拒绝且按上表需审批、命令安全解析为不确定、或请求在宿主上执行 → 创建审批请求入队 → 该次判定在结论到达前挂起（调用方不轮询、不注册回调）。挂起期间 tools 先向 Agent 返回「待审批」结果（Agent 不必重复提交、可继续其它工作），审批结论到达后由 tools 把结论作为后续消息注入该轮对话（工具结果的消息注入机制见 [tools 多工具调用](../tools/multi-tool-calls.md)）。
- **并发语义**：审批挂起不改变 [tools 多工具调用](../tools/multi-tool-calls.md) 的并发分类；同轮其它工具调用按各自分类执行，不被这次挂起阻塞。
- **审批单号**：操作类审批全局唯一、跨会话与跨渠道连续自增，不按会话重新计数；同一进程生命周期内不复用已分配的单号。Owner 在任意会话发出的审批指令均按单号命中对应请求，与发出指令的会话无关。
- **标识命名**：操作类审批（权限拒绝、宿主上执行、安全审批）共用「审批单号」（整数）；新用户注册用 `request_id`（字符串）。
- **去重**：同一 Agent-User 组合下、操作类型与参数相同的重复申请仍按当前生效规则重新评估——命中新规则即放行；仍被拒绝时直接返回拒绝结果，不复用也不延长已有的审批请求，不重复推送审批。审批完成或超时后，该操作的重复申请限制解除，Agent 可重新发起。
- **等待与超时**：等待时长取权限配置的全局段配置项（定义、默认值与生效规则见 [权限配置管理](permission-configuration.md#配置文件与结构)）。操作类审批超时未响应则自动向 Agent 返回拒绝结果；超时后 Owner 再对该单号发审批指令，系统返回「该审批已超时」。已被决策的单号再次收到审批指令时返回「该审批已处理」。
- **回调**：Owner 决策后按审批单号关联等待中的判定调用，使其以允许或拒绝返回，系统据此向对应 Agent 通知审批结果（由等待它的调用注入对话，不另设独立回调接口）。等待方已不可用（会话终止/进程退出）时，请求以拒绝结束。
- **可捕获的关闭流程**：所有等待中的请求以拒绝结束并通知对应 Agent。进程崩溃/重启后内存队列本身不存在；Session 恢复时按 [session 恢复机制](../session/session-recovery.md) 对挂起的工具调用注入失败结果，不依赖队列残留。
- **Owner 离线**：请求照常计时；超时后不补推，审批生命周期事件保留在调试日志与审计条目中，供事后查询；不阻塞系统其他功能。

### 审批信息与投递

审批请求入队后立即推送，不批量延迟。推送的信息包含：

- 审批单号（注册请求为 `request_id`）
- 审批类型：权限拒绝（含文件访问被拒、高风险名单命中、网络被拒、其它维度拒绝）/ 宿主上执行 / 安全审批 / 新用户注册
- 发起操作的 Agent ID、当前 User ID（本轮 caller）
- 操作类型和参数（路径、命令、目标等）
- 风险等级提示（普通操作 / 高风险操作）
- 超时时刻
- 本次可选的决策集（高风险操作、解释器类命令等不可加入白名单的对象不含「加入白名单」项；其余请求单次放行 / 加入白名单 / 拒绝均可选）
- 审批指令的用法提示（含单号与维度参数的写法）

命令类操作另附 Agent 提供的命令用途说明；命令安全解析为不确定时另附原始命令、解析失败原因与风险标签（`security_note`）。宿主上执行的请求额外标明「在宿主上执行」与所需网络访问范围（`network_targets`）。注册请求的发起 Agent 字段为空，操作字段也为空。

**投递通道**：

- 推送经 [common ApprovalNotifier](../common/core-traits.md#approvalnotifier) 交给 Gateway 投递；Gateway 按 [gateway §F7](../../requirements/gateway.md) 出站规则投递到 Owner 最近使用的 IM 平台，失败时按最近使用顺序回退，全部失败时记录日志。
- IM 渠道由 IM Adapter 渲染为平台卡片；CLI 渠道输出与卡片内容一致的终端提示，覆盖全部等待中的请求（见 [cli §F1](../../requirements/cli.md)）。
- 卡片与终端提示是通知载体，Owner 的决策经审批指令表达（见「Owner 决策」）；交互控件不在当前范围（见 [im_adapter 需求](../../requirements/im_adapter.md)）。
- 投递结果（已投递 / 无可用渠道 / 投递失败）只用于记录调试日志，不重试、不延长等待——等待计时自请求创建起计。

### 新用户注册审批

新用户注册请求同样经审批队列，但它是**卡片专属**的确认流程，不走操作审批的三选一决策：

- 注册请求以 `request_id` 标识，该标识写入推送信息；审批指令只寻址操作审批单号，不用于寻址注册请求。
- Owner 的决策是批准或拒绝（[RegistrationConfirmation](../common/shared-types.md#approvalcard--approvaldecision--approvaldelivery)），不是单次放行/加入白名单/拒绝；批准后的 User 不获得任何权限，后续由 Owner 通过权限指令授予规则。确认由 Gateway 硬拦截 Owner 的注册确认指令后提交审批队列并回填结果（提交与回调按 `request_id` 关联）；确认指令的指令面归 slash 模块。
- 注册请求的等待计时与操作审批同一规则（同一全局等待时长），`deadline` 同样随卡片推送；超时后请求作废，Owner 再确认时返回「该请求已超时」。
- 同一用户已有等待中的注册请求时直接拒绝新请求；批准后由 Gateway 权限指令处理层生成 [UserRegistration](../common/shared-types.md#userregistration--usercreationrequest)，用户记录由 config 的账户绑定存储，权限系统不为其写入任何规则（见 [权限配置管理](permission-configuration.md#修改入口)）。

> **与 PermissionGate 的关系**：权限判定的入口只有一个——消费方（tools / session / gateway）经 [common PermissionGate](../common/core-traits.md#permissiongate) 发起判定，权限引擎在实现内部把需审批的请求入队并挂起直至有结论；审批队列不对外暴露独立的判定接口。新用户注册不经过权限判定，其处理在队列内独立流转。

审批队列为内存结构，不阻塞系统其他功能；无 Owner 在线时系统保持可用。

### Owner 决策

所有审批请求只推送给 Owner；非 Owner 用户没有审批权力，其审批指令由 Gateway 直接拒绝。Owner 通过审批指令表达决策（[slash §F13](../../requirements/slash.md)），Gateway 硬拦截指令后把决策提交审批队列。Owner 可选择：

- **单次放行**：仅本次操作放行，不持久化规则，后续相同操作仍需重新审批。
- **加入白名单**：写入持久化规则；当前这次等待中的操作按写入后的新规则重新求值并放行，后续同类操作同样按新规则评估。写入失败（校验不通过、属不可加入白名单的对象、原子写入中断）时，本次请求以拒绝结束并向 Owner 返回失败原因，原规则不变。
- **拒绝**：操作被拒绝。

Owner 可按 Agent 维度和用户维度分别决策：

- 只放行触发操作的 Agent、只放行当前 User 上下文、或两者均放行；指令的维度参数表达这一选择，未指定时按两者处理。
- 单次放行按所选维度注入一次性允许；未选维度按当前规则评估；非 Owner caller 两维度都允许才执行，Owner caller 只评估 Agent 维度。
- 加入白名单按所选维度写入规则。
- **命令类与工具调用类操作只涉及 Agent 维度**：规则主体只能是 Agent（见 [权限配置管理](permission-configuration.md#配置文件与结构)），不提供用户维度放行。
- **Owner 自身调用被拦截时，只评估 Agent 维度（用户维度已豁免），不存在用户维度决策。**

宿主上执行的「加入白名单」写入命令白名单，表示该命令后续可在宿主上执行，不是普通权限规则（见 [沙盒](sandbox.md#宿主上执行)）。宿主上执行的「单次放行」只改变本次执行位置，不向规则层注入允许规则。文件访问被拒的「单次放行」仅调整本次执行策略（越界加入允许集、规则拒绝从拒绝集移除），不写规则。

**合并卡片**：宿主上执行与网络访问被拒同次发生时合并为一张卡片；「单次放行」同时放行本次的宿主执行与该次网络访问，「加入白名单」只把命令写入命令白名单、不持久化网络授权（该命令后续在宿主上执行时，网络访问仍按网络维度单独评估）。

非工具操作的审批恢复：命令类斜杠指令的拒绝由 Gateway 挂起 SlashResult，审批通过后由 Gateway 重放执行并回发结果；收发消息被拒由 Gateway 挂起消息，审批通过后重新投递；不依赖 Session 工具挂起。

### 高风险操作

标注为高风险（命中硬编码高风险名单）的操作有额外限制：即使规则允许也进入审批，永远只能单次放行，不能被加入白名单。

- 名单按路径命中，作用于 Agent 对名单内路径的文件读写操作；命令对同一路径的访问按命令行维度评估，不按本名单判定。
- 当前名单包含版本控制目录（`.git`）的读写；配置写入维度下的操作天然属高风险（见 [权限维度](permission-dimensions.md#配置写入)）。
- 名单由系统预定义并随版本增补，Owner 不能自行增删。
- 推送的审批信息不提供「加入白名单」项；审批指令路径对高风险操作同样拒绝加入白名单。
- 风险等级（普通 / 高风险）不改变审批触发条件，只限制可选决策。

### 规则变更与审批

审批请求**不记录规则版本快照**。Owner 作出决策后，系统按当前生效规则处理该操作：

- **单次放行**：在本次评估中按所选维度注入一次允许，仅对本次操作有效；不写入规则（宿主上执行与文件访问的例外见上）。
- **加入白名单**：先把规则写入当前规则集，再按新规则求值本次操作并放行后续操作。
- **拒绝**：本次操作拒绝。

等待期间规则变更立即影响本次决策所依据的规则集，不存在「按旧规则放行」的窗口期；规则变更也不会使已入队的请求失效，Owner 仍可对该请求作出决策。

### 调试日志

- 审批请求的创建、推送、单次放行、加入白名单、拒绝、超时写入调试日志。
- 审批处置同时写入 AuditLogEntry（操作内容、风险等级、最终处置），供审计查询（审计的产品背景见 [gateway §F7](../../requirements/gateway.md)）；F11 要求的触发规则只进调试日志。
- 推送内容不包含规则名称、优先级或配置路径等内部实现信息。

## 数据流

```
操作被拒绝 / 请求宿主执行 / 安全可疑
  │
  ├─ 子 Session / 黑名单 / 沙盒不可用 / 严格模式 / 权限配置文件 → 直接拒绝或通知（结束）
  │
  └─ 进入审批
        │
        ▼
     去重检查：按当前生效规则重新评估 → 命中新规则即放行 / 仍拒绝则直接返回拒绝，不重复推送
        │
        ▼
     创建审批请求（分配全局唯一审批单号）→ 判定调用挂起，tools 向 Agent 返回待审批
        │
        ▼
     推送（经 ApprovalNotifier → Gateway：IM 平台卡片 / CLI 终端提示）
        │
        ▼
     Owner 在任意会话发出审批指令（Gateway 硬拦截）→ 按单号提交决策
        │
        ├─ 单次放行 → 注入一次性允许 / 仅本次宿主执行 / 调整本次执行策略 → 判定返回允许
        ├─ 加入白名单 → 写入规则 → 本次按新规则求值 → 判定返回结论
        └─ 拒绝 → 判定返回拒绝

新用户注册请求 → 队列（request_id）→ 推送 → Owner 确认指令 → 回填 → Gateway 生成 UserRegistration
```

关键分支：

- 超时 → 自动返回拒绝，重复申请限制解除；已处理单号再次收到指令 → 返回「该审批已处理」。
- 可捕获的关闭流程 → 清空队列，所有等待请求以拒绝结束；进程崩溃/重启由 Session 恢复机制处理。
- 推送经 Gateway / IM Adapter 出站；审批指令经 Gateway 硬拦截，与发起会话无关。

## 模块关系

> 「上游/下游」指数据流与调用关系（含经 common trait 完成的调用），不等于 crate 依赖；crate 依赖以 [STANDARDS.md 依赖方向允许边表](../STANDARDS.md) 为准。

- **上游**：权限引擎（产出拒绝结论与审批入队）、Gateway（审批指令拦截后提交决策）、tools / session（经 PermissionGate 发起需审批的判定，含安全审批与宿主上执行请求）、沙盒（宿主上执行与文件访问被拒的请求入队）
- **下游**：Gateway（实现 [common ApprovalNotifier](../common/core-traits.md#approvalnotifier) 的推送通道，承载审批指令提交与结果回发）、IM Adapter（经 Gateway 渲染审批卡片）、CLI（经 Gateway 输出终端审批提示）、Session（恢复执行或返回拒绝）、权限配置管理（白名单规则写入）、config（新用户注册的用户记录与账户绑定落盘）、沙盒（宿主上执行与被拒访问的决策结果回传）、[common AuditLogger](../common/core-traits.md#auditlogger)（审批处置审计条目）、debug_log（审批生命周期事件）
- **共享类型 / 核心 trait**：[common ApprovalCard / ApprovalDecision / ApprovalDelivery](../common/shared-types.md#approvalcard--approvaldecision--approvaldelivery)（推送与决策载荷）、[common ApprovalNotifier](../common/core-traits.md#approvalnotifier)（消费方）、[common AuditLogger](../common/core-traits.md#auditlogger)（实现方）、UserCreationRequest（注册请求载荷）
- **相关**：权限配置管理（新用户注册与白名单写入）、slash（审批指令与注册确认指令的语法与 Immediate 标记）
- **无关**：LLM Provider（不参与审批）

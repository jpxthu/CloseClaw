# 权限维度

## 概述

权限维度定义了权限系统管控的八类操作，每类操作独立管理，各自有默认策略、判定规则与执行位置。默认策略的基线是：Agent 维度默认仅可收发消息，User 维度默认无任何权限；读、写、工具、网络、跨 Agent、配置写入默认拒绝；命令行默认无宿主执行权限（白名单为空），沙盒内命令按模式执行；收发消息按身份默认。

## 架构

### 维度总览

```
读        ─── 文件读取范围；由沙盒在操作系统层强制；默认拒绝
写        ─── 文件写入范围；由沙盒在操作系统层强制；默认拒绝
命令行    ─── 白名单 + 黑名单；黑名单优先；默认无宿主执行权限；沙盒内命令按模式执行
工具      ─── 能否调用某个工具；默认拒绝；Workflow 系统工具例外
收发消息  ─── User 与 Agent 之间的消息往来；Agent 默认允许、User 默认无权限
网络      ─── 主机、端口访问；默认拒绝
跨 Agent  ─── spawn、消息传递等；默认拒绝（含直接父子）
配置写入  ─── 系统配置文件写入；默认拒绝；永远为高风险
```

高风险是跨维度的硬编码名单（至少含版本控制目录读写、权限配置文件读取、系统配置文件写入、破坏性删除命令），命中时按 [审批工作流](approval-workflow.md#高风险操作) 处理，不是某一维度独有的属性。

规则参数与维度的对应：

| 维度 | 规则参数 |
|------|---------|
| 读 / 写 | 路径 |
| 命令行 | 命令（白名单/黑名单） |
| 工具 | 工具名 |
| 网络 | 主机、端口 |
| 跨 Agent | 目标 Agent / Session |
| 配置写入 | 文件路径 |
| 收发消息 | 方向（入站/出站） |

评估与拦截位置：读/写、命令行由权限引擎评估并交沙盒强制；工具与配置写入由 tools 经 common PermissionGate 触发；跨 Agent（spawn）由 Session 经 PermissionGate 触发；网络随命令执行与移出沙盒审批处理；收发消息在消息进入/离开 Agent 时评估。所有操作均经 [common PermissionGate](../common/core-traits.md#permissiongate) 单一入口进入权限引擎，不另设窄接口。

### 读

- 控制 Agent 可读取的文件和目录范围；通过文件操作表达，同时约束工具内部的读取行为。
- 可读范围由沙盒边界给出（可写范围 ∪ 读维度配置的路径范围），见 [沙盒](sandbox.md#边界来源)。
- 沙盒启用时由操作系统级强制；`always allow` 模式除外。
- `always allow` 不启用沙盒，但规则层路径 Allow/Deny 仍评估，只是没有 OS 级边界。
- 规则层 Allow/Deny 与沙盒边界同时生效：沙盒负责 OS 层边界，规则层仍可 Deny 边界内路径；workspace 专属路径例外。
- 边界之外的访问进入「文件越界审批」，不是硬拒绝（见 [沙盒](sandbox.md#文件越界审批)）。
- 权限配置文件与权限配置目录的读取受硬编码保护（见 [权限配置管理](permission-configuration.md#配置保护)）。
- workspace 专属路径是强制授权例外：直接 Allow，不受 Deny 规则影响；命中高风险名单时仍按高风险审批处理。
- 读与写共用同一套文件级权限评估路径，不重复定义规则格式。

### 写

- 控制 Agent 可写入的文件和目录范围；通过文件操作表达，同时约束工具内部的写入行为。
- 可写范围由沙盒边界给出（写维度配置的路径范围 ∪ workspace 专属路径），见 [沙盒](sandbox.md#边界来源)。
- 沙盒启用时由操作系统级强制；`always allow` 模式除外。
- `always allow` 不启用沙盒，但规则层路径 Allow/Deny 仍评估，只是没有 OS 级边界。
- 边界之外的访问进入「文件越界审批」；删除类写操作命中高风险名单时按高风险审批处理。
- workspace 专属路径的强制授权例外同「读」。
- 写入必然伴随读取，因此可读范围包含可写范围。

### 命令行

- 控制 Agent 可执行的命令；白名单与黑名单并存，同一命令同时列入两表时**黑名单优先**。默认无宿主执行权限（白名单为空）；沙盒内命令按沙盒模式决定是否允许与执行位置。
- **黑名单**内的命令无论沙盒内外均不允许执行，也不进入审批流程；黑名单先于命令安全解析生效。
- **命令安全解析**（仅对非黑名单命令）：malicious 命令直接拦截并通知 Owner（不经审批）；uncertain 命令直接进入审批；trusted 命令继续进入白名单匹配（命令安全解析见 [tools 命令安全防护](../tools/bash-security.md)）。
- **白名单**是「可在宿主执行的命令」集合：白名单内的命令在宿主执行，不受沙盒范围强制。
- 其余命令和所有脚本的执行位置由沙盒模式决定（见 [沙盒](sandbox.md#模式)），默认为沙盒内执行；`whitelist` 模式下白名单外命令直接拒绝。
- 破坏性删除命令即使不在黑名单，也命中高风险名单，按高风险审批处理。
- 解释器类命令（shell 等脚本解释器）不得加入白名单（见 [沙盒](sandbox.md#模式)）。
- **Owner 命令执行豁免**：Owner 通过斜杠指令执行的命令类操作（`/exec`、`/git` 等）默认放行，不进入权限评估与审批，也不受沙盒约束；被列入黑名单的命令除外，且仍受命令安全解析约束（malicious 拦截、uncertain 审批）。
- Owner 通过 bash 等工具执行命令时**不享受**命令执行豁免：仍按 Agent 维度与命令行维度评估，Owner 只跳过 User 维度。

### 工具

- 控制 Agent 能否调用某个工具；默认拒绝。仅符合工具调用格式的 LLM 输出会进入工具模块，格式解析先于权限评估。
- 工具维度只判断「能否调用该工具」；工具内部的文件读写由读/写维度评估，命令执行由命令行维度评估，不重复计入工具维度。
- 系统级 Workflow 工具（workflow_start / workflow_verify / workflow_jump / workflow_blocked）按 [tools 安全边界](../tools/README.md) 的例外处理，不经权限引擎。
- `sessions_spawn` / `sessions_steer` / `sessions_kill` 同时是工具调用与跨 Agent 操作：工具维度与跨 Agent 维度都要 Allow，任一 Deny 即拒绝。

### 收发消息

- 控制 User 与 Agent（LLM）之间的消息往来：User 消息送入 LLM，以及 LLM 和工具发往 User 的消息。
- 默认策略：新建 Agent 可收发消息；新建 User 无任何权限（含收发消息），需 Owner 显式授予后才能开始交互（见 [README](README.md#身份体系)）。
- 该维度与渠道（IM 或 CLI）无关，对所有渠道一致生效。
- 评估点：User 消息送入 LLM 前、LLM/工具消息发往 User 前；消息路由与格式解析本身不评估。
- 系统通知（workflow 暂停/恢复提示、子 Session 超时预警等）与 CLI Admin 命令不经过本维度。

### 网络

- 控制 Agent 可访问的网络资源（主机、端口）；默认拒绝所有网络访问，需要时由 Owner 显式授予。
- 当前产品没有独立网络工具，网络访问主要由命令产生：命令声明的网络目标按本维度评估；沙盒内默认不提供网络能力。
- 白名单命令与 `always allow` 的宿主命令同样在启动前评估网络维度；没有网络授权时直接拒绝，不因宿主执行而自动放行。
- 沙盒内命令需要网络访问时，走「移出沙盒执行」审批；该审批同时确认命令的网络访问范围，不额外拆成两次审批（见 [沙盒](sandbox.md#移出沙盒执行)）。
- 移出沙盒只改变执行位置，不自动授予网络访问；网络授权随该次审批一并决定。

### 跨 Agent 通信

- 控制 Agent 之间能否通信，包括 spawn、steer、kill、消息传递等；默认拒绝。
- **默认拒绝所有跨 Agent 操作，包括直接父子 Session**；默认配置下 spawn / steer / kill 均不可用，需 Owner 显式授予跨 Agent 权限。
- agent 需求中「默认仅直接父子 Session 之间互通」是路由层的默认配置，只决定消息路由可达性，不构成权限放行；消息送达需同时满足路由配置与权限允许，两者是 AND 关系。
- 父子 Session 要通信，仍需权限规则显式允许；扩展 Agent 通信范围的配置也只解决路由可达性，不改变本维度的默认拒绝。
- spawn 的权限取三方交集：目标 Agent 配置 ∩ 父 Session 实际权限 ∩ 继承的 User 上下文权限；沿链路只能变窄，Deny 逐级传播（见 [README](README.md#子-agent-权限继承)）。
- 跨 Agent 操作被拒时按 [审批工作流](approval-workflow.md#审批分流) 分流；子 Session 场景静默拒绝，不触发审批。

### 配置写入

- 控制 Agent 能否写入系统配置文件；默认拒绝。系统配置文件指 CloseClaw 自身的业务配置（`~/.closeclaw/config/` 下业务配置与 `~/.closeclaw/agents/*/config.json`），不含权限配置文件。配置写入维度优先于写维度：命中即高风险审批，不进入沙盒边界（Owner 单次放行除外）。
- 该维度下的操作一律为高风险，只能单次放行，不能被加入白名单（决策限制见 [审批工作流](approval-workflow.md#高风险操作)）。
- 权限配置文件的读写另受硬编码保护：读取需 Owner 单次放行，写入一律拒绝，不走本维度的白名单机制（见 [权限配置管理](permission-configuration.md#配置保护)）。

## 数据流

```
操作入口
  ├─ 权限配置文件/目录读写 → 硬编码保护（默认 Deny；Owner 单次放行，不可白名单）
  ├─ workspace 专属路径读/写 → 直接 Allow（高风险命中仍审批）
  ├─ 工具调用 → 工具维度
  │     └─ 工具内部操作：文件读写 → 读/写维度；命令 → 命令行维度；配置写入 → 配置写入维度
  ├─ 命令类斜杠指令 → 命令行维度（Owner 命令执行豁免）
  ├─ 收发消息 → 收发消息维度
  ├─ spawn / steer / kill → 跨 Agent 维度 + 链路交集
  └─ 心跳 → 按任务配置的 User 上下文评估
  │
  ▼
一次操作可能触发多个维度：全部 Allow 才放行；任一维度 Deny 即 Deny
  │
  ▼
Deny → 按 [审批工作流](approval-workflow.md#审批分流) 分流
```

关键分支：

- 命令执行按命令安全解析 → 黑名单 → 白名单 → 沙盒模式顺序分流（分流顺序见 [沙盒](sandbox.md#命令分流)）；malicious 直接拦截，blacklist 与 `whitelist` 模式白名单外命令不进入审批。
- 文件越界 → 文件越界审批；workspace 专属路径 → 直接 Allow（高风险命中仍审批）。
- 网络访问 → 随命令的移出沙盒审批一并确认。
- caller 为 Owner → 跳过 User 维度规则；Owner 的命令类斜杠操作按命令执行豁免处理。

## 模块关系

- **上游**：tools 模块（工具调用时触发各维度检查）、Gateway（命令类斜杠指令）、Session/心跳（消息与跨 Agent 操作入口）
- **下游**：沙盒（读/写、命令行的 OS 级强制）、审批工作流（Deny 分流）、debug_log（维度判定与拒绝事件）
- **相关**：权限引擎（以维度为单位匹配操作类型）、[权限配置管理](permission-configuration.md)（维度规则、命令黑白名单与沙盒模式的存储和修改）
- **无关**：IM Adapter（消息解析与渲染）、LLM Provider（不参与权限判定）

# 权限维度

## 概述

权限维度定义了权限系统管控的七类操作，每类操作独立管理，各有判定语义、执行位置与审批交互。各维度的默认取值来自内置默认基线（唯一清单见 [README](README.md#默认基线)）；本文件描述各维度的判定语义、评估位置与执行位置。

## 架构

### 维度总览

```
读        ─── 文件读取范围；workspace 自动放行，其余由沙盒在操作系统层强制；默认拒绝
写        ─── 文件写入范围；workspace 自动放行，其余由沙盒在操作系统层强制；默认拒绝
工具调用  ─── 能否调用某个工具；按配置档案工具范围收窄
收发消息  ─── User 与 Agent 之间的消息往来；Agent 允许、User 无权限
网络访问  ─── 主机、端口访问；默认拒绝
配置写入  ─── 系统配置文件写入；默认拒绝；天然属高风险
命令行    ─── 白名单 + 黑名单；黑名单优先；默认无宿主执行权限；沙盒内命令按模式执行
```

高风险是跨维度的硬编码名单（名单内容与处置唯一定义见 [审批工作流](approval-workflow.md#高风险操作)），配置写入维度下的操作天然属高风险。

规则与维度的对应（主体的生效范围见 [README](README.md#决策顺序与交集)）：

| 维度 | 规则主体 | 生效对象 |
|------|---------|---------|
| 读 / 写 | Agent 或 User | 文件系统路径 |
| 工具调用 | 仅 Agent | 工具名 |
| 网络访问 | Agent 或 User | 主机、端口 |
| 命令行 | 仅 Agent | 命令名（白名单 / 黑名单条目） |
| 收发消息 | Agent 或 User | 不细分对象 |
| 配置写入 | Agent 或 User | 不细分对象 |

**判定语义**：读、写、网络访问、命令行（宿主执行）、配置写入按**允许清单**求值（无允许规则即不允许；白名单只决定「能否在宿主上执行」，沙盒内执行的许可由沙盒模式决定）；工具调用与收发消息在 Agent 维度为**基线 + 收窄**（可用集合 = 基线 − 拒绝规则，允许规则不能把范围扩大到基线之外；工具基线为配置档案的工具范围、收发消息基线为 Agent 允许），用户维度无基线（无允许规则即拒绝）。

**评估与拦截位置**：读/写、命令行由权限引擎评估并交沙盒强制；工具调用与配置写入由 tools 经 common PermissionGate 触发；收发消息由 Gateway 在消息进入/离开 Agent 处经 PermissionGate 评估；网络访问随宿主上执行请求与工具的网络请求评估。除系统级 Workflow 工具（不经权限引擎，见 [tools 安全边界](../tools/README.md)）与 spawn 可用性（由层级深度决定）外，其余操作均经 [common PermissionGate](../common/core-traits.md#permissiongate) 单一入口进入权限引擎，不另设窄接口。

### 读

- 控制 Agent 可读取的文件和目录范围；通过文件操作表达，同时约束工具内部的读取行为。
- 可读范围由沙盒边界给出（公式与求值规则唯一定义见 [沙盒](sandbox.md#边界来源)）。
- 文件类工具的访问由操作系统级强制；放行模式下不经沙盒强制，仅按本维度规则评估。
- 规则层允许/拒绝与沙盒边界同时生效；workspace 专属路径自动放行（见 [README](README.md#决策顺序与交集)）。
- 边界之外的访问进入「文件越界审批」，不是硬拒绝（见 [沙盒](sandbox.md#文件越界审批)）；命中拒绝规则的路径同样进入审批，单次放行仅对本次执行生效。
- 命中高风险名单的路径读写（如 `.git` 目录）即使位于 workspace 或规则允许范围内，也按高风险操作处理——只能单次放行，优先于 workspace 自动放行。
- 权限配置文件的访问受硬编码保护，对任何 Agent 一律不可读写（见 [权限配置管理](permission-configuration.md#配置保护)）。
- 读与写共用同一套文件级权限评估路径，不重复定义规则格式。

### 写

- 控制 Agent 可写入的文件和目录范围；通过文件操作表达，同时约束工具内部的写入行为。
- 可写范围由沙盒边界给出（公式与求值规则唯一定义见 [沙盒](sandbox.md#边界来源)）。
- 写权限包含读权限（能写必然能读），读权限不包含写权限。
- 文件类工具的访问由操作系统级强制；放行模式下不经沙盒强制，仅按本维度规则评估。
- 边界之外的访问进入「文件越界审批」；命中高风险名单的路径读写（含删除、覆盖等路径下的写操作）按高风险审批处理。
- workspace 专属路径的强制授权例外与高风险优先级同「读」。

### 工具调用

- 控制 Agent 能否调用某个工具。仅符合工具调用格式的 LLM 输出会进入工具模块（格式解析先于权限评估）。
- 可用工具集合 = Agent 配置档案的工具范围 ∩ 本维度的规则——配置档案给出可用范围的基线（默认允许），规则只能在该范围内收窄，不能放大（需求 [agent §F1](../../requirements/agent.md)）。
- 工具维度只判断「能否调用该工具」；工具内部的文件读写由读/写维度评估，命令执行由命令行维度评估，不重复计入工具维度。
- 系统级 Workflow 工具（workflow_start / workflow_verify / workflow_jump / workflow_blocked）按 [tools 安全边界](../tools/README.md) 的例外处理，不经权限引擎。
- **spawn 工具是本维度内唯一不受收窄的对象**：其可用性只由该 Agent 生效的子 Session 层级深度决定——层级深度大于 0 时强制开放，不受配置档案的工具范围与本维度规则收窄；目标白名单与并发数量是 spawn 请求本身的配置约束，不改变工具可用性（需求 [agent §F9](../../requirements/agent.md)）。
- sessions_steer / sessions_kill 按本维度评估（工具名是否可用）；目标 Session 的归属关系由 Session 另行校验，不属于权限维度。

### 收发消息

- 控制 User 与 Agent（LLM）之间的消息往来：User 消息送入 LLM，以及 LLM 与工具发往 User 的消息。出站方向同样受本维度约束（「LLM 普通文本消息不进入工具维度」不等于不受收发消息维度约束）。
- 默认策略：Agent 维度可收发消息；用户维度无任何权限（含收发消息），需 Owner 显式授予后才能开始交互（见 [README](README.md#身份体系)）。
- 该维度与渠道（IM 或 CLI）无关，对所有渠道一致生效。
- 评估点：User 消息送入 LLM 前、LLM/工具消息发往 User 前，由 Gateway 在该时机经 PermissionGate 评估；消息路由与格式解析本身不评估。
- 拒绝后果：被拒绝的消息按 [审批工作流](approval-workflow.md#审批分流) 处理——非子 Session 场景进入审批，审批通过后由 Gateway 重新投递；子 Session 场景静默拒绝（见「审批工作流·Owner 决策」）。
- 系统通知（workflow 暂停/恢复提示、子 Session 超时预警等）与 CLI 管理命令不经过本维度。
- Agent 之间的消息投递与子 Session 的任务下发不构成本维度评估项，也不进入权限判定（需求 [session §F4](../../requirements/session.md)）。

### 网络访问

- 控制 Agent 可访问的网络资源（主机、端口）；默认拒绝所有网络访问，需要时由 Owner 显式授予。
- 沙盒内的命令没有网络能力；因此本维度作用于两类请求：
  - **宿主上执行的命令**：命令的网络访问在该命令的放行或审批中一并判定——被拒绝的网络访问进入审批。放行模式下命令缺省在宿主上执行且不进入审批，其网络访问不受本维度约束（放行模式本身即高风险基线）。
  - **工具代表的 Agent 级网络请求**：工具替 Agent 发起的网络请求受本维度约束，被拒绝时按 [审批工作流](approval-workflow.md#审批分流) 分流。平台通道自身的出站（IM 消息收发、LLM 调用、告警投递等）不属于 Agent 的网络访问，不受本维度约束。
- 宿主上执行只改变执行位置，不自动授予网络访问；网络授权随该次审批一并决定，不额外拆成两次审批（见 [沙盒](sandbox.md#宿主上执行)）。
- 白名单命令在宿主上执行前同样按本维度评估网络访问；被拒绝的网络访问进入审批（不伴随宿主上执行请求时单独成一张卡片）。

### 配置写入

- 控制 Agent 能否写入系统配置文件；默认拒绝。系统配置文件指 CloseClaw 自身的业务配置（配置目录下的业务配置与各 Agent 的 `config.json`），不含权限配置文件。
- 该维度下的操作一律为高风险：只能单次放行，不能被加入白名单（决策限制见 [审批工作流](approval-workflow.md#高风险操作)）。
- 本维度优先于写维度：命中即按高风险审批处理，不进入沙盒边界；Owner 单次放行后，该次写入在宿主上执行（同样不经沙盒边界）。
- 规则不细分生效对象；操作携带的文件路径只用于审批卡片与审计定位。
- 权限配置文件另行受硬编码保护：对 Agent 一律不可读写，不进入审批、无放行路径（见 [权限配置管理](permission-configuration.md#配置保护)）。

### 命令行

- 控制 Agent 可执行的命令；后台任务中的命令执行、命令类斜杠指令（`/git` 的写操作）同样按本维度评估。默认无宿主执行权限（白名单为空），沙盒内的非黑白名单命令按模式允许。
- **黑名单**内的命令无论沙盒内外均不允许执行，也不进入审批流程；黑名单先于命令安全解析生效。
- **命令安全解析**（仅对非黑名单命令）：malicious 命令直接拦截并通知 Owner（不经审批）；uncertain 命令直接进入安全审批；trusted 命令继续。未命中白名单的 trusted 命令**不创建审批**，直接按沙盒模式在沙盒内执行（安全防护只负责恶意与可疑判定，见 [tools 命令安全防护](../tools/bash-security.md)）。
- **白名单**是「可在宿主上执行的命令」集合；白名单命令在沙盒内外均可执行，且无需审批——执行位置由 Agent 在单次调用中指定，缺省按沙盒模式（默认模式与严格模式在沙盒内，放行模式在宿主上）。
- **其余命令和所有脚本**的执行位置由沙盒模式决定（见 [沙盒](sandbox.md#模式)）：默认模式在沙盒内执行，Agent 可请求在宿主上执行并进入审批；严格模式一律拒绝；放行模式缺省在宿主上执行，Agent 可指定在沙盒内执行。
- 命令的审批只涉及 Agent 维度：命令白名单是 Agent 维度资产，不提供用户维度放行。
- 解释器类命令（shell 等脚本解释器）以及可派生解释器的命令不得加入白名单（见 [沙盒](sandbox.md#模式)）。
- **Owner 命令执行豁免**：Owner 通过斜杠指令执行的命令类操作（`/exec`、`/git` 等）默认放行——不进入权限评估与审批，不受沙盒约束，也不受 Agent 维度的命令规则与沙盒模式（含严格模式的仅白名单限制）约束。此豁免仍受两项安全约束：被列入黑名单的命令一律拒绝；命令安全防护的恶意模式拦截仍生效（拦截并通知 Owner，不执行该命令），但可疑命令不因 Owner 身份进入审批。`/exec` 仅 Owner 可用。
- Owner 通过 bash 等工具执行命令时**不享受**命令执行豁免：仍按 Agent 维度与命令行维度评估，Owner 只跳过用户维度。

## 数据流

```
操作入口
  ├─ 权限配置文件的读写 → 硬编码拒绝（不审批、无放行路径）
  ├─ 沙盒引擎不可用且操作受沙盒约束 → 直接拒绝（终局，不降级、不审批）
  ├─ 子 Session 操作 → 拒绝时静默返回，不进入审批
  ├─ 读写命中高风险名单 → 高风险审批（仅单次放行）
  ├─ workspace 专属路径读/写 → 自动放行
  ├─ 配置写入 → 高风险审批（不进入沙盒边界）
  ├─ 工具调用 → 工具维度（基线 − 拒绝规则；spawn 由层级深度决定）
  │     ├─ 工具内部操作：文件读写 → 读/写维度；命令 → 命令行维度；配置写入 → 配置写入维度
  │     └─ 工具发起的网络请求 → 网络访问维度
  ├─ 命令类斜杠指令 → 命令行维度（Owner 命令执行豁免）
  ├─ 收发消息 → 收发消息维度（消息进入/离开 Agent 时）
  └─ 宿主上执行请求 → 命令行维度 + 网络访问合并审批
  │
  ▼
一次操作可能触发多个维度：全部允许才放行；任一维度拒绝即拒绝
  │
  ▼
拒绝 / 需审批 → 按 [审批工作流](approval-workflow.md#审批分流) 分流
```

关键分支：

- 命令执行按黑名单 → 命令安全解析 → 白名单 → 沙盒模式顺序分流（分流顺序见 [沙盒](sandbox.md#命令分流)）；malicious 直接拦截，黑名单与严格模式白名单外命令不进入审批。
- 文件访问被拒（越界或规则拒绝）→ 审批；workspace 专属路径 → 自动放行；高风险名单命中优先于 workspace 自动放行。
- 网络访问 → 随宿主上执行请求或工具网络请求一并判定。
- caller 为 Owner → 跳过用户维度规则；Owner 的命令类斜杠操作按命令执行豁免处理。

## 模块关系

> 「上游/下游」指数据流与调用关系（含经 common trait 完成的调用），不等于 crate 依赖；crate 依赖以 [STANDARDS.md 依赖方向允许边表](../STANDARDS.md) 为准。

- **上游**：tools 模块（工具调用时触发各维度检查）、Gateway（命令类斜杠指令、消息进出 Agent 时的收发消息判定）、Session（提供本轮 caller 与子 Session 继承上下文）
- **下游**：沙盒（读/写、命令行的 OS 级强制）、审批工作流（拒绝与宿主执行分流）、debug_log（维度判定与拒绝事件）
- **相关**：权限引擎（以维度为单位匹配操作类型）、[权限配置管理](permission-configuration.md)（维度规则、命令黑白名单与沙盒模式的存储和修改）
- **无关**：IM Adapter（消息解析与渲染）、LLM Provider（不参与权限判定）

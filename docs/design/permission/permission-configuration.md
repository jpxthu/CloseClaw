# 权限配置管理

## 概述

权限配置管理负责权限规则的修改、持久化、热加载、加载容错和配置文件访问保护。所有权限修改只能通过权限系统自身完成。

## 架构

### 配置文件与结构

- 每个 Agent 的权限规则独立存储在 `~/.closeclaw/agents/<agent-id>/permissions.json`，与 `config.json` 同目录；两个文件独立读写、独立热更新。
- 文件内容包括：
  - **规则集**：Agent 维度规则与 User+Agent 维度规则，定义主体、操作维度、参数（路径/命令/主机端口/工具等）与 Allow/Deny 效果。
  - **命令黑白名单**：Agent 维度资产，User 维度不覆盖；语义见 [权限维度](permission-dimensions.md#命令行)。
  - **沙盒模式**：按 Agent 维度存储，取值、默认值与模式行为见 [沙盒](sandbox.md#模式)；User 维度不能覆盖。
- **规则项结构**：每条规则包含主体（Agent / User+Agent）、操作维度、参数（路径/命令/主机端口/工具）、效果（Allow / Deny）。具体序列化格式由实现定义，CLI `rule check` 以同一语义校验。
- User+Agent 规则与 Agent 规则同文件存储，按 Agent 隔离；某个 Agent 的规则不影响其他 Agent。
- 全局默认策略为内置基线，在 Daemon 初始化阶段装配，不依赖配置文件（见 [README](README.md#规则加载策略)）：Agent 维度默认仅可收发消息，User 维度默认无任何权限。两者交集后，新建 User 实际不能交互，需 Owner 授予。
- 权限文件缺失或不可用时使用系统默认权限基线（见「加载容错」）。

### 修改入口

权限系统是权限规则的唯一写入方；外部触发有 Owner 斜杠指令、审批白名单与新用户注册三条，均不在 Agent 会话流程内直接改文件：

- **Owner 斜杠指令**：被 Gateway 硬拦截后由权限指令处理层直接执行，不进入 Agent Session。支持增删各维度的 Allow/Deny 规则、增删命令白名单与黑名单、设置 Agent 的沙盒模式。每条指令执行前验证调用方为 Owner。
- **审批白名单**：Owner 在处理审批卡片时选择「加入白名单」，触发权限系统写入规则；移出沙盒执行的「加入白名单」写入命令白名单（见 [沙盒](sandbox.md#移出沙盒执行)）。
- **新用户注册**：Owner 审批 UserCreationRequest 时确认或调整 InitialPermissionSet；审批通过后由 Gateway 权限指令处理层生成 UserRegistration，用户记录由 config 的 accounts 存储，权限系统只将 InitialPermissionSet 映射为 User+Agent 规则写入当前已注册的全部 Agent；后续新增 Agent 需另行授予。未选择预置权限集时，注册后的 User 不获得任何规则。

三条路径共用同一套校验、原子写入与热加载流程。非 Owner 的修改请求直接拒绝；Agent 不能直接修改权限配置。

### 写入与热加载

- **写入**：先校验规则语法与冲突，再写入临时文件并原子替换；校验失败或写入中断时保留原有配置，不产生部分覆盖。冲突判定：同一主体 + 同一维度 + 同一参数同时存在 Allow 与 Deny 视为冲突，拒绝写入；黑名单优先不是冲突。写入校验同时拒绝解释器/可派生解释器命令进入白名单、高风险路径进入白名单。
- **热加载**：config 的变更通知不覆盖 agents/ 下的权限文件，权限模块自行检测 `permissions.json` 的变更；变更确认后原子替换内存规则集，下一次权限评估即使用新规则，无需重启 Agent 或系统。
- **生效范围**：规则、命令黑白名单与沙盒模式均即时生效；已创建的审批请求不因规则变更失效（见 [审批工作流](approval-workflow.md#规则变更与审批)）。
- **缓存边界**：缓存与求值边界见 [README](README.md#规则加载策略)。
- **连续写入**：同一文件的连续多次写入以最后一次校验通过的规则集为准；校验失败的写入不替换当前生效规则。

### 加载容错

- **启动时缺失或损坏**：不阻塞 Agent 加载，CloseClaw 照常启动；优先保留其他可用配置，其他 Agent 的权限文件不受影响。
- **单个 Agent 无可用配置**：该 Agent 退化为系统默认权限（Agent 维度仅收发消息，User 维度无任何权限），并记录警告、通知 Owner；不自动删除或覆盖损坏文件（备份恢复时另存损坏文件）。
- **运行期首次出现且校验失败**：该 Agent 使用默认权限并通知 Owner，不阻塞 CloseClaw 启动。
- **运行期重载失败**：保留此前已生效的规则继续运行，不恢复默认权限；记录警告并通知 Owner。此后再修改并校验通过，可恢复正常。
- **运行期文件被删除**：保留此前已生效的规则继续运行并通知 Owner；下次成功写入后恢复使用文件内容。
- **原子写入**：写入失败不会产生损坏文件，因此不会因写入中断触发加载降级。

### 备份与恢复

- 权限配置文件由权限模块自行维护有限份数的近期备份，备份位于 `~/.closeclaw/agents/<agent-id>/.backups/`，受权限配置目录保护；config 模块的 BackupManager 不覆盖 agents 下的权限文件。
- 启动时文件损坏，先把损坏文件另存为 `.corrupt.<时间戳>`，再用最新可用备份恢复；恢复成功后照常启动并通知 Owner。
- 无可用备份且文件不可加载时，该 Agent 使用系统默认权限基线并通知 Owner。
- 运行期重载失败不回退备份，保留此前已生效规则（见上节）。

### 配置保护

以下保护为硬编码规则，不可被任何配置覆写：

- **权限配置文件读写**：仅 Owner 可直接写入；Agent 对权限配置文件的读取默认拒绝，属高风险操作，仅经 Owner 单次放行允许本次读取，不能加入白名单；Agent 的写入一律拒绝。该保护不因白名单机制或 workspace 强制授权放宽。
- **权限配置目录**：`~/.closeclaw/agents/` 整棵树对 Agent 默认禁止访问（含所有 Agent 的 config.json / permissions.json）；该目录不在 workspace 路径下，即使显式工作目录指向该目录，硬编码保护优先。当前 Agent 的 permissions.json 读取可经 Owner 单次放行例外，写入不例外。
- **系统设计约束**：Owner 无法禁用自身身份校验；系统不提供「绕过权限系统」的选项。
- **最小信息原则**：Agent 被拒绝时只收到操作被拒绝的结果，不暴露规则名称、优先级或配置路径等内部信息。

### 新建 User

- 非 Owner 用户创建需 Owner 审批；审批时 Owner 可显式选择该用户的初始权限集合（如 BasicMessaging），也可不授予任何规则。预置集是显式授予，不是默认权限。
- 未选择初始权限集时，新建 User 无任何权限，包括不能与任何 Agent 通信；创建后 Owner 需另行授予权限，用户才能开始交互。
- 同一用户已有等待中的注册请求时，新请求直接拒绝。

### 只读查询

- CLI Admin 的 `rule check` / `rule list` 只读查看权限规则：`check` 校验单条规则语法，`list` 默认列出全部 Agent 的规则、可按 Agent 过滤（规则来源、维度与存储见本文件）。
- 只读查询不修改规则，不触发热加载；权限规则的修改只能走斜杠指令、审批白名单或新用户注册。

### Workspace 路径安全

- 路径中的 Agent ID 和 User ID 必须通过路径穿越校验：拒绝含 `../` 或绝对路径前缀等危险模式，防止用特殊字符绕过 workspace 隔离。
- 并行启动时 workspace 目录创建幂等，无竞态问题。
- workspace 强制授权仅覆盖专属路径 `{数据根目录}/workspaces/{agent_id}/{user_id}/`；`/cd` 或 spawn 工作目录参数指向其他路径时不获得强制授权（见 [README](README.md#交集模型) 与 [沙盒](sandbox.md#边界来源)）。

## 数据流

```
权限修改触发
  │
  ├─ Owner 斜杠指令
  │     │
  │     ▼
  │   Gateway 硬拦截 → 验证调用方 = Owner
  │     │
  │     ▼
  │   校验规则 → 原子写入 permissions.json → 热加载 → 下一次评估生效
  │
  ├─ 审批白名单
  │     │
  │     ▼
  │   Owner 审批卡片选择「加入白名单」
  │     │
  │     ▼
  │   校验规则 → 原子写入 → 热加载
  │
  └─ 新用户注册审批
        │
        ▼
      Owner 审批 UserCreationRequest
        │
        ▼
      Gateway 生成 UserRegistration → 权限系统映射 InitialPermissionSet 为规则 → 原子写入 → 热加载

CLI Admin rule check/list → 只读读取规则文件，不写入
```

关键分支：

- 调用方非 Owner → 拒绝。
- 规则校验失败 / 写入失败 → 保留原有配置，返回错误。
- 运行期重载解析失败 → 保留此前生效规则并通知 Owner。
- 启动时无可用配置 → 该 Agent 使用默认权限并通知 Owner。

## 模块关系

- **上游**：Gateway（斜杠指令拦截后传入、审批白名单与用户注册审批结果）、审批工作流（白名单决策）
- **下游**：权限引擎（规则集与热加载通知）、沙盒（沙盒模式与命令黑白名单）、CLI Admin（`rule check/list` 只读读取规则文件）、文件系统（规则持久化）、debug_log（规则变更与加载告警）
- **相关**：config（配置文件目录布局与热重载边界）、agent 配置（`permissions.json` 的存储位置）、[审批工作流](approval-workflow.md)（白名单与新用户注册审批）
- **无关**：Agent Session（权限修改不进入 Session 上下文）、IM Adapter（不读取或修改权限规则）

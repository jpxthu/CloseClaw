# 权限配置管理

## 概述

权限配置管理负责权限规则的修改、持久化、热加载、加载容错和配置文件访问保护。规则的写入只经三条路径：Owner 权限指令、审批时加入白名单、新用户注册；此外 Owner 可直接编辑权限配置文件（属配置层操作，不是产品交互路径），审批等待时长只能以此方式修改。权限配置文件对 Agent 一律不可读写。

## 架构

### 配置文件与结构

- 权限配置分两类文件，各自独立读写、独立热更新：
  - **全局权限配置文件** `{配置目录}/permissions.json`：用户维度规则 + 审批等待时长。
  - **Agent 权限配置文件** `{配置目录}/agents/<agent-id>/permissions.json`：Agent 维度规则、命令黑白名单、沙盒模式。
  - 配置目录的操作系统位置见 [platform](../platform/README.md)。
- **文件结构**（两类文件同构，顶层为对象）：
  - `rules`：规则项数组，每个规则项由**规则要素**四项构成——主体（Agent 或 User）、作用维度、生效对象、决策结果（允许 / 拒绝）。字段名与枚举取值由实现定型，维度枚举与 [权限维度](permission-dimensions.md) 的七类一致。
  - `sandbox_mode`（仅 Agent 文件）：沙盒模式，取值与行为见 [沙盒](sandbox.md#模式)。
  - `approval_wait_seconds`（仅全局文件）：审批等待时长，见下。
  - 命令黑白名单不单独存储：命令行的允许规则即该 Agent 命令白名单的条目、拒绝规则即黑名单的条目。
- **各维度的生效对象形态**：读、写为文件系统路径；命令行与工具调用为命令名 / 工具名；网络访问为主机与端口；收发消息与配置写入不细分对象。
- **规则主体限制**：命令行与工具调用两个维度只能以 Agent 为规则主体——命令执行与工具范围不作为用户维度的权限项；其余维度可用 Agent 或 User 主体。用户维度规则对其生效的全部 Agent 一致生效（见 [README](README.md#决策顺序与交集)）。
- **同一对象的允许与拒绝并存**：允许同一主体 + 同一维度 + 同一对象同时存在允许与拒绝规则，求值时**拒绝优先**（全部维度一致，命令黑名单优先是同一规则的实例）；重复写入同效果规则时拒绝。
- **全局默认基线**为内置策略，在 Daemon 初始化阶段装配，不依赖配置文件（清单见 [README](README.md#默认基线)）。
- **审批等待时长**：存于全局权限配置文件的 `approval_wait_seconds`，不按 Agent 存储；不提供权限指令修改，Owner 编辑后随热加载生效，对修改后发出的下一个审批请求生效（需求 [permission §F5](../../requirements/permission.md)）。该项缺失或不可解析时按默认 5 分钟回退，不阻塞启动。
- **沙盒模式**属 Agent 权限基线中的配置项，不属于规则的四要素模型（需求 [permission §F12](../../requirements/permission.md)）。
- 权限文件缺失或不可用时按「加载容错」处理。

### 修改入口

权限规则的写入只有三条路径，均不在 Agent 会话流程内执行：

- **Owner 权限指令**（[slash §F16](../../requirements/slash.md)）：被 Gateway 硬拦截后由权限指令处理层直接执行，不进入 Agent Session。指令面为 `list`（列出规则并按序编号）、`allow` / `deny`（新增允许 / 拒绝规则）、`remove`（按编号删除规则）、`sandbox`（设置当前会话目标 Agent 的沙盒模式）。每条指令执行前验证调用方为 Owner。
- **审批加入白名单**：Owner 在处理审批请求时选择「加入白名单」，触发权限系统写入规则；宿主上执行的「加入白名单」写入命令白名单（见 [沙盒](sandbox.md#宿主上执行)）。
- **新用户注册**：Owner 批准 UserCreationRequest 后由 Gateway 权限指令处理层生成 UserRegistration，用户记录由 config 的账户绑定存储；权限系统不为其写入任何规则（新建 User 零权限），后续由 Owner 通过权限指令授予。

三条路径共用同一套校验、原子写入与热加载流程；非 Owner 的修改请求直接拒绝，Agent 不能直接修改权限配置。

**编号与作用域**：`list` 与 CLI `rule list` 的编号覆盖当前读取范围内的全部规则——全局文件的用户维度规则与目标 Agent 文件的 Agent 维度规则连续编排，输出标注每条规则的来源文件；`remove` 按该编号定位并写回其来源文件。

### 写入与热加载

- **写入方式**：按段合并——系统写入规则时只替换对应文件的 `rules` 段（以及受影响的 `sandbox_mode`），保留其它字段（如 Owner 手工维护的 `approval_wait_seconds`）；写入前先校验，再写入临时文件并原子替换，校验失败或写入中断时保留原文件，不产生部分覆盖。
- **写入期校验**：拒绝语法不完整或四要素缺失的规则；拒绝解释器类（及可派生解释器的）命令进入白名单；拒绝高风险路径（如 `.git` 目录）进入白名单；拒绝命令行与工具调用维度以 User 为规则主体。
- **热加载**：权限模块自行检测全局权限配置文件与 `agents/` 下权限文件的变更（Agent 级文件在首次加载后纳入监听，未被使用过的 Agent 保持惰性加载）；config 对 `agents/` 的变更通知不参与规则替换，权限模块以自身检测为准。变更确认后先做校验（同写入期校验），通过则原子替换内存规则集，下一次权限评估即使用新规则，无需重启 Agent 或系统；校验失败保留旧规则并通知 Owner。
- **生效范围**：规则、命令黑白名单、沙盒模式与审批等待时长均即时生效；已创建的审批请求不因规则变更失效（见 [审批工作流](approval-workflow.md#规则变更与审批)）。
- **缓存边界**：缓存与求值边界见 [README](README.md#规则加载策略)。
- **连续写入**：同一文件的连续多次写入以最后一次校验通过的规则集为准；校验失败的写入不替换当前生效规则。

### 加载容错

- **启动时缺失或损坏**：不阻塞 Agent 加载，CloseClaw 照常启动；保留其它可用的权限配置。
- **全局文件缺失或损坏**：用户维度规则按拒绝处理（用户维度无基线，不放大权限），审批等待时长回退默认值；记录警告并通知 Owner。
- **单个 Agent 无可用配置文件或文件损坏且无可用备份**：该 Agent 按系统默认权限基线运行（见 [README](README.md#默认基线)），记录警告、通知 Owner，不自动删除或覆盖损坏文件；退化后不再享有初始 Agent 的例外。
- **初始 Agent 的文件缺失**：权限模块按初始 Agent 基线补写一次（见 [README](README.md#默认基线)）。
- **运行期首次出现且校验失败**：该 Agent 按默认权限基线运行并通知 Owner，不阻塞运行。权限配置文件的容错由本模块自管，不适用 config §F4 对「运行期新增配置文件」的阻塞语义。
- **运行期重载失败**：保留此前已生效的规则继续运行，不恢复默认权限；记录警告并通知 Owner。此后再修改并校验通过，可恢复正常。
- **运行期文件被删除**：保留此前已生效的规则继续运行并通知 Owner；下次成功写入后恢复使用文件内容。
- **原子写入**：写入失败不会产生损坏文件，因此不会因写入中断触发加载降级。

### 备份与恢复

- 权限配置文件由权限模块自行维护有限份数的近期备份：全局文件的备份位于 `{配置目录}/.backups/`，各 Agent 文件的备份位于 `{配置目录}/agents/<agent-id>/.backups/`；备份与回退规则与 config 的滚动备份机制一致（需求 [config §F3](../../requirements/config.md)），config 模块的备份管理不覆盖权限文件。
- 启动时文件损坏，先把损坏文件另存为 `.corrupt.<时间戳>`，再用最新可用备份恢复；恢复成功后照常启动并通知 Owner。
- 无可用备份且文件不可加载时按「加载容错」处理（Agent 走默认基线 / 全局规则按拒绝）；运行期重载失败不回退备份。

### 配置保护

以下保护为硬编码规则，不可被任何配置覆写：

- **权限配置文件**：任何 Agent 对任何 Agent（含自身与初始 Agent）的权限配置文件一律不可读写——读取与写入都直接拒绝，不进入审批、不存在放行路径；该保护不因规则、白名单机制或 workspace 强制授权放宽（需求 [permission §F4](../../requirements/permission.md)）。保护范围为全部权限配置文件及其备份目录。Owner 通过权限指令与审批加入白名单修改配置，不经文件写入。
- **其它系统配置文件**：Agent 配置、渠道与账户绑定、Gateway 参数等按配置写入维度评估（高风险，只能单次放行），不在本节的硬编码保护内；读取按读维度规则评估。
- **系统设计约束**：Owner 无法禁用自身身份校验；系统不提供「绕过权限系统」的选项。
- **最小信息原则**：Agent 被拒绝时只收到操作被拒绝的结果，不暴露规则名称、优先级或配置路径等内部信息。

### 新建 User

- 非 Owner 用户创建需 Owner 审批（批准 / 拒绝）；批准后的 User 无任何权限，需 Owner 另行授予。
- 新建 User 无任何权限（含不能与任何 Agent 通信）；Owner 授予后用户才能开始交互。
- 同一用户已有等待中的注册请求时，新请求直接拒绝。

### 只读查询

- CLI 的 `rule check` / `rule list` 只读查看权限规则（需求 [cli §F7](../../requirements/cli.md)）：`check` 校验权限规则文件能否正确解析，再逐条校验四要素完整性，输出规则位置与失败原因（默认覆盖全局文件与全部 Agent 文件，也可只校验指定文件）；`list` 列出规则（含四项要素与来源文件），可按 Agent 过滤。
- 只读查询不修改规则，不触发热加载；权限规则的修改只能走权限指令、审批加入白名单或新用户注册。

### 路径安全

- Agent ID 与 User ID 参与拼接的**全部路径**（专属 workspace、Agent 权限配置文件、备份目录）都必须通过路径穿越校验：拒绝含 `../` 或绝对路径前缀等危险模式，防止用特殊字符越权到目录树之外。
- 任意时点的并发创建（启动装配与运行期 spawn 均可能触发同一 workspace 路径）均幂等：目录已存在则直接复用，不产生失败或相互干扰。
- workspace 强制授权仅覆盖专属路径（路径格式与自动放行规则见 [README](README.md#决策顺序与交集)）；其他路径不因该授权被纳入可读写范围（见 [沙盒](sandbox.md#边界来源)）。

## 数据流

```
权限修改触发
  │
  ├─ Owner 权限指令（allow / deny / remove / sandbox）
  │     │
  │     ▼
  │   Gateway 硬拦截 → 验证调用方 = Owner → 按编号/参数定位来源文件
  │     │
  │     ▼
  │   校验规则 → 按段合并写入（原子替换）→ 热加载 → 下一次评估生效
  │
  ├─ Owner 只读指令（list）/ CLI rule check·list → 只读返回，不写入、不热加载
  │
  ├─ 审批加入白名单（含宿主上执行的「加入白名单」→ 命令白名单）
  │     │
  │     ▼
  │   校验规则 → 按段合并写入 → 热加载
  │
  ├─ Owner 编辑配置文件（审批等待时长或规则）→ 权限模块自检变更 → 校验 → 热加载（失败保留旧配置）
  │
  └─ 新用户注册确认
        │
        ▼
      Owner 批准 UserCreationRequest → Gateway 生成 UserRegistration
        │
        ▼
      用户记录由 config 落盘；权限系统不为其写入规则（零权限）→ 无权限配置变更

CLI rule check / list → 只读读取规则文件，不写入
```

关键分支：

- 调用方非 Owner → 拒绝。
- 规则校验失败 / 写入失败 → 保留原有配置，返回错误（审批路径下本次审批请求以拒绝结束）。
- 运行期重载解析失败 → 保留此前生效规则并通知 Owner。
- 启动时某 Agent 无可用配置 → 该 Agent 使用默认权限基线并通知 Owner；全局规则不可用 → 用户维度按拒绝、等待时长回退默认。
- Agent 访问权限配置文件或备份目录 → 直接拒绝，不进入审批。

## 模块关系

> 「上游/下游」指数据流与调用关系（含经 common trait 完成的调用），不等于 crate 依赖；crate 依赖以 [STANDARDS.md 依赖方向允许边表](../STANDARDS.md) 为准。

- **上游**：Gateway（权限指令拦截后传入、审批白名单与用户注册确认结果）、审批工作流（白名单决策）
- **下游**：权限引擎（规则集与热加载通知）、沙盒（沙盒模式与命令黑白名单）、CLI（`rule check/list` 只读读取规则文件）、config（新用户注册的用户记录与账户绑定落盘）、文件系统（规则持久化）、debug_log（规则变更与加载告警）
- **共享类型 / 核心 trait**：UserRegistration / UserCreationRequest（注册落盘与规则映射载荷，定义见 [common/shared-types](../common/shared-types.md#userregistration--usercreationrequest)）
- **相关**：config（配置目录布局与热重载边界）、agent 配置（`permissions.json` 的存储位置）、platform（系统标准配置目录）、[审批工作流](approval-workflow.md)（白名单与新用户注册审批）
- **无关**：Agent Session（权限修改不进入 Session 上下文）、IM Adapter（不读取或修改权限规则）

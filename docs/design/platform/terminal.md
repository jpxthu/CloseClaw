# 终端能力检测

## 概述

终端能力检测接口检测用户终端的 ANSI 能力标记与终端可用宽度，供 CLI 决定渲染模式与宽度截断策略（见 [requirements/platform.md §F3](../../requirements/platform.md)，消费侧规则见 [requirements/cli.md §F2](../../requirements/cli.md)）。Linux、macOS 与 Windows（经 WSL2）的接口语义一致，原生 Windows 不支持。

## 架构

接口在调用方进程内采集并返回 ANSI 能力标记与终端可用宽度两项平台原语，检测对象为调用方进程的标准输出与其终端；在无终端进程中调用（如 daemon）时，标准输出不是终端，结果为不支持 ANSI、宽度不可得：

- **ANSI 能力标记**：`TERM` 未设置、为空或为 `dumb` → 不支持；其余值 → 支持。标准输出不是终端（重定向到管道或文件）时同样按不支持处理，避免转义序列落入日志。该判定为启发式：以 `TERM` 声明为准，无法识别的终端按支持处理，明确不支持 ANSI 的终端可用 `TERM=dumb` 声明。不支持时由终端渲染器降级为纯文本渲染。
- **终端可用宽度**：通过操作系统终端尺寸接口获取当前可用列数。标准输出不是终端、获取失败或返回无效值（0 或负值）时，宽度标记为「不可得」；接口不提供默认宽度，由上层按宽度不可得处理（终端渲染的超宽截断与分割线取值见 [requirements/cli.md §F2](../../requirements/cli.md)）。
- **调用时机**：由 CLI 渲染侧在每次渲染会话开始前调用一次，同一渲染会话内复用该结果。渲染会话指一次回复的渲染过程：批式渲染指一次回复的整次渲染，流式渲染指整个流式回复的增量渲染过程；窗口宽度变化在下次渲染会话生效。接口不缓存，渲染侧自行保存本次渲染会话的结果。

## 数据流

1. 每次渲染会话开始前，CLI 渲染侧在用户终端所在进程中调用终端能力检测接口
2. 接口先判定标准输出是否为终端：不是终端（如重定向到管道或文件、在无终端进程中调用）→ ANSI 不支持
3. 标准输出是终端时读取 `TERM` 并按匹配规则判定 ANSI 能力
4. 同一次调用内采集可用宽度：查询终端尺寸；标准输出不是终端、查询失败或无效值时标记「不可得」，不填充默认宽度
5. 返回 ANSI 能力标记与可用宽度（列数或「不可得」）两项结果
6. 渲染侧将两项结果作为渲染入参，决定渲染模式与宽度截断策略（宽度不可得时不做宽度截断）

## 模块关系

- **上游**：CLI Chat（调用本接口，将两项结果交给终端渲染器决定渲染模式与宽度截断策略）、CLI Admin（命令输出的超宽行按同一截断规则处理，见 [requirements/cli.md §F9](../../requirements/cli.md)）
- **下游**：操作系统环境变量与终端尺寸 API（本接口调用）
- **无关**：IM Adapter——不调用本接口，也不消费检测结果；Gateway 经 terminal 渠道插件调度间接涉及，不直接调用本接口
- **与模块内其他子功能**：与进程生命周期管理、配置目录、文件路径处理、临时目录并列，互不依赖

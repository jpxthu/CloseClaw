# 进程生命周期管理

## 概述

进程生命周期管理是 Platform 的进程抽象接口，封装 daemon 进程的 PID 自注册、存活检测、终止请求、PID 文件清理与关闭信号订阅，使上层在不同操作系统上获得一致的进程实例管理行为。

## 架构

**PID 自注册**：daemon 进程启动时，在配置目录就绪后、组件初始化之前，把自身 PID 写入配置目录下的固定文件 `daemon.pid`（覆盖可能残留的旧文件），作为进程实例登记的权威记录。写入为单次小文件操作，不引入等待或重试，不构成启动瓶颈。系统约定 daemon 仅经 CLI Admin 的 run 启动；正常启动路径由 CLI Admin 先清理残留，覆盖仅作防御。

**存活检测**：接口读取 PID 文件并查询操作系统进程状态。进程存在 → 报告实例存活；进程不存在 → 报告无实例，并清除残留的 PID 文件。CLI Admin 在启动 daemon 前经本接口执行存活检测，拒绝重复启动。

**终止**：上层请求终止时，接口向目标进程发送 SIGTERM 请求退出，而非强制杀死；随后以操作系统进程状态确认目标进程已不存在，退出后调用 PID 清理。等待期间不设平台侧超时，关闭进度由 daemon 关闭流程向 Owner 展示。PID 文件不存在或对应进程已不存在时，按「无实例」正常返回，不报错。终止方完成退出确认与进程回收，不遗留僵尸进程或 PID 文件残留。

**PID 清理**：删除 PID 文件；文件不存在视为成功，重复调用幂等。供终止路径与 daemon 关闭完成阶段调用。

**关闭信号接收**：接口仅负责订阅并分发 SIGTERM / SIGINT 至 daemon 关闭流程，不参与关闭模式判定。首次信号触发优雅关闭、关闭进行中的后续信号与强制关闭升级，均由 [daemon 关闭流程](../daemon/shutdown.md) 决定；daemon 在关闭完成阶段调用本接口的 PID 清理。信号语义在 Linux、macOS 与 Windows（经 WSL2）下一致，原生 Windows 不做适配。

## 数据流

启动路径（跨进程 + 进程内自调用）：

1. CLI Admin 调用存活检测；发现残留 PID 文件则由接口清除，无实例则继续
2. CLI Admin 派生 daemon 进程
3. daemon 先确保配置目录存在，再调用接口写入自身 PID
4. 写入失败时返回错误，daemon 启动失败

终止路径（请求-响应）：

1. 上层调用终止接口
2. PID 文件不存在或对应进程已不存在 → 按「无实例」成功返回
3. 否则发送 SIGTERM → 等待目标进程退出（以操作系统进程状态确认，不设平台侧超时）→ 调用 PID 清理
4. 返回执行结果

关闭信号路径（被动触发，不属请求-响应）：

1. 操作系统向运行中的 daemon 送达 SIGTERM / SIGINT
2. 接口分发信号至订阅的 daemon 关闭流程
3. daemon 判定 graceful / forceful 并完成关闭，最后调用 PID 清理（详见 [daemon 关闭流程](../daemon/shutdown.md)）

## 模块关系

- **上游**：CLI Admin（经本接口做启动前存活检测、经本接口请求终止 daemon）、Daemon（启动时先确保配置目录存在，再经本接口自注册 PID；经本接口订阅关闭信号；关闭完成阶段经本接口清理 PID）
- **下游**：操作系统进程与信号 API、文件系统 API（本接口调用）
- **无关**：CLI Chat、Gateway、IM Adapter（不涉及 daemon 进程实例管理）
- **与模块内其他子功能**：与配置目录、终端能力检测、文件路径处理、临时目录并列，均为独立的 OS 能力抽象。PID 文件位于配置目录下的固定位置，沿用配置目录的 `.closeclaw` 布局与同一 `~` 解析规则，但本接口不调用配置目录接口；PID 文件路径不依赖文件路径处理接口。

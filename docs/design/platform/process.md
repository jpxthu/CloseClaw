# 进程生命周期管理

## 概述

进程生命周期管理是 Platform 的进程抽象接口，封装 CloseClaw 主进程（daemon）的启动、终止、存活检测与关闭信号接收，使上层在不同操作系统上获得一致的进程行为。

## 架构

**启动（PID 自注册）**：daemon 进程启动时把自身实例写入平台统一固定路径下的 PID 文件，作为进程实例追踪的唯一事实源。

**终止**：上层请求终止时，接口通过操作系统标准信号（SIGTERM / SIGINT）请求目标进程退出，而非强制杀死；随后等待进程退出确认，退出后清理 PID 文件，不产生僵尸进程或 PID 文件残留。

**存活检测**：接口按 PID 文件判断对应进程实例是否存活，供上层识别异常残留（PID 文件存在但进程已不存在）。

**关闭信号接收**：接口向 daemon 关闭流程提供关闭信号（SIGTERM / SIGINT）订阅能力，触发优雅关闭。信号语义在 Linux、macOS 与 Windows（WSL2）下一致。

## 数据流

请求-响应路径：

1. 调用方调用进程管理接口，指定操作（启动 / 终止 / 存活检测）
2. 按操作分派：
   - 启动（PID 自注册）：daemon 启动时写入自身 PID 至 PID 文件
   - 终止：发送终止信号 → 等待进程退出确认 → 清理 PID 文件
   - 存活检测：读取 PID 文件并判断对应进程状态（进程不存在 → 报告无实例）
3. 返回执行结果

关闭信号路径（被动触发，不属请求-响应）：

1. 操作系统向运行中的 daemon 送达 SIGTERM / SIGINT
2. 接口分发信号至订阅的 daemon 关闭流程
3. daemon 关闭流程进入优雅关闭（详见 [daemon 关闭流程](../daemon/shutdown.md)）

## 模块关系

- **上游**：CLI Admin（run 拉起 daemon 进程并在启动前做存活检测、stop 终止 daemon 进程）、Daemon（启动时经本接口自注册 PID、经本接口订阅关闭信号）
- **下游**：操作系统进程与信号 API
- **与模块内其他子功能**：与配置目录、终端能力检测、文件路径处理并列，均为独立的 OS 能力抽象；PID 文件路径为平台硬编码的固定常量，不依赖文件路径处理接口

# 进程生命周期管理

## 概述

进程生命周期管理是 Platform 的进程抽象接口，封装 daemon 进程的 PID 自注册、存活检测、终止请求、PID 文件清理与关闭信号订阅，使上层在不同操作系统上获得一致的进程实例管理行为（对应需求 [platform §F1](../../requirements/platform.md)）。daemon 进程的派生由 CLI Admin 承担，不在本接口范围。

## 架构

**PID 自注册**：daemon 进程启动时，在配置目录就绪后、组件初始化之前，把自身 PID 写入配置目录下的固定文件 `daemon.pid`（路径固定为配置根目录下的该文件，不受启动参数覆盖），作为进程实例登记的权威记录。写入为单次小文件操作、以原子替换完成（读取方不会读到半写入内容），并持续持有该文件的独占锁；已有实例持锁时注册失败，daemon 启动失败，不覆盖现有记录。写入不引入等待或重试，不构成启动瓶颈。系统约定 daemon 仅经 CLI Admin 的 run 启动；该启动路径由存活检测清除残留文件，残留文件在注册时被替换。

**存活检测**：接口读取 PID 文件并查询操作系统进程状态。进程存在 → 报告实例存活；进程不存在 → 报告无实例，并清除残留的 PID 文件。CLI Admin 在启动 daemon 前经本接口执行存活检测，拒绝重复启动。

**终止**：上层请求终止时，接口向目标进程发送 SIGTERM 请求退出，而非强制杀死。PID 文件不存在或对应进程已不存在时，按「无实例」正常返回并清除残留的 PID 文件，不报错。发出信号后由终止方以操作系统进程状态确认目标进程已不存在，等待期间不设平台侧超时，关闭进度展示与再次发送信号的时机由终止方安排。关闭完成后的 PID 清理由 daemon 关闭完成阶段执行；终止方在确认退出后调用清理作为幂等兜底。终止方只负责退出确认，不承担父进程的进程回收职责（daemon 由 run 派生后由 init 收养），不遗留 PID 文件残留。

**PID 清理**：删除 PID 文件；文件不存在视为成功，重复调用幂等。供 daemon 关闭完成阶段与终止路径调用（后者为幂等兜底）。

**关闭信号接收**：接口负责订阅并向 daemon 关闭流程分发 SIGTERM / SIGINT，订阅在整个关闭窗口内持续有效——优雅关闭进行中收到的后续信号同样投递，供其判定强制关闭升级；接口不参与关闭模式判定。首次信号触发优雅关闭、关闭进行中的后续信号与强制关闭升级，均由 [daemon 关闭流程](../daemon/shutdown.md) 决定。订阅在 PID 自注册之前建立，避免启动窗口内的信号绕过关闭流程而留下 PID 残留。daemon 在关闭完成阶段调用本接口的 PID 清理。信号语义在 Linux、macOS 与 Windows（经 WSL2）下一致，不做原生 Windows 适配。

## 数据流

启动路径（跨进程 + 进程内自调用）：

1. CLI Admin 调用存活检测：检测到存活实例 → 拒绝启动；发现残留 PID 文件则由接口清除；无实例则继续
2. CLI Admin 派生 daemon 进程
3. daemon 先确保配置目录存在，再调用接口写入自身 PID（原子替换、独占注册；已有实例持有时注册失败）
4. 写入失败时返回错误，daemon 启动失败

终止路径（请求-响应）：

1. 上层调用终止接口
2. PID 文件不存在或对应进程已不存在 → 按「无实例」成功返回，并清除残留的 PID 文件
3. 否则发送 SIGTERM → 等待目标进程退出（以操作系统进程状态确认，不设平台侧超时）→ 调用 PID 清理（幂等兜底）
4. 返回执行结果

关闭信号路径（被动触发，不属请求-响应）：

1. 操作系统向运行中的 daemon 送达 SIGTERM / SIGINT
2. 接口分发信号至订阅的 daemon 关闭流程
3. daemon 判定优雅 / 强制关闭并完成关闭，最后调用 PID 清理（详见 [daemon 关闭流程](../daemon/shutdown.md)）

## 模块关系

- **上游**：CLI Admin（经本接口做启动前存活检测、经本接口请求终止 daemon）、Daemon（启动时先确保配置目录存在，再经本接口自注册 PID；经本接口订阅关闭信号；关闭完成阶段经本接口清理 PID）
- **下游**：操作系统进程与信号 API、文件系统 API（本接口调用）
- **无关**：CLI Chat、Gateway、IM Adapter（不涉及 daemon 进程实例管理）；config 模块不调用本接口，仅其管理的配置根目录承载 PID 文件（见 [配置目录](config-directory.md)）
- **与模块内其他子功能**：与配置目录、终端能力检测、文件路径处理、临时目录并列，均为独立的 OS 能力抽象。PID 文件位于配置目录下的固定位置，沿用配置目录的 `.closeclaw` 布局与同一 `~` 解析规则，但本接口不调用配置目录接口；PID 文件路径不依赖文件路径处理接口。

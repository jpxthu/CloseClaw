# 进程生命周期管理

## 概述

进程生命周期管理是 Platform 的进程抽象接口，封装 daemon 进程的 PID 自注册、存活检测、终止请求、PID 文件清理与关闭信号订阅，使上层在不同操作系统上获得一致的进程实例管理行为（对应需求 [platform §F1](../../requirements/platform.md)）。daemon 进程的派生由 CLI Admin 承担，不在本接口范围；「拒绝重复启动」与「关闭期间强制关闭升级」的消费侧要求见 [requirements/cli.md §F3](../../requirements/cli.md)，关闭模式判定与关闭进度通道见 [daemon 关闭流程](../daemon/shutdown.md)。

## 架构

- **实例锁与 PID 文件**：实例唯一性与存活判定以**实例锁**为准——daemon 在完整生命周期内持有配置根目录下 `daemon.lock` 的独占锁；`daemon.pid` 只承载实例 PID 记录，以原子替换方式写入（读取方不会读到半写入内容）。写入不绑定锁，替换 PID 文件不影响实例锁的持有判定。
- **PID 自注册**：daemon 进程启动时，在关闭信号订阅建立后、组件初始化之前完成注册：先以非阻塞方式取得实例锁——已被持有则注册失败、daemon 启动失败且不覆盖现有记录；取得成功则以 [配置目录](config-directory.md) 接口的「确保存在」语义取得配置根目录，并把自身 PID 原子写入根目录下的 `daemon.pid`（路径固定于配置根目录，不随启动参数变化）。写入为单次小文件操作，不引入等待或重试，不构成启动瓶颈。
- **存活检测**：接口以非阻塞方式尝试取得实例锁——取得成功则无实例存活（随即释放锁），存在残留 `daemon.pid` 时清除该文件后报告无实例；取得失败则报告实例存活，并从 PID 文件读取其 PID（文件缺失或内容无法读取时报存活、PID 视为无法读取）。检测不创建配置根目录：以配置目录接口的「仅解析」语义取根目录，除清除残留 PID 文件外不写任何文件；根目录不存在时直接报告无实例。CLI Admin 在启动 daemon 前经本接口执行存活检测，拒绝重复启动（见 [requirements/cli.md §F3](../../requirements/cli.md)）。
- **终止**：分投递与等待两类能力，由终止方组合使用：
  - 投递终止信号：以配置目录接口的「仅解析」语义取根目录，根目录不存在时按「无实例」成功返回（不创建目录）；根目录存在则以实例锁校验目标实例——锁未被持有则按「无实例」成功返回并清除残留 PID 文件；锁被持有且 PID 可读取才向该 PID 发送 SIGTERM，随即返回，不阻塞等待；PID 无法读取时不发送信号，也不调用 PID 文件清理。主目录无法解析等其它失败按错误返回。
  - 再次投递：关闭进行中，终止方可在等待期间再次投递关闭信号（如 CLI 收到 Ctrl+C 后转发给 daemon），语义与首次投递相同，供 daemon 判定强制关闭升级（见 [requirements/daemon.md §F3](../../requirements/daemon.md)）。
  - 等待退出：以操作系统进程状态等待目标进程退出，不设平台侧超时，等待期间可穿插再次投递。关闭进度展示与「继续等待 / 强制关闭」的选择由终止方按 [daemon 关闭流程](../daemon/shutdown.md) 暴露的通道安排。终止方只做退出确认，不承担父进程的进程回收职责——daemon 的派生与进程组归属由 CLI Admin 负责，派生后由 init 收养，不产生僵尸进程。
- **PID 文件清理**：删除 `daemon.pid`；文件不存在视为成功，重复调用幂等。仅当文件内容仍等于调用方记录的 PID 时才删除，避免误删后续实例的登记。供 daemon 关闭完成阶段调用；终止方在确认目标退出后调用一次作为兜底。
- **关闭信号订阅**：接口订阅 SIGTERM / SIGINT / SIGHUP 并向 daemon 关闭流程分发——SIGHUP（终端断开）按优雅关闭处理，避免绕过关闭流程而留下 PID 残留。订阅在运行期与整个关闭窗口内持续有效：首次信号触发优雅关闭，关闭进行中收到的后续信号同样投递，供其判定强制关闭升级；接口不参与关闭模式判定（见 [daemon 关闭流程](../daemon/shutdown.md)）。订阅在 PID 自注册之前建立，订阅后若关闭流程尚未就绪，信号先入队、就绪后按序投递，不丢弃；若注册完成前收到首个关闭信号，daemon 完成注册后立即进入关闭流程、不执行组件初始化，保证关闭流程的 PID 文件清理路径成立。信号语义在 Linux、macOS 与 Windows（经 WSL2）下一致，不做原生 Windows 适配。

## 数据流

启动路径（跨进程 + 进程内自调用）：

1. CLI Admin 调用存活检测：报告实例存活 → 拒绝启动；无实例 → 残留 PID 文件由接口清除后继续（不创建配置根目录）
2. CLI Admin 派生 daemon 进程
3. daemon 建立关闭信号订阅（关闭流程未就绪时信号先入队）
4. daemon 调用本接口注册：取得实例锁 → 失败则 daemon 启动失败；成功则经配置目录接口的「确保存在」语义取得配置根目录并原子写入 PID
5. 注册失败时返回错误、daemon 启动失败；成功后进入组件初始化（注册前已收到关闭信号时直接进入关闭流程）

终止路径（请求-响应，投递与等待分离）：

1. 终止方投递终止信号（以「仅解析」语义取配置根目录）
2. 根目录不存在 → 按「无实例」成功返回，不创建目录
3. 实例锁未被持有（无实例或残留）→ 清除残留 PID 文件，按成功返回
4. 锁被持有且 PID 可读取 → 发送 SIGTERM 并立即返回；PID 无法读取时不发送信号、不做清理
5. 终止方等待退出；等待期间可再次投递关闭信号，用于强制关闭升级
6. 确认退出后调用 PID 文件清理（幂等兜底，仅内容仍为原 PID 时删除）

主目录无法解析等失败按错误返回，不视为「无实例」。

关闭信号路径（被动触发，不属请求-响应）：

1. 操作系统向运行中的 daemon 送达 SIGTERM / SIGINT / SIGHUP
2. 接口分发至订阅的 daemon 关闭流程（关闭流程未就绪时先入队）
3. daemon 判定优雅 / 强制关闭并完成关闭，最后调用 PID 文件清理（详见 [daemon 关闭流程](../daemon/shutdown.md)）

## 模块关系

- **上游**：CLI Admin（启动前经本接口做存活检测；经本接口投递终止信号与再次投递、等待退出，确认退出后做清理兜底）、Daemon（启动时经本接口自注册 PID；经本接口订阅关闭信号；关闭完成阶段经本接口做 PID 文件清理）
- **下游**：操作系统进程与信号 API、文件系统 API（本接口调用）
- **无关**：CLI Chat、Gateway、IM Adapter（不涉及 daemon 进程实例管理）；config 模块不调用本接口，仅在其目录结构中登记 `daemon.pid` 的位置（见 [config/README](../config/README.md)）
- **与模块内其他子功能**：与终端能力检测、文件路径处理、临时目录并列，均为独立的 OS 能力抽象；[配置目录](config-directory.md) 为本接口提供配置根目录（单向依赖：注册路径用「确保存在」语义，存活检测与终止投递用「仅解析」语义）。PID 文件与实例锁的路径不经文件路径处理接口。

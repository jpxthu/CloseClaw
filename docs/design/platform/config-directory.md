# 配置目录

## 概述

配置目录接口提供 CloseClaw 的配置根目录（`~/.closeclaw`，即该根目录本身，而非其下的 `config/` 子目录）的绝对路径，供上层定位其中的配置数据与运行数据（见 [requirements/platform.md §F2](../../requirements/platform.md)）。该根目录同时承载配置数据与运行期数据（配置文件、Agent 目录、workspace、各模块的运行期数据文件、PID 文件与实例锁等）；config 模块的目录结构与创建范围见 [config/README](../config/README.md)，其余子项由对应使用方自行创建。本模块称该目录为「配置根目录」；同一路径在需求与其他模块文档中亦称「操作系统标准配置目录」「系统标准配置目录」「数据根目录」，占位符 `{config_dir}` 亦指该路径，均指此根目录、不含其下的 `config/` 子目录。各受支持平台路径规则一致，上层无需处理平台差异。

## 架构

- **路径取值**：配置根目录为用户主目录下的 `.closeclaw`；Linux、macOS 与 Windows（经 WSL2）一致。返回绝对路径，以 `/` 分隔且不含末尾分隔符。其他模块不得在运行期自行拼装该路径，一律经本接口或上层 config 模块的封装取得；各模块文档中出现的 `~/.closeclaw/<子目录>` 表示该根目录下的固定布局，不构成自行解析根目录。
- **主目录解析**：解析规则与 [文件路径处理](file-path.md) 一致（规则在该文档统一定义，两接口各自实现、互不调用）；本接口不使用其路径归一化能力；无法解析时不返回相对路径。
- **取值语义**：接口提供两种取值语义，由调用方按是否需要写入选择——
  - **确保存在**：解析根目录，不存在时创建，返回绝对路径；供需要在该目录下写入的调用方使用（config 模块的目录布局、daemon 启动、[进程生命周期管理](process.md) 的注册路径）。
  - **仅解析**：只解析并返回绝对路径，不创建、不修改任何文件系统内容；根目录不存在时返回独立的「根目录不存在」结果态。供只读调用方使用（[进程生命周期管理](process.md) 的存活检测与终止投递）。
- **目录创建**：创建时设置为仅当前用户可访问；已存在时不修改其权限（配置文件与凭据的权限纠正属 config 模块职责，见 [config/README](../config/README.md)）。本接口仅保证根目录本身：`config/`、`agents/`、`skills/`、`workflows/` 等子目录由 config 模块布局与创建；`workspaces/` 等运行期数据目录的位置由 config 模块登记，其下级目录由对应使用方按需创建；PID 文件与实例锁文件由进程生命周期接口在本目录下维护（见 [进程生命周期管理](process.md)）。根目录创建或解析失败时返回错误，由调用方处理。
- **路径使用**：使用方经本接口取值后按目录层级拼接下级路径，不硬编码分隔符；需要在该目录下写入的用「确保存在」语义，只读的用「仅解析」语义，不得自行拼装根目录。
- **失败语义**：「根目录不存在」（仅解析语义下）、「主目录无法解析」、「根目录创建失败」为相互独立的结果，调用方分别处理；只读调用方按「根目录不存在」判定无实例等业务状态。
- **幂等性**：重复调用不重复创建目录，除首次创建外无副作用。

## 数据流

1. 上层（config 模块、Daemon）与模块内进程生命周期接口调用配置目录接口
2. 解析用户主目录；无法解析时返回错误
3. 拼接 `.closeclaw`，得到配置根目录的绝对路径
4. 「确保存在」语义下：根目录不存在则创建并设置仅当前用户可访问，创建失败返回错误；「仅解析」语义下：根目录不存在则返回「根目录不存在」结果态，不创建
5. 返回配置根目录的绝对路径

## 模块关系

- **上游**：config 模块（经本接口的「确保存在」语义获取配置根目录，负责 `config/`、`agents/`、`skills/`、`workflows/` 等子目录的布局与创建及配置读写，见 [config/README](../config/README.md)）；Daemon（启动期经本接口初始化配置根目录，见 [daemon/README](../daemon/README.md)）；模块内[进程生命周期管理](process.md)（注册路径用「确保存在」，存活检测与终止投递用「仅解析」）。以该根目录为路径基准的其他模块经本接口取值（只读用「仅解析」、需写入用「确保存在」）或经 config 模块的封装取得，不自行拼装根目录；本接口不代为创建其数据子目录。
- **下游**：操作系统文件系统、环境变量与用户信息 API（本接口调用）
- **无关**：Gateway、IM Adapter（不直接调用本接口；其配置数据经 config 模块读写，不自行解析配置目录路径）
- **与模块内其他子功能**：与终端能力检测、文件路径处理、临时目录并列，互不依赖。文件路径处理负责上层传入路径的通用展开与规范化，本接口只解析并返回自身固定的配置根目录路径；两者对主目录的解析规则同源（规则见 [文件路径处理](file-path.md)），但本接口不经文件路径处理接口转换。进程生命周期管理接口经本接口取得配置根目录以定位 PID 文件（见 [进程生命周期管理](process.md)），两者为单向依赖。

# 配置目录

## 概述

配置目录接口提供 CloseClaw 的配置目录绝对路径，供上层定位其中的配置数据与运行数据（见 [requirements/platform.md §F2](../../requirements/platform.md)）。各受支持平台路径规则一致，上层无需处理平台差异。

## 架构

- **路径取值**：配置目录为用户主目录下的 `.closeclaw`；Linux、macOS 与 Windows（经 WSL2，daemon 运行于 WSL2 内）一致。返回绝对路径，以 `/` 分隔且不含末尾分隔符。
- **home 解析**：以操作系统用户主目录解析 `~`。HOME 环境变量优先；未设置、为空、指向非目录或不可访问时，按系统用户信息获取；仍无法解析时返回错误，调用方可修复环境后重试。
- **目录创建**：根目录不存在时由本接口创建，确保首次启动无需手工建目录；本接口仅保证根目录存在。`config/`、`agents/`、`skills/` 等子目录由 config 模块布局与创建，PID 文件由进程生命周期接口在本目录下维护。根目录创建失败时返回错误，由调用方处理；子目录创建失败由对应消费方处理。
- **路径使用**：使用方按目录层级拼接下级路径，不硬编码分隔符。
- **幂等性**：重复调用不重复创建目录，除首次创建外无副作用。

## 数据流

1. 上层（config 模块、Daemon）调用配置目录接口
2. 解析用户主目录；无法解析时返回错误
3. 拼接 `.closeclaw`，得到配置目录绝对路径
4. 根目录不存在则创建；创建失败返回错误
5. 返回配置目录绝对路径

## 模块关系

- **上游**：config 模块（经本接口获取配置目录，负责 `config/`、`agents/` 等配置子目录的布局与读写，以及 `skills/` 等共享目录的布局，见 [config/README](../config/README.md)）；Daemon（启动期先经本接口确保配置目录存在，再执行 PID 自注册与组件初始化，见 [daemon/README](../daemon/README.md)）。Skills 模块消费 config 模块提供的技能目录布局，不直接调用本接口。
- **下游**：操作系统文件系统、环境变量与用户信息 API（本接口调用）
- **无关**：Gateway、IM Adapter（不调用本接口，也不消费配置目录路径）
- **与模块内其他子功能**：与进程生命周期管理、终端能力检测、文件路径处理、临时目录并列，互不依赖。文件路径处理负责上层传入路径的通用展开与规范化，本接口只解析并返回自身固定的配置目录路径；两者对 `~` 的解析规则保持一致，但本接口不经文件路径处理接口转换。进程生命周期管理接口的 PID 文件位于本目录下，两者遵循同一 `~` 解析规则与 `.closeclaw` 布局，但不互相调用。

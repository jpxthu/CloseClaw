# 文件路径处理

## 概述

文件路径处理接口把上层传入的原始路径展开并归一化为平台无关路径表示（展开 home 简写 `~` 与环境变量），使上层无需自行处理简写与分隔符（见 [requirements/platform.md §F4](../../requirements/platform.md)）。

## 架构

- **home 展开**：仅当路径为 `~` 本身或以 `~/` 开头时，把该 `~` 展开为当前用户主目录；`~user` 形式、`~` 后接其他字符（含 `~\`）与其他位置的 `~` 按字面保留。HOME 环境变量优先，未设置、为空、指向非目录或不可访问时按系统用户信息获取，仍无法解析时返回错误。
- **环境变量展开**：在 `~` 展开后对整条路径执行，不做段边界限制（路径中任意位置的 `$` 都按变量引用识别）；仅支持 `$VAR` 与 `${VAR}` 两种形式（变量名为字母或下划线开头，后续为字母、数字或下划线）；不构成合法变量引用的 `$`（单独 `$`、`$1`、`${}`）与 `${VAR:-default}` 等扩展形式、Windows `%VAR%` 按字面保留。变量未设置或为空时返回错误。变量值本身不再二次展开（不递归）。
- **统一表示**：展开后的路径以 `/` 作为分隔符表示；受支持平台（Linux、macOS 与 Windows 经 WSL2）本身即以 `/` 为分隔符，无需转换。反斜杠在这些平台上不是分隔符，按字面保留。
- **归一化**：去除重复分隔符、`.` 段与末尾分隔符（根路径除外）；不解析符号链接、不折叠 `..`，不改变路径的绝对/相对属性；不裁剪有效路径中的空白。空路径或仅由空白字符构成的路径返回错误，纯分隔符归一为根路径 `/`。
- **失败语义**：home 或环境变量无法解析、路径为空或纯空白时返回错误，由上层提示用户。
- **纯转换**：接口不做文件内容读写；对 home 仅做目录属性校验（是否为目录、是否可访问）。

## 数据流

1. 上层传入原始路径（可能含 `~` 或环境变量）
2. 展开路径首段的 `~` 为用户主目录；无法解析时返回错误
3. 展开 `$VAR` / `${VAR}`；变量未设置或为空时返回错误
4. 以 `/` 分隔并归一化：去除重复分隔符、`.` 段与末尾分隔符（根路径除外），不折叠 `..`；空路径或纯空白路径返回错误，纯分隔符归一为根路径 `/`
5. 返回平台无关路径表示给上层

## 模块关系

- **上游**：tools（文件类工具与命令执行的文件路径参数，需展开 `~`，见 [requirements/tools.md](../../requirements/tools.md)）
- **下游**：操作系统环境变量与用户信息 API、home 目录属性校验所需的文件系统 API（本接口调用）
- **无关**：Gateway、IM Adapter——不调用本接口；其路径来自 config 模块的配置数据，不自行展开 home
- **与模块内其他子功能**：与进程生命周期管理、配置目录、终端能力检测、临时目录并列，互不依赖。本接口与 [配置目录](config-directory.md)接口遵循相同的 home 解析规则；配置目录接口自行解析固定路径，不经本接口转换。

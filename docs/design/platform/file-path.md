# 文件路径处理

## 概述

文件路径处理接口把上层传入的原始路径展开并归一化为平台无关路径表示（展开 home 简写 `~` 与环境变量），使上层无需自行处理简写与分隔符（见 [requirements/platform.md §F4](../../requirements/platform.md)）。

## 架构

- **home 展开**：仅识别路径首段的 `~`，展开为当前用户主目录；HOME 环境变量优先，未设置、为空、指向非目录或不可访问时按系统用户信息获取，仍无法解析时返回错误。`~user` 形式与其他位置的 `~` 按字面保留。
- **环境变量展开**：在 `~` 展开后执行，仅支持 `$VAR` 与 `${VAR}` 两种形式；`${VAR:-default}` 等扩展形式、Windows `%VAR%` 按字面保留。变量未设置或为空时返回错误。每段只扫描一次，不递归展开。
- **统一表示**：展开后的路径统一为 `/` 分隔符的平台无关表示；受支持平台（Linux、macOS 与 Windows 经 WSL2）均使用 `/`，无需平台分支。反斜杠不视为分隔符，按字面保留。
- **归一化**：去除重复分隔符、`.` 段与末尾分隔符（根路径除外）；不解析符号链接、不折叠 `..`，不改变路径的绝对/相对属性；不裁剪空白字符。空路径或纯空白路径返回错误，纯分隔符归一为根路径 `/`。
- **失败语义**：home 或环境变量无法解析时返回错误，由上层提示用户。
- **纯转换**：接口只做路径表示转换并返回结果，不直接读写文件系统。

## 数据流

1. 上层传入原始路径（可能含 `~` 或环境变量）
2. 展开路径首段的 `~` 为用户主目录；无法解析时返回错误
3. 展开 `$VAR` / `${VAR}`；变量未设置或为空时返回错误
4. 统一为 `/` 分隔并归一化
5. 返回平台无关路径表示给上层

## 模块关系

- **上游**：CLI Admin（当前唯一调用方，处理用户传入的路径参数）
- **下游**：操作系统环境变量与用户信息 API（本接口调用）
- **无关**：Gateway、IM Adapter（不涉及文件路径解析）
- **与模块内其他子功能**：与进程生命周期管理、配置目录、终端能力检测、临时目录并列，互不依赖。本接口与配置目录接口遵循相同的 `~` 解析规则；配置目录接口自行解析固定路径，不经本接口转换。

# 文件路径处理

## 概述

文件路径处理接口把上层传入的原始路径中的 home 简写 `~` 展开，并归一化为平台无关的路径表示，使上层无需自行处理简写与分隔符（见 [requirements/platform.md §F4](../../requirements/platform.md)）。相对路径的解析基准（Session 所属 Agent-User 组合的 workspace）由调用方负责，不在本接口范围。

## 架构

- **home 展开**：仅当路径为 `~` 本身或以 `~/` 开头时，把该 `~` 展开为当前用户主目录；`~user` 形式、`~` 后接其他字符（含 `~\`）与其他位置的 `~` 按字面保留。主目录解析规则：HOME 环境变量优先，但须为绝对路径且指向可访问的目录（可访问指以运行本接口的进程身份可进入该目录）；未设置、为空、非绝对路径、指向非目录或不可进入时按系统用户信息获取，仍无法解析时返回错误。HOME 不可用时的回退不经调用方确认（该规则为模块内主目录解析的唯一定义，[配置目录](config-directory.md) 沿用）。`~\` 属不受支持的原生 Windows 形态，按字面保留、不承诺展开。
- **不展开环境变量**：`$VAR`、`${VAR}` 等一律按字面保留——需求只要求展开路径简写，含 `$` 的合法文件名因此保持可达；代价是 `$HOME/x` 不等价于 `~/x`，同样按字面路径处理。
- **统一表示**：受支持平台（Linux、macOS 与 Windows（经 WSL2））均以 `/` 为分隔符，需求中的「按平台转换分隔符」在受支持平台上为恒等操作；路径以 `/` 表示，反斜杠不是分隔符、按字面保留。
- **归一化**：去除重复分隔符、`/./` 中的 `.` 段与末尾分隔符（根路径除外）；不解析符号链接、不折叠 `..`，不改变路径的绝对/相对属性；不裁剪路径中的空白。结果判定：空路径、仅由空白字符构成的路径、除空白与分隔符外无其他内容的路径（如 ` / `）返回错误；纯分隔符路径（如 `//`）归一为根路径 `/`；路径仅为 `.` 或 `./` 时归一为 `.`。
- **失败语义**：返回两类可区分的结果——「路径为空或非法」（含空白与分隔符混合等）与「主目录无法解析」；文件是否真实存在等文件系统状态不属本接口判定范围，由调用方在展开后自行处理。失败由上层按自身呈现规则处理（面向 Agent 的工具返回机器可读文案，见 [requirements/tools.md §F12](../../requirements/tools.md)）。
- **转换边界**：接口不做文件内容读写、不做权限判定；对主目录仅做目录属性校验（是否为目录、是否可进入）。调用方在本接口展开后再做权限判定与相对路径解析，不以未展开的 `~` 路径参与匹配。
- **调用时机**：每次需要时调用，不缓存主目录解析结果。

## 数据流

1. 上层传入原始路径（可含 `~`）
2. 仅当路径为 `~` 本身或以 `~/` 开头时，把 `~` 展开为主目录；主目录无法解析时返回错误
3. 归一化为 `/` 分隔表示：去除重复分隔符、`/./` 中的 `.` 段与末尾分隔符（根路径除外），不折叠 `..`，不改变绝对/相对属性；空路径、仅由空白构成的路径、除空白与分隔符外无其他内容的路径返回错误，纯分隔符归一为根路径 `/`，仅为 `.` 或 `./` 时归一为 `.`
4. 返回展开并归一化后的路径；相对路径不做绝对化，由调用方按 Session 的工作目录（workspace）解析

## 模块关系

- **上游**：tools（文件类工具与命令执行的文件路径参数，需展开 `~`；其中「命令执行的文件路径参数」指 Bash 工具的 `cwd` 参数，命令串内部的路径由 shell 自行解释、不经本接口。相对路径基于 Session 所属 Agent-User 组合的工作目录（workspace）解析，不在本接口范围，见 [requirements/tools.md](../../requirements/tools.md)）
- **下游**：操作系统环境变量与用户信息 API（主目录解析）、主目录目录属性校验所需的文件系统 API（本接口调用）
- **无关**：Gateway、IM Adapter——不调用本接口，也不对用户输入做路径展开
- **与模块内其他子功能**：与进程生命周期管理、配置目录、终端能力检测、临时目录并列，互不依赖。本接口与 [配置目录](config-directory.md) 遵循相同的主目录解析规则（规则在本接口定义，配置目录接口自行实现、不经本接口转换）。

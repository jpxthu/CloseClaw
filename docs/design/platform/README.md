# Platform

## 概述

- 关联需求文档：[requirements/platform.md](../../requirements/platform.md)
- 一句话：Platform 是操作系统抽象层，将进程生命周期管理、配置目录、终端能力检测、文件路径处理、临时目录五类操作系统相关操作封装为平台无关的接口，使上层模块不感知操作系统差异。
- 术语：本模块的「平台」指操作系统平台；IM 渠道的 platform（消息平台标识，见 [common 共享类型](../common/shared-types.md)）与 [im_adapter](../im_adapter/README.md) 的平台插件无关。

## 架构

Platform 按操作系统能力维度划分为五个能力接口，每个接口对应一类操作系统能力。上层模块以同一套接口调用；平台差异只体现为各接口约定的取值与失败条件（见 §平台实现边界），不改变调用方式。

Platform 的抽象范围限于进程生命周期、配置目录、终端能力、文件路径与临时目录五类操作系统能力。沙盒/隔离执行的平台机制选择不属本模块抽象范围，由 [permission 沙盒引擎](../permission/sandbox.md)自行实现；进程派生（由 CLI Admin 承担）与工具进程的强制终止（由 session、tools 的清理路径执行）同样不在本模块接口范围。受支持平台的环境变量语法一致（原生 Windows 不在支持范围），需求 §F5 所列「环境变量格式」在本模块体现为主目录解析（HOME 等用户信息）以及终端能力、临时目录读取的环境变量（`TERM`、`TMPDIR`）；路径本身只展开 `~`、不展开环境变量（见 [文件路径处理](file-path.md)），其他模块读取环境变量不因此产生平台分支。

五个接口中，进程生命周期接口经 [配置目录](config-directory.md) 接口取得配置根目录以定位 PID 文件（单向依赖）；[文件路径处理](file-path.md) 定义主目录解析规则，[配置目录](config-directory.md) 按同一规则自行实现、不经该接口转换。其余接口彼此独立。

### 平台实现边界

- **Linux**：原生支持
- **macOS**：进程信号、文件路径、终端能力检测、配置目录的接口语义均与 Linux 一致；临时目录的取值与缺失处理与 Linux 不同（见 [临时目录](temp-directory.md)）
- **Windows**：经 WSL2 覆盖，行为等同 Linux，不做原生 Windows 适配

各接口的平台差异另有子文档级界定（如临时目录的取值差异见 [临时目录](temp-directory.md)）。

## 数据流

1. 上层模块调用 platform 接口（平台无关）
2. 接口层经操作系统 API 完成实际操作，平台差异按各接口的解析规则处理（见 §平台实现边界）
3. 返回平台无关的结果给上层模块

按能力的关键分支（各接口的完整规则见对应子文档）：

- 进程生命周期：输入为存活检测、PID 自注册、终止投递与等待、PID 文件清理、关闭信号订阅请求；输出为「实例存活 / 无实例」判定、注册与终止的执行结果（无实例的终止按成功返回）。链路为实例锁保证唯一性与存活判定、PID 文件记录实例 PID、存活检测（含残留 PID 文件清除）、终止（投递 SIGTERM → 等待退出 → PID 文件清理兜底）与关闭信号订阅
- 配置目录：输入为取配置根目录请求（「确保存在」或「仅解析」语义）；输出为绝对路径或错误（确保存在语义下根目录不存在则创建、创建失败返回错误；仅解析语义下根目录不存在返回该结果态、不创建）
- 文件路径：输入为上层传入的原始路径；输出为平台无关路径或两类可区分错误（展开 `~`，归一化为以 `/` 分隔的表示；「路径为空或非法」与「主目录无法解析」分别返回）
- 终端能力：无入参（检测对象固定为调用方进程的标准输出与其终端）；输出为 ANSI 能力标记与终端原始列数（或「不可得」，不可得时不填充默认宽度）
- 临时目录：无入参；输出为绝对路径或「临时目录无法解析」错误（按平台解析 `$TMPDIR`，缺失按平台规则回退或报错）

被动信号路径（不属请求-响应）：操作系统向 daemon 送达 SIGTERM / SIGINT / SIGHUP → 接口分发至订阅的 daemon 关闭流程 → daemon 判定优雅 / 强制关闭并完成关闭，最后调用 PID 文件清理（见 [进程生命周期管理](process.md)）

## 模块关系

> 「上游/下游」指数据流与调用关系，不等于 crate 依赖；crate 依赖以 [STANDARDS.md 依赖方向允许边表](../STANDARDS.md) 为准。

- **上游**：CLI Chat（终端能力检测，由终端插件在 CLI 进程内调用（即用户终端所在进程），见 [终端能力检测](terminal.md)）、CLI Admin（进程管理与命令输出的宽度截断）、Daemon（启动关闭时的进程与信号处理、经配置目录接口初始化配置根目录）、config 模块（经配置目录接口定位配置根目录，并在其下布局子目录与读写配置数据，见 [配置目录](config-directory.md)）、tools（后台任务输出与超长命令输出经临时目录接口落盘，见 [临时目录](temp-directory.md)；文件路径参数经 [文件路径处理](file-path.md) 展开 `~`）。以配置根目录为路径基准的其他模块经配置目录接口取值（只读用「仅解析」、需写入用「确保存在」，见 [配置目录](config-directory.md)），其数据子目录由各自创建
- **下游**：操作系统 API（进程与信号、文件系统与配置目录惯例、终端尺寸与 `TERM` 等终端环境变量、主目录解析用的环境变量与用户信息、系统临时目录惯例）——platform 调用操作系统完成实际操作
- **无关**：IM Adapter、Gateway——不调用本模块接口，也不消费本模块产出（Gateway 经 terminal 渠道插件间接涉及用户终端，该插件实现在 CLI 模块，Gateway 不直接调用本模块接口）。各子接口的无关界定见对应子文档
- **共享类型**：无——platform 收发的为操作系统原语及其结果（路径字符串、进程标识、终端能力标记与宽度等），不与业务模块共享 [common](../common/README.md) 中定义的数据结构。五类能力接口及其收发类型属 platform 自有定义（基础层不依赖 common），消费方经 platform 接口取得，不在 common 重复定义

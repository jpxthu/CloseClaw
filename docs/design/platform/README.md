# Platform

## 概述

- 关联需求文档：[requirements/platform.md](../../requirements/platform.md)
- 一句话：Platform 是操作系统抽象层，将进程生命周期管理、配置目录、终端能力检测、文件路径处理、临时目录五类操作系统相关操作封装为平台无关的接口，使上层模块不感知操作系统差异。

## 架构

Platform 按操作系统能力维度划分为五个独立的接口，每个接口对应一类操作系统能力。上层模块只调用平台无关的接口；受支持平台的接口语义一致，具体取值遵循各平台惯例（见 §平台实现边界）。

### 子功能索引

| 文档 | 内容 |
|------|------|
| [进程生命周期管理](process.md) | PID 自注册、存活检测、终止请求与关闭信号订阅 |
| [配置目录](config-directory.md) | 返回配置目录，缺失时自动创建 |
| [终端能力检测](terminal.md) | 检测终端 ANSI 能力与可用宽度 |
| [文件路径处理](file-path.md) | 展开路径简写与环境变量并统一为平台无关表示 |
| [临时目录](temp-directory.md) | 返回系统临时目录路径 |

### 平台实现边界

- **Linux**：原生支持
- **macOS**：进程信号、文件路径、终端能力检测、配置目录的接口语义均与 Linux 一致；临时目录取 launchd 注入的 `$TMPDIR`，缺失时返回错误（与 Linux 未设置或为空时回退的 `/tmp` 不同，见 [临时目录](temp-directory.md)）
- **Windows**：经 WSL2 覆盖，行为等同 Linux，不做原生 Windows 适配

## 数据流

1. 上层模块调用 platform 接口（平台无关）
2. 接口层经操作系统 API 完成实际操作，平台差异按各接口的解析规则处理（见 §平台实现边界）
3. 返回平台无关的结果给上层模块

按能力的关键分支：

- 进程生命周期：PID 自注册（daemon 启动时进程内自调用）；存活检测（读 PID 文件并查进程状态，残留文件被清除）；终止（发 SIGTERM → 等待退出 → 清理 PID，无实例按成功返回）
- 配置目录：目录不存在则创建，创建失败返回错误
- 文件路径：先展开 `~` 再展开环境变量，解析失败返回错误，最后统一 `/` 分隔
- 终端能力：按 `TERM` 启发式判定 ANSI 能力；宽度获取失败或无效时回退 80 列
- 临时目录：Linux / WSL2 未设置或为空时回退 `/tmp`；macOS 缺失 `$TMPDIR` 时返回错误

被动信号路径（不属请求-响应）：操作系统向 daemon 送达 SIGTERM / SIGINT → 接口分发至订阅的 daemon 关闭流程 → daemon 判定 graceful / forceful 并完成关闭，最后调用 PID 清理（见 [进程生命周期管理](process.md)）

## 模块关系

> 「上游/下游」指数据流与调用关系（含经 common trait 完成的调用），不等于 crate 依赖；crate 依赖以 [STANDARDS.md 依赖方向允许边表](../STANDARDS.md) 为准。

- **上游**：CLI 模块（Chat 层的终端能力检测；Admin 层的进程管理与文件路径处理）、Daemon（启动关闭时的进程与信号处理、配置目录初始化）、config 模块（经配置目录接口定位配置目录并布局其下子目录，见 [配置目录](config-directory.md)）、tools 模块（后台任务输出与超长命令输出经临时目录接口落盘，见 [临时目录](temp-directory.md)）
- **下游**：操作系统 API（进程与信号、文件系统与配置目录惯例、环境变量、终端尺寸）——platform 调用操作系统完成实际操作
- **无关**：Gateway、IM Adapter——不调用本模块接口，也不消费本模块产出；其余模块按需消费本模块能力。各子接口的无关界定见对应子文档
- **共享类型**：无——platform 收发的均为操作系统原语（路径字符串、进程标识、终端尺寸等），不与业务模块共享 [common](../common/README.md) 中定义的数据结构

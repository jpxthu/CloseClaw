# Fake LLM Server

## 概述

- 关联需求文档：[requirements/fake_llm.md](../../requirements/fake_llm.md)
- Fake LLM Server 是仅监听本地回环地址的独立测试进程，用 OpenAI、Anthropic 标准协议为真实 CloseClaw 二进制提供可复现的黑盒端到端测试；不进入发布构建，不随产品分发。

## 架构

服务由本地控制面、协议端点（含解析与编码的协议层）、场景引擎、缓存模拟与投递层组成。控制面负责运行命名空间的创建、重置与释放，不对被测方暴露为对话端点；对话与模型发现请求只经协议端点进入。协议形态样本见 [fixtures](fixtures.md)。

```text
测试者 / 测试运行器 -> 控制面：创建、重置、释放运行命名空间，装载场景集
                    -> 被测侧模型端点配置：指向本服务并启用本地测试关联
CloseClaw 二进制 -> 回环端点：校验运行命名空间，解析匿名关联信息与协议请求
  -> 场景引擎
    对话：定位匿名会话 -> 匹配场景 -> 响应步骤与逻辑时间 -> 缓存模拟
    模型发现：运行级独立发现序列，不进入对话匹配或缓存
  -> 协议层：编码 JSON / SSE
  -> 投递层：按已编码序列发送，执行错误与延迟注入
  -> CloseClaw 二进制
测试日志 <- 匹配、响应与用量、缓存事件、投递结果
```

- **协议与供应商特性分离**：模拟标准协议形态，不复刻具体供应商或模型；内容覆盖文本、推理/思考、单个与并行工具调用及其流式增量。用量五个分项按真实采集归纳的落点编码（落点表见 [llm/protocol-mapping](../llm/protocol-mapping.md)），落点缺失的分项按缺失处理，不虚构字段、不借用其他字段承载。
- **确定性**：同一初始状态、场景声明、同一尝试次序与逻辑时间推进产生同一决策；请求内容相同不合并为同一请求尝试。真实投递延迟不改变缓存决策，过期可由场景推进，不依赖运行速度。
- **会话隔离**：被测调用链把已有会话身份映射为匿名键，经 [LLM 本地测试关联](../llm/protocol-mapping.md#本地测试关联) 带外传递；服务端不接收原始 Session、Agent 或 User 标识。同一 Agent、同一端点、相同请求的并发 Session 各自推进，子 Session 使用自身键；提示词和标准协议正文不携带测试标记。
- **缓存分区**：缓存状态按运行命名空间、匿名会话键、协议与模型分别持有，场景只决定可缓存范围策略与用量来源；模型或协议切换使用各自分区，切回是否仍有效由该分区的逻辑过期决定，见 [kv-cache-simulation](kv-cache-simulation.md)。

运行命名空间由控制面创建和释放，用于隔离测试运行；各匿名会话的场景和缓存状态在命名空间内独立持有。命名空间装载时校验场景集，全部配置通过后才发布该次运行的就绪状态，失败不静默降级。状态归属、匿名键缺失时的无状态边界及请求错误规则唯一见 [scenario-engine](scenario-engine.md)。本服务不依赖外部网络或真实模型。

可观测性贯穿端点、场景、缓存和投递，记录实际制造的输入与发送结果，不自行定义被测方的正确性标准。

- [endpoints](endpoints.md) — 独立进程、控制面、回环监听、带外关联、双协议与发现端点。

## 数据流

1. 测试者或运行器启动服务；控制面创建运行命名空间并装载场景集；运行器把命名空间写入被测侧的接入配置并启用本地测试关联。
2. 对话请求到达端点，先校验命名空间与匿名关联信息，再把完整协议请求交场景引擎；模型与消息内容不用于猜测会话身份。
3. 引擎在本运行选定的场景集内定位本匿名会话匹配的场景，原子取下一响应步骤、推进逻辑时间、生成内容与用量并提交状态；缓存计量委托缓存模拟完成。
4. 协议层编码 JSON 或 SSE，投递层按已编码序列发送并执行错误与延迟注入，不占用决策状态。
5. 模型发现请求只携带运行命名空间，使用独立发现序列，不消耗对话步骤、逻辑时间或缓存。
6. 全链路写测试日志；运行结束由控制面释放命名空间或关闭实例，销毁全部状态并拒绝迟到请求。

请求失败分三类：命名空间不存在或已释放为运行错误，协议正文或关联信息无法解析、协议语义非法为请求错误，零命中且无兜底、需要会话状态但会话键缺失、用量约束不成立或序列耗尽为场景执行错误。三类错误都不推进步骤、时间或缓存，不影响其他会话，也不返回隐式默认响应。投递失败不回滚已提交的决策。

## 模块关系

> 「上游/下游」指数据流与调用关系，不等于 crate 依赖；crate 依赖以 [STANDARDS.md 依赖方向允许边表](../STANDARDS.md) 为准。

- **上游**：测试者与运行器经控制面管理服务并装载场景；真实 CloseClaw 二进制通过 HTTP 发起对话与发现请求。运行命名空间与本地测试关联的接入配置由 [config](../config/README.md) 承载、被测侧读取，本服务不读取配置文件。真实采集响应（`tests/fixtures/llm/`）是协议事实的只读来源，见 [fixtures](fixtures.md)。
- **下游**：被测二进制消费响应；测试运行器消费日志和结果；生成方与消费方单元测试消费合成 fixture，集成测试复用测试者编写的场景定义。被测设计入口另见 [llm/protocol-mapping](../llm/protocol-mapping.md)、[llm/model-discovery](../llm/model-discovery.md)、[llm/cache-adapter](../llm/cache-adapter.md)。
- **无关**：[test_support](../test_support/README.md) 是测试代码内部的编译期辅助库，不是运行时假模型服务，本模块不依赖它。
- **共享类型**：场景文件格式由本模块唯一所有（定义见 [scenario-engine](scenario-engine.md) 与 [fixtures](fixtures.md)），集成测试复用而不另立定义；带外匿名关联契约由 [llm/protocol-mapping](../llm/protocol-mapping.md#本地测试关联) 定义，本模块只消费。不引用 CloseClaw crate，被测侧的会话上下文不作为服务端内部类型。

缓存统计及一致性校验以 [llm 需求 F9](../../requirements/llm.md) 为产品权威，设计入口见 [session/llm-session-enhancements](../session/llm-session-enhancements.md)；本模块只制造输入，不另定判定、豁免或通知策略。

# 场景引擎

## 概述

场景引擎按声明匹配协议请求，在独立测试会话内推进响应步骤，编排模式响应与模型发现序列，生成内容、用量与投递控制，使并发对话和重试均可确定性重放。

## 架构

### 场景声明与匹配

场景文件声明匹配条件、响应序列、缓存策略与投递控制，同一套定义在集成测试与黑盒端到端测试中复用。测试者声明文本、推理、工具调用、用量与延迟等效果，不必编写协议 JSON 或 SSE；协议形态样本见 [fixtures](fixtures.md)。缓存策略是场景级声明，延迟与断流等投递控制按响应步骤声明。

测试运行器为每次测试运行创建命名空间，并为其选定场景集。场景以命名空间内唯一的身份登记；同一份不可变声明可被多个命名空间复用，但可变状态不共享。场景匹配与校验均在各命名空间内部完成，不跨命名空间检测声明冲突。

匹配条件使用有限的声明式规则：模型与请求参数的精确比较，以及消息内容、工具的包含或排除条件，可作逻辑组合。可比较的请求参数限于流式开关与协议原生推理参数。消息内容条件作用于 System Prompt、角色内容块与工具调用/结果的内容；工具条件作用于请求中的工具定义。协议不进入匹配条件，由场景的允许匹配协议集合限定：省略时两种协议均可匹配，集合内每种协议都必须能承载该场景的协议相关声明。

请求参数包含协议原生推理控制参数，按协议分别声明；允许集合含两种协议时，须为每种协议各声明一份条件或整体省略。匹配读取请求实际发送的原生参数值，逻辑档位到原生参数的转换由被测方完成，本服务不复刻其降级规则。

协议解析保留完整请求语义，不能只抽取可见文本或工具名称。匹配读取场景所声明的特征；缓存比较所需的完整内容、顺序和缓存标记按 [kv-cache-simulation](kv-cache-simulation.md) 保留，不因匹配特征较少而丢失。

命名空间装载时把规则编译为精确索引和确定性判定结构，编译与冲突检查不进入请求热路径。内容条件按预编译结构处理，不线性遍历全部场景或随场景数增长的候选桶，匹配成本随请求大小变化而不随场景总数增长；仅含排除条件的规则在加载期折算为可索引的判定结构。

同一命名空间内，可能匹配同一协议请求的非兜底场景必须互斥。仅分别包含两个不同片段不构成互斥，可用精确参数或排除条件消歧；重叠或无法静态判断的规则拒绝加载，不按文件顺序择一。兜底场景是只声明协议集合、不含模型/参数/内容条件的场景；它不参与互斥校验，只在该协议无任何非兜底场景命中时使用，每个命名空间的每种协议至多一个。

加载期拒绝非法规则、重复身份、空响应序列，以及所选协议集合无法承载的声明（如集合内某种协议没有标记表示却声明了显式缓存策略，或声明断流/首帧延迟却未要求流式请求）；用量分项无落点不属此列，按缺失处理。该次运行的配置全部校验通过才发布就绪状态，失败不静默降级。

请求期错误分三类：命名空间不存在或已释放为运行错误；协议正文或关联信息无法解析、协议语义非法（如缓存标记位置或值非法）为请求错误；零命中且无兜底、需要会话状态但会话键缺失、用量约束不成立或序列耗尽为场景执行错误。三类均不修改状态、不终止其他会话，也不返回隐式默认响应，并在测试日志中区别于刻意注入的错误。

### 会话身份与状态隔离

同一 Agent、同一模型端点上的不同 Session 也必须隔离，不能靠消息内容、模型名、连接或端口推断会话。身份来自已有的 [InternalRequest 会话上下文](../common/shared-types.md#internalrequest--internalmessage--systemblock--tooldefinition)，由被测调用链按 [LLM 本地测试关联](../llm/protocol-mapping.md#本地测试关联) 通过带外 HTTP 元数据传递；不修改标准协议请求正文或提示词。

| 层次 | 归属与生命周期 |
|------|----------------|
| 运行命名空间 | 控制面创建，选择场景集与发现序列，运行结束时整体释放 |
| 匿名会话键 | 由调用方现有 Session 身份稳定关联；同一端点可自动接纳多个主/子 Session |
| 场景状态 | 每个匿名会话内按场景身份持有响应步骤游标；逻辑时钟按会话持有，同一会话的各场景共享 |
| 缓存分区 | 完整键为运行命名空间、匿名会话键、协议与模型；场景不参与分区 |

新请求先验证运行命名空间存在，再按匿名会话键创建或复用状态。同一会话原样重试沿用会话键；动态 spawn 的子 Session 使用自身键，不能继承父键。压缩、历史变化、模型或协议切换不改变会话身份；响应序列按「会话 + 场景身份」持有，切换后若仍匹配同一场景则继续该序列，匹配到另一场景（含兜底）则从该场景第一步开始。缓存按协议与模型分区，不含场景；切换场景不清空缓存，是否仍有效由该分区逻辑过期决定。同一运行中需要共享会话状态的多个本地接入地址应指向同一进程的同一命名空间，不能把多个独立服务进程误当作天然共享状态。

无状态场景在声明中显式标记，加载期要求其响应序列只有一步、不声明缓存策略相关状态、不推进逻辑时间。没有会话键的请求只可匹配无状态场景，每次独立求值，不持有游标、逻辑时间或缓存；需要多步序列、缓存或并发隔离时必须提供会话键，缺失时返回场景执行错误，不能静默归入公共会话。无状态场景一旦命中即不保留状态，因此同一请求重复执行得到同一响应。直接协议测试可由运行器提供匿名测试会话键，协议 fixture 本身无需包含真实 Session 标识。

各匿名会话独立提交状态，互不阻塞。一个会话内每个请求尝试具有明确次序；测试声明需要特定先后关系时，由运行器排序发起。同一匿名会话的并发在途请求在引擎内按到达序串行提交，先到者先推进；未由运行器排序时，结果不承诺重放一致，也不把同时到达的无序请求当成确定序列。不同会话的执行交错不改变各自结果。释放命名空间时清除所有游标、缓存和时钟；在途请求按已完成的决策继续投递，尚未提交的请求返回运行错误；迟到请求不得重新创建已释放的命名空间。不以真实空闲时间清理状态而改变重放结果。

### 响应编排

响应序列按本匿名会话、本场景的请求尝试推进：每个成功匹配且决策提交的请求消费一个步骤，包括声明的 HTTP 错误或断流；没有匹配、会话键缺失、动态约束失败或序列耗尽不消费步骤。第一次请求可以限流，完全相同的原样重试可以成功；请求内容相同不代表同一个请求尝试，也不触发隐式去重。跨多轮对话的响应同样按声明的尝试序列编排。需求的「同一输入产出同一输出」以同一尝试次序为前提；同一输入处于不同尝试序号时取不同步骤，这是可重放性的细化而非例外。

取步骤、推进逻辑时间、生成响应与提交状态构成一次原子决策；动态约束在提交前校验，失败则不提交也不消费步骤。没有匹配、关联缺失、约束失败或序列耗尽后，游标与缓存保持原状；耗尽后保持耗尽，直到运行器显式重置或释放测试状态，不循环重放。投递失败不回滚已经提交的步骤。HTTP 错误不生成模型响应和缓存读写；断流保留已完成的缓存决策。

同一初始状态、声明和同一尝试次序下的有序请求序列产生同一决策，匿名键只划分状态，不影响响应内容选择。投递等待发生在提交之后，不持有决策锁。流式或非流式由请求开关决定；分段和段间延迟只作用于流式路径，不能把非流式请求擅自改成 SSE。声明断流或首帧延迟的场景必须在匹配条件中要求流式请求，由加载期校验保证非流式请求不会命中这类步骤。

### 模型发现编排

模型发现配置属于运行命名空间，与对话场景并列。运行器选定一份发现响应序列并声明其协议，序列包含模型列表、错误与延迟；每个命名空间至多一份，多份在加载期拒绝。发现请求不携带协议身份，因此该命名空间按声明的协议编码列表与错误体；某协议形态的发现声明缺失不阻止纯对话测试启动，但收到发现请求时返回场景执行错误。

发现请求按尝试推进命名空间内独立的发现游标，不参加对话匹配，不消耗会话响应步骤、逻辑时间或缓存。声明的错误步骤与成功步骤同样消费游标；只有未声明、解析失败或耗尽等执行错误不消费。发现游标不按会话分区，多个会话并发发起发现请求时按到达序消费；需要确定顺序时由运行器串行发起。不同供应商需要不同发现剧本时使用不同运行命名空间，不能依赖未声明的凭据内容猜测供应商。发现的协议投递与用例入口见 [endpoints](endpoints.md)。

### 响应内容与用量

| 维度 | 声明能力 | 详细机制 |
|------|----------|----------|
| 内容 | 文本、推理/思考、单个或并行工具调用；工具结果在后续请求进入 | [llm/protocol-mapping](../llm/protocol-mapping.md) |
| 投递 | 流式分段、结束原因、HTTP 错误、流内错误事件、断流、首帧、逐段与整体延迟 | [delivery](delivery.md) |
| 用量 | 输入、输出、推理消耗、缓存命中与缓存写入，支持逐次变化和缺失 | 本节与 [kv-cache-simulation](kv-cache-simulation.md) |

推理控制可匹配请求中实际发送的开关、档位或预算参数，选择场景预先给定的推理内容，以验证被测方的参数传递，而不只是给响应贴档位标签。场景覆盖 low、medium、high、max 与关闭效果；关闭不输出推理内容，其余档位对应的内容由场景固定。Fake LLM 不复刻供应商的强制推理、档位降级或真实生成能力。

用量包含输入、输出、推理消耗、缓存命中与缓存写入五个分项。报告用量时输入与输出必填；推理消耗、缓存命中、缓存写入可按场景声明取值、显式零或缺失，并支持逐次变化。整块用量可因协议开关缺失（如 OpenAI 流式未启用量开关），此时各分项一并缺失，不补造为零。协议落点以 [llm/protocol-mapping](../llm/protocol-mapping.md) 的用量表为唯一权威，该表由真实采集响应归纳：某分项在所选协议没有落点时，该分项不出现在该协议响应中，按缺失处理；加载期只校验声明本身合法（非负、分项与总量约束），不因协议落点缺失拒绝场景。未被承载的声明值如何记入日志见 [kv-cache-simulation](kv-cache-simulation.md) 的「显式注入、缺失与自动生成」。实采未出现某落点只说明当前无该证据，不构成协议不提供该分项的判定；出现新落点后按实采扩展。

缓存字段分别支持显式值、缺失和自动生成；输入总量及缓存分项的统一计量见 [kv-cache-simulation](kv-cache-simulation.md)。输出与推理分项按场景声明或保持协议允许的缺失，不自行推算；输出总量包含推理消耗，不重复累加。OpenAI 流式用量仍遵守请求的用量开关，见 [delivery](delivery.md)。

### 可观测性

对话请求记录运行命名空间、匿名会话键、命中场景、响应步骤、协议与模型、响应和最终用量、缓存事件及逻辑时间；发现请求记录独立序列、协议和发现步骤，不伪造会话与缓存字段。投递结果与决策关联记录。

装载错误单独记录校验原因；请求失败记录可取得的关联信息与失败阶段（运行、请求或场景执行），不虚构尚未命中的场景或步骤。测试日志只描述制造了什么输入，不替代被测产品需求作正确性判据。

## 数据流

1. 端点校验命名空间与关联信息，解析协议正文，取得运行命名空间。
2. 有会话键时按匿名会话键定位状态；无会话键时只保留无状态场景候选，其余候选不参与匹配。
3. 对话请求选唯一非兜底场景或协议兜底；零命中、需状态但缺键或条件不满足则报错，不改状态。
4. 在本会话、本场景内原子取下一响应步骤，推进逻辑时间，生成内容与用量，委托缓存模拟补齐计量并校验约束；约束失败则不提交、不消费步骤。
5. 提交游标、时间与缓存状态，释放决策状态后由协议层编码、[delivery](delivery.md) 投递。
6. 发现请求只走命名空间声明的独立发现序列，只提交发现游标并交协议层投递，不经过对话与缓存路径；未声明或耗尽返回场景执行错误。
7. 记录决策和投递结果；运行器释放命名空间时回收其全部状态并拒绝迟到请求。

运行错误（命名空间不存在或已释放）发生在第 1 步；请求错误（协议正文或关联信息无法解析）发生在第 1 步；场景执行错误发生在第 3、4、6 步。三类错误均不推进游标、时间或缓存。

## 模块关系

- **模块内上游**：[endpoints](endpoints.md) 提供协议请求与关联信息；[fixtures](fixtures.md) 提供协议形态样本。
- **模块内下游**：[kv-cache-simulation](kv-cache-simulation.md) 生成缓存用量，[delivery](delivery.md) 执行发送；响应先交端点的协议层编码。
- **模块外上游**：测试运行器装载场景、管理命名空间；被测调用链依 [LLM 本地测试关联](../llm/protocol-mapping.md#本地测试关联) 传递匿名会话键。接入配置见 [config](../config/README.md)。
- **共享类型**：Fake LLM 不引用 CloseClaw crate；[InternalRequest](../common/shared-types.md#internalrequest--internalmessage--systemblock--tooldefinition) 是被测侧内部契约，不作为服务端运行时类型。

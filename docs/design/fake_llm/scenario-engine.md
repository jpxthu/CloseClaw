# 场景引擎

## 概述

场景引擎按声明匹配协议请求，在独立测试会话内推进响应步骤，生成内容、用量与投递控制，使并发对话和重试均可确定性重放。

## 架构

### 场景声明与匹配

场景文件声明匹配条件、响应序列、缓存与投递控制，同一套定义在集成测试与黑盒端到端测试中复用。测试者声明文本、推理、工具调用、用量与延迟等效果，不必编写协议 JSON 或 SSE；协议形态基线见 [fixtures](fixtures.md)。

测试运行器为每次测试运行创建命名空间，并为其选定场景集。场景以命名空间内唯一的显式身份登记；同一份不可变声明可被多个命名空间复用，但可变状态不共享。场景匹配与校验均在各命名空间内部完成，不跨命名空间检测声明冲突。

匹配条件使用有限的声明式规则：协议、模型、请求参数的精确比较，以及消息内容、工具的包含或排除条件，可作逻辑组合。请求参数包含流式开关和协议原生的推理控制参数。每个场景声明其允许匹配的协议集合；省略时表示两种协议均可匹配，专有能力必须对该集合内每种协议都有效，不能以运行期的「当前协议」替代加载校验。

协议解析保留完整请求语义，不能只抽取可见文本或工具名称。匹配读取场景所声明的特征；缓存比较所需的完整内容、顺序和缓存标记按 [kv-cache-simulation](kv-cache-simulation.md) 保留，不因匹配特征较少而丢失。

启动时把规则编译为精确索引和确定性判定结构，编译与冲突检查不进入请求热路径。内容条件按预编译结构处理，不线性遍历全部场景或随场景数增长的候选桶，匹配成本随请求大小变化而不随场景总数增长。

同一命名空间内，可能匹配同一协议请求的显式场景必须互斥。仅分别包含两个不同片段不构成互斥，可用精确参数或排除条件消歧；重叠或无法静态判断的规则拒绝加载，不按文件顺序择一。每个命名空间的每种协议至多一个兜底场景；即使模型未出现在精确索引中，也在该协议无显式命中时使用兜底。

加载期拒绝非法规则、重复身份、空响应序列和不支持的能力声明；本轮配置全部校验通过才发布服务就绪。请求期零命中且无兜底、解析失败、用量约束不成立或序列耗尽，则向请求方返回明确的场景执行错误，并在测试日志中区别于刻意注入的错误；不修改状态、不终止其他会话，也不返回隐式默认响应。

### 会话身份与状态隔离

同一 Agent、同一模型端点上的不同 Session 也必须隔离，不能靠消息内容、模型名、连接或端口推断会话。身份来自已有的 [InternalRequest 会话上下文](../common/shared-types.md#internalrequest--internalmessage--systemblock--tooldefinition)，由被测调用链按 [LLM 本地测试关联](../llm/protocol-mapping.md#本地测试关联) 通过带外 HTTP 元数据传递；不修改标准协议请求正文或提示词。

| 层次 | 归属与生命周期 |
|------|----------------|
| 测试运行命名空间 | 运行器创建，选择场景集与独立的发现序列，结束测试时整体释放 |
| 匿名会话键 | 由调用方现有 Session 身份稳定关联；同一端点可自动接纳多个主/子 Session，无需预先知道其数量 |
| 场景状态 | 每个匿名会话内按场景身份持有响应步骤游标和逻辑时钟 |
| 缓存分区 | 完整键为运行命名空间、匿名会话键、场景身份、协议与模型 |

新请求先验证运行命名空间存在，再按匿名会话键创建或复用状态。同一会话原样重试沿用会话键；动态 spawn 的子 Session 使用自身键，不能继承父键。压缩、历史变化、模型或协议切换不改变会话身份；同一运行中需要共享该会话状态的本地接入地址由运行器接入同一服务状态域，不能把多个独立服务进程误当作天然共享状态。

没有会话上下文的请求只可使用明确声明的无状态场景，每次独立求值；若要推进多步序列或使用缓存状态，必须提供关联上下文，缺失时明确报错，不能静默归入公共会话。直接协议测试可由运行器提供匿名测试会话键，协议 fixture 本身无需包含真实 Session 标识。

各匿名会话独立提交状态，互不阻塞。一个会话内每个请求尝试具有明确次序；测试声明需要特定先后关系时，由运行器排序发起，不把同时到达的无序请求当成确定序列。不同会话的执行交错不改变各自结果。释放命名空间时清除所有游标、缓存和时钟，迟到请求不得重新创建已释放的命名空间；不以真实空闲时间清理状态而改变重放结果。

### 响应编排

响应序列按本匿名会话、本场景的请求尝试推进：每个成功解析并匹配的请求消费一个步骤，包括声明的 HTTP 错误或断流。第一次请求可以限流，完全相同的原样重试可以成功；请求内容相同不代表同一个请求尝试，也不触发隐式去重。跨多轮对话的响应同样按声明的尝试序列编排。

取步骤、推进逻辑时间、生成响应与提交状态构成一次原子决策。没有匹配、关联缺失、动态约束失败或序列耗尽不消费步骤；耗尽后保持耗尽，直到运行器显式重置或释放测试状态，不循环重放。投递失败不回滚已经提交的步骤。HTTP 错误不生成模型响应和缓存读写；断流保留已完成的缓存决策。

同一初始状态、声明和有序请求序列产生同一决策，匿名键只划分状态，不影响响应内容选择。投递等待发生在提交之后，不持有决策锁。流式或非流式由请求开关决定；分段和段间延迟只作用于流式路径，不能把非流式请求擅自改成 SSE。

### 模型发现编排

模型发现配置属于运行命名空间，与对话场景并列；运行器可选定一份发现响应序列，声明模型列表、错误与延迟。多份选定声明在加载时拒绝；未声明不阻止纯对话测试启动，但收到发现请求时明确返回场景执行错误。

发现请求按尝试推进命名空间内独立的发现游标，不参加对话匹配，不消耗会话响应步骤、逻辑时间或缓存；耗尽与失败不消费步骤的规则同响应编排。需要不同供应商的独立发现剧本时使用不同运行命名空间，不能依赖未声明的凭据内容猜测供应商。发现的协议投递与用例入口见 [endpoints](endpoints.md)。

### 响应内容与用量

| 维度 | 声明能力 | 详细机制 |
|------|----------|----------|
| 内容 | 文本、推理/思考、单个或并行工具调用；工具结果在后续请求进入 | [llm/protocol-mapping](../llm/protocol-mapping.md) |
| 投递 | 流式分段、HTTP 错误、断流、首 token、逐段与整体延迟 | [delivery](delivery.md) |
| 用量 | 输入、输出、推理消耗、缓存命中与写入，支持逐次变化和缺失 | 本节与 [kv-cache-simulation](kv-cache-simulation.md) |

推理控制可匹配请求中实际发送的开关、档位或预算参数，选择场景预先给定的推理内容，以验证被测方的参数传递，而不只是给响应贴档位标签。场景覆盖 low、medium、high、max 与关闭效果；关闭不输出推理内容，其余档位对应的内容由场景固定。Fake LLM 不复刻供应商的强制推理、档位降级或真实生成能力。

用量按各协议原生能力覆盖，完整覆盖由两种协议合起来完成，不添加非标准响应字段。OpenAI 支持独立推理用量但无缓存写入量；Anthropic 可返回缓存写入量，但推理消耗计入输出而不独立返回。原生落点以 [llm/protocol-mapping](../llm/protocol-mapping.md) 的用量表为唯一权威。能力校验按场景允许匹配的协议集合执行，不能静默丢弃不支持的显式声明。

缓存字段分别支持显式值、缺失和自动生成；输入总量及缓存分项的统一计量见 [kv-cache-simulation](kv-cache-simulation.md)。输出与独立推理用量按场景声明或保持协议允许的缺失，不自行推算；输出总量包含推理消耗，不重复累加。OpenAI 流式用量仍遵守请求的用量开关，见 [delivery](delivery.md)。

### 可观测性

对话请求记录运行命名空间、匿名会话键、命中场景、响应步骤、协议与模型、响应和最终用量、缓存事件及逻辑时间；发现请求记录独立序列和发现步骤，不伪造会话与缓存字段。投递结果与决策关联记录。

启动错误单独记录校验原因；请求失败记录可取得的关联信息与失败阶段，不虚构尚未命中的场景或步骤。测试日志只描述制造了什么输入，不替代被测产品需求作正确性判据。

## 数据流

1. 端点解析带外关联信息与完整协议请求，取得已创建的运行命名空间。
2. 对话请求按匿名会话键定位状态，选唯一显式场景或协议兜底；未匹配或关联不满足要求则报错，不改状态。
3. 在本会话、本场景内原子取下一响应步骤，推进逻辑时间，生成内容与用量，委托缓存模拟补齐计量并校验约束。
4. 提交游标、时间与缓存状态，释放决策状态后由协议层编码、[delivery](delivery.md) 投递。
5. 发现请求走命名空间选定的独立序列，只提交发现游标并交协议层投递，不经过对话与缓存路径。
6. 记录决策和投递结果；运行器释放命名空间时回收其全部状态并拒绝迟到请求。

## 模块关系

- **模块内上游**：[endpoints](endpoints.md) 提供协议请求与关联信息；[fixtures](fixtures.md) 提供固定响应形态基线。
- **模块内下游**：[kv-cache-simulation](kv-cache-simulation.md) 生成缓存用量，[delivery](delivery.md) 执行发送；响应先交端点的协议层编码。
- **模块外上游**：测试运行器装载场景、管理命名空间；被测调用链依 [LLM 本地测试关联](../llm/protocol-mapping.md#本地测试关联) 传递匿名会话键。接入配置见 [config](../config/README.md)。
- **共享类型**：Fake LLM 不引用 CloseClaw crate；[InternalRequest](../common/shared-types.md#internalrequest--internalmessage--systemblock--tooldefinition) 是被测侧内部契约，不作为服务端运行时类型。

# 投递层

## 概述

投递层向被测二进制发送协议层已编码的 JSON 或 SSE 事件，执行场景声明的延迟、HTTP 错误、流内错误事件与流中途中断，不修改已编码内容、响应步骤、缓存或逻辑时间。

## 架构

### 协议编码与发送边界

[endpoints](endpoints.md) 的协议层按场景粒度切分内容、构造原生事件和响应对象；投递层消费编码后的序列，安排发送间隔与断流位置。分段粒度可从逐字符直到整段，覆盖文本、推理和工具参数增量，不能把切分或编码职责留给 HTTP 发送器猜测。

响应形态的映射以 [llm/protocol-mapping](../llm/protocol-mapping.md) 为权威，固定样本见 [fixtures](fixtures.md)。用量编码规则（含 Anthropic 初值与最终值的覆盖、OpenAI 用量开关）由协议层执行，本层不增删或改写已编码的用量字段，只按断流位置截断与按延迟发送。

- **OpenAI**：投递 `delta.role=assistant` 首帧、文本、推理与工具调用增量，保留响应步骤声明的结束原因（正常、工具调用、长度截断等）。结束原因之后可有用量尾块，发送完尾块后再结束流；除断流外，成功场景（含长度截断）都以协议结束标记收尾，不能在工具调用结束时提前丢弃用量。
- **Anthropic**：投递消息开始、内容块开始/增量/结束、消息增量与消息结束事件；推理块的 `signature_delta` 与内容增量同路径发送。结束原因由 `message_delta` 携带。

投递层不解析请求，也不决定用量是否随流发送；请求侧协议参数与用量开关的判断在协议层完成，见 [endpoints](endpoints.md) 与 [llm/protocol-mapping](../llm/protocol-mapping.md)。

### 延迟注入

延迟值来自响应步骤或发现步骤，固定且无随机抖动，不改变编码内容、事件次序或服务端缓存时钟：

| 类型 | 作用位置 |
|------|----------|
| 首帧延迟 | 流式响应的首个事件发送前（OpenAI 为 `role` 帧，Anthropic 为消息开始帧） |
| 逐段延迟 | 相邻已编码流式事件之间，含内容增量与控制事件 |
| 整体延迟 | 非流式成功响应、发现响应或 HTTP 错误响应发送前 |

首帧延迟作用在协议首帧而非首个内容增量；需要构造「首个内容增量前超时」时，用逐段延迟在该增量前插入等待。HTTP 错误步骤只支持整体延迟；声明断流与分段控制的步骤不得同时声明 HTTP 错误，冲突在加载期拒绝。

发送或等待均不持有引擎决策锁。同一匿名会话的响应按提交顺序串行发送，后一响应等待前一响应投递结束；不同会话可并发投递，互不阻塞。

### 错误注入与状态边界

- **HTTP 错误**：在发送成功响应或流式首帧前，发送协议格式的错误状态与错误体，至少覆盖认证失败、权限不足、非法请求、限流、计费/配额错误、服务端错误与超时（504）。场景声明空响应体的协议错误形态时，按声明发送状态码而不附带错误体。
- **流内错误事件**：已发送部分事件后，以协议原生错误事件终止流（不改变已发送的 HTTP 状态码），不伪造成功结束。
- **流中途中断**：按声明的断流位置发送部分事件后直接断开。断流位置以已编码流式事件序号声明（从 1 起），必须早于结束原因与用量尾块；非流式请求不得命中声明断流的步骤，冲突在加载期拒绝。

错误按请求尝试编排，步骤推进与提交规则唯一见 [scenario-engine](scenario-engine.md)。供应商特有的错误形态（如 HTTP 200 加业务错误体）不在本层制造，由真实采集响应与供应商适配文档验证。客户端断开或发送中断不回滚已提交决策。对话错误与延迟归属其运行、匿名会话及场景；发现错误与延迟归属运行级独立发现步骤，不借用会话游标。释放命名空间不终止已提交决策的在途投递；进程销毁时一并终止。

## 数据流

1. 从场景引擎取得已提交决策与投递控制，从协议层取得已编码响应、分段序列与断流位置。
2. 若声明 HTTP 错误，按整体延迟等待后发送错误，不进入成功响应路径。
3. 非流式成功路径等待整体延迟后发送完整 JSON；流式成功路径等待首帧延迟，再按逐段间隔发送编码好的事件。
4. 流式路径若达到断流位置立即断开；声明流内错误时在指定位置发送协议错误事件并终止；否则按协议顺序发送用量与结束事件。客户端断开时停止发送和等待。
5. 模型发现响应复用非流式发送与错误/延迟机制，不改变对话状态。
6. 将发送完成、中断或客户端取消结果写入与决策关联的测试日志。

## 模块关系

- **模块内上游**：[scenario-engine](scenario-engine.md) 选择内容并声明投递控制，[endpoints](endpoints.md) 的协议层构造可发送的响应和事件。
- **模块内下游**：被测二进制的 HTTP 连接；投递层不调用被测业务组件。
- **跨模块**：[llm/protocol-mapping](../llm/protocol-mapping.md) 定义协议映射与用量编码规则，[llm/model-discovery](../llm/model-discovery.md) 是发现被测链路的设计入口，真实采集响应（见 [fixtures](fixtures.md)）是已采集错误与流式形态的事实依据，未采集的错误形态（429、5xx、403、504 等）按构造值支持测试、不作为供应商行为证据；被测错误处理以对应需求为准，不在此复制重试、回退或上下文策略。

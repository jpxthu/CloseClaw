# 投递层

## 概述

投递层向被测二进制发送协议层已编码的 JSON 或 SSE 事件，执行场景声明的延迟、HTTP 错误和流中途中断，不修改场景响应步骤、缓存或逻辑时间。

## 架构

### 协议编码与发送边界

[endpoints](endpoints.md) 的协议层按场景粒度切分内容、构造原生事件和响应对象；投递层消费编码后的序列，安排发送间隔与断流位置。分段粒度可从逐字符直到整段，覆盖文本、推理和工具参数增量，不能把切分或编码职责留给 HTTP 发送器猜测。

完整协议形态以 [llm/protocol-mapping](../llm/protocol-mapping.md) 为唯一映射权威，固定输入/响应基线见 [fixtures](fixtures.md)：

- **OpenAI**：投递文本、推理与工具调用增量，保留声明的结束原因（正常、工具调用、长度截断等）；结束原因之后仍可有用量尾块，发送完尾块后再结束流，不能在工具调用结束时提前丢弃用量。正常场景以协议结束标记收尾。
- **Anthropic**：投递消息开始、内容块开始/增量/结束、消息增量与消息结束事件；输入侧用量初值和最终用量分别按协议规则编码，支持最终字段缺失时由消息开始初值提供回退输入。

OpenAI 流式用量仅在请求启用用量时发送；场景显式注入不绕过该开关。协议允许缺失的用量保持缺失，不由投递层改成零。请求选择流式或非流式，分段控制只作用于流式发送。

### 延迟注入

延迟值来自响应步骤，固定且无随机抖动，不改变编码内容、事件次序或服务端缓存时钟：

| 类型 | 作用位置 |
|------|----------|
| 首 token 延迟 | 流式成功响应的首帧发送前 |
| 逐段延迟 | 已编码流式事件之间 |
| 整体延迟 | 非流式响应或发现响应返回前 |

延迟超过被测方时限可制造超时；不响应的超时场景由声明的等待控制，收到客户端断开或测试取消后结束等待。发送或等待均不持有引擎决策锁，也不阻塞其他会话的投递。

### 错误注入与状态边界

- **HTTP 错误**：在发送成功响应或流式首帧前，发送协议格式的错误状态与错误体，覆盖认证失败、限流、服务端错误。场景可携带重试相关响应头，但被测方是否重试及如何退避由其需求定义。
- **流中途中断**：按声明发送部分事件后断开，不伪造成功结束。被测方的界面保留与历史写入规则以 [llm 需求 F2](../../requirements/llm.md) 为准，包含完整 Thinking 块、已配对工具调用/结果的保留规则；本层不另立「所有不完整内容都丢弃」的判据。

错误按请求尝试编排，步骤推进与提交规则唯一见 [scenario-engine](scenario-engine.md)。投递失败或取消不回滚已提交决策。对话错误与延迟归属其运行、匿名会话及场景；发现错误与延迟归属运行级独立发现步骤，不借用会话游标。

## 数据流

1. 从协议层取得已编码响应、分段序列与投递控制，关联引擎已提交的决策。
2. 若声明 HTTP 错误，在成功响应头或首帧前按声明等待后发送错误，不进入成功响应路径。
3. 非流式成功路径等待整体延迟后发送完整 JSON；流式成功路径等待首 token 延迟，再按逐段间隔发送编码好的事件。
4. 流式路径若达到断流位置立即断开；否则按协议顺序发送用量与结束事件。客户端断开或测试取消时停止发送和等待。
5. 模型发现响应复用非流式发送与错误/延迟机制，不改变对话状态。
6. 将发送完成、中断或取消结果写入与决策关联的测试日志。

## 模块关系

- **模块内上游**：[scenario-engine](scenario-engine.md) 选择内容与投递控制，[endpoints](endpoints.md) 的协议层构造可发送的响应和事件。
- **模块内下游**：被测二进制的 HTTP 连接；投递层不调用被测业务组件。
- **跨模块**：[llm/protocol-mapping](../llm/protocol-mapping.md) 定义协议映射，[llm/model-discovery](../llm/model-discovery.md) 是发现被测链路的设计入口；被测错误处理以对应需求为准，不在此复制重试、回退或上下文策略。

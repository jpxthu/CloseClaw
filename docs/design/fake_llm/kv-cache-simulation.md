# KV Cache 前缀缓存模拟

## 概述

以确定性的测试模型制造缓存首次写入、连续命中、前缀断开和过期的用量序列，支持自动推导与逐次显式注入，验证 CloseClaw 的缓存统计和异常处置。它不复刻具体供应商或模型的缓存服务，也不定义被测方的正确结果。

## 架构

### 隔离与计量基础

每个运行命名空间、匿名会话键、场景、协议和模型组合持有独立缓存状态。运行与会话身份及响应步骤由 [scenario-engine](scenario-engine.md) 管理；不同 Session 即使共用 Agent、端点与相同请求也不共享缓存。带外关联信息不参与前缀比较。跨 Session 的真实供应商共享缓存不在本测试模型内。模型或协议切换使用各自分区，切回时是否仍有效由该分区的逻辑过期时间决定。

缓存比较使用服务实际收到的有序请求语义：System Prompt、工具定义、角色及内容块、工具调用与结果的标识和参数均保留。不能只比较可见文本、只保留工具名称、排序工具后认为等价，或由测试服务替客户端清理 Thinking 内容。协议层解析表示差异，但不得改变被测请求的顺序与内容。

自动计量使用内置的确定性模拟分词规则：把保留角色、块边界和顺序的请求内容规范编码后，每个 UTF-8 字节计为一个模拟 token，完整输入与各前缀均用同一规则计数；带外关联和缓存标记不计入内容。它是测试计量，不是对真实模型分词或计费的估算。需要真实采集数值的边界用例使用显式用量。不能用截断或偷偷改写数值掩盖用量冲突，校验阶段见下方「显式注入、缺失与自动生成」。

缓存连续性限于同一分区；切换场景意味着使用另一份缓存和时钟，不保证沿用原场景的命中。需要跨流式开关或参数变化验证连续缓存时，在同一场景的多步骤中编排，不把条件变化拆成不同场景后又假设它们共享状态。

### 前缀缓存模型

每个分区维护一条缓存前缀与一个到期点，不模拟真实供应商的多条前缀索引或容量策略。缓存比较有序内容的最长公共前缀，不要求增长后的完整请求指纹等于上次指纹。命中量只覆盖本次可缓存范围内、与未过期缓存相同的部分；写入量只计该范围中未命中的部分。

请求或标记范围缩短但现有内容未被改写时，只缩小本次可报告的命中范围，保留原先较长的未过期缓存；发生内容分叉则以本次可缓存内容替换旧分支，不保留多个历史分支。因此 A→B→A 不保证重用第一次的缓存，此为通用测试模型的明确边界。摘要替换、历史改写或 System Prompt 变化不重置场景响应步骤。

可缓存范围策略由场景声明，独立于用量的协议编码，不按协议名称推断供应商能力：

- **自动前缀（默认）**：可缓存范围为完整请求输入，不要求显式标记；两种协议均可使用这一通用测试模型。
- **显式标记**：仅适用于请求协议支持缓存标记的场景，范围截至当前请求最后一个有效标记；无标记时不建立、读取或刷新缓存。标记向后移动不等于内容被改写，匹配仍取该范围内与已缓存内容一致的公共前缀；标记本身不计入内容 token。

使用显式策略时保留标准标记的作用范围；有效标记须符合协议允许的位置和值，非法标记作为请求错误，不静默忽略。协议是否有标记表示、场景是否选择标记策略是两件事，不据此推断某供应商支持缓存。声明要求不支持标记表示的协议采用显式策略时拒绝加载。验证客户端是否正确打标记必须选显式策略，不能以默认前缀模型命中作为标记正确性的证据。

模型不包含具体模型的最小可缓存长度、供应商的查找窗口、收费折扣或容量淘汰策略。其目的为验证前缀稳定性和缓存用量处理，不据此证明某供应商必然命中。供应商特有行为由 [fixtures](fixtures.md) 所述供应商 fixture 体系验证。

| 输入条件 | 本次结果 | 提交后的缓存 |
|----------|----------|--------------|
| 首次请求或无有效缓存 | 命中为零，可缓存范围产生写入 | 保存本次可缓存内容与逻辑到期时间 |
| 前缀稳定或仅尾部追加，缓存有效 | 当前范围内的已缓存公共前缀命中；新增可缓存部分写入 | 扩展为本次可缓存内容 |
| 请求或标记范围缩短，内容仍是旧缓存的前缀 | 仅报告当前范围内命中，写入为零，记录范围变化 | 保留较长缓存，不当作内容断开 |
| 前缀内容分叉 | 公共部分命中，其余可缓存部分写入；记录前缀变化与命中变化 | 保存新的可缓存分支 |
| 逻辑时间已到期 | 命中为零，记录过期事件；本次即重新写入 | 保存本次可缓存内容 |
| 当前无可缓存范围 | 命中与写入均为零，记录无可缓存范围原因 | 不建立或刷新缓存；旧内容按原到期时间失效 |

断开和过期是可观测事件，不额外消耗一个请求步骤。日志保留前缀变化、范围变化、实际命中变化及显式注入原因，断开用例以声明并返回的命中骤降验证，不把细小内容变化自动等同于被测侧缓存异常。前缀扩展时可同时命中和写入；是否独立报告写入量仍受协议能力限制。

### 可控时间与生命周期

每个运行命名空间内，各匿名会话的各场景分别持有从零开始的逻辑时钟，只按本场景响应步骤声明的时间增量推进，默认增量为零。各模型/协议分区共享本场景时钟，各维护一个缓存到期点；未被调用的分区也随该时钟老化。有效期由场景配置，默认五分钟；逻辑时间达到到期点即失效。

一次决策先在暂存状态计算本步骤的新时间，再判断过期；只有决策成功才一起提交。有效命中或写入刷新本分区整条保留缓存的单一到期点，不按内容段分别计时。范围为空不刷新；无既有缓存的首请求是首次写入，不记为过期。

真实等待、流式投递间隔、客户端重试退避、机器快慢均不推进缓存时钟。测试者无需真实等待即可复现过期；同一请求序列和时间声明可重放出相同结果。HTTP 错误步骤可推进逻辑时间，但不命中、写入或刷新缓存。

此逻辑时钟只控制 Fake LLM。它不改变 CloseClaw 的调用时间或判定；需要验证被测方时间分支时，测试环境须另行控制其时间或实际等待，不能把服务端缓存已过期当成客户端已度过相同时长。运行命名空间释放时全部缓存与时钟一并清除，不用真实空闲回收改变行为。

### 显式注入、缺失与自动生成

可缓存范围策略与字段取值来源是独立维度。对场景允许匹配的协议集合均支持的缓存字段，分别选择显式数值（包括零）、声明缺失或自动生成；同一字段的矛盾声明在加载时拒绝。支持两个缓存字段的协议可为二者选择不同来源，未声明来源时采用自动生成。

显式注入覆盖本次报告数值，字段缺失则不输出该字段；两者不篡改前缀比较、逻辑时间和底层缓存演进。引擎仍计算并提交相同的自动状态，日志分别记录模拟事件与最终报告值，使下一步自动模式可复现。HTTP 错误不生成用量或缓存事件，断流不回滚已完成的缓存决策，规则见 [scenario-engine](scenario-engine.md)。

协议落点与输入总量合成规则唯一引用 [llm/protocol-mapping](../llm/protocol-mapping.md) 的用量字段表：OpenAI 无原生缓存写入字段，内部写入不向响应添加自定义字段；Anthropic 可独立返回缓存命中与缓存写入。显式要求 OpenAI 返回缓存写入量属于不支持的声明，明确报错；内部自动写入不等于该项声明。字段缺失保留为缺失，不伪造为零。

最终用量须非负，实际报告的缓存命中与缓存写入不重叠、二者之和不超过输入总量。总量未声明时采用上述自动计量；显式总量可不同于模拟分词计数，但仍须满足该分项约束，混合自动分项超出总量同样报错。Anthropic 的未缓存输入为总量减去实际报告的缓存分项，缺失分项在合成时按零处理；OpenAI 输出已含缓存部分的输入总量。不把内部缓存状态冒充为未报告字段，也不重复累加。

最终是否在响应中发送用量仍遵守协议开关，尤其 OpenAI 流式请求的用量开关；显式注入不绕过该前提，见 [delivery](delivery.md)。

加载时校验可静态确定的声明；只有结合实际请求才能判断的自动计量冲突在本次决策提交前校验，失败返回场景执行错误且不推进游标、时间或缓存。不能把未知请求的计量假装成加载时已经验证。

### 被测分支的输入

场景可构造前缀稳定命中、追加轮显式低命中、摘要替换或历史改写、System Prompt 或工具变化、模型切换、逻辑过期、字段缺失与显式零值。断开事件只说明测试输入的缓存前缀发生变化，不自行判定是否触发 CloseClaw 的异常通知。

缓存命中率、可比较调用、容忍余量与 Owner 通知均以 [llm 需求 F9](../../requirements/llm.md) 为产品权威，[session/llm-session-enhancements](../session/llm-session-enhancements.md) 为被测实现设计入口。本模块日志记录制造了什么输入，测试断言对照这些权威，不复制或修改其豁免清单。

## 数据流

1. 场景引擎交付运行命名空间、匿名会话键、场景身份、协议/模型、完整请求及本步骤的时间与用量声明。
2. 在暂存决策中计算本场景的新逻辑时间；HTTP 错误不读写缓存，其余请求定位独立缓存分区。
3. 解析可缓存范围，比较未过期内容的公共前缀，计算命中、写入、断开或过期事件。
4. 分字段应用显式值、缺失或自动结果，按协议能力与输入总量约束校验用量。
5. 与响应步骤一起提交缓存和时间状态，记录模拟事件与最终报告用量；协议层序列化后交 [delivery](delivery.md) 投递。
6. 运行命名空间释放时销毁其全部缓存状态。

## 模块关系

- **模块内上游**：[scenario-engine](scenario-engine.md) 提供运行与会话关联、响应步骤和请求语义，并持有状态生命周期。
- **模块内下游**：用量先返回 [scenario-engine](scenario-engine.md) 合成响应决策，再由 [endpoints](endpoints.md) 的协议层序列化、[delivery](delivery.md) 执行发送；不构成缓存组件直接调用端点。
- **跨模块**：[llm/protocol-mapping](../llm/protocol-mapping.md) 是协议映射权威；[llm/cache-adapter](../llm/cache-adapter.md) 是被测请求侧策略；[session/llm-session-enhancements](../session/llm-session-enhancements.md) 消费被测链路归一化的缓存用量。本模块以黑盒 HTTP 制造输入，不引用其 crate 或共享类型。

# KV Cache 前缀缓存模拟

## 概述

模拟真实供应商前缀缓存的完整生命周期——首次写入、后续命中、断开（命中量骤降）、过期——以确定性状态机驱动缓存字段的取值，使 CloseClaw 的缓存命中率统计与缓存命中一致性校验（定义于 [session/llm-session-enhancements](../session/llm-session-enhancements.md)）可被精确验证。一致性校验关注「追加扩展轮」上缓存命中数与上一轮输入 token 总数的偏差：缓存断开意味着请求前缀已变（不参与校验，属豁免）；追加扩展轮上的命中骤降才是触发缓存异常通知的典型输入。

## 架构

### 两种驱动模式

缓存字段的取值有两种驱动方式，显式优先：

| 模式 | 驱动方 | 适用场景 |
|------|--------|---------|
| 自动模拟（默认） | 状态机按请求前缀稳定性推导 | 验证 CloseClaw 缓存命中一致性校验对「真实供应商行为」的响应（含追加扩展轮判定、压缩/System Prompt 变化豁免） |
| 显式注入 | 测试者逐轮声明命中/写入 token 数 | 精确验证一致性校验判定（异常/豁免）、容忍余量边界、Owner 通知触发 |

自动模拟是默认行为：测试者只声明对话内容，缓存字段的演变由状态机自动给出符合真实供应商语义的序列。显式注入是覆盖行为：场景声明了缓存字段值时状态机让位，按声明值返回——用于构造自动模拟难以精确到达的边界（如「追加扩展轮上命中骤降至上一轮输入的三成」构造异常输入，或「压缩后首轮命中骤降」构造豁免输入）。两种模式可在同一场景的不同轮次混用。此外，字段缺失声明（模拟不返回缓存字段的供应商）是独立于两种驱动方式的第三种取值来源（声明字段缺省，不驱动取值，故不入上表），优先级介于显式注入与自动模拟之间，详见「用量字段的落点」。

### 前缀匹配状态机

自动模式的核心是「请求前缀指纹」：对每个请求计算除尾部新增消息外的稳定前缀的指纹（消息历史的公共前缀 + system prompt + 工具定义，按实际发送给 provider 的形态、取 Thinking 清理后）。状态机按指纹连续性转移：

1. 首请求 → **写入**
2. 写入 → 前缀稳定 → **命中**
3. 命中 → 前缀变化 → **断开**（单轮事件）→ 重新**写入**
4. 命中 → TTL 到期 → **过期**（回退全价）→ 下一请求 → **写入**

- **写入**：首次见到某前缀，响应的缓存写入字段（cache write）计前缀 token 数，命中字段为 0
- **命中**：前缀与状态机记录的指纹一致，响应的缓存命中字段（cache read）计前缀 token 数（该前缀即上一轮请求的完整输入，故命中量与上一轮输入 token 总数相符），写入为 0
- **断开**（单轮事件，非持久状态）：前缀指纹变化（消息历史被改写、system prompt 变动、工具集变动），新前缀不匹配旧缓存——该轮命中骤降（残留部分命中按新旧前缀公共部分推导）或归 0，随即重新写入。断开轮的前缀已变，属缓存命中一致性校验的豁免情形（不参与校验）
- **过期**：距上次命中超过 TTL 窗口（可配置，默认模拟真实供应商的 5 分钟量级），缓存失效，下轮重新写入（回退全价）。TTL 默认值与供应商缓存有效期一致，以便与 [session/llm-session-enhancements](../session/llm-session-enhancements.md) 的「缓存自然过期」豁免判定对齐

前缀指纹的计算与协议无关：OpenAI 的自动前缀缓存与 Anthropic 的显式 `cache_control` 标记在服务端行为上一致（前缀相同即命中），状态机不为两种协议维护不同语义。Anthropic 请求携带 `cache_control` 标记时，标记本身不改变状态机决策——真实供应商中标记只是请求方声明，命中与否仍由前缀决定。

### 一致性校验的输入边界用例

状态机须能制造一致性校验各分支所需的输入形态（判定口径以 [session/llm-session-enhancements](../session/llm-session-enhancements.md) 为权威）：

- **追加扩展轮 + 命中正常**：前缀稳定的连续轮次，命中量与上一轮输入相符
- **追加扩展轮 + 命中骤降**：显式注入使某追加扩展轮的命中量远低于上一轮输入
- **压缩后首轮**：上下文被整体替换，前缀变化
- **System Prompt 变化轮**：前缀变化
- **历史被改写轮**：前缀变化
- **模型/供应商切换轮**：本轮模型或供应商与上一轮不同（分词口径不可比）
- **自然过期轮**：上一轮与本轮间隔超过缓存有效期（本轮命中预期为 0）
- **响应缺缓存字段**：字段缺失声明

### 用量字段的落点

状态机产出的命中/写入 token 数填入响应的用量字段，协议原生位置为：

- **OpenAI**：`usage.prompt_tokens_details.cached_tokens`（命中）。写入字段无协议原生位置，OpenAI 协议下不模拟显式写入量
- **Anthropic**：`usage.cache_read_input_tokens`（命中）、`usage.cache_creation_input_tokens`（写入）；`input_tokens` 计本轮未命中缓存的输入部分，与 [protocol-mapping](../llm/protocol-mapping.md) 的「输入 token 总数 = `input_tokens` + `cache_read_input_tokens` + `cache_creation_input_tokens`」口径一致

完整字段形状以 [llm/protocol-mapping](../llm/protocol-mapping.md) 的用量字段形状表为权威。字段可缺失（模拟不返回缓存字段的供应商），缺失声明优先于自动模拟。

### 命中量数值的确定性

自动模式下命中/写入的具体 token 数由前缀的确定性函数推导——该函数以前缀的 token 计量为基准（与响应返回的输入 token 口径一致，不使用字符数折算），断开轮的残留命中按新旧前缀公共部分推导；同一场景同一输入永远得到相同数值，不引入随机性，保证测试可重复执行，并使「追加扩展轮命中正常」等一致性校验用例可按设计意图验证。

## 数据流

1. 场景引擎产出响应决策
2. 缓存字段填充，按优先级取其一：
   - **显式注入**：按声明值填充，状态机记录但不干预取值
   - **字段缺失声明**：不填充
   - **自动模拟**：请求前缀指纹计算，结果四选一——
     - 指纹未见过（首请求/断开后）→ 写入值填充，记录指纹
     - 指纹与记录一致且未过 TTL → 命中值填充，刷新 TTL
     - 指纹与记录一致但已过 TTL → 写入值填充（回退全价），重置 TTL
     - 指纹与记录不一致 → 断开：命中骤降（或残留部分命中），重新写入
3. 自动模拟路径的命中/断开/过期事件写入测试日志（可观测性；显式注入与缺失声明无状态机事件）
4. 用量字段随响应交 [delivery](delivery.md) 投递

## 模块关系

- **模块内上游**：[scenario-engine](scenario-engine.md)（响应决策触发缓存字段推导；前缀指纹依赖其会话识别）
- **模块内下游**：[delivery](delivery.md)（填充后的用量随响应投递）
- **跨模块（被测行为权威）**：缓存命中率统计与缓存命中一致性校验 → [session/llm-session-enhancements](../session/llm-session-enhancements.md)；前缀稳定性原则与缓存策略（显式标记 vs 自动前缀）→ [llm/cache-adapter](../llm/cache-adapter.md)、[llm](../llm/README.md)。本模块只制造输入（缓存字段序列），不定义被测方如何统计与校验

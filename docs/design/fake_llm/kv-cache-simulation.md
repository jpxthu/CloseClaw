# KV Cache 前缀缓存模拟

## 概述

以确定性的测试模型制造缓存首次写入、连续命中、前缀断开和过期的用量序列，支持自动生成与逐次显式注入，验证 CloseClaw 的缓存统计和异常处置。它不复刻具体供应商或模型的缓存服务，也不定义被测方的正确结果。

## 架构

### 隔离与计量基础

每个运行命名空间、匿名会话键、协议和模型组合持有独立缓存状态；场景不参与分区，只决定可缓存范围策略与用量来源。无会话键的无状态场景不建立缓存分区，见 [scenario-engine](scenario-engine.md)。运行与会话身份及响应步骤由场景引擎管理；不同 Session 即使共用 Agent、端点与相同请求也不共享缓存。带外关联信息不参与前缀比较。跨 Session 的真实供应商共享缓存不在本测试模型内。模型或协议切换使用各自分区，切回时是否仍有效由该分区的逻辑过期时间决定。

缓存比较使用服务实际收到的有序请求语义：System Prompt、工具定义、角色及内容块、工具调用与结果的标识和参数均保留。不能只比较可见文本、只保留工具名称、排序工具后认为等价，或由测试服务替客户端清理 Thinking 内容。协议层解析表示差异，但不得改变被测请求的顺序与内容。推理控制参数、`tool_choice`、`stop`、`max_tokens` 与流式开关不参与前缀比较；其中流式开关与推理控制参数可用于场景匹配，其余参数既不参与匹配也不参与前缀比较。

该比较是语义级而非字节级：客户端序列化抖动（键序、空白、转义形式）在本模型中视为同一前缀。本模型不覆盖字节级前缀稳定性，该类用例由真实采集响应与被测侧的缓存适配规则验证。

自动计量使用内置的确定性模拟分词规则：把参与比较的全部内容（System Prompt、工具定义、消息与工具结果的角色、块类型、顺序和内容）按统一规则规范编码，每个 UTF-8 字节计为一个模拟 token；完整输入与各前缀用同一规则计数，单元之间不计分隔符，保证前缀计数可累加。带外关联和缓存标记不计入内容。它是测试计量，不是对真实模型分词或计费的估算。需要真实采集数值的边界用例使用显式用量。不能用截断或偷偷改写数值掩盖用量冲突，校验阶段见下方「显式注入、缺失与自动生成」。

同一对话在两种协议下的规范编码形态不同，模拟 token 数不必相等；计量只用于同一协议内的可复现比较，不用于跨协议数值对比。

缓存连续性限于同一分区；切换场景不重置缓存与时钟，场景只改变可缓存范围策略与用量来源，策略改变按范围变化处理，仍取新范围内与已缓存内容的公共前缀。模型或协议切换进入各自分区，不保证沿用原命中。需要跨流式开关验证连续缓存时，在同一场景的多步骤中编排。

### 前缀缓存模型

每个分区维护一条缓存前缀与一个到期点，不模拟真实供应商的多条前缀索引或容量策略。缓存比较有序内容的最长公共前缀，不要求增长后的完整请求指纹等于上次指纹。命中量只覆盖本次可缓存范围内、与未过期缓存相同的部分；写入量只计该范围中未命中的部分。

请求或标记范围向请求头部收缩但现有内容未被改写时，只缩小本次可报告的命中范围，保留原先较长的未过期缓存；发生内容分叉则以本次可缓存内容替换旧分支，不保留多个历史分支。因此 A→B→A 不保证重用第一次的缓存，此为通用测试模型的明确边界。摘要替换、历史改写或 System Prompt 变化不重置场景响应步骤。

可缓存范围策略由场景声明，独立于用量的协议编码，不按协议名称推断供应商能力：

- **自动前缀（默认，范围策略）**：可缓存范围为完整请求输入，不要求显式标记；两种协议均可使用这一通用测试模型。
- **显式标记（范围策略）**：仅适用于请求协议支持缓存标记的场景，范围截至当前请求最后一个有效标记；无标记时不建立、读取或刷新缓存。标记向请求尾部移动表示范围扩大，向头部移动表示范围收缩；匹配仍取该范围内与已缓存内容一致的公共前缀；标记本身不计入内容 token。

使用显式策略时保留标准标记的作用范围；每个标记的位置和值须符合协议允许范围，位置或值非法作为请求错误，不静默忽略。断点数量上限与最小可缓存长度不建模：超过某供应商实际断点上限的请求照常接受，并在日志中标注该差异。场景选择显式策略而所选协议没有标记表示时拒绝加载。验证客户端是否正确打标记必须选显式策略，不能以默认前缀模型命中作为标记正确性的证据。

模型不包含具体模型的最小可缓存长度、供应商的查找窗口、收费折扣或容量淘汰策略。命中判定只在本场景声明的可缓存范围与未过期缓存之间比较最长公共前缀，不等同于任何供应商的命中规则；前缀相同而未命中、未达供应商最小可缓存长度、或超出其断点数量的情形，以真实采集为事实验据，不在本模型的预测范围内。供应商特有行为由 [fixtures](fixtures.md) 的真实采集响应验证。

| 输入条件 | 本次结果 | 提交后的缓存 |
|----------|----------|--------------|
| 该分区从未建立缓存 | 命中为零，可缓存范围产生写入 | 保存本次可缓存内容与逻辑到期时间 |
| 前缀稳定或仅尾部追加，缓存有效 | 当前范围内的已缓存公共前缀命中；新增可缓存部分写入 | 扩展为本次可缓存内容 |
| 请求或标记范围收缩，内容仍是旧缓存的前缀 | 仅报告当前范围内命中，写入为零，记录范围变化 | 保留较长缓存，不当作内容断开 |
| 前缀内容分叉 | 公共部分命中，其余可缓存部分写入；记录前缀变化与命中变化 | 保存新的缓存分支 |
| 该分区曾建立缓存且逻辑时间已达到期点 | 命中为零，记录过期事件；本次即重新写入 | 保存本次可缓存内容 |
| 当前无可缓存范围 | 命中与写入均为零，记录无可缓存范围原因 | 不建立或刷新缓存；旧内容按原到期时间失效 |

断开与过期是可观测事件，不额外消耗一个请求步骤。断开指同一分区本次报告命中量低于上一成功请求，且该次决策记录了前缀分叉或范围收缩；日志记录上一命中量、本次命中量、前缀与范围变化原因。过期指曾建立缓存的分区在成功请求读取时已越过到期点。两者都以本次决策的记录为准，不按真实时间回溯推断。

### 可控时间与生命周期

每个运行命名空间内，各匿名会话持有从零开始的逻辑时钟，只按当前响应步骤声明的时间增量推进，默认增量为零，同一会话的各场景共享该时钟。各模型/协议分区维护自己的缓存到期点；未被调用的分区也随该时钟老化。有效期由场景配置，默认五分钟；逻辑时间达到到期点即失效。

一次决策先在暂存状态计算本步骤的新时间，再判断过期；只有决策成功才一起提交。本次命中量或写入量大于零时刷新本分区整条保留缓存的单一到期点，不按内容段分别计时；命中与写入均为零不刷新。范围为空不刷新；无既有缓存的首请求是首次写入，不记为过期。

真实等待、流式投递间隔、客户端重试退避、机器快慢均不推进缓存时钟。测试者无需真实等待即可复现过期；同一请求序列和时间声明可重放出相同结果。HTTP 错误步骤可推进逻辑时间，但不命中、写入或刷新缓存，也不判定或记录过期；过期在之后该分区被成功读取时判定并记录。

此逻辑时钟只控制 Fake LLM。它不改变 CloseClaw 的调用时间或判定；需要验证被测方时间分支时，测试环境须另行控制其时间或实际等待，不能把服务端缓存已过期当成客户端已度过相同时长。

### 显式注入、缺失与自动生成

推理消耗、缓存命中与缓存写入三个分项各自选择取值来源：显式数值（包括零）、声明缺失或自动生成；输入与输出必填，按场景声明或自动计量得出。同一字段的矛盾来源声明在加载时拒绝，不同分项可选择不同来源，未声明来源时采用自动生成。来源与协议落点是两个独立维度：响应只报告落点在所选协议存在的分项，来源决定该分项报告什么值或是否缺失。

- **显式**：报告声明的数值。注入值覆盖本次报告值，不篡改前缀比较、逻辑时间和底层缓存演进；注入值是构造输入，不是供应商实测基准。
- **缺失**：不输出该字段，不伪造为零。
- **自动**：报告引擎按测试模型算出的命中或写入量。自动命中随前缀稳定性变化；自动写入是内部缓存演进的计量结果，日志标注来源为自动，不得冒称为供应商实测值，也不得由它断言真实供应商会返回同值。

无论选择哪种来源，引擎仍计算并提交相同的自动状态，日志分别记录模拟事件与最终报告值，使下一步自动模式可复现。HTTP 错误不生成用量或缓存事件，断流不回滚已完成的缓存决策，规则见 [scenario-engine](scenario-engine.md)。

协议落点与输入总量合成口径唯一见 [llm/protocol-mapping](../llm/protocol-mapping.md) 的用量字段表，本文不复述各协议字段位置。某分项在所选协议没有落点时，响应按缺失处理：不报错、不改写数值，并在日志标注该声明未被该协议承载；不得把写入计入命中、未命中或输入总量字段，也不得新增非标准字段。实采出现新的落点后按实采扩展，不因当前未采到而判定协议不支持。

最终用量须非负，实际报告的缓存命中与缓存写入不重叠、二者之和不超过输入总量。总量未声明时采用自动计量；显式总量可不同于模拟分词计数，但仍须满足该分项约束，混合自动分项超出总量同样报错。分项缺失不参与该校验，也不补造为零。显式总量只改变本轮报告值，自动命中仍按模拟分词计算；跨轮混用会让被测方一致性校验的参考值与本轮自动命中不同源，日志须标注来源以便核对。

加载时校验可静态确定的声明；只有结合实际请求才能判断的自动计量冲突在本次决策提交前校验，失败返回场景执行错误且不推进游标、时间或缓存。不能把未知请求的计量假装成加载时已经验证。

### 被测分支的输入

场景可构造前缀稳定命中、追加轮显式低命中、摘要替换或历史改写、System Prompt 或工具变化、模型切换、逻辑过期、字段缺失与显式零值。断开事件只说明测试输入的缓存前缀发生变化，不自行判定是否触发 CloseClaw 的异常通知。

两类构造通常进入被测方的异常路径，测试断言须按此预期：逻辑过期造成的命中归零在真实时间维度通常不满足自然过期豁免条件；模型或协议切换造成的分区切换对被测方不可见，其命中归零表现为前缀未扩展。需要验证豁免分支时，须另行控制被测方时间或实际等待，不能把这两类构造当作豁免用例。被测方的豁免清单以需求与 session 设计为准，本模块不扩充。

缓存命中率、可比较调用、容忍余量与 Owner 通知均以 [llm 需求 F9](../../requirements/llm.md) 为产品权威，[session/llm-session-enhancements](../session/llm-session-enhancements.md) 为被测实现设计入口。本模块日志记录制造了什么输入，测试断言对照这些权威，不复制或修改其豁免清单。

## 数据流

1. 场景引擎交付运行命名空间、匿名会话键、场景身份、协议/模型、完整请求及本步骤的时间与用量声明。
2. 在暂存决策中计算本场景的新逻辑时间；HTTP 错误不读写缓存，其余请求定位独立缓存分区；无状态请求不进入本路径。
3. 解析可缓存范围，比较未过期内容的公共前缀，计算命中、写入、断开或过期事件。
4. 分字段应用显式值、缺失或自动结果，按协议落点与输入总量约束校验用量。
5. 与响应步骤一起提交缓存和时间状态，记录模拟事件、来源与最终报告用量；协议层序列化后交 [delivery](delivery.md) 投递。
6. 运行命名空间释放时销毁其全部缓存状态。

## 模块关系

- **模块内上游**：[scenario-engine](scenario-engine.md) 提供运行与会话关联、响应步骤和请求语义，并持有状态生命周期。
- **模块内下游**：用量先返回 [scenario-engine](scenario-engine.md) 合成响应决策，再由 [endpoints](endpoints.md) 的协议层序列化、[delivery](delivery.md) 执行发送；不构成缓存组件直接调用端点。
- **跨模块**：[llm/protocol-mapping](../llm/protocol-mapping.md) 是协议映射与用量落点的权威；[llm/cache-adapter](../llm/cache-adapter.md) 是被测请求侧策略；[session/llm-session-enhancements](../session/llm-session-enhancements.md) 消费被测链路归一化的缓存用量。本模块以黑盒 HTTP 制造输入，不引用其 crate 或共享类型。

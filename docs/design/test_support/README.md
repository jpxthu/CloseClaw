# test_support

## 概述

- 关联需求文档：无（不提供 User / Agent 可感知的产品行为）
- test_support 是跨 crate 共享的**编译期测试基础设施**：为各 crate 的测试提供统一的**依赖边界守卫**，把 [依赖方向允许边表](../STANDARDS.md) 对 workspace 内部依赖的约束逐 crate 机械校验，使任一 crate 的 manifest 一旦越界即在测试期暴露。它是开发 / 测试工具，不进入发布构建，不参与产品运行。

## 架构

test_support 的定位是 [依赖方向允许边表](../STANDARDS.md) 中的**测试基础设施**（与 [fake_llm](../fake_llm/README.md) 同层），只承担一个内聚能力——**依赖边界守卫**，自身不引用任何其它模块。

守卫由下列部件构成，沿「解析 → 判定 → 断言」单向串接：

- **manifest 解析器**：以标准 TOML 文法解析目标 crate 的 manifest，不依赖手写扫描，对形近段名（如 `[workspace.dependencies]`、`[package.metadata.dependencies]`）、带点或带引号的 target 键等边界形态给出确定结果。
- **依赖分类与内部成员判定器**：把依赖按声明段分为常规（含 target 限定的常规依赖）、测试期、构建期三类，仅常规依赖参与判定（与允许边表口径一致）；再判定一条常规依赖是否指向 workspace 内部成员——显式路径声明，或经根清单 `[workspace.dependencies]` 继承而来——以区分内部成员与外部 crate。
- **边界规约**：由调用方声明，含三类约束——允许的 workspace 内部依赖集合、仅允许出现在测试 / 构建期的内部依赖、按名禁止出现在常规段的依赖。
- **断言器**：按边界规约对常规段的内部依赖判定越界，越界时列出越界项。

调用方为各 crate 的测试，边界规约随调用传入。四个部件同属一个守卫、不可独立使用，故本模块为单一内聚能力，无独立子功能文档。

## 数据流

某 crate 的测试启动 → 守卫读取该 crate 的 manifest → 解析并分类各依赖段 → 取常规段（含 target 限定）中的 workspace 内部依赖 → 与调用方声明的边界规约比对 → 有规约外的内部依赖即失败并列出越界项，否则通过。

关键判断点与分支：

- 非 workspace 内部依赖（外部 crate）不参与判定；
- 测试期 / 构建期依赖不参与判定——其越界不由本守卫负责；
- 经根清单继承而来的内部依赖，按根清单解析其真实来源后再判定，避免把外部 crate 误判为内部成员。

## 模块关系

> 「上游 / 下游」指调用与数据流关系，不等于 crate 依赖；crate 依赖以 [依赖方向允许边表](../STANDARDS.md) 为准。

- **上游**：各 crate 的测试（以 dev-依赖引用本守卫，传入本 crate 的 manifest 与允许集）。属测试代码的调用，非产品模块调用。
- **下游**：无。守卫不调用任何其它模块。
- **无关**：[fake_llm](../fake_llm/README.md)——同为测试基础设施（在依赖边表中同层，该分层只反映依赖口径、不反映运行时形态），但它是黑盒运行时服务（于回环地址模拟 LLM 协议），与本模块的编译期依赖边界守卫职责不同、不重叠。
- **共享类型**：无。守卫只读取 manifest、产出断言结果，不向其它模块传递共享数据结构。

依赖边界规则的**唯一权威定义**在 [依赖方向允许边表](../STANDARDS.md)；本模块只实现其机械判定，不另行定义规则，各 crate 测试中声明的允许集以该表为准。

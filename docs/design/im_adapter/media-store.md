# 媒体存储

## 概述

媒体存储是 IM Adapter 的通用子功能（平台无关）：定义入站媒体落盘、出站媒体读取、Agent 上下文中的媒体形态与媒体生命周期管理。目标：媒体内容可被 Agent 使用、不随平台侧链接过期而失效，且本地文件系统路径不暴露给 Agent 上下文。

## 架构

### 存储布局

统一媒体存储目录（路径由 [config media.json](../config/README.md) 配置），按方向分两个子目录：

- **入站子目录**（inbound/）：入站消息携带的媒体落盘
- **出站子目录**（outbound/）：Agent 发出的媒体保留副本（审计与重发）

文件命名：保留经安全净化的原始文件名（去除路径分隔符、控制字符等），附加唯一后缀防止冲突。每份媒体记录文件大小与 MIME 类型。

### 媒体引用（MediaRef）

媒体引用是系统内消费媒体的唯一形态（[MediaRef 结构](../common/shared-types.md#normalizedmessage)）——入站 Adapter 落盘后填充，包含本地存储路径；平台侧下载地址与下载凭证仅在 Adapter 下载瞬间使用，不进入 MediaRef、不跨模块传递。下游模块一律以引用消费媒体，不感知下载过程。

### 入站落盘

平台插件在入站解析阶段识别消息携带的媒体资源（图片、文件等），立即下载并写入入站子目录，随后填充 NormalizedMessage 的 media_refs。下载失败与超出大小上限的媒体不落盘、不进 media_refs，其资源标识记入 NormalizedMessage 的 unavailable_media 字段，作为 Gateway 触发「媒体不可得」提示的依据（载体定义见 [common 共享类型](../common/shared-types.md#normalizedmessage)）。

### 上下文形态

含媒体的消息经 Gateway 路由时，按媒体类型与可得性决定进入 LLM 上下文的形态（决策执行方为 Gateway，规则定义于此）。

两个大小概念的边界：**大小上限**是媒体内容可获得的约束——超出上限时平台/系统不提供媒体内容，媒体不可得；**大小阈值**是图片「内容 vs 引用」的形态分界——超过阈值的图片仍可得，以媒体引用进入上下文。

| 媒体状态 | 上下文形态 |
|---------|-----------|
| 图片，大小不超过阈值（阈值由 media.json 配置） | 图片内容直接进入对话历史与 LLM 请求，Agent 可直接看图 |
| 图片，超过大小阈值 | 媒体引用进入上下文 |
| 文件、音频等非图片媒体 | 媒体引用进入上下文，Agent 通过引用使用媒体内容 |
| 媒体不可得（下载失败、超出大小上限——媒体内容无法获得，标识在 unavailable_media 中） | 不进入 LLM 对话——Gateway 向用户提示「该消息内容无法获取」（经简化出站路径），消息流程结束 |

**媒体引用的文本表示**：媒体引用在上下文文本中以引用记号呈现（含资源标识与文件名），**不出现本地文件系统路径**——路径对 Agent 与 LLM 不可见。

**媒体引用解析**：Agent 使用媒体（读取、分析、转发）发生在工具执行边界——工具执行前，系统将其上下文中的媒体引用翻译为媒体存储内的本地文件路径供本次执行读取；翻译仅作用于当次工具执行，不进入工具参数持久化与日志正文。引用无法解析时工具收到清晰错误。

### 出站读取

Agent 发送媒体时，出站内容以媒体引用（先前收到的媒体）或工作区内路径（Agent 生成的文件）表示：

- **相对路径**：相对路径基于当前 Session 工作区解析为绝对路径
- **来源白名单**：系统仅从工作区目录与媒体存储目录读取待发送文件；解析后范围外路径拒绝发送并返回清晰错误
- **保留副本**：发出的媒体先复制到出站子目录，再上传发送

### 生命周期

- **保留期清理**：媒体存储后台定时任务按固定保留期清理入站与出站媒体（保留期可配置，默认 7 天；设为 0 表示禁用定期清理）。保留期属媒体配置项，变更后自下一次清理扫描起生效（边界生效类），配置重载机制见 [config 热重载](../config/hot-reload.md)，需求见 [im_adapter §F4](../../requirements/im_adapter.md)
- **Session 联动清理（可选、低优先级）**：跟随 Session 生命周期清理对应媒体——Session 被清理（purge）且不再被任何 Session 引用时清理其关联媒体；归档不算清理。此机制为可选项，可不实现；若实现，以低优先级执行，不影响系统正常使用。实现载体为 ArchiveSweeper 职责扩展（媒体引用查询），见 [session-lifecycle](../session/session-lifecycle.md)
- 两种机制同时启用时互不依赖，各自独立执行

## 数据流

### 入站

```
1. 平台消息（含媒体）到达，插件解析识别媒体资源
2. 立即下载，写入入站子目录（净化文件名 + 唯一后缀，记录 size/mime）；下载失败或超出大小上限时不落盘，资源标识记入 unavailable_media
3. 填充 NormalizedMessage.media_refs（本地引用）
4. Gateway 路由按「上下文形态」决策（图片内容 / 媒体引用 / 不可得提示）
5. 工具执行时按「媒体引用解析」翻译为本地路径
```

### 出站

```
1. Agent 输出媒体引用或工作区路径
2. 相对路径按工作区解析为绝对路径
3. 来源白名单校验（工作区 / 媒体存储，越界拒绝并返回清晰错误）
4. 复制到出站子目录
5. 上传发送
```

## 模块关系

- **所属**：IM Adapter 模块的通用子功能，与代码块渲染、流式渲染并列
- **上游**：Gateway（路由时消费上下文形态决策）、各平台插件（入站落盘与出站读取的执行方）
- **下游**：Session（对话历史中的媒体内容块/引用随消息持久化）、Tools（工具执行边界的媒体引用解析）、LLM（图片内容块经协议映射进入请求，模型不支持图片输入时按媒体引用降级，见 [llm model-discovery](../llm/model-discovery.md) 输入能力）
- **相关模块**：Config（media.json：存储目录、图片阈值、保留期；大小上限为平台可得性约束、非本模块配置项）、debug_log（落盘、越界拒绝、清理各环节记录日志）
- **无关**：Processor Chain（media_refs 入站仅透传，形态决策在 Gateway）、Permission（媒体读取不经过权限检查——白名单即边界）

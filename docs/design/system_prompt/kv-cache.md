# 边界标记与前缀缓存

## 概述

边界标记是 System Prompt 静态层和动态层之间的分隔锚点。System Prompt 模块在组装完成后以边界标记为切分点，将全文拆分为静态区和动态区两个独立字段，作为缓存适配层的输入。本模块负责「不变/变化内容的划分」和「前缀稳定性保证」；切分后各字段的缓存控制参数注入策略由缓存适配层按供应商适配，详见 [llm/cache-adapter](../llm/cache-adapter.md)。

## 架构

### 边界标记

静态层和动态层之间通过 `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` 标记分隔。标记在静态层之后、动态层之前，追加区位于动态层之后、对话历史之前。System Prompt 模块以标记为切分点将全文分离：标记之前（静态层）为静态区字段，标记之后（动态层 + 追加区）为动态区字段，两个字段作为独立字段传递给缓存适配层。

标记是 System Prompt 模块与缓存适配层之间的接口合约——System Prompt 模块负责切分并传递分离后的字段（静态区、动态区），缓存适配层负责按供应商策略处理各字段。切分契约保证静态区在 Session 生命周期内字节不变、动态区（含追加区）每次请求即时构建，两者边界清晰，使缓存层能识别可缓存的前缀范围。接口细节详见 [llm/cache-adapter](../llm/cache-adapter.md)。

### 前缀缓存

静态区内容在 Session 生命周期内保持字节稳定，动态区每次请求即时构建、不参与显式前缀缓存（但服务端自动前缀缓存的供应商仍可因稳定前缀获益）。本模块保证前缀稳定性；静态区的显式缓存标记、动态区的非缓存处理等供应商特定适配由缓存适配层完成，详见 [llm/cache-adapter](../llm/cache-adapter.md)。

## 数据流

```
1. System Prompt 组装完成（静态层 + 边界标记 + 动态层 + 追加区）
2. System Prompt 模块以边界标记为切分点，分离为静态区字段（静态层）和动态区字段（动态层 + 追加区）
3. 缓存适配层接收已分离的字段，按供应商策略处理（详见 llm/cache-adapter.md）
4. 发送 LLM 请求
```

## 模块关系

### 上游

- **System Prompt 构建流程**：静态层构建完成后、动态层之前插入边界标记。

### 下游

- **缓存适配层（Cache Adapter）**：接收 System Prompt 模块切分好的静态区和动态区字段，按供应商策略处理。缓存控制参数的具体注入策略见 [llm/cache-adapter](../llm/cache-adapter.md)。

### 无关

- **Compaction 模块**：边界标记不参与对话消息压缩。压缩后触发 System Prompt 重建，静态层重建时边界标记随之重新定位。
- **追加区**：追加区位于动态层之后、边界标记之后，不参与前缀缓存。

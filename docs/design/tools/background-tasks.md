# 后台任务

## 概述

后台任务系统为 agent 提供异步命令执行能力。agent 触发长运行命令后无需阻塞等待，命令在后台继续执行，完成后通过通知机制将结果注入 agent 对话流。系统还提供自动后台化、运行中任务查看、任务终止、卡死检测等运维能力。

## 架构

后台任务系统由任务管理器和通知系统协同工作。任务管理器内部包含输出管理、卡死检测等子组件：

```
agent 提交后台命令
    │
    ▼
任务管理器 ──→ 创建任务（状态：running）
    │              │
    ├─ 输出管理器 ──→ 输出写入磁盘文件
    │              │
    ├─ 卡死检测器 ──→ 监控输出停滞，识别交互式提示
    │              │
    ├─ 终止 ──→ 更新状态（killed）
    │
    └─ 进程退出 ──→ 更新状态（completed / failed）
                     │
                     ▼
              通知系统 ──→ 向 agent 注入完成消息
```

### 任务状态机

后台任务的生命周期包含以下状态：

```
        创建
         │
         ▼
      running ────────────────→ killed（被终止）
         │
         ▼
    ┌─────────────┐
    │ completed   │（退出码 0）
    │ failed      │（退出码非 0）
    └─────────────┘
```

状态变迁不可逆。正常路径由进程退出事件驱动（exit 0 → completed，非 0 → failed）；killed 是外部触发的终态（agent 主动终止或系统清理），不等待退出事件——一旦进入 killed 状态，后续进程退出通知被忽略。

任务启动及每次进入终态（completed / failed / killed）时，通过调试日志框架记录关键事件（含任务标识、命令文本、新状态）。后台任务属非 webhook 内部事件，追踪标识由本模块自行生成（见 [debug_log/README.md](../debug_log/README.md)）。

### 两种后台化路径

#### 显式后台化（run_in_background）

agent 调用 BashTool 时设置 `run_in_background: true`，命令立即转入后台。agent 在返回结果中获得 `backgroundTaskId` 和输出文件路径，无需等待即可继续工作。命令完成后，通知系统向 agent 注入格式化的完成消息。

#### 自动后台化

agent 以前台模式调用 BashTool 时，有两种方式触发自动后台化：

- **agent 显式设置超时**：agent 调用命令时传入超时参数（如 `timeout: 30s`），命令运行超过该时长后自动转为后台继续运行。超时参数有系统上限，防止 agent 设定过长超时使机制失效。
- **系统阻塞预算兜底**：agent 未设置超时参数时，使用系统默认阻塞预算（15 秒），命令超过 15 秒后自动转为后台

转后台后返回 `assistantAutoBackgrounded: true` 和 `backgroundTaskId`，告知 agent 命令仍在执行。此机制确保长时间编译、测试等操作不会让 agent 陷入无响应的等待状态。

自动后台化有命令白名单排除机制，仅作用于系统阻塞预算兜底路径：`sleep` 等已知无实际工作的命令不因预算到期被转后台（前台继续执行，受总执行时长兜底约束），避免产生无意义的后台任务和通知噪音。agent 显式设置超时的命令不受白名单排除，超时后一律转后台。

命令的时间约束分三层，各管一段：
- **阻塞预算（15 秒）**：决定前台命令是否转后台，到期未完成即转后台，不终止命令
- **超时参数上限（10 分钟）**：约束 agent 可设置的超时时长，超上限被钳制（见 [bash-tool.md](bash-tool.md) 超时控制）
- **总执行时长上限**：单条命令整个生命周期（含前台阶段与后台阶段）的最后防线，到期强制终止，必然大于超时参数上限，否则“超时后转后台”机制形同虚设

### 输出管理

后台命令的输出写入磁盘文件，而非内存累积。agent 可通过文件读取工具按需查看输出内容。输出文件按 session 隔离存放于系统临时目录。

输出文件的生命周期与 session 绑定：
- 任务执行中：输出持续写入
- 任务进入终态（completed / failed / killed）后：输出保留可读，直至 session 销毁，不受 session 停止影响
- session 销毁时：该 session 全部后台任务的输出（含各终态）一并回收，无需 agent 手动清理（session 销毁仅由按时间清理触发，归档不是销毁，见 [session/session-lifecycle.md](../session/session-lifecycle.md)）
- session 存续期间网关重启：输出保留，仍可回读
- 系统重启：临时目录丢失，输出不可恢复

### 卡死检测

后台任务运行期间，系统监控输出文件的增长速率。当输出在 45 秒内无增长，且尾部内容匹配交互式提示特征（如 `(y/n)`、`Continue?`、`Are you sure?` 等），系统判定命令被交互式提示卡住，向 agent 注入警告通知，建议终止任务并以管道输入方式重新运行。

仅慢速但有效的命令（如大型构建、长时间计算）不会触发卡死检测——检测只在尾部内容疑似交互式提示时才告警。

### 总执行时长兜底

每条后台命令有总执行时长上限（系统配置，必然大于超时参数上限，见自动后台化的三层时间约束）。任务达到上限仍未退出时，系统强制终止（状态 killed）、记调试日志并向 agent 注入通知。该机制与卡死检测互补：卡死检测识别交互式卡住，总时长兜底约束真慢任务，确保单个命令不会无限期占用资源。白名单命令前台执行期间同样受此上限保护。

### 通知机制

任务完成或卡死时，系统生成结构化通知消息注入 agent 的消息队列。通知包含：

- 任务标识（taskId）
- 输出文件路径
- 完成状态（completed / failed / killed）
- 原始命令文本（command）
- 操作建议（suggestion）——卡死警告等需要 agent 采取行动的场景附带
- 可读摘要（"Background command '&lt;command&gt;' completed"）

通知有三种优先级，决定消息在队列中的顺序和展示前缀。所有优先级的通知在同一轮对话中注入，区分仅在于队列顺序和前缀：

- **now**：最高优先级，排在其他通知之前，展示前缀标示紧急。用于系统级通知
- **next**：中等优先级，展示前缀标示需要 agent 及时关注。用于卡死警告等场景
- **later**：最低优先级，展示前缀为普通标记。用于后台命令完成通知

通知带去重保护：同一任务只发一次通知，防止消息队列中重复注入。

### 提示词引导

为防止 agent 在后台任务执行期间做无意义的轮询，系统提示词中明确注入以下行为约束：

- **不需要立即检查输出**：告知 agent 后台命令完成后会自动收到通知，无需主动查询状态
- **不主动 poll**：agent 不应调用进程查询工具去检查后台任务是否完成。push-based 通知机制保证 agent 在下一轮对话中自动看到结果
- **使用 run_in_background 的建议场景**：预计运行时间超过 10 秒的命令应显式后台化，不阻塞 agent 的后续工作

工具描述（BashTool 的 `description` 字段）中也直接嵌入此指引，确保 agent 在每次决定是否后台化时能看到行为约束。

### 运行中任务列表

每轮对话开始时，系统向 agent 注入当前 session 中所有后台任务的运行状态清单。agent 无需主动查询即可了解：

- 哪些任务仍在执行
- 每个任务的 taskId、命令文本和已运行时长

清单仅在 session 中有正在运行的后台任务时注入，无运行任务时不出现。

### 终止后台任务

agent 通过指定 taskId 终止某个正在运行的后台任务。终止由后台任务管理器执行（与 session 停止清理共用同一终止路径），操作同步完成：

- 向对应进程发送终止信号
- 任务状态变为 killed，同时取消卡死检测
- 记调试日志：任务到达终态（关键事件）
- 已产生的输出保留可读，直至 session 销毁（见输出管理）
- 后续进程退出通知被忽略

## 数据流

### 任务创建与完成

1. BashTool 以 `run_in_background: true` 提交命令，任务管理器创建后台任务，状态设为 running
2. 记调试日志：任务启动（关键事件）；启动卡死检测定时器
3. 命令异步执行，输出写入磁盘
4. 进程退出后读取退出码，更新状态：退出码 0 → completed，非 0 → failed
5. 记调试日志：任务到达终态（关键事件）；取消卡死检测
6. 通知系统生成完成消息，注入 agent 消息队列（优先级 later）
7. 输出文件保留可读，直至 session 销毁统一回收（见输出管理）

### 自动后台化流程

1. BashTool 以前台模式开始执行命令，确定超时预算：agent 指定了超时参数则使用该时长，超过系统上限时钳制到上限（上限与 BashTool 超时参数上限一致，见 [bash-tool.md](bash-tool.md)）；未指定则使用系统默认阻塞预算（15 秒）
2. 走系统阻塞预算兜底时先做白名单检查：命中排除名单的命令（`sleep` 等已知无实际工作的命令）不因预算到期转后台，前台继续执行（受总执行时长兜底约束）；agent 显式设置超时的命令不做白名单检查
3. 预算耗尽前完成：正常返回结果，流程结束
4. 预算耗尽未完成（且未被白名单排除）：命令转后台（进程继续运行），此刻创建后台任务（前台执行期间不存在后台任务），状态设为 running
5. 返回 `assistantAutoBackgrounded: true`、`backgroundTaskId` 和输出文件路径，agent 被告知命令仍在后台运行
6. 后续完成时走任务完成通知流程；转后台后任务的状态管理（卡死检测、完成通知、输出文件生命周期）与显式后台化任务完全相同

### 运行中任务列表注入

1. 每轮对话开始时，Session 组装消息队列，查询当前 session 运行中的后台任务
2. 无运行任务：不注入清单，跳过
3. 有运行任务：生成任务清单（taskId、命令文本、已运行时长），注入消息队列（优先级 later），agent 在下一轮对话中看到

### 卡死检测与通知

1. 后台任务运行中，每 5 秒检查一次输出文件大小
2. 输出在增长：重置停滞计时器，继续监控
3. 输出停滞达到 45 秒：读取输出尾部内容
4. 尾部不匹配交互式提示特征：继续监控（可能是慢任务）
5. 尾部匹配交互式提示特征：向 agent 注入警告通知（优先级 next），建议终止任务并重试（如用管道输入绕过交互），此任务不再重复检测

### 停止时的清理

当 session 被停止（用户 `/stop`、父 session 级联停止、或系统优雅关闭）时，该 session 的所有后台任务进程被终止。任务状态标记为 killed，已产生的输出保留可读——停止清理不删除任何输出文件，输出回收统一发生在 session 销毁时（见输出管理）。终止后的进程退出通知被忽略——killed 状态不可逆。

停止模式按触发入口区分（详见 [session/session-execution.md](../session/session-execution.md) 停止入口节）：`/stop` 固定 Forceful（无等待、无超时——终止信号发出后不等进程退出即进入下一步，三阶段清理本身仍按序执行）；系统优雅关闭为 Graceful（等待 in-flight 操作，超时向调用方报告）；级联停止继承父 session 的模式。

清理通过两种终止适配器实现，前台和后台走不同路径：

- **前台终止适配器**：持有子进程的共享句柄，停止时直接向进程发送终止信号。子进程被立即终止，已累积的输出保留可读
- **后台终止适配器**：通过异步运行时桥接调用后台任务管理器的终止方法。后台任务管理器负责定位并终止对应进程，已写入磁盘的输出文件保留可读

Session 停止时的清理分三个有序阶段，执行顺序不可颠倒：

1. **级联停子会话**：递归停止所有子 session，确保子孙树被完整清理。Graceful 模式下每个子 session 设超时（级联超时保护，超时后不无限等待、向调用方报告该子 session 进度）；Forceful 模式直接终止，不设超时
2. **终止工具进程**：遍历会话注册的所有终止适配器，逐一调用终止方法。Graceful 模式下每个适配器设超时，避免单个僵尸进程阻塞整体清理，超时后向调用方报告该等待项；Forceful 模式直接 kill
3. **清除执行状态**：清空 LLM 状态、工具进程注册表、子会话追踪表，会话回到空闲状态。`/stop` 入口在清除执行状态后额外清空统一消息队列（见 [session/session-execution.md](../session/session-execution.md) 停止流程第 5 步）

取消信号通过令牌链传播：父会话的取消令牌触发时，子会话的 LLM 请求同步感知取消信号，避免子会话在父会话已停止后继续执行。

### 销毁时的回收

session 销毁（仅由按时间清理触发，见 [session/session-lifecycle.md](../session/session-lifecycle.md)）时，系统对该 session 的全部后台任务做终态回收：

1. 终止仍在运行的后台任务进程（终止路径与停止清理的第二阶段一致，任务状态变为 killed）
2. 回收该 session 全部后台任务的输出文件（含各终态），不留孤儿资源

销毁回收与停止清理互不替代：停止只终止进程不碰输出，销毁是进程与输出的统一终点。

## 模块关系

- **上游**：BashTool（触发后台执行、自动后台化）、Session 模块（停止时触发进程清理、销毁时触发进程终止与输出回收）
- **下游**：文件系统（输出持久化、session 销毁时回收输出文件）、消息队列（通知注入）、调试日志框架（任务启动与到达终态的关键事件记录）、agent 会话（通知被 agent 在下一轮对话中看到）
- **无关**：权限引擎（权限检查在 BashTool 层完成，后台系统不重复检查）、processor_chain（通知注入走消息队列，不走出站处理链）
